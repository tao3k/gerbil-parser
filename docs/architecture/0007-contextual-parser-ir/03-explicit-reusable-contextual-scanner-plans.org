* 2026-10-03: explicit reusable contextual scanner plans

The remaining preparation profile motivated separating validated static scanner
work from per-input state. The ownership pattern is comparable to the fixed
compiled pattern and separate match data described by the [[https://www.pcre.org/current/doc/html/pcre2api.html][PCRE2 API]]. This
transfers a staging/ownership idea; it supplies no scanner algorithm or Gerbil
concurrency proof.

=prepare-contextual-scanner-plan= takes an explicit owned snapshot of compiled
scanner IR and validates its schema, opcode contract and digest. It copies
pairs and strings, preserves DAG sharing and symbol identities, and rejects
cycles and values outside closed scalar/list data. Rule and dispatch indexes
are built once. Catalogs of at least 128 literals retain both the linear short
input variant and the trie variant selected at 64 source characters. No
process-global identity cache is introduced.

#+begin_src scheme
(def plan (prepare-contextual-scanner-plan compiled-scanner-ir))
(def first (prepare-contextual-scanner plan first-source))
(def second (prepare-contextual-scanner plan second-source))
#+end_src

Each binding creates a new scanner and initial state; delimiter queues remain
input-local. The digest string is copied per binding because canonical
checkpoint receipts expose it. Subsequent mutation of the original IR or a
bound scanner's checkpoint digest cannot change the plan or other bindings.
Caller changes to the original IR require a new plan to take effect. Callers
must avoid modifying IR concurrently during plan creation. Source strings
retain the existing ownership contract and must stay stable while scanned.
The raw IR entrypoint continues digest admission on every call.

The plan is opaque through the exported API; constructors, predicates and
accessors are private. It is not a serialized receipt. Scanner IR, opcode and
checkpoint schemas, state field count and scan semantics remain unchanged.
This is an opt-in scanner interface: =parse-source/contextual= still accepts
its existing product and prepares raw scanner IR. Full parser product plans,
public declaration-macro binding and contextual GLR state admission are not
implemented by this change.

* 2026-10-03: prepared contextual parser requests

The scanner plan is now usable through a complete contextual parser request.
=prepare-contextual-parser machine product= validates the product's schema,
base grammar, machine Parser IR digest, product digest, LR position table and
scanner admission once. It binds the generated machine, an owned scanner plan,
a private position vector and a copied product digest. Position IDs must be
symbols, matching the compiler's existing declaration contract; even a
self-consistent forged string-position product is rejected. Copying the table
spine alone would leave mutable position values shared.

#+begin_src scheme
(def plan (prepare-contextual-parser machine compiled-product))
(def first (parse-source/contextual/prepared plan first-source))
(def second (parse-source/contextual/prepared plan second-source))
#+end_src

Every request creates fresh scanner state, token accumulation and LR checkpoint.
Raw and prepared entrypoints share the same deterministic drive and artifact
construction. =parse-source/contextual= still admits raw product data on every
call. The prepared entrypoint accepts only an opaque plan and a source, so it
cannot be used with another machine argument. It copies the published product
digest per request: mutating an artifact's =grammarDigest= cannot poison future
plan requests. Scanner plans already isolate their checkpoint digest strings.

Generated =ParserMachine= AOT IR and runtime must remain immutable after module
initialization, as declared by =src/compiler/machine.ss=. This plan references
the machine; it does not snapshot its executable runtime or protect against
violating that machine contract. Prepare after initialization and driver
installation. Caller-owned product data may change after preparation without
changing the plan. Avoid concurrent mutation during preparation. Input source
strings retain their existing stability requirement while being parsed.
Changes to the product require a new plan to take effect.

This extends the internal contextual deterministic LR slice. Public contextual
declaration-macro binding, contextual GLR branch state and optional CLI
qualification remain separate. Existing generated language parsers do not
switch to this API automatically; the HCL grammar supplies the bounded
integration fixture, rather than a full language scanner implementation.

** Rejected candidate 1: scalar match selection

=best-match= currently constructs =scan-match= records while folding over rules.
The prototype removed that private record, retained selected rule/end in loop
variables and hoisted source/start reads. It preserved longest extent, rank
priority, equal form/action tie handling and ambiguity rejection. The three
existing scanner/parser/deferred suites passed in source with normal exit.
Full prepared request pairs also matched every ParseArtifact, including
rejected inputs and Unicode suffix coverage.

** Rejected candidate 2: ASCII opcode byte width

=horizontal-whitespace+= accepts only space/tab; =newline= and =newline-one=
accept CR/LF. Their consumed character width is therefore their UTF-8 byte
width. The prototype used this closed-opcode fact to avoid allocating a UTF-8
vector solely for token length, and retained the existing encoder path for
other matchers. It did not cache literal widths from mutable caller IR.
Full prepared request pairs again matched every artifact. This establishes
conformance only for the measured shapes, not every opcode or invalid input.

** Next falsifiable experiment: reduction and recognition materialization

The next probe should count the actual semantic operations before changing
representations:

1. Count generated =direct-step= production frequencies and classify pass,
   field and alias reductions, including reduction widths.
2. Count =recognition-children-field= singleton versus fragment-wrapping paths,
   and =recognition-sequence->list= calls that actually flatten a rope. The
   existing rope already gives constant-time concatenation; introducing a
   second concatenation representation is not justified by this profile.
3. Select a measured hot class, then test fusion of adjacent field/alias work
   only where the Parser IR proves the shape. Nested field scopes, empty
   reductions, byte boundaries and immutable shared children must be preserved.
   The public field setter means mutating or reusing children cannot be assumed
   safe merely because the final tree looks similar.
4. Compare complete prepared artifacts against the indexed/generated baseline
   on short, long, Unicode and rejected shapes. Source CPU admission comes
   before native compilation; native paired evidence and the original wall
   ceilings remain required for retaining a runtime candidate. Operation counts
   alone cannot qualify a change.

=src/compiler/hcl-reductions.ss=. Reduction experiments
