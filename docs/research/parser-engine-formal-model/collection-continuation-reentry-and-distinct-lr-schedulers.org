* Collection, continuation reentry and distinct LR schedulers

This extension follows the paper-to-implementation obligations above. The LR
item and finite terminal domains remain those of the existing research basis;
GC and dynamic extent are additional Scheme runtime obligations, not results
attributed to an LR paper. The universal algorithms are in
[[file:../../../formal/ParserEngine/Operational.lean][Operational.lean]], the executable counterexamples in
[[file:../../../formal/quint/GrammarPipeline.qnt][GrammarPipeline.qnt]], and the implementation controls in
[[file:../../../t/canonical-lr1-reference-test.ss][canonical reference tests]] and
[[file:../../../t/layout-boundary-test.ss][layout boundary tests]]. These models add no parser dispatch or runtime
performance change.

** Reachability, relocation and suspended roots

=Collection.Reachable= follows pair edges and vector slots from an explicit
root set. =Relocation= requires each reachable cell to be copied with renamed
references and the address map to be injective on reachable objects.
=frozen_survives= preserves a published immutable tree by induction over its
heap representation. =identity_survives= preserves equality of live references;
=private_owner_survives= preserves separation from retained live owners.

A numeric allocation frontier is not invariant under a moving collector.
The post-collection ownership statement therefore uses renamed live reference
sets, rather than comparing relocated addresses with the old frontier.
=suspended_publication_survives= explicitly includes captured continuation
roots alongside active roots. Omitting a suspended root prevents application
of the theorem; Quint includes that invalid-root-set control.

This is a collector contract, not a verification of Gambit's collector,
root discovery, foreign-pointer pinning or concurrent collection. Opaque atom
values carry no modeled heap references. The theorem does not permit foreign
mutation of a published tree.

** Dynamic extent and repeated reentry

=Reentry.commonPath= compares activation identities along the two wind paths.
Equal parameter values do not establish a shared activation. =resume= checks
and exits departed activations from inside to outside, preserves the shared
prefix, then enters target activations from outside to inside.
=resume_captured_path= derives the resulting stack through these operations;
=repeated_resume= admits repeated use of the same captured path without a
one-shot flag. =captured_context_restored= selects the captured layout context.
=captured_column_survives= connects its column reference to the relocation
contract and the captured root set.

The native control captures a continuation in the real LR action selector
following a layout shift, escapes the inner parameter scope, forces GC, and
resumes that continuation twice. Both resumed requests finish parsing, with
inner frame/column contents restored and outer frame/column identities and
contents restored on return. Inner wind hooks run three times in each
direction, while the shared outer extent enters and exits once. The action
rows are compared with an independent recursive pair snapshot after GC.

The logical activation environment follows the engine's scoped parameter
bindings. Arbitrary mutation of captured parameter cells and arbitrary effects
of wind hooks are outside this model. This is not a complete Scheme
continuation interpreter, a proof of forced thread termination, or a Rust
cancellation proof.

** Backward follow-block refinement

The actual backward builder in
[[file:../../../src/compiler/lr-follow-automaton.ss][lr-follow-automaton.ss]] computes successor-signature buckets inside each
old block. Its changed flag means that at least one old block produced more
than one bucket. Initial blocks in
[[file:../../../src/compiler/lr-conflict-candidates.ss][lr-conflict-candidates.ss]] are created from actual follow bits and are
nonempty. The model retains that essential premise.

=Backward.insert= and =buckets= construct the buckets; =buckets_mass= proves
exact occurrence preservation and =buckets_nonempty= proves each emitted
bucket is nonempty. =refine= never merges different old blocks.
=changed_grows= derives strict block-count growth from the constructed bucket
predicate, rather than assuming that any changed flag implies progress.
=rounds= recomputes signatures at every round and recurses on the measure
=vertices - blocks=. =round_bound= bounds the complete run by the initial
measure plus one. Quint demonstrates why empty old blocks invalidate that
argument. Native controls check positive, pairwise-disjoint block masks and
exact coverage of each core's forward follow mask.

Native bitset enumeration, successor-index equality, cache invalidation and
active dependency scheduling remain representation and producer obligations.
The round theorem alone does not prove these adapters or semantic quiescence.

** Canonical closure and interning

The canonical closure in
[[file:../../../src/compiler/lr-lookahead.ss][lr-lookahead.ss]] can append an owner already pending when new mask bits
arrive. This differs from the coalesced LALR scheduler. The canonical model
retains duplicate queue entries: =closure_enqueue_decreases= proves progress
with =2 * remaining facts + pending owners= because every publication consumes
at least one fresh fact. A stale publication is unchanged.

For physical core count C and terminal count T, =matrices= enumerates every
length-C mask vector bounded by 2^T. =catalogue= converts them to sparse keys,
omitting zero masks in physical core order. =native_key_admitted= proves
membership for arbitrary bounded input vectors; =catalogue_count= derives
catalogue size (2^T)^C. This is a finite upper bound, not an expected state count
or a performance claim. Native tests reconstruct dense vectors from real
canonical states and check their normalized sparse keys, mask bounds, key
uniqueness, state zero and transition endpoints.

=Canonical.intern= reuses existing keys without enqueueing them and appends
only novel keys. =Admitted= carries unique discovered keys, catalogue
membership and =pending + processed = discovered=. =admit=, =removeHead= and
=expand= preserve those invariants. =finish= runs the complete drain/expand
loop by well-founded recursion on
=2 * (catalogue size - discovered keys) + pending owners=.
=finish_quiescent= derives an empty queue and =finish_processes_all_keys=
derives equality of final processed and discovered counts. These results do
not assume a final execution certificate supplied by the caller.

Targets must be finite, catalogue-admitted and generated by a terminating
callback. Relating native hash tables, queue identities and target generation
to these operations remains a source-level refinement obligation. In
particular, the native builder's returned state count is not an independently
instrumented dequeue count; the test does not use it as such. Neither the
catalogue bound nor queue accounting proves language completeness or conflict
resolution semantics.

** Complete LR table publication from generated rows

*** Paper obligation and native owner

[[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing, sections 2.1--2.2]] specifies states by LR items,
lookahead prediction and goto, and relates accepted input to a grammar
derivation. A dimensionally valid action table alone does not establish that
contract. Each retained shift, reduction or acceptance needs its item origin;
the publication process must preserve those origins through every state row.
Conflict-policy language completeness is a separate obligation.

The native owner is =compile-lr-spec/selected= in
[[file:../../../src/compiler/lr-compiler.ss][lr-compiler.ss]]. Its final tail builds action rows, rejects a publication-count
mismatch, builds gotos, validates both vectors, then constructs the spec. The
spec retains the same production, nullable, FIRST, action and goto values.
LALR, canonical, partitioned and follow-partition constructions add their
existing metadata in different branches. Metadata remains in the schema/spec;
this work introduces no versioned API, namespace or file.

*** General composition and source admission

[[file:../../../formal/ParserEngine/TablePublication.lean][TablePublication.lean]] removes the previous final-publication premise from
this layer. For arbitrary lists of state-event plans and arbitrary finite
terminal widths, =row_origin= derives every retained alternative from
=vector_layout_publication=. This includes forks and layout-suppressed raw
reductions. =complete_table= then derives =TableSupported= from individual
producer admission checks. It does not require a caller to supply support or
publication histories for the completed table.

=cellsRow= freezes resolved cells and their layout fallbacks before request
selection. =writeRows= publishes those final rows, derives the publication count
by recursion and writes each state slot in order. =published_slot= proves every valid physical slot, while
=untouched_after= and =stored_rows= cover the entire address domain, including
absent/out-of-range states. =physical_table_exact= connects table reads from
that computed store to the logical table. The =engine= constructor composes
this result with the existing raw-request engine and selector certificate.
The existing =RawRequest.complete_request= theorem applies to this engine;
final-table support is derived inside construction rather than passed again.

The Scheme reader now retains the entire actual selected compiler declaration
as data. An independent, manually maintained Lean schema admits the complete
final publication tail, including every operand, count guard, validation call,
field binding and algorithm branch. Earlier lowering, completion, FIRST and
state-builder code is outside this tail's source admission. Mutation witnesses
reject removed validation, a tautological count check, crossed action/goto
fields and crossed nullable/FIRST names.

=Source.execute= gives only this recognized tail a restricted interpretation.
It rejects a false validation result or mismatched reported row count.
=complete_publication= combines source admission, the count computed from row
writes, every physical state slot, exact logical/physical table correspondence
and semantic action support. This source-specific interpretation is not a
general Scheme evaluator; its vector/loop correspondence and producer
refinements remain explicit implementation boundaries.

*** Extracted observations to the published physical table

=Events.extract= models the exact item branch order. A present terminal index
selects shift, including index zero and target zero; a missing shift target
fails before installation. An incomplete nonterminal produces no action.
A completed item expands all enumerated lookaheads and distinguishes physical
production zero from authored reductions before semantic decoding.

=Events.extracted_admitted= works for arbitrary grammars, production IDs, dots
and lookahead lists. Its inputs are explicit observations of the production
vector, current item set, next symbol, goto and completed lookaheads. Authored
production membership is derived from a nonzero index into =augmented :: g=;
augmentation identity is derived from index zero. Neither is an additional
final-action support assumption.

=Events.plan= propagates failed extraction rather than silently dropping a
missing shift. =plan_admitted= composes every generated candidate across an
arbitrary observation list. =published_from_extraction= feeds that result into
the previous frozen-row/physical-store publication theorem. The table boundary
therefore consumes observed-record facts and an extraction execution relation,
rather than a caller-supplied admission property of the final action table.
Item/goto/nullable/FIRST producer facts still need their own source refinement.

*** Conflict and validator fidelity

=shift_reduce_exact= and =reduce_reduce_exact= prove the native condition order
agrees with the existing abstract decisions for all optional priorities and
integer ranks. =same_shift_rank= proves the retained same-target shift carries
the maximum present rank; =same_shift_tie= retains the current cell on ties.
The complete dispatcher schema preserves fork handling before non-associative
rejection and preserves argument reversal for reduce/shift pairs.

The actual =union-values= folds only the right list into the left list.
Existing duplicates on the left survive; newly observed values are appended
once. =union_members= proves the exact membership union without equating this
operation with append or claiming that an arbitrary left list becomes unique.
The source tests explicitly retain a duplicated left reduction. The older
=Construction.installChoice= remains an origin abstraction; it is not relabeled
as exact fork representation or complete conflict-policy language equivalence.

The validator model starts with untyped values, including signed integers and
unsupported host-value classes. Its decoder recognizes only atomic actions,
flat forks of at least two atomic alternatives and the closed layout wrapper.
Recursive forks and malformed arities cannot acquire meaning by fallback.
=untyped_admission= and =action_members= prove that every accepted member has
its own key/range check. Priority ranks may be arbitrary integers, including mathematically integral
flonums accepted by Scheme =integer?=. The untyped model retains that category
and normalizes only its rank value. Such flonums are rejected as IDs by
=fixnum?=, even when their value is zero. Numeric classification, normalization
and ordering are explicit host premises. Target and
production IDs must also satisfy the host-supplied nonnegative fixnum ceiling.
The terminal decoder must preserve native key equality. These are explicit
representation contracts, not assumptions that every Lean Nat fits a fixnum.

=rows_admit= proves for arbitrary row lengths and initial seen sets that an
accepted row has valid vocabulary/value callbacks, no initial-seen key, and no
duplicate keys. Source admission retains the check-before-insert order and the
original return value. This is structural table admission, not =TableSupported=.
The outer validator's production-derived layout/vocabulary, dimensions and
reachable-acceptance queue remain separately owned composition obligations.

*** Outer queue: discovery is not renumbering

The queue stores native state IDs, including a discovery sequence such as
=0, 2, 1=. It must not reuse a canonical-interning queue whose payload is a
discovery ordinal. The model's =remaining= list represents the complement of
the native =seen= vector. First discovery removes one unseen ID and appends it
to the FIFO; duplicates leave both unchanged.

The measure =remaining.length + pending.length= is conserved by enqueue and
strictly decreases at dequeue. =run= therefore terminates by well-founded
recursion, without caller-supplied fuel or a presumed completed certificate.
=run_correct= establishes reachable acceptance on success and a closed seen
set on exhaustion. =exhaustive_no_accept= and =acceptance_iff= give both sides
of the decision. =ValidatedGraph.outer_queue_exact= obtains the finite-domain
premise from admitted action/goto targets, including signed-index checks.
Positive state count is required because the source enqueues state zero.

The accepting iteration still enqueues action and goto successors before
returning. =pop_expand= justifies the model's expansion/dequeue normalization;
it does not remove these source effects or mask an invalid target read.
This theorem concerns reachable acceptance in the admitted graph. Production
vocabulary extraction, dimensions and layout-capability discovery remain
separately owned input-admission obligations.

*** Mutable resolver replay: order, private failure state and composition

=Replay.run= takes arbitrary initial stores, event sequences and an exact
supplied resolver. It assumes neither associativity nor a final conflict
history. =slot_projection= proves that every key in a successful mutable
execution equals chronological logical replay at that key. =run_append=
composes arbitrary prefixes: a failed prefix retains its private store and
error, and the suffix never executes.

The source records a raw layout reduction before invoking the resolver.
=failure_storage= retains that write on error, while preserving the previous
action and first-touch list. There is no invented rollback, successful row
publication, or execution of later candidates. First-touch order and duplicate
raw reductions remain represented independently of the resolved action slot.
The Scheme controls execute the unchanged extracted closure with the real
conflict dispatcher, including rejection and fork construction.

The theorem is generic in the resolver; the preceding native-action results
own its SR/RR/rank policy decisions. =Construction.installChoice= remains an
origin abstraction. Exact mutable replay is not relabeled as an unconditional
equality between native fork representation and that abstraction.

*** Whole physical extraction: core coordinates and mask ordinals differ

=Records.state= reads the state item list and its initial lookahead offset,
then executes the complete ordered scan. The physical view distinguishes an
unavailable field from a valid =#f= payload. Shifts read target and production
precedence without reading a mask. Incomplete nonterminals read neither;
completed items read their mask. Every item advances the mask ordinal,
including branches that do not consume a mask.

=scan_reads= and =state_reads= derive every record's exact read at
=stateOffset + itemOrdinal=, for arbitrary item counts and sparse core IDs.
=dense_read= derives production/dot coordinates from the previously proved
physical owner/offset write replay. =mask_keys= accounts for every set bit
inside the terminal domain. The source checks include the state-list guard,
per-state bindings, complete =for-each= traversal and production precedence
accessor, in addition to the item callback.

A model mismatch was corrected: shift admission previously demanded an item
whose lookahead was =none=. Native shift extraction uses the production/dot
core and ignores that field. Admission now requires a real item with the same
production and dot, retaining its actual lookahead. The unchanged semantic
=CellSupported= conclusion follows from that witness. A directed proof control
uses a table containing only a non-EOF lookahead; no fabricated EOF item is
inserted.

=PhysicalFacts= states catalogue/item/goto/lookahead coherence at the actual
physical reads, as an obligation of their producers. =plan_admitted= derives
candidate admission from those reads, and =published_from_records= composes it
with frozen-row publication and the certified engine's table-support boundary.
Producer coherence, supplied conflict-choice interpretation and host primitive
contracts remain explicit; this is not unconditional whole-compiler closure.

*** Directory and core-symbol production

=collect_reverse= relates the native reverse accumulator to stable insertion
in source scan order. =catalogue_members= and =catalogue_unique= prove exact
membership and uniqueness with EOF seeded before RHS scanning. Operand
annotations never become directory keys. =catalogue_roundtrip= proves that
installation into the native index and publication into the terminal vector
agree at every generated ordinal, even over arbitrary prior stores.

=CoreSymbols.fill= models the actual source writes: a production writes only
its RHS bases, then advances by =rhs.length + 1=. =symbol_at= proves each
written value; =complete_at= proves the skipped completed slot retains its
initial =#f=. This includes epsilon productions and avoids inventing a write
to a slot that the source leaves initialized.

=terminal_producer= combines those results for an arbitrary actual RHS
terminal occurrence. Its physical core slot, installed index, terminal vector
entry and validator vocabulary all designate the same canonical base. The
ordinal is derived by catalogue membership and the actual write replay; no
caller supplies a completed index/vector agreement property.
=eof_ordinal= proves that EOF is always installed at ordinal zero. =keyCode=
is computed from the installed directory, and =key_code_exact= proves every
non-EOF encoding; a caller-provided ordinal mapping is not required.

*** Lookahead rows and physical record consumption

=Lookahead.starts_at= proves prefix offsets for arbitrary rows. =offset_at=
includes the source's final sentinel write and shows it cannot overwrite a
real state's offset. Empty adjacent rows may share an offset. =packed_pair=
proves that core and mask projections preserve the same row/ordinal address;
a zero mask remains an entry and cannot be dropped as absent.

=publish= reconstructs the actual record consumer fields from ordered source
rows and the two write passes. =published_record= derives state item, state
offset and mask reads together. =published_bits= transports a producer-mask
interpretation through those actual writes. It assumes no equality or support
property of the final event list or action table.

=published_quiescent= further composes the existing
=Worklist.batch_quiescent_exact= theorem with the generated physical mask.
A completed worklist execution establishes Horn-program entailment; final
semantic equality or a final closure certificate is not assumed. The queried
mask read is proved successful before the totalized bit view is used, so an
unavailable physical field is not silently admitted as a zero mask.

The propagation-program construction and its relation to the real native
execution trace remain parser-owned obligations. A conditional worklist
execution theorem is not a proof that an arbitrary source-produced graph
implements the paper's lookahead relation. This boundary must remain visible
when connecting FIRST/nullable, prediction, transitions and viable items.

*** Vocabulary, capability and outer validator

=goto_key_exact= admits exactly the declared LHS names, rather than every
RHS reference or an annotation name. =action_key_exact= admits EOF or a
terminal in the generated directory, subject to the declaration-derived
layout predicate. =layout_exact= accounts for both layout-end actions and
layout-start/layout-next RHS bases. =catalogue_admitted= derives the key
callback for every generated directory entry.

Two source predicates intentionally remain distinct. The validator derives
layout capability from layout terminals or layout-end actions. The action
builder enables raw-reduction fallback retention only from layout-end
actions. =fallback_capable= proves the latter implies the former; a directed
control shows a layout-terminal-only declaration makes the converse false.
This work does not alter either runtime predicate or presume they must agree.

=Admission.normalized_actions= and =normalized_gotos= derive graph bounds from
the actual declaration callbacks and per-entry action admission.
=queue_after_declarations= feeds those bounds into the previous exact queue
result. =table_check_exact= composes the production-count ceiling, positive
state count, equal action/goto dimensions, row callbacks and reachable
acceptance. Earlier rejection cannot be replaced by success in the graph
layer. Duplicate-key handling remains owned by =Validator.rows_admit=.

The typed view starts with admitted canonical production operands and keys.
Native symbol/string identity, positive literal validation and the typed

behavior remain external premises. The semantic relation of produced states
and lookaheads to viable items, and the exact native conflict representation
