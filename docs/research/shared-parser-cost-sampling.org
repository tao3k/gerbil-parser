#+title: Shared parser cost sampling and optimization admission
#+startup: overview

Implementation baseline: PR #13 =ecebab9= plus this slice. This module closes
the ownership gap between the [[file:artifact-publication-cost-boundaries.org][publication storage experiment]],
[[file:engine-reduction-generation.org][shared reduction implementation]] and existing cross-language LR benchmarks.
It is part of the same recognition -> reduction -> canonical publication study,
not another language-specific optimization proposal.

* Research obligation and implementation gap

The independent event-container control closely tracks event-publication
allocation in the measured families. It does not reveal a large removable
traversal allocation budget. Recognition/reduction experiments therefore need
consistent complete-product sampling and admission across languages.

The repository already has cross-language selected-derivation counts, prepared
LR controls, independent GLR publication equality and matched complete-request
comparisons. Those mechanisms are retained. The gap was ownership: the generic
batch sampler, GC snapshots, percentile selection and allocation summaries lived
in =t/benchmarks/gql/runtime/matched-stages.ss=. The cross-language LR benchmark
imported that GQL module and renamed =measure-gql-component=. A shared algorithm
therefore acquired an unrelated language dependency and language-tagged receipts.

* Implemented owner and consumer contract

=t/benchmarks/parser-stage-cost/benchmark.ss= now owns the shared operations:

| Operation | Contract |
|-----------+----------|
| =measure-parser-batch= | Integral, nontruncated calls; no implicit warmup, forced GC or logging; complete expected-result equality outside the interval |
| =measure-parser-component= | Validate sample/batch dimensions before warmup; one warmup and initial GC; preserve naturally occurring GC in timed observations |
| =sample-at-percentile= | Select the actual ranked observation, retaining its own CPU/GC counters; sample identity resolves ties |
| =sample-gc-snapshot= | A new collection exposes only the latest whole-VM snapshot; a no-GC interval cannot inherit a stale collection |
| =component-allocation-summary= | Single-caller intervals admit only nonnegative, no-GC deltas; thread-switching process observations do not acquire request allocation ownership |

GQL workload selection, GQL actors and the cross-language LR benchmark import
the shared operations directly. The old GQL sampling definitions, names and
rename adapter are removed. GQL stage selection and directed-token reconstruction
remain language-owned. Shared receipts use =PARSER-GC-BASELINE=,
=PARSER-COMPONENT-SAMPLE= and =PARSER-COMPONENT-SUMMARY=; final workload receipts
still identify the workload. This is a direct migration, without compatibility
aliases or a versioned namespace.

The native local diagnostic plan compiles the shared dependency before GQL
consumers and checks its compiled product in prepared mode. Its required
receipt names now match the shared sampler. The existing conformance build
catalog already owns the shared module and its focused test suite.

* Scheme witness and design questions

#+begin_src scheme
(import :gerbil-parser/t/benchmarks/parser-stage-cost/benchmark
        :gerbil-parser/languages/arithmetic/parser
        (only-in :gerbil-parser/src/runtime/artifact parse-artifact-valid-for-source?))

(let* ((source "1 + 2 + 3")
       (reference (parse-arithmetic source)))
  (unless (parse-artifact-valid-for-source? reference source)
    (error "reference failed source admission"))
  ;; A shared sampler receives a complete result; no GQL import is needed.
  (measure-parser-component 'arithmetic-complete 20 20
    (lambda () (parse-arithmetic source)) reference)
  ;; The inclusive observed stages serve attribution, not a latency comparison.
  (measure-parser-stages parse-arithmetic source 20))
#+end_src

** Question: why does this improve the DSL and Scheme abstraction boundary?

Language declarations continue expressing syntax/rules and parser metadata.
Sampling, VM counter admission and batch validation are shared algorithms,
implemented as named procedures over complete results. A language selects a
workload; it does not implement or rename a different sampling policy. The
canonical product remains the comparison boundary. No new =deflanguage= slot,
grammar-level profiling declaration or public semantic storage protocol is added.

POO dispatch remains appropriate for extensible parser capabilities and prepared
representation selection. A homogeneous batch's arithmetic, ordering and
counter validation require no extensible type decision. Adding generic methods
here would not improve the scientific contract or remove grammar complexity.

** Question: why is this scientifically testable?

Existing controls preserve the wall-ranked observation's own CPU/GC values,
reject stale GC attribution, retain unavailable thread ownership and reject
truncated or changed products. New language-independent controls require invalid
component dimensions to fail before any warmup call, count every admitted batch
call and preserve an original thrown condition. The diagnostic plan explicitly
owns the shared dependency. The cross-language caller still validates prepared
and complete canonical products independently and reports actual source routes.

Neither copying a sampler nor introducing a new owner proves a runtime speedup.
Prepared LR and full-source costs are different experiments, not additive pieces
of one request. Observer capture and derivation replay remain untimed controls;
they must not be silently included in a production latency claim. Earlier
rejected stack, unary-corridor and deferred-consumption candidates remain rejected.

* Qualification and next decision

Qualification must cover the shared native producer, all migrated consumers,
source contract controls and cross-language complete requests. Exact-head Linux,
macOS and Rust AOT CI remains a separate gate. The next optimization needs a
measured recognition/reduction construction boundary and complete-request
admission, rather than another GQL-owned measurement primitive.
