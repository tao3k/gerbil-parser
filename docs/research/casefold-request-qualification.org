#+title: Casefold vocabulary and complete request qualification
#+startup: overview

Part of [[file:shared-ranked-scanner-execution.org][the integrated execution study]].
Historical revisions, failed experiments and receipt limits retain their original scope.

* Shared literal vocabulary and casefold lookup qualification

A row-without-literals guard alone changes none of the measured allocation
values in the initial twelve-route child. The next candidate reuses the shared
literal trie representation for case-insensitive LR lookup. One prepared
vocabulary is shared by all action rows; the original row index still admits
only the current state's entry and preserves first duplicate semantics.
ASCII prefixes are converted while traversing the trie, avoiding a new whole
uppercase string. Non-ASCII input delegates to the original whole-string
Unicode conversion. The exact literal lookup retains priority over normalized
lookup and token-kind fallback. There is no language hint or loader option.

The trie builder also owns bounded and ranked literal preparation. Existing
ranked matching, precedence, declaration order and mode admission stay in their
original execution loops. Independent action-index tests compare the new
casefold operation with the original whole-string conversion across empty keys,
prefixes, list/table boundaries, duplicate entries, row-specific misses and
Unicode mappings. The following native qualification bounds the performance claims.


Native construction initially fails the five-second idle fence twice, at
54.246 and 60.068 seconds. The runtime object completes when selected real GCC
pass products are observed, but the later macro-phase compilation fails that
fence at 73.113 seconds. Gerbil's compiler driver deliberately drops ordinary
GSC C options for the macro phase (=gsc-cc-options= with =phi?=), so runtime
instrumentation does not cover that phase. Compiling the same generated macro
source with the SDK GSC and selected GCC diagnostic products completes in
14.996 seconds. Compiler and optimization flags remain unchanged apart from
diagnostic output. An all-pass diagnostic attempt writes about 679 MB and fails
the total fence at 127.608 seconds; it is not a successful build receipt.

** CPU rejection and verifier negative controls

CPU benefit admission requires both unchanged Arithmetic controls to have child
median ratios within 0.95--1.05 and an observed ratio range containing one.
A stage must also have its slower candidate child median below 0.95 times the
faster reference child median. All timed CPU samples, including GC, participate.
This is a conservative repeated-run gate, not a statistical confidence interval.

The unchanged prepared Arithmetic ratio is 0.9057; its unchanged source ratio
is 1.1933. The control gate therefore fails. No complete-parser CPU benefit is
admitted. Descriptive ratios of child medians for the larger identifier padding
are 0.6851/0.6823 at prepared boundaries and 0.8485/0.8749 at source boundaries.
Short prepared GQL has ratio 1.0687. None of these ratios is promoted to causal
CPU evidence while the controls drift. The smaller-padding, larger source
request also has ratio 0.9856, preserving a useful near-zero result.

The first verifier attempt rejects a fractional allocation summary: converting
raw counters to exact integers produces an exact rational quotient, while the
sampler publishes a flonum. Summary parity now explicitly compares the sampler's
flonum representation; exact integers still own all saving calculations. No
tolerance or admission threshold is relaxed. The corrected verifier completes
in 15.208 seconds with =CASEFOLD-REQUEST-EVIDENCE-OK=.

Three controlled corrupted receipts are rejected: an allocation counter changed
by eight bytes, a CPU summary changed by one millisecond, and a missing completed
workload marker. The negative-control child completes in 7.132 seconds with exit
zero and =CASEFOLD-EVIDENCE-NEGATIVE-CONTROL-OK=. No forged positive receipt is
stored in the repository. Validation and replay remain Scheme-owned.

* State-initial admission experiment: withdrawn

A proposed dispatch refinement added a 26-bit uppercase ASCII initial mask to
prepared LR action rows. It rejected an ASCII letter before walking the shared
literal trie when that state's vocabulary could not admit that initial. Empty
strings, punctuation and non-ASCII initials retained the existing path; a later
Unicode character still used whole-string conversion when traversal reached it.
The implementation followed the SDK's =fxarithmetic-shift=/=fxand= idiom, also
used by its vector utilities. No language-specific rule was introduced.

The 44-case, seven-module semantic gate passed in 16.829 seconds. The independent
whole-string oracle now includes =ZÉ=, =+É=, =zé=, =xé= and =+é= to exercise row
admission before a later Unicode character, as well as punctuation and existing
cross-state, duplicate and entry-identity controls.

** Complete-request decision

The same twelve complete-request stages ran candidate/reference/reference/
candidate, twenty samples of twenty calls each: 19,200 timed calls. Both variants
used the =9184d01= Scheme graph; only the action-index object changed (=o4= mask,
=o3= original). LR =o17=, lexical =o6= and the native benchmark caller remained
fixed. Children completed in 19.216, 17.019, 16.916 and 17.628 seconds. Compiler,
heap and qualification fences stayed unchanged. The concurrently published
=ad8c6a3= change affects Rust execution and documentation, not this Scheme graph.

The shared Scheme verifier now exposes
=compare-casefold-request-cpu-receipts= for dispatch-only experiments. It uses
the same raw-sample reconstruction and CPU gate, while requiring every repeated
complete-request allocation counter to remain exactly unchanged. The verifier
admitted 920 no-GC intervals and completed in 12.143 seconds. Arithmetic control
ratios were 0.9712 prepared and 1.0460 source, satisfying the existing control
gate. No stage satisfied the repeated CPU benefit gate.

| Request | Units | Prepared median ratio | Source median ratio |
|---------+-------+-----------------------+---------------------|
| Padding 32 | 64 | 1.1469 | 1.0672 |
| Padding 32 | 256 | 0.9829 | 1.0430 |
| Padding 256 | 64 | 1.0576 | 1.1062 |
| Padding 256 | 256 | 0.9439 | 1.0760 |
| Short GQL control | 64 | 1.0248 | 1.0640 |

Ratios divide the sum of two candidate child CPU medians by the sum of two
reference medians. They are descriptive, not confidence intervals. The smaller
prepared request is slower in both candidate children than both references;
the apparent 0.9439 result does not repeat across children. This experiment does
not justify publication. The production mask and its native/static products
are removed. The original shared trie remains, with its previously established
complete-request allocation savings. The additional Unicode oracle cases and
allocation-preserving CPU verifier remain as reusable qualification tools.


* Guarded CPU controls and lookup workload coverage

The current =benchmark-lr-casefold= replaces the earlier count-only component
with complete vectors of original action entries. Before measurement it checks
entry identity for every state. The reference now skips rows without literals
before calling =string-upcase=, matching the production guard. Historical early
miss ratios above therefore do not qualify this stronger reference.

The existing Scheme batch sampler measures process user plus system CPU from
Gambit process-statistics slots 0 and 1. ASP's nearest-rank percentile helper is
reused. The ASP micro-kernel source uses =cpu-time= and a minimum batch duration;
its baseline-subtracted operation budget is not substituted for this paired
parser comparison. Natural GC remains part of measured CPU. Wall time and
allocation observations are retained but cannot satisfy the CPU gate.

Each workload has twenty ABBA/BAAB groups, bracketed by two twenty-group
identical-reference controls. Both control P10/P90 ranges must stay within
0.90..1.10; production P90 must be below 0.95. Every batch must resolve at least
one millisecond of CPU. These decisions are reported separately from successful
completion and semantic equality. A false admission is not a correctness failure.

The native twenty-iteration matrix completes in 68.574 seconds, exit zero,
with =LR-CASEFOLD-CPU-CONTROLS-OK=. It executes 68,016,000 timed state lookups,
including controls, across 2,834 actual GQL rows.

| Workload | Production/reference CPU P50 | CPU P90 | Stable controls | CPU benefit admitted |
|----------+------------------------------+---------+-----------------+----------------------|
| Early miss, 43 characters | 0.2116 | 0.2742 | No | No |
| Early miss, 267 characters | 0.0414 | 0.0501 | No | No |
| Keyword hit, match | 2.1993 | 2.7419 | No | No |
| Late miss, matching | 1.5871 | 1.9155 | No | No |
| Unicode fallback, eclair with accented initial | 1.0594 | 1.4663 | No | No |

These observations expose a workload boundary missing from the old long-miss
component. Uniform traversal of every state is a diagnostic distribution, not
the state frequencies of complete requests. Short hit and late-miss ratios
must not be hidden by long identifier results or described as portable causal
regression percentages while the identical-operation controls drift.

A focused repeat selects =early-miss-43= with 200 iterations using the same
entry oracle, guard, order, native objects and admission thresholds. It completes
in 87.556 seconds, exit zero, with the same completion marker. Its 136,032,000
timed lookups produce CPU P50 0.1902 and P90 0.2076. Before-control P10/P90 is
0.8781/1.0963; after-control is 0.8039/1.1555. Increasing the batch does not make
these controls pass, so the repeat also refuses CPU admission. The 120-second
total and five-second real-progress watchdog are unchanged.

Receipt stems are =parser-cpu-controls-a= and
=parser-cpu-controls-short-large=. Raw paired batches retain CPU, wall and GC
observations; no frozen engine or JSON result snapshot is checked in. The
historical matrix preceded the final single-entry-point consolidation and the
one-millisecond admission check; the larger repeat uses the consolidated body.
Final source compilation and focused semantic qualification are recorded below.

The next engine decision must address the crossover between bounded keyword
lookup and early rejection of long identifiers. A dispatch change needs matched
complete-request CPU qualification as well as hit, late-miss and Unicode
controls. This benchmark change ships no new runtime optimization and does not
claim that the Bash/tree-sitter throughput gap has closed.
