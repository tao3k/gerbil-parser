* Implementation: single-runtime Scheme test preparation and Workers

The Scheme Suite entry starts one =gxi=. A single preparation owner admits the
native FFI dependencies and expands each source test module once before any
Suite executes. Its loaded-module and interface caches survive the whole run.
The runtime must finish module initialization before Worker execution; runtime
loading and source expansion are not concurrent test jobs.

The repository runner accepts an explicit =--workers N= argument before its
source roots and =--remaining-conformance= option. This is repository scheduling,
not a Gerbil configuration: official =gxtest= and =TestConfig= have no Worker
count option or =GERBIL_TEST_CORES= environment variable. Without this argument,
the repository runner queries Gambit's =##core-count= directly, bounded again
by the number of admitted modules. CI uses this same portable default on Linux
and macOS; it does not launch another interpreter or depend on shell =nproc=. The two-Worker negative controls explicitly
request two to exercise their rendezvous contract, not to set CI capacity.

The runtime shares a 3 GiB heap budget. Loading the full source suite exceeded
the previous 1 GiB budget before execution; this budget covers all loaded modules
and Workers. The inherited POO Case profile uses the same absolute heap
cap because its sampler measures process-wide memory; its growth, sampling,
failure, and duration policies remain inherited unchanged. Each module owns its
=std/test= harness and thread-local test parameters;
shared-runtime barrier controls require two modules to rendezvous in one process.
Modules may export a symbolic =test-worker-affinity= for runtime thread ownership.
Modules may independently export a boolean =test-worker-exclusive?= for CPU/GC
or wall-time admission. All resource-contract owners declare that constraint.
Worker zero remains the caller across parallel and exclusive phases, preserving
ABI thread ownership. An official =std/sync/barrier= drains preceding console
messages before resource admission. The phase barrier creates no test progress.
Declared affine owners execute on the same persistent Worker; independent modules use
the shared queue. The output supervisor never moves a test onto another thread.
Failures stop new admission, join active Workers, and return a failing status.
The original five-second silence and ninety-second module budgets remain;
preparation time is deducted from the execution budget. A timed-out thread ends
the runtime rather than continuing with partially mutated state.

The conformance build has one content-admission owner. Its S-expression receipt
covers project sources, dependency products/sources, SDK, compiler/environment,
and the native executable plus loadable helpers. SHA-256 and file modes are
checked, failed or input-mutating builds cannot publish a usable receipt, and an
OS file lock releases on exit. Source-only test interfaces removed by
=prepare-gxtest!= are deliberately outside the retained output identity.

CI restores an isolated conformance product store. Only an exact content match
can copy its declared executable/helper products into the working library;
dependency/package cache restoration remains a separate owner. Scheme controls
exercise unchanged inputs, changed/corrupt/missing products, corrupt receipts,
failed preparation, store recovery/corruption, and mutation during preparation.
These changes remove repeated process startup and unchanged preparation work;
no end-to-end speedup is asserted without a matched complete-call measurement.

* Implementation: disjoint compiled and source execution ownership

The compiled conformance semantic entry runs every declared Suite in one process,
checks Suite object identity for repetition, and enforces the original ten-second
budget for each group. The outer supervisor retains its five-second idle fence.
Research commands with process-owning entrypoints remain separate.

=scripts/test-plan.ss= compares the build catalog, imported Suite names and actual
Suite execution declarations. Missing owners, omitted Suites and repeated execution
fail admission. Following a successful compiled gate, CI passes
=--remaining-conformance= to the source runner. Fully covered modules are excluded before
source preparation; the remaining modules share the existing runtime and Workers.
The default source runner still qualifies every source module when requested.

GQL support is compiled as one union for local diagnostics, while CI consumes the
products of its prior preparation owners. Missing products fail before execution.
Workspace Rust qualification includes its source-policy integration test, so CI
no longer pays for a separate invocation of that same test.

Compilation also compares each module's actual phase-zero =-test= exports with
its imported conformance Suites. Public expander metadata is inspected with
runtime evaluation disabled. This catches additional exported Suites even when
all handwritten import declarations are internally consistent. Current-head
source-versus-compiled Case names are compared before admitting the partition.

Source-only Suite declarations cover genuine source admission boundaries. The
SANY closure Suite needs dynamic module loading for its portable-build rejection
control. It runs in the source runtime; other Suites from the same file run in the
compiled runtime. Declared ownership has a complete union and an empty intersection,
checked against actual exported Suite names during compilation. Source selection
uses the same validated ownership and does not repeat the compiled Suites.

Python process/compiler controls run once per Scheme CI platform. Ubuntu coverage
is retained there; the Rust-only Ubuntu job no longer repeats the same discovery.
macOS controls remain separate platform evidence.

The old =t/versioned-language-pack-test.ss= forwarding module is removed. It had
no Cases of its own and re-exported language leaf Suites already discovered from
=languages=. Source admission now requires each test binding to belong to its
module and each Suite object to have one owner. Re-exporting leaf Suites or
admitting one Suite object twice fails instead of multiplying execution costs.


* Failure visibility and historical Darwin startup qualification

Regular run =38760618212= failed its Darwin DSL research semantic process with
an idle timeout before any Suite receipt. The preceding conformance failure
control was expected and its step passed. That negative assertion is not the CI
root cause. Its exact native artifact's ranked subcommand exited successfully in
1.398711 seconds locally, and in 1.395143 seconds with the CI default heap policy.
These historical subcommand diagnostics do not reproduce or repair the full CI
semantic timeout. Full local replay is relocation-sensitive because diagnostic
tests retain the original compiler source locations. It is not counted as current
native semantic acceptance.

The run published product archives but no qualification-log artifacts. The
artifact uploader defaults omit the hidden =.data= directory. All existing
=.data/**/*.log= uploads now explicitly include hidden files, keeping their
existing file glob and retention. Unexpected process exits also publish status,
reason, acknowledged native phase, elapsed time and the final 8192 characters of
real child output before raising. This adds no heartbeat, extends no deadline,
and does not accept a failed exit. A controlled child exiting 3 retained its
failure status while exposing its native phase and output tail; all four
conformance process controls still passed. The historical Darwin runtime timeout
remains unresolved pending reproducible stack or child-stage evidence.

* Canonical LR corpus preparation ownership

Regular run =38773656015= at PR head =48607f3= exhausted the existing Source
owner budget in =t/canonical-lr1-reference-test.ss= while continuously checking
parse equivalence. Its helper called public =lr-parse= twice per enumerated
word. That entry constructs =lr-prepare= on every call, repeating the same
immutable grammar preparation throughout one sweep.

Lean's =prepared_corpus_preserves= gives the pure preparation/execution equality;
=corpus_preparations_saved= charges two preparations per sweep instead of two per
word. Native execution must additionally preserve fresh request state and input
ownership. The helper now retains one prepared runtime per parser within the
sweep. Every word still allocates its own tokens and executes the full parser.
There is no global preparation cache or mutable token reuse. A new control
compares prepared and fresh public requests across accepted words, rejected
words, and acceptance after rejection. Its first fixture invocation mistakenly
passed a positional construction argument as a keyword; that failed run is
retained and the call corrected without changing parser expectations.

The corrected four-owner batch passed in 23.875752 seconds: canonical LR 22
Cases, Rust syntax 17, Source index 7, and Rust generation 12. This is local
functional/scheduling evidence. It is not a matched Scheme CPU measurement of
the sweep or remote macOS acceptance.

The separate manual run =38773702045= stopped earlier in the source callback
history control. Its child log contains only =HISTORY-COMMIT-START= before the
five-second idle fence. This establishes a pre-first-module-admission boundary;
it does not identify the exact loader operation or prove that the corpus change
repairs that earlier failure. Both failures retain their original deadlines.


** Source-caller import admission before script expansion

A local replay of the original history command stopped in 5.583568 seconds with
zero child-log bytes. SDK =gerbil/main.ss= documents Gambit's script =##begin=
wrapper, and =runtime/eval.ss= compiles begin bodies before evaluation. A
script's first expression is therefore not a reliable boundary before its
static import expansion. Its runtime preference/preload expressions can be too
late to govern that expansion. This explains a possible cold admission path;
the original remote 21-byte log does not by itself establish its exact stack.

The CI invocation now uses the existing =preload-test-imports= in a preceding
=-e= expression of the same =gxi=, then executes the original source script. The
shared helper admits the script's declared dependencies through the official
loader with actual module/interface boundary tracing. Every history assertion
and native callback still executes from the same source caller. There is no
extra process, synthetic heartbeat, timeout increase, or conversion of the
control to an AOT caller. The revised invocation passed locally in 22.491491
seconds with the unchanged five-second idle and 90-second total bounds. This is
local source-caller acceptance; current-head macOS CI remains an independent gate.
