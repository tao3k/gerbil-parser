#+title: gerbil-parser

A programmable syntax engine in Gerbil Scheme, with declarative language packs,
lossless parse artifacts, and Rust integration.

Languages declare syntax and metadata; the engine owns scanning, grammar
normalization, LR construction, parsing and result publication. Hygienic macros
and POO prototypes provide constrained extension points. Gerbil remains the
compiler authority for generated Rust products.

This is an active implementation and research project. Supported syntax and
portable products are qualified per language and target; a shared authoring
interface does not imply complete language coverage or backend parity.

* Language authoring

A language pack exposes three Scheme interfaces:

| File | Responsibility |
|------+----------------|
| =grammar.ss= | Declarative syntax and pinned grammar resources |
| =parser.ss= | Production POO Loader, metadata and parse entry |
| =parser-test.ss= | Development Loader, fixtures and declarative conformance tests |

Grammar sources and corpus files remain resources beside these interfaces.
Versions, contracts and source digests belong to metadata, not versioned module
names. Scanner implementations, parser state and C/Rust bridge code belong to
the engine.

For example, a small identifier language declares its syntax in =grammar.ss=:

#+begin_src scheme
(import (only-in :gerbil-parser/language-support/grammar deflanguage))
(export example-syntax)

(deflanguage example
  (syntax
    (lexical
      (root name)
      (lex (identifier Identifier (identifier)))))
  (rules (name (node Name (field value identifier)))))
#+end_src

Its =parser.ss= publishes the entry through the Loader:

#+begin_src scheme
(import (only-in :gerbil-parser/language-support/entry
                 deflanguage-parser-loader)
        ./grammar)
(export example-language parse-example)

(deflanguage-parser-loader example-language
  (grammar example-syntax)
  (parse parse-example)
  (slots metadata: '((language . "example")
                    (version . "v1")
                    (contract . "example.syntax.v1"))))
#+end_src

The Loader is a POO object. Inheritance, value overrides and extension contracts
are admitted before publishing the parse entry. Fixture values are ordinary
slots; the engine owns evaluation, catalog construction and service binding.
=deflanguage-parser-tests= constrains test declarations and checks acceptance,
lossless source, identities and structural expectations.

See the [[file:languages/README.org][language authoring guide]] and
[[file:docs/architecture/0018-downstream-language-products.org][downstream product guide]] for development Loaders,
POO extensions, fixtures and product generation.

* Execution and integration

| Product | Execution boundary |
|---------+--------------------|
| Scheme library | Prepared engine parser returns a lossless ParseArtifact |
| Independent Rust AOT | Generated immutable scanner/parser tables run in the generic Rust runtime; no Scheme VM at request time |
| C ABI and Rust FFI | A reusable Gerbil runtime and language handle execute Scheme parsing; Rust owns result buffers and borrows indexed views |

Parse artifacts preserve source text, syntax structure and spans, with source
and grammar identities. The artifact is the shared publication boundary for
traversal and downstream tooling.

The language-independent C ABI initializes the runtime once and reuses handles
across requests. Its optional Rust Tokio integration queues requests to a
persistent Scheme owner thread. Applications own queue limits and lifecycle.
See [[file:rust/gerbil-parser-ffi/README.org][Rust FFI and Tokio ownership]] and
[[file:rust/gerbil-parser-artifact/README.org][Rust artifact admission and navigation]].

Independent AOT uses the same admitted Grammar/Parser IR through a separate
product gate. It does not automatically support every Scheme source parser or
POO policy. See [[file:docs/architecture/0006-rust-aot.org][Rust AOT design]] and the
[[file:t/fixtures/runtime-record-assignments/README.org][standalone record-language consumer]].

* Build and try

Use the repository's Gerbil SDK environment and dependencies pinned in
=gerbil.pkg=. Scheme compilation uses the SDK's GCC configuration.

#+begin_src sh
gxpkg deps --install
GERBIL_BUILD_CORES=12 gerbil build
GERBIL_BUILD_CORES=12 gerbil env gxi build-gparse.ss compile
.gerbil/bin/gparse help
.gerbil/bin/gparse check "1 + 2 * value"
#+end_src

The command is an optional consumer of the library. It does not own a separate
parser implementation. Rust workspace checks run with:

#+begin_src sh
cargo test --workspace --all-features --locked
#+end_src

Native Scheme, generated products and real C/Rust hosts have separate
qualification lanes. See the [[file:docs/architecture/qualification.org][qualification guide]] for their commands and
[[file:.github/workflows/ci.yml][CI entrypoint]] for the current job graph.

* Reference languages and implementation boundaries

The builtin packs are Arithmetic, Bash, HCL, HL7, FHIRPath, openCypher, GQL and
TLA+. All use the three-interface authoring boundary. Their syntax coverage,
source admission and portable capabilities differ; consult the
[[file:languages/README.org][per-language status]] before selecting a product.

Bash currently uses the shared Scheme source engine. Complete standalone Bash
Command/Source AOT remains open. Scheme-only CST policies also require a shared
representation and parity evidence before independent Rust execution.
