Source and runtime failure semantics differ. import-module owns source promises
and retry behavior; load-module retains failed runtime exceptions until explicit
reload. Parser must not invent a common exception cache. Diagnostic dynamic
bindings restore the previous importer/evaluator and preserve zero/multiple values
and exceptions. Synthetic context setters only construct test-owned fixtures;
no production or imported-context promise is replaced.

* Controls and failure custody
Positive controls cover descriptor selection, same-size edits, Core post-effect
source admission, real helper initialization once, native order, and typed init
services. Negative controls retain malformed imports/arity, invalid selectors,
initializer failures, source rewrite under an outer read-cache, deferred/quoted
loads, and a first failed child preventing a later cold suffix.

The initial candidate failures are retained in the enclosing integration logs:
- A manually appended helper list duplicated a target already projected by Core;
  the list was removed rather than deduplicated by another Parser scheduler.
- An in-Suite build-projection check incorrectly required installed compiled
  dependencies to be recompiled. An isolated native projection returned ().
  The aggregate experiment additionally encountered a public-source identity
  refusal. Nested projection was removed from that Suite; native build support
  remains the executable closure check. This is no claim that arbitrary nested
  source-reader use is fixed upstream.
- Initial source controls contained an undefined exported binding and an illegal
  compiler declaration in interpreted source. These fixtures were corrected.
- A proposed raw load-scheme test hit a local runtime/Gambit arity mismatch. No
  product uses that API here; runtime controls exercise load-module/reload-module!.
  No compiler change or compatibility loader was introduced.

The developer build-test-support recipe had reused the test-runtime1GiB option
for compiler work. The new native projection exhausted that heap before compiler
dispatch; the original failed log is retained. That recipe now uses the existing
2GiB compiler budget, matching CI, while test heap/process limits remain.
Two build workers and the existing compiler ceiling remain. Parser's former
package180s build cap is not reinstated. std Djot remains paused. No Gerbil/SDK
source, private installation environment or local dependency patch is introduced.
