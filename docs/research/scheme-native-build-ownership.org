#+title: Scheme native build ownership
#+startup: overview

This module follows [[file:scheme-engine-library-boundary.org][the engine/library boundary]] and records native build
ownership, failed controls and qualification evidence. =std/make= owns library
builds; native =gxtest= owns source test evaluation; the closed conformance product
owns independently bounded native controls.

* Standard native workgroup

The static object build now delegates workers, queueing and exception propagation
to =std/sync/wg= (=make-wg=, =wg-add!=, =wg-wait!=). The project no longer owns a
mutex or hand-written thread pool. Native =list-sort= orders large inputs first;
=std/wg= alone owns queueing and workers. Two workgroups share the existing
core budget: large objects use at most =cores - 1= workers and small objects use
one. This retains real progress from independent compiler products; it does not
report a timer heartbeat. Native =dynamic-wind= drains the small group when the
large group raises. Module translation
and object compilation still retain the compiler-generated source inputs.

An earlier warm native conformance control completed in 82.20 seconds under
the unchanged 240/5-second fence. Compiler diagnostics report actual optimization work; no
synthetic heartbeat or compiler optimization downgrade is introduced.

Gambit link partitioning remains in the compiler adapter. Migrating it requires
the compiler-owned program manifest accepted by =gerbil-scheme-rust='s archive
API and preserving this executable's bootstrap, link order and runtime lifecycle.
A static archive is not yet this project's executable publication contract.
