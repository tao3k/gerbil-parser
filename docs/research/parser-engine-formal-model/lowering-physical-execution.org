#+title: Scoped physical lowering execution

* One construction contract

This extension connects the derivational grammar semantics in
[[file:../../../formal/ParserEngine/Lowering.lean][Lowering]], the recursive native-shaped producer in
[[file:../../../formal/ParserEngine/LoweringTraversal.lean][LoweringTraversal]], and the retained LeanPoo construction described by
[[file:construction-vocabulary.org][the construction vocabulary]]. It removes the former caller-materialization
adapter. Physical row alignment is now a generated theorem for the supported
protocol, rather than an input assumption or a finite corpus comparison.

| Stage | Generated obligation | Implementation |
|-------+----------------------+----------------|
| Source admission | Complete root and recursive helper schemas equal extracted source | LoweringBranchSource, LoweringNamesSource |
| Root storage | Execute actual initializer forms; allocate separate mutable cells and table identities; preserve prior storage | SchemeStorage, LoweringRootStorage |
| Lexical module | Construct the allocation interface from every directly nested source procedure and initialized root bindings | LoweringRootScope |
| Recursive dispatch | All branches compile to scoped code with exact logical erasure | LoweringProgram, LoweringProgramBuilder |
| Fresh names | Recursive source evaluation generates complete allocation and cross-call histories | LoweringNames, LoweringFreshEvaluation, LoweringAllocationCalls |
| Mutable storage | Occupied names retain their meanings across subsequent claims | LoweringNameStore |
| Lexical references | Captured operands preserve their physical names across scope extension | LoweringScope |
| Call/return | Every lower-to call returns before its caller continuation; frames balance | LoweringCallStack |
| Physical emission | Final packets derive complete RealizedRows and origin admission | LoweringProgram.physical_realized, LoweringProtocol.generated_origin |
| Construction | Complete physical input check retains the original dependent LeanPoo product | LoweringProtocol.construct, complete |

The paper target is still grammar derivation, not just equality of event lists.
=declarations_language_sound= composes origin admission with the paper semantics.
Recognition erasure alone does not prove AST semantics or language completeness.

* Names, scopes and actual invocation boundaries

The source has one mutable candidate counter and an occupied-name set. The
model searches candidates in exactly increasing counter order. For an injective
candidate encoding, at most =used.length + 1= probes are needed to find a free
name. The bound is derived from occupancy; it is not a runtime timeout or
user-supplied fuel. =search_trace= generates all retries and the final claim.

Authored names and references are reserved before recursive execution. Physical
handles carry their logical meaning. Store extension preserves every existing
handle, including outer operands captured before an inner helper allocation.
Two different names may decode to the same expression; the model never replaces
per-occurrence names with one global expression-to-name map.

Lexical binding lifetime and the native lower-to invocation are distinct.
The CPS compiler retains a helper reference while constructing the caller's
remaining operands. That lexical lifetime must not extend the recorded callee
execution across the caller continuation. Separate =bind= and =call=
instructions enforce this: allocation extends scope; =call= emits enter, body,
return, then caller continuation. Every execution generates a balanced-frame
proof for any starting stack. Empty choices still allocate a helper even when
they emit no production, so allocation cannot be reconstructed from rows alone.

The compiler covers arbitrary finite syntax depth, n-ary width and declaration
lists. Its termination measure combines structural size with dispatch phases,
including unisolated loops passing through isolated helpers. This closes the
scoped compiler's recursive paths without assuming a finite observed trace.

* Proof-directed implementation audit

The model is a way to find violated implementation obligations, not a second
parser whose agreement on examples is called a proof. Each admitted source
fragment needs operational semantics, an invariant, a counterexample search and
an executable regression against the real parser. The original retained
LeanPoo construction product remains the shared consumer; adding a separate
certified wrapper around the same unchecked source would not close a gap.

| Obligation from the unified contract | Native audit result | Evidence and remaining work |
|-------------------------------------+---------------------+-----------------------------|
| Keep every authored declaration for a shared lhs | Nullable diagnostic indexing overwrote earlier declarations | Fixed; operational table evaluation and complete bucket theorem cover arbitrary lists |
| Preserve candidate counter and occupied-name state | Source increments the counter before claim; strong per-assignment refinement is false | Source fresh/claim recursion now simulates one completed allocation, including arbitrary collision prefixes |
| Preserve captured operands across recursive calls | Captured variables must denote shared cells, not copied values | Closure and recursive-call evaluation plus arbitrary allocation-call composition are proved; lower-to dispatch integration remains open |
| Publish rows, recipes and callbacks in one order | Shared publication protocol checks complete retained output | Arbitrary native observer and exceptional execution remain outside the normal-return theorem |

** Discovered declaration-loss defect

Lowering preserves repeated authored declarations for one nonterminal. The
nullable fixed point therefore sees all alternatives. The native diagnostic
witness previously used a scalar table entry and replaced every earlier body
with the last body. For =item -> empty= followed by =item -> "x"=, repetition is
correctly rejected, but its nullable reference path becomes false. A nullable
exit beside a cyclic duplicate can disappear in the same way. This defect
concerns diagnostic completeness; it is not evidence of incorrect acceptance.

The new =rule-index-by-lhs= keeps every body in source order. Witness traversal
expands all nullable declarations once per referenced name, retaining the
existing BFS and cycle guard. The nullable fixed point remains authoritative.
The macro regression reproduces the old missing-path failure, then passes both
declaration orders and cyclic siblings against the corrected implementation.

** Operational proof and its limits

[[file:../../../formal/ParserEngine/SchemeTableEvaluation.lean][SchemeTableEvaluation]] evaluates actual source Datum expressions, lexical
bindings, primitive arguments, sequences, lambda bodies in for-each and table
reads/writes. Its rules do not turn source equality into an invocation of a
separate index algorithm. [[file:../../../formal/ParserEngine/SchemeEvaluationDeterminism.lean][The mutual determinism proof]] quantifies over all
returning evaluations of this supported fragment.

[[file:../../../formal/ParserEngine/RuleIndexSource.lean][RuleIndexSource.simulate]] connects the extracted native loop to that relation.
The complete theorem proves exact original order and multiplicity for arbitrary
rule lists, plus preservation of every other physical table. The overwrite
counterexample explains why the old scalar representation cannot meet the
contract. No finite corpus, successful source digest or supplied row-alignment
premise replaces these theorems.

Fresh-table allocation and primitive behavior have explicit semantic contracts;
constructing and passing the correct initial table and cells remains a parser
source obligation. The reader, compiler and collector are external. Faithful,
injective native symbol
to model-key transport is a separate parser representation obligation; it must
not be silently declared a proved host property. Source payloads must also stay
stable during traversal. The theorem starts after allocation with
the captured table and rule-list environment. It does not certify arbitrary
closures, the complete lowering dispatcher, all diagnostic BFS behavior or exact
source locations for duplicate declarations sharing one owner metadata entry.
Those obligations remain in the unified chain rather than being declared solved.

** Captured cells and complete allocation calls

The operational evaluator now represents lexical environments separately from
mutable heap cells. Closures capture environments containing cell addresses;
every invocation reads those cells from the current heap. Mutually recursive
procedure groups and named-let calls retain the same captured scope. Arguments
and sequences thread heap effects in order. Primitive application requires an
unshadowed global; it cannot bypass a locally bound procedure of the same name.
Optional missing arguments currently support literal defaults only.

[[file:../../../formal/ParserEngine/SchemeCells.lean][SchemeCells]] proves arbitrary shared-counter calls and lexical scope, and
rejects the proposed strong simulation: with no occupied names, the source
counter-increment state cannot be a completed =Names.Trace= transition. This is
a defect in that proposed correspondence, not evidence of a parser acceptance
bug. Changing source mutation order merely to fit that model is unjustified.

[[file:../../../formal/ParserEngine/LoweringClaimEvaluation.lean][LoweringClaimEvaluation]] and [[file:../../../formal/ParserEngine/LoweringFreshEvaluation.lean][LoweringFreshEvaluation]] extract the actual fresh
and claim declarations into procedures. Operational derivations execute their
real bodies, including the captured counter assignment, occupied/free branches,
recursive loop call and return. =fresh_unique= covers every returning evaluation
of the supported fragment. =allocation_simulation= derives the abstract history
at complete-allocation boundaries, with all intervening collisions included.

[[file:../../../formal/ParserEngine/LoweringAllocationCalls.lean][LoweringAllocationCalls.source_history]] composes arbitrary request sequences
over the same physical heap. It generates both the source evaluations and one
abstract history. =source_unique= derives global helper uniqueness and reserved
name exclusion, including repeated owners. Counter/table projections are
preserved after every return; =committed_frame= proves every other location is
unchanged. These properties come from the grammar's name-separation obligation,
not equality with a second allocator on a finite input corpus.
=every_return= uses call-sequence determinism to extend that generated history
to every returning operational execution of the sequence.

The allocation interface now accepts the real lexical module. It no longer
replaces that module with a separate two-procedure environment. The original
retained LeanPoo construction remains authoritative; no parallel certificate or
unchecked factory wrapper is introduced.

** Root storage, module capture and name encoding

[[file:../../../formal/ParserEngine/SchemeStorage.lean][SchemeStorage]] gives the initializer fragment allocation semantics with an
owned frontier. That frontier denotes fresh logical identities, not physical GC
addresses or a memory-capacity estimate. Each table consumes its own identity,
even though its initial entry map is empty. Assigned variables receive mutable
cells; immutable bindings retain their initialized values.

[[file:../../../formal/ParserEngine/LoweringRootStorage.lean][LoweringRootStorage.source_entry]] executes the initializer list extracted from
the actual root declaration. Conservative mutation collection ignores quoted
data and includes nested procedures. For any prior heap satisfying the fresh
frontier contract, it generates three distinct mutable cells and two distinct
tables. The initial values, empty table contents and preservation of every
previously owned location are kernel theorems. Root setup is no longer an
independently supplied parser premise.

[[file:../../../formal/ParserEngine/LoweringRootScope.lean][LoweringRootScope]] extracts every directly nested procedure, preserving the
emitter, recursive dispatcher and proof helpers. It constructs the generic
allocation scope using the real root environment. Primitive behavior remains a
host interface; actual counter/table bindings and procedure lookup are proved
from source. =root_allocations= composes arbitrary allocation calls in that
complete module immediately after initialization. Reservation-prefix execution
and deriving the call sequence from the dispatcher remain parser obligations;
the theorem does not pretend those prefix effects have already occurred.

[[file:../../../formal/ParserEngine/SchemeNameEncoding.lean][SchemeNameEncoding]] executes the extracted =name-id= loop using named-let,
ordered cond tests and recursive calls. For every successful directory lookup,
every returning evaluation has the same ordinal and unchanged heap. The proof
uses the existing =ConstructionEncoding.lookup= and its identity-preservation
theorem, including duplicate directory entries and nonzero loop indices.
The directory domain is canonical interned source symbols. Native controls show
that two distinct uninterned symbols may print identically while receiving
different ordinals; the source renderer rejects such symbols rather than
silently transporting their printed text as identity. Decimal candidate
injectivity and broader native symbol transport still need their own proofs.

** Discovered zero-row helper and vocabulary gap

The grammar =start -> choice(sequence(choice()), literal("x"))= allocates a
helper for the empty choice. That helper denotes the empty language and has no
lhs production. The scoped lowering model already permits this trajectory;
its allocation history cannot be reconstructed from emitted rows.

The real witness producer nevertheless built its name directory from authored
names, source references and production lhs values. It then attempted to encode
the separately observed helper binding, raising =missing grammar name= for
=$start.0=. The fix interns every observed binding as well as every row owner.
The new native fixture retains the allocation even when no helper row exists;
the complete origin/recipe comparison now covers 24 generated fixtures.

This repair also exposes an independent canonical-IR boundary. The native
validator and =ConstructionGrammar.operandAllowed= both require every referenced
nonterminal to occur as an lhs row. =missing_owner_rejected= proves rejection
for arbitrary records with such a missing owner, independent of a finite
fixture. The new native control records that current rejection while retaining
the productive literal alternative. No validation guard has been weakened.
Closing this gap requires a declaration vocabulary distinct from production
rows throughout the producer/consumer contract, or a proved grammar-wide
elimination of empty-language branches. It is not solved by the encoder fix,
and whole-engine model closure remains open until that obligation is discharged.

* Source correspondence and remaining proof obligations

The source-data macro extracts the complete =lower-rules= definition, not only
the shared emitter. Independent schemas include reserve prepasses, fresh and
claim mutations, recursive dispatch, recipes, declaration order and finalizer.
The source gate rejects any different root. This prevents unnoticed changes to
admitted source control order, but schema equality is not a general evaluator
adequacy theorem.

The following boundary remains explicit:

- The physical interpreter denotes the restricted normal-return source protocol.
  Table indexing and recursive allocation now have operational simulations.
  The complete dispatcher, reservation prefix and emitter still need their
  joint simulation into that interpreter. These are parser source-refinement
  obligations, not assumed host theorems. Closure allocation proofs do not
  discharge the dispatch-to-request edge. Directory lookup now has a source
  simulation; native symbol transport and candidate encoding remain explicit.
- Native symbol/text normalization must preserve the reserved vocabulary and
  injective candidate encoding. The complete raw physical CFG is checked
  against generated emissions before the retained construction is admitted.
- The source can reject dynamic precedence and malformed DSL inputs. Arbitrary
  exceptional exits, mutating observers and continuation reentry are outside
  this normal-return proof. Existing publication failure proofs remain separate.
- Actions, field/alias labels, layout capabilities and precedence policy require
  their semantic/request correspondence beyond recognition erasure.
- Primitive allocation, storage, arithmetic, symbol identity, compiler and GC
  behavior are external contracts. Gambit and the installed SDK are neither
  modified nor built.

Thus universal scoped generation is proved; arbitrary actual Scheme evaluation
and whole-engine model closure are not claimed. Local parser performance
optimization remains gated on the remaining model obligations.
