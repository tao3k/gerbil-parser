#+title: Capture fold costs, terminal observations and complete-request qualification

* Starting point

This study starts at =459ec36e1961f3d8d95ce4ebec13843d164a4bdf=, including
the earlier selector/goto/owned-stack optimization and the rejected scanner

* Paper and current-code model

The representation and ordered-computation discussion in
[[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing]] motivates eliminating intermediate traversal.
The context-maintenance costs in
[[https://harmonia.cs.berkeley.edu/papers/twagner-parsing.pdf][Efficient and Flexible Incremental Parsing]] require paying for retained
capture and reuse data. Neither source proves an optimization in this engine.

The [[file:singleton-scanner-model-first.org][preceding cost diagnosis]] found 322 fragments, 256 terminal leaves and eight
sparse snapshots of semantic depth five in the actual 64-record request. Its
captured-LR samples included substantial natural GC. These observations identify
a paid path; they do not establish that object records alone explain allocation
counters or that increasing a heap limit removes the work.

The existing capture reduction restores source-order children and counts in one
reverse-stack pass. It then traverses children again to build the terminal yield.
Metadata accessors separately classify ordinary tokens, fragments and views.
The first hypothesis fused terminal-yield construction into the existing pass;
its measured rejection led to demand-driven derived-index construction.
The nullable path, sparse snapshot policy, source grammar and published event
representation remain the same. The later shared-context hypothesis changes the
private fragment representation and therefore requires its own model and controls.

=yield_join_order= preserves the ordered terminal sequence. The left and right
fold lemmas imply =fused_yield_observation=. A relocated subtree remains an opaque
piece; the transformation neither distributes nor reconstructs a view. Binary
association is private metadata. Transfer's token comparisons and successful
terminal/branch visit counts are preserved; the number of diagnostic visits
before an early mismatch may depend on the changed binary association.

=CaptureCost= accounts separately for transitions, allocated work, retained data
and collection. =capture_cost_requires_all_charges= needs premises for each
charge; fewer logical classifications alone does not prove lower total cost.
The native allocation counter is not an inventory of retained Scheme objects.
The fragment/children/terminal tree and snapshot results remain fully paid.

* Demand-driven terminal index

[[file:../../src/runtime/lr-parser/recognition.ss][The capture owner]] already retains a complete immutable grammar topology,
span/count metadata, semantic values and exact lookahead. A terminal-yield tree
is a derived index used by transfer admission. The new candidate keeps a pending
cache in the same physical slot and constructs that index only upon a transfer
query. Nullable productions retain their known empty index. No capture signature,
source-boundary check, fragment production or public event is discarded.

The first query uses an explicit postorder work list so deep left recursion does
not create a recursive Scheme call chain. Each fragment publishes only a complete
index. Children retain their original source-order left fold and exact binary
association. Relocation wrappers retain their original nesting. Subsequent queries
reuse the cached tree. Grammar topology and relocation metadata are engine-owned
immutable inputs; changing them behind the index invalidates the producer premise.
Token leaves remain the original objects, as in the eager index. Semantic observer
updates do not alter that grammar topology.

=delayed_yield_first_exact= and =delayed_yield_warm_exact= bind the memo to its
immutable producer. =fresh_yield_allocations_eliminated= applies only when there
is no index demand. =forced_yield_allocations_retained= keeps all construction
charges in the forced case. [[file:../../formal/quint/YieldMemo.qnt][YieldMemo]] covers fresh capture without derived work,
cold/warm queries, invalid topology and rejected partial publication. It passed
four directed histories and 1,000 seeded invariant traces.

* Shared transition context

The next hypothesis separates request payload from repeated transition metadata.
The initial immutable five-slot context retained runtime, executor, production, entry state
and exit state. A fragment retains nine payload slots. The runtime owns a
production/entry directory capped at 65536 row-entry cells, with rows prepared once at the canonical capture driver entrance.
Executor and exit-target checks remain live; replacement publishes a new context
and cannot change contexts already retained by old fragments. Cloned runtimes
start with independent directories; oversized tables use uncached contexts.

The Lean payload reconstruction theorem preserves arbitrary consumers, while
its slot-cost condition explicitly charges contexts and directory cells. A
smaller fragment alone does not establish lower total allocation. The Quint
protocol exercises repeated acquisition, executor/target replacement, old-node
retention and rejection of stale context reuse. Native controls passed 198
frozen capture variants and 54 semantic Cases. The historical oracle reduction
body remains unchanged; a test-only constructor adapter maps its logical fields
to the new representation. The first shared-context run had stable reference controls, but candidate
P10/P50/P90 0.919248/0.952465/0.975666 failed admission in 48.851939 seconds.
The next hypothesis hoists directory admission to the canonical driver entrance.
A private runtime/production row supplies coordinates. Lean requires that
producer premise and retains live executor/target checks for each reduction.
Direct calls retain checked coordinate admission. Uncaptured execution does not prepare rows. Custom captured execution uses the
checked per-reduction path and can prepare a directory on first demand. Frozen controls also compare this prepared-row path.
CPU admission remains a separate obligation.

The terminal index relies on engine-owned immutable capture topology. It
publishes only a complete derived index. Concurrent first queries may construct
equivalent indexes more than once; the model does not claim a lock-free
exactly-once allocation guarantee.

* Diagnostic demand states and remaining model-directed work

finite models establish an incremental-transfer speedup across languages.
