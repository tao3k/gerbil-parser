#+title: Objective and evidence boundary

[[file:../parser-engine-formal-model.org][Model and evidence index]]

* Objective and evidence boundary

This model connects one complete deterministic reduction path: canonical
field/alias actions, retained factories, reverse LR operands, logical AST
children and sequence materialization. Production remains Scheme. Lean checks
universal properties of the reference algorithms; Scheme controls check the
implementation; matched benchmarks measure CPU and allocation. These are
three separate obligations, not interchangeable receipts.

The executable package is [[file:../../../formal/ParserEngine.lean][formal/ParserEngine.lean]]. The checked toolchain and LeanPoo revision are recorded in
[[file:../../../formal/lean-toolchain][lean-toolchain]], [[file:../../../formal/lakefile.toml][lakefile.toml]] and its locked manifest. LeanPoo is a verification dependency only.
Its =Functional.Requirements.Factories= and =Selected= retain typed factories;
=prepare_ok_iff= establishes that successful preparation selected exactly
those factories. Our executor threads transformed children through that tuple:
LeanPoo's independent-result =build= is deliberately not used for sequential
actions. No new Scheme dispatch facility or author interface is introduced.

* Architecture alignment audit and qualification order

The architecture model is *incomplete*. A successful Lean build establishes the
listed theorems; successful Quint runs check their stated finite histories.
Neither establishes coverage of all paper mechanisms, all engine routes or a
refinement of Scheme. Hash-binding a source file only identifies that file.
It does not connect a source transition to a theorem.

The local reduction objective above is historical scope, not a complete engine
specification. This section is the shared coverage ledger. Extend this ledger
and its connected models before another runtime optimization. Do not use a new
local object-count identity as evidence that an architecture gap has closed.

** Unified construction correspondence audit

[[file:construction-vocabulary.org][The vocabulary correspondence audit]] follows reader data, native records,
catalogue indices, the retained LeanPoo factory and physical edges as one chain.
The new transport proof closes the gap between injective raw encoding and the
final producer-owned ordinal. Symbol discovery and the paper target are derived
from the same raw operand occurrence and retained construction product.

Its responsibility table records remaining native producer, lookahead/selector/
policy and AST metadata obligations. Input admission and a finite native corpus
do not establish arbitrary producer execution. Host behavior remains external.
This closes vocabulary composition within the supported construction protocol,
not the complete engine model; local runtime optimization remains gated.

[[file:lowering-publication.org][The lowering publication contract]] now connects the source constructor,
initial bindings, common emitter and finalizer to the retained construction.
It derives dense IDs, paired values/recipes and failure-before-commit for
arbitrary finite emission trajectories. [[file:lowering-traversal.org][Recursive lowering generation]] now derives
the ordered emission/recipe list for arbitrary syntax depth, n-ary width and
authored declaration counts, then feeds the same retained LeanPoo factory.
[[file:lowering-physical-execution.org][Scoped physical execution]] generates helper allocation, call boundaries and
complete physical realization universally, yielding origin admission in the
same retained factory. Complete source-schema equality gates the current root.
Operational source evaluation exposed a declaration-loss bug in the nullable
witness index; the corrected fragment now has an all-rule simulation proof.
Complete recursive Scheme evaluator adequacy, rejection paths and action metadata
remain open; neither source admission nor native controls certify arbitrary execution.

** Parser ownership, prepared requests and the macOS timeout

Host implementation is outside this parser change. Gambit sources, compiler,
collector, synchronization macros and SDK binaries must not be modified or
rebuilt here. Their behavior is an explicit external premise of the parser's
physical execution. Recording a premise does not establish it: the ordinary
plain-poll visibility counterexample below remains unqualified and cannot be
silently admitted as a successful acquire. No host repair or SDK deployment
is claimed by this parser qualification.

The [[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][Essence of LR Parsing, sections 2--4]] distinguishes grammar-dependent
parser structure from input-dependent execution. The present test correction
uses the parser's existing preparation boundary. It does not implement the
paper's partial evaluator or claim its performance results.

Runtime objects contain lazily derived caches; the entire runtime record is
not claimed immutable. The test boundary fixes the grammar and preparation
policy and reuses derived metadata. Tokens, stacks, counters, remainders and
returned products remain request responsibilities. No previous request's
checkpoint is reused by this change.

*** Selected checkpoint constructor correspondence

The parser-side adapter is =RawRequest.Entry= in

action/shift counts and an optional empty recognition stack. The observer flag
and non-layout guard are separate inputs; a false flag is not an empty list.
The native =lr-parse/prepared= layout branch uses the batch owner instead and
is outside this constructor theorem.

=scanEnd_le_iff= proves the accumulator bound for every token list and initial
offset, and =token_end_bounded= derives that every decoded token end is covered.
The decoder admits nonnegative ends; arbitrary Scheme values are not admitted.
A final-token shortcut would be wrong for the constructor's input contract:
ends 23, 4, 17 must produce 23. This is a field-construction control, not a claim
that such a list is a lexically ordered complete source.

premise =engine.graph.entry = 0=. =constructed_valid= then establishes the
reference initial invariant, and =complete_from_constructed= composes it with
the existing universal accepted-derivation theorem for any admitted request
trace. This closes the reference constructor-to-request composition; it does
not infer table/selector certificates or a whole Scheme operational refinement.
The empty native semantic-value list must decode to empty model frames;
nonempty semantic-value decoding is outside this initial adapter.

constructor. This is the next boundary between the paper's grammar-dependent

already cached value. =complete_request= instantiates the kernel with the
certified raw-token engine, composes selection with the zero-state constructor,

Backend-specific reducers, reduction plans and AST allocation are excluded from

Quint checks branch precedence and includes a foreign-cache counterexample:

*** Complete requests, typed extraction and canonical event products

The paper's accepted-derivation obligation and the implementation's AST/event
obligation now share one ID-bearing request trace. [[file:../../../formal/ParserEngine/RequestAST.lean][RequestAST.lean]] retains
the original runtime opcode selection, exact production-vector lookup, reduction
width and source boundary. A reduction's offset must be the pending raw token's
start or the request's EOF boundary; arbitrary caller offsets are not admitted.
Nullable operand anchors follow the next nonempty semantic value before falling
back to that invocation boundary. Pending starts come from the decoded leaf
span; the complete product contract also binds EOF to the selected constructor's
maximum input-token end.

=step_erases= and =trace_erases= connect this trace to the existing certified
raw-token LR engine. =step_executes= and =trace_executes= execute its semantic
instructions using the same production IDs and ordered operand actions.
=complete_request= obtains the grammar derivation and complete AST replay from
that one trace. The final single unfielded root is an explicit native admission,
not inferred from grammar recognition alone. Table/selector decoding and native
step extraction must establish the trace; a successful artifact flag cannot do so.

[[file:../../../formal/ParserEngine/Publication.lean][Publication.lean]] adds a finite typed extraction of native token/node/fragment
records and ordered child lists/branches. Tokens retain their kind, lexeme and
coordinates. =decodeValue= projects the logical AST while =valueOps= retains
the full token payload for publication. =rootOps= rejects token/fragment roots
and widens a root node to the complete source byte range, matching
[[file:../../../src/runtime/artifact.ss][with-recognition-event-walk]].

*** Actual record extraction, physical frames and callback histories

The LR paper establishes the recognition/derivation obligation. Native record
layout, event callbacks and artifact publication are additional implementation
obligations. This extension keeps their connection to the same complete-request
trace explicit; it does not attribute these representations to the paper.

[[file:../../../src/runtime/event-program.ss][event-program-inspect]] projects one layer of the actual private instruction
record. It does not call either walker. Tokens retain kind, lexeme and signed
coordinates; branches retain both child references and all cached fields;
views retain their child and signed delta; append envelopes retain prefix,
newest-first blocks, tail, bounds and height; chunks retain ordered items and
bounds; value and field records retain name, bounds and body. The false root
projects to the empty tag. The projection copies chunk slots and the append
block list so callers cannot mutate private instruction storage through a packet.
The parsing path does not invoke this verification projection.

[[file:../../../formal/ParserEngine/IteratorEncoding.lean][IteratorEncoding.lean]] defines exactly these typed packets. =record_roundtrip=
and =record_exact= prove both directions of the record decoder for arbitrary
payloads and references, including fields not used by walking. =Extract= requires
a successful record read and a finite recursive witness for every referenced
child. The =node_callbacks=, =field_callbacks=, =fragment_callbacks=, =chunk_callbacks=
and =append_callbacks= theorems establish callback order for arbitrary bodies,
signed positions and references. =lowerRecord= handles all record branches, including field headers and
footers, node headers and footers, fragment boundaries, chunk order and append
block order. There is no axiom that converts an arbitrary heap into an extraction
witness. Name conversion, object/reference identity and primitive slot reads
must satisfy their stated external contracts.

|-------------------------+------------------------+--------------------|
| Four-slot sibling and chunk frames | =frame_roundtrip=, =frame_exact= | Exact packet width, reference, Boolean and integer classification |
| Five-slot node/field/fragment finish frames | =opening_return_retained=, =saved_zero_is_not_missing= | False context differs from an integer result, including zero |
| Whole encoded pending stack | =stack_roundtrip= | Every packet decodes; malformed packets cannot be skipped |
| Tail-first, newest-first append pushes | =physical_append_stack= | The stored block list is stable throughout traversal |
| Chunk slot-one mutation | =physical_chunk_write=, =advanced_chunk_suffix= | The signed index is admitted as a natural and is within vector bounds |
| Initial chunk index one | =extracted_chunk_has_successor=, =block_join_has_successor= | A physical chunk has at least two items; native singleton leaves are not chunks |

The index-one condition is consequential: a one-item chunk would leave an
invalid resume frame after its first item. The current producer joins two
nonempty blocks, and the extraction contract requires the resulting successor.
This is a producer invariant, not permission to extend a timeout or silently
accept a malformed chunk. Cached heights and bounds remain bound in record
extraction even though the event decoder does not use them to select callbacks.

*** Checked witness generation and whole iterator control flow

The construction now connects actual record projection to a terminating
physical iterator model before composing request publication. The connection
is generic over finite heaps, references, names and signed coordinates; the
Scheme cases exercise that connection without replacing its proof obligations.

The direct/CPS distinction in section 4 of
[[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing]] motivates making pending control explicit. That
paper's recognition and specialization arguments do not prove this parser's
private event representation or host execution. The additions below therefore
state their own extraction and control invariants, rather than interpreting
CPS conversion as a CPU optimization.

**** From finite certificates to extraction witnesses

[[file:../../../formal/ParserEngine/Extraction.lean][Extraction.lean]] provides a terminating, fuel-bounded generator. A Boolean
checker validates every record in a supplied finite domain: decoding and tag
admission must succeed, references must remain in the domain, and every child
rank must be strictly smaller. =verify_certificate= derives the certificate
from a successful check. =checked_generate= then generates an =Extract= witness
at rank plus one, without assuming either an extraction proof or a semantic
child environment. =generate_sound= covers every successful generation;
=generate_complete= establishes sufficient fuel for arbitrary certified heaps.
A failed or cyclic graph cannot acquire a witness through these theorems.

The generator collects every declared child before lowering a record.
=collect_lookup= makes repeated references consistent. =extraction_unique=
proves that all extraction witnesses for the same heap and address yield the
same program. Consequently =environment_equation= derives all record-lowering
equations from the generated environment; they are not independent premises.
The finite domain may include shared subgraphs and unreachable records, but
all admitted records must satisfy the same checks.

[[file:../../../t/fixtures/event-iterator-extraction.ss][The Scheme verification helper]] independently computes ranks with a tri-color
DFS, checks the result, and generates a simple rope witness using decreasing
fuel. It retains references assigned from real object identities. This helper
is verification code, not an added parse-path conversion. The Lean decoder
uses typed cells; actual primitive type checks, identity preservation and
stable record reads remain explicit source adapter obligations.

**** Physical dispatch, progress and callback context

[[file:../../../formal/ParserEngine/IteratorMachine.lean][IteratorMachine.lean]] models the current registers and decoded pending frames
as one task sequence. Its fourteen grouped transitions cover empty/token,
branch/view/append/chunk dispatch, last/middle chunk resume, value/fragment/field
entry, and their three footer branches. A false current register followed by
stack restoration is grouped into the next task dispatch. This is a model of
the complete event iterator control flow, not an instruction-level proof of
the whole compiler or parser.

| Obligation | Derived result |
|------------+----------------|
| Every physical dispatch preserves meaning | =step_simulates=, =trace_simulates= |
| Child references and resumed indices stay valid | =step_preserves_validity= |
| Every nonempty valid task sequence can execute | =progress= |
| Each physical transition strictly reduces structural work | =step_decreases=, =physical_steps_wellFounded= |
| A valid initial state has a finite completed trace with exact events | =machine_completes=, =initial_completes= |
| Footer context matches actual opening IDs and field names | =step_controls=, =trace_controls=, =complete_callbacks_bracketed= |
| Fallback preserves active registers and encoded frames | =fallback_projection= |
| A nested traversal returns to unchanged outer frames | =step_under_suffix=, =fallback_returns_to_caller= |
| Physical traversal composes with accepted request, AST and publication | =complete_request_product= |

The termination measure counts structural work; it is not elapsed time, CPU
instructions, allocation or GC cost. Progress and preservation are proved
separately, so a decreasing but stuck machine is insufficient for completion.
The callback bracketing stack is a ghost invariant derived from actual pending
footer frames. No extra runtime stack is assumed. The artifact model increments
opening IDs by one; the native comparison also exercises arbitrary retained
returns with stride seven. It does not claim that arbitrary callbacks obey
the artifact publisher's counter protocol.

The complete-request theorem consumes the physical machine trace and derives
the corresponding abstract iterator trace. It no longer requires a separate
abstract traversal trace as input. The request/AST adapter, signed position
resolution, source payload identity and normal-return callback history retain
their explicit admission premises. Callback exceptions, continuation reentry,
host GC, compiler correctness and concurrent mutation remain outside this
normal-return relation. Gambit was neither changed nor built.

*** Executable packet dispatch and generated execution witnesses

*** Native recursion, sequential loops and iterative fallback

[[file:../../../formal/ParserEngine/HybridIterator.lean][HybridIterator.lean]] closes the preceding source-control obligation at the
normal-return Scheme semantics boundary. It follows =event-program-walk/inline=
in [[file:../../../src/runtime/event-program.ss][event-program.ss]]: empty instructions return before the cutoff test,
ordinary records recurse with depth plus one, and a nonempty instruction at
the cutoff executes the packet iterator before its native caller resumes.
The production threshold is 64; the proof quantifies over every natural
threshold and initial depth, rather than qualifying only that constant.

Section 4 of [[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing]] distinguishes native call control
from continuation-based control. Here that distinction motivates an explicit
relation between their representations. The paper does not prove the event
iterator, its private records or the Scheme compiler, and no performance
conclusion is inferred from changing control representation in this model.

**** Source clauses and the execution relation

The model retains three kinds of native activation: a call with its signed
translation, moved provenance and depth; a sequential loop with its remaining
children; and a footer with its saved opening return. These are ghost call
activations, not physical vector frames. Their projection into pending work
is used only for semantic comparison and callback bracketing. In particular,
the source chunk loop may be represented by a sequence of remaining calls
without claiming that it allocates a vector frame for each of them.

| Real source control | General correspondence |
|---------------------+------------------------|
| False instruction returns before the depth guard | =advance_transition=, empty transition |
| Value/field body call and saved footer local | =plan_simulates=, =plan_controls= |
| Token callback and ordered branch calls | =plan_simulates= |
| View accumulates signed shift and sets moved provenance | =plan_simulates= |
| Chunk vector loop visits indices zero through length minus one | =sequence_index_refines=, =sequence_end_refines= |
| Append visits prefix, reversed stored blocks, then tail | =plan_simulates= and the sequence projection |
| Deep call runs the packet iterator with inherited counter and coordinates | =fallback_refines= |
| Suspended native caller resumes with its own saved footer and remaining siblings | =transition_simulates=, =transition_controls= |
| Every executable dispatch yields the corresponding source transition | =advance_transition= |

The vector-loop correspondence uses a stable ordered list projection of the
record's items. At index i, =items.drop i= is the remaining work; executing its
head advances to =items.drop (i + 1)= with unchanged child-call depth. At the
vector length the loop returns without emitting an event. Object identity,
primitive vector reads and list projection stability retain their explicit
adapter contracts.

The fallback does not assume a relational machine walk. It consumes successful
=IteratorExecutor.run= execution, derives that walk and its final empty pending
work, then applies the existing suffix theorem to restore the suspended caller.
The inherited counter is arbitrary at this seam, so a nested fallback cannot
reset it to zero. Header IDs saved before the fallback remain available to the
outer footer after all nested calls have returned.

**** Totality, exact observations and complete request composition

=transition_valid= preserves native activation admission. A structural measure
accounts for calls, loops and footers, including administrative loop steps that
preserve event meaning. =transition_decreases= and =progress= establish normal
completion with sufficient verification fuel. =fallback_budget_valid= derives
a finite uniform packet budget from the checked finite domain; no independent
termination oracle is assumed. These bounds are verification resources, not
parameters added to the parsing API or a prediction of CPU, stack or GC cost.

=initial_completes= constructs a successful finite run for any cutoff and initial
depth. =complete_events= proves both exact event meaning and well-bracketed
retained callback contexts. =controlled_trace_unique= establishes that, for the
artifact publisher's counter protocol, equal events and an admitted initial
control state uniquely determine the entire observation history. Therefore
=cutoff_independent= proves equality of all observations and final counters,
not just equality after erasing footer IDs. =packet_equivalent= proves the same
full-observation equality between hybrid and physical packet execution.

=checked_execution= composes Boolean finite-graph admission, generated extraction
witnesses, derived fallback budgets and completed hybrid execution. The hybrid
=complete_request_product= theorem constructs a corresponding physical execution
witness and transports the callback history before reusing the accepted LR
request, AST replay and canonical publication theorem. A caller no longer
supplies the recursive/iterative equivalence or a physical control-flow trace.

This is a universal proof over the typed record projection and the source's
normal-return control semantics. It is not a mechanically verified compilation
of the Scheme syntax, nor a proof of the host ABI, collector, memory visibility,
exceptions or continuation reentry. Primitive classification/reads, stable
identity, source/position resolution and admitted publisher effects remain
separate premises. Gambit was neither modified nor built. Whole-parser closure
still requires those explicit parser adapters; their finite controls are not
