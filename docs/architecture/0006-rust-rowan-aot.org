#+title: RFC 0006 — Gerbil-owned Rust/Rowan AOT Product
#+startup: overview

* Status

The generic deterministic LR and bounded selective-GLR engine, arithmetic
reference product, and an independent downstream custom-language fixture are
executable. GQL and Cypher remain Scheme-owned language descriptions consumed
through the generic engine boundary.

The lexical algebra also admits =(line)= as a generic, allocation-free
whole-line primitive. Scheme and Rust both consume LF, CRLF, bare CR, or a
final unterminated line losslessly. A bounded POO =LineStructure= declaration
now projects heading, opaque-block, and text-line rules to an immutable Rust
table. The generic engine executes section nesting and block masking over that
table; all markers and syntax-kind identities remain language-owned. This is
not yet a complete contextual Parser IR or an Org parser cutover.

* Decision

=grammar.ss= remains the single language-authoring authority.  Its hygienic
declaration expands into canonical Grammar IR v1 and Parser IR v1 exactly as it
does for the Scheme runtime.  A compiler-owned Rust backend serializes the
already resolved syntax-kind catalog, lexical rules, productions, LR actions,
gotos, field actions, aliases, identity, and grammar digest into an immutable
Rust module.  Rust never resolves grammar conflicts or reparses a grammar
declaration.

The generic =gerbil-parser-rowan= crate executes those static tables and
publishes a lossless Rowan green tree plus a receipt binding language, version,
contract, grammar digest, and source digest. The parser does not publish a
second vertical Rust package for GQL: consumers load the Scheme-owned language
description through this generic boundary. A parse request runs no fallback
Rust grammar, JSON grammar DSL, or S-expression interpreter.

For grammars whose structure cannot be reduced to a finite flat terminal
stream, the same crate also exposes a generic structural-event Rowan sink.
An AOT-generated downstream parser may emit node-start, source-backed token,
and node-finish events. The sink validates generated kind categories, balanced
nesting, and exact ordered UTF-8 coverage before returning one green tree. It
contains no language-specific recognition or recovery policy. The event sink
constructs nodes bottom-up without Rowan's node-cache hash recursion, so deep
but valid hierarchies do not incur quadratic hashing in the generic layer.

The sink is not itself an AOT compiler for procedural =parser.ss= code.  A
downstream script that prints a handwritten Rust scanner or event algorithm is
not an implementation of the single-authority decision above, even when it
embeds a Scheme-source digest and passes differential fixtures.  The remaining
compiler boundary is a fuller contextual Parser IR derived from Scheme-owned
language declarations. The current =LineStructure= table validates kind
references against the canonical grammar digest and covers headings, opaque
blocks, and text lines only. Other line/byte recognition, lexical state
transitions, structural actions, and typed recovery still need explicit
admission. The Rust runtime executes the admitted table and hands source-backed
events to the generic Rowan sink.
Org-like languages may use a scan phase internally, but there is no separately
authored =generate-scanner= program, second Rust grammar, or downstream event
algorithm.  Arbitrary Scheme procedures are not silently translated to Rust;
unsupported procedural behavior fails the AOT contract until it is expressed
in the admitted Parser IR.  A downstream Cargo consumer never invokes Scheme.

Cargo-only custom generation crosses a narrow native ABI: build support passes
the downstream =grammar.ss= path to =gerbil_parser_rowan_compile=.  The
precompiled Scheme product loads that module through Gerbil's own expander,
requires exactly one exported language descriptor, and returns the existing
=compiler/rust-rowan.ss= output as owned bytes. Rust writes those bytes to
=OUT_DIR=; it never reparses Scheme, implements Grammar IR, or constructs LR
tables. The normal parse-time dependency remains =gerbil-parser-rowan= and
does not link the generator.

The native generator product must be distributed for every admitted target.
Its =defbuild-script= owner projects a public ASP Building API package spec
into std/make. The runtime modules, executable, and native TLS options remain
declarative build data, and release support does not reconstruct that graph
from mutable cache objects.
Until a clean Cargo consumer can use that product on Linux and macOS without a
Gerbil installation, the native ABI is an executable boundary but the
Cargo-only authoring claim remains open.

The dedicated =gerbil-parser-rowan-aot= executable qualifies the same owner as
a standalone product. It calls =gerbil-load-expander!= before loading the
downstream module and can replace the runtime load path with an explicit
metadata bundle through =GERBIL_PARSER_ROWAN_AOT_LIB=. Its public authoring
surface is the minimal =:gerbil-parser/rust-rowan-grammar-support= facade, so a
direct custom grammar does not pull the source-import and fixture facades into
its build product. CI consumes the closed executable under =env -i= with no
Gerbil command on =PATH= and explicit expansion-metadata roots. A source module
still requires =.ssi= interfaces; packaging those immutable interfaces is a
release concern, not a reason to reconstruct the runtime object graph.

Downstream projects may own CST-to-domain-IR lowering, but they do not own
another GQL parser package, syntax-kind catalog, lexer, precedence map,
recovery table, or parser runtime.

The downstream qualification fixture owns the complete versioned language-pack
shape: =grammar.ss=, =parser.ss=, =fixtures.ss=, =parser-test.ss=, native
=corpus/=, and a committed generated Rust module. It deliberately has no
=gerbil.pkg= and requires no Gerbil installation in its Rust consumer path.
Upstream generation invokes only the public Gerbil facade; the resulting Rust
module imports =gerbil_parser_rowan= as a normal dependency and compiles outside
the root Cargo workspace. This is the acceptance boundary for custom DSL
authors; an in-workspace generated module alone is not sufficient evidence.

* Stable v1 boundary

This work adds a backend for the existing v1 declarations.  It does not add a
second grammar schema or a v2 compatibility route.  Generated numeric Rowan
kinds follow Grammar IR declaration order and remain valid only with the exact
grammar digest carried by the product.  Catalog overflow, unknown kinds,
malformed tables, invalid UTF-8 boundaries, uncovered source, and missing LR
actions fail closed.

Rowan is a lossless syntax-tree representation, not the grammar authority and
not a parser generator.  The Rust runtime therefore consumes only tables whose
conflicts and precedence were already resolved by Gerbil's compiler.

* First vertical slice

Arithmetic v1 is the executable reference grammar.  The generic runtime admits
the complete native LexicalExpr v1 algebra: whitespace, newline, decimal and
profiled numbers, identifiers, quoted strings, heredocs, line and block
comments, ordered choice, literals, precedence projection, and fallback.  It
executes deterministic LALR actions, applies generated field and alias
reductions, preserves trivia, constructs one balanced root, and verifies that
the Rowan tree reproduces the exact source.  Selective-GLR forks enumerate all
admitted actions within a bounded speculative-depth budget.  Complete branches
are ranked by dynamic precedence and maximal consumption; equivalent CSTs
merge, while distinct equal-score CSTs fail with a typed ambiguity diagnostic.
The parse publishes a request-local =SelectiveGlrReceipt= for those decisions.

The ISO/IEC 39075:2024 GQL Scheme language pack must losslessly accept the
pinned OpenGQL 1.9.0 corpus through the generic consumer boundary. That corpus
exercises real fork exploration and equivalent-completion merging; it is an
admission floor, not yet the complete downstream cutover proof.

The initial slice deliberately rejects unsupported generated features instead
of silently interpreting them differently.  Before publishing GQL or Cypher,
the Rust backend must add and qualify:

- pinned external scanners;
- case-insensitive keyword behavior over the complete corpora;
- recovery behavior and diagnostic parity;
- generated typed node and field accessors;
- exact Scheme/Rust acceptance, rejection, CST-shape, roundtrip, and receipt
  parity for the pinned language corpora.

* Downstream cutover gate

=gql-rust= may remove its native Gerbil runtime and local Rowan sink only after
the generated GQL product passes the full pinned corpus and malformed-input
differential gates.  Its private CST-to-=MetaQueryIR= lowering remains a
downstream semantic owner and is not moved into =gerbil-parser=.
