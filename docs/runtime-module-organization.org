* Correspondence and reproduction

[[file:../t/runtime-module-organization-test.ss][Native source-form controls]] compare facade exports and the multiset of
all original execution forms against the named baseline Git revision. They
reject omitted, duplicated or changed forms. The baseline commit must be
available in the invoking Git clone. This checks source correspondence, not
compiler correctness or end-to-end performance.

Use the current Scheme package environment, with installed dependencies at
the revisions declared in =gerbil.pkg=. Qualify production source policy with
=ASP_GERBIL_SCHEME_POLICY=1 gxpkg build github.com/tao3k/gerbil-parser=.
Then run =just test-runtime-organization= to prepare the existing qualification
FFI owner, link the declared native gxtest values and execute organization, semantic/action
preparation, stack reduction, fragment transfer and recovery/incremental.
The existing native process owner enforces 120-second total / five-second
idle budgets and checks a deliberate failed assertion exits 42.
The native closure also runs the test-style contract and the AOT lock control:
74 Cases passed locally. The lock control uses native assertions and an owned
fixture port, rather than console snapshots; dirty locks remain rejected and
their evidence remains unchanged. This repairs a baseline CI rejection without
exempting that control from the source contract.
Provide the current OpenSSL =pkg-config= metadata for AOT linking rather than
depending on a previously installed Homebrew version directory.
Build and test-closure preparation run
serially because they write the same package-native products.

Keep the existing one-GiB runtime heap, five-second genuine-output watchdog
and 120-second overall native test budget. A source policy pass, build pass,
runtime suite pass and downstream consumer pass are distinct evidence.
Local monitoring output is not a retained evidence reference.

* Exact-head CI input and cold-loading corrections

The semantics job fetches repository history so the named source-form baseline
is available in the CI clone. A shallow checkout failed all three controls;
missing baseline input is not a reason to skip the comparisons.

Module-loading controls initialize their existing preloader before importing
the two public compiler boundaries. The preloader reports real native module
and interface admission, with the original static imports and control bodies
unchanged. The controls passed locally in 9.75 seconds, retaining a five-second
idle limit, 90-second total limit and one-GiB heap. Interface tracing is not a
synthetic heartbeat or an initializer-failure exemption.

* Public language and declaration entry

The package selects =prelude: :tao3k/yuanxu/prelude= in =gerbil.pkg=.
=init.ss= invokes the public =yuanxu!= declaration supplied by that prelude;
consumers do not import =module-system/selection/init-syntax= directly.
The prelude provides the shared Gerbil/POO language and a deferred declaration
entry, while Yuanxu retains selection, source admission and native build
ownership. Importing the prelude alone does not load Parser subsystems or
execute a generator. Parser runtime and grammar APIs keep their existing module
identities; the prelude does not reexport the entire parsing engine.

The shared-prelude candidate completed native =gerbil build --optimized= with
2 GiB/600 seconds on the installed macOS ARM64 SDK. Native runtime,
graph-query and source-grammar Suites passed 19 cases under 1 GiB/120 seconds.
The separate language-source-contract Suite could not load its test benchmark,
which requires the independently declared ASP development dependency; that
attempt is not counted as a pass. Full development/benchmark and remote CI
qualification remain separate gates.
