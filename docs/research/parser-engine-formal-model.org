#+title: Parser engine semantics and operation model

* Objective and evidence boundary

This model connects one complete deterministic reduction path: canonical
field/alias actions, retained factories, reverse LR operands, logical AST
children and sequence materialization. Production remains Scheme. Lean checks
universal properties of the reference algorithms; Scheme controls check the
implementation; matched benchmarks measure CPU and allocation. These are
three separate obligations, not interchangeable receipts.

The executable package is [[file:../../formal/ParserEngine.lean][formal/ParserEngine.lean]]. The checked toolchain and LeanPoo revision are recorded in
[[file:../../formal/lean-toolchain][lean-toolchain]], [[file:../../formal/lakefile.toml][lakefile.toml]] and its locked manifest. LeanPoo is a verification dependency only.
Its =Functional.Requirements.Factories= and =Selected= retain typed factories;
=prepare_ok_iff= establishes that successful preparation selected exactly
those factories. Our executor threads transformed children through that tuple:
LeanPoo's independent-result =build= is deliberately not used for sequential
actions. No new Scheme dispatch facility or author interface is introduced.

* Architecture alignment audit and qualification order

The architecture model is *incomplete*. A successful Lean build establishes the
listed theorems; successful Quint runs check their stated finite histories.
Neither establishes coverage of all paper mechanisms, all engine routes or a
refinement of Scheme. Hash-binding a source file only identifies that file.
It does not connect a source transition to a theorem.

The local reduction objective above is historical scope, not a complete engine
specification. This section is the shared coverage ledger. Extend this ledger
and its connected models before another runtime optimization. Do not use a new
local object-count identity as evidence that an architecture gap has closed.

** Responsibilities and shared vocabulary

1. Papers define mechanisms, premises and limits. Transfer to this engine must
   identify both retained premises and differences in algorithm/representation.
2. Quint describes legal histories, invalidation and interleavings. Its bounded
   transition envelope must name the same owners and observations as Lean.
3. Lean defines denotations, representation relations, transition preservation
   and cost recurrences under explicit premises. It must not replace producer
   premises with facts that only a native implementation could establish.
4. Scheme/Rust controls discharge implementation-specific correspondence and
   failure obligations. Complete-request benchmarks measure the resulting CPU,
   allocation and GC behavior. Neither timing nor byte counts prove semantics.

The request state vocabulary is: admitted grammar/IR identity; source identity
and generation; lexical position/mode; pending raw token with its admission
basis; state-selected grammar terminal; LR states; semantic values; retained recognition yields; branch and
layout context; checkpoint/history owner; public artifact; and FFI owner/lifetime.
A source coordinate, token ordinal, grammar state and object identity are four
different quantities. Mutable tokens need a real producer protocol; an abstract
revision field does not supply one to Scheme.

The common observations are recognition outcome, exact remainder, terminal
order/identity, tree fields and spans, diagnostics, published bytes/events and
ownership after cancellation/edit/retry. Cost observations additionally include
preparation, scanning, selection, shifts/reductions, capture, reuse checks and
failed reuse, materialization, validation/digest/publication, FFI transport,
allocation/GC and scheduling. Counted operations are not CPU weights.

** First connected kernel: retained terminal flow

[[file:../../formal/ParserEngine/Request.lean][Request.lean]] composes the existing =Capture.splitPrefix= semantics with LR
state/value depth. A configuration contains a top-first state stack, top-first
terminal-yield frames and the unconsumed significant-token suffix. Its invariant
is both stack alignment and:

#+begin_example
flatten(reverse(frames)) ++ rest = admitted significant-token input
#+end_example

=shift_valid= consumes exactly one pending token. =reduce_valid= uses an admitted
width, contracts only that prefix in source order, preserves its suffix and
leaves pending input unchanged, including width zero. =trace_valid= composes
these steps over arbitrary finite traces. =root_and_remainder= separates prefix
observation from =complete_root='s explicit empty-remainder premise.

[[file:../../formal/quint/RequestFlow.qnt][RequestFlow.qnt]] uses the same state and observation, with an empty input control and input ordinals
1--3, at most six frames, arbitrary abstract targets and reduction widths 0--3.
Its ten directed controls include full consumption, nullable/repeated
reductions, retained suffix, prefix acceptance, rejection and three deliberate
faults. Seeded 1,000-sample/20-step exploration checks this envelope; it is not
exhaustive model checking. Fault actions are excluded from the admitted step.
Neither model asserts grammar acceptance, scan correctness, AST yield equality,
native identity, progress or complete engine coverage.

Historical qualification at =24e47d9=: =lake build= completed 57 jobs;
=npm --prefix formal/quint test= passed 137 directed controls across 16 modules
and 15 seeded invariant explorations; the evidence host/input controls passed
four tests. =RequestFlow='s final ten controls and 1,000-sample exploration also
passed independently. These results establish the stated model properties and
input invalidation behavior, not native refinement or model completeness.

The Scheme correspondence obligations are concrete:

- =batch.ss= shift adds the current terminal and advances =rest= once.
- =batch.ss= reduction obtains source-order operands, retains the remaining
  states/values and recurses with the original =rest= after a successful goto.
- =recognition.ss= capture retains a terminal-yield description independent of
  the possibly lossy semantic value. =Request.frames= denotes that description,
  not arbitrary public AST children.
- =batch.ss= accept returns a root and remainder. =parser.ss='s
  =parse-tokenized/with= checks the remainder before success publication.
  Low-level accept checks the top semantic value, not a singleton stack.
  The single-frame premise of =root_and_remainder= must therefore come from
  the start-production/table correspondence; it is not discharged here.
- The direct checkpoint, contextual and generated paths need their own
  transition correspondence. Hash-binding these owners does not prove it.

These obligations are now visible; the source-to-model simulation is still
open. Counterexamples demonstrate that correct depth can coexist with reversed
terminals, and that a valid prefix is not a complete request. They are model
falsifiers, not claims that the production runtime has those faults.

** Connected grammar, scanner and table foundation

The new [[file:../../formal/ParserEngine/Grammar.lean][Grammar.lean]] starts at admitted base symbols. Its terminal
ordinals denote grammar terminals, not raw token kinds. DSL hygiene, lowering
of annotations and native ordinal encoding are outside that initial boundary.
It connects the earlier request kernel to grammar meaning in one namespace:

| Boundary | Definition / theorem | What it actually establishes |
|----------+----------------------+------------------------------|
| CFG -> finite terminal words | =Derives=, =derives_append= | Production membership and ordered contextual composition |
| Empty derivation -> nullable | =nullable_iff_derives= | Both directions for the inductive nullable closure |
| Grammar clauses -> fact environments | =nullable_least=, =first_least= | Semantic facts belong to any environment closed under the stated clauses; no native queue invariant is assumed proved |
| FIRST -> reachable sentence prefix | =Rewrite=, =Reach=, =first_reach= | A reachable terminal prefix, without requiring the remaining sentence to be productive |
| Nullable -> productive | =nullable_productive= | An empty finite derivation is a productivity witness; the converse is not asserted |
| Nullable/FIRST -> LR(1) lookahead | =LookaheadAllowed=, =Predicts= | FIRST of the suffix plus inherited lookahead only when the suffix is nullable |
| LR item -> goto/action support | =Advances=, =CellSupported=, =TableSupported= | Named semantic producer obligations; not a proof that the current compiler satisfies them |
| Grammar frames -> capture contraction | =reduction_derives=, =erase_reduce= | Actual RHS symbol agreement preserves a grammatical frame and erases exactly to the earlier capture/request operation |
| Table-driven finite request -> CFG result | =driven_trace_valid=, =table_driven_acceptance= | Selected shifts/reductions/gotos, admitted cells, RHS agreement and complete start-root premises compose |
| Fixed lexical policy -> complete source claim | =Lexes=, =source_request_derivation= | A character-source segmentation and the same grammar-terminal request theorem compose without confusing characters with token ordinals |

This applies the grammar/item/lookahead meanings of
[[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing, section 2]], with an explicit stack representation.
It does not claim equivalence to the paper's direct-style or CPS specializer.
The least-closure statements use the distinction between semantic facts and
closed abstract environments motivated by the
[[https://www.di.ens.fr/~cousot/COUSOTpapers/publications.www/CousotCousot-POPL-77-ACM-p238--252-1977.pdf][abstract interpretation paper]]. They do not prove the native worklist's
convergence, least solution or physical scheduling from file hashes.

*** Scanner selection has a producer obligation

=Preparation.ranked_fold_maximum= proves membership and weak maximum over the
entire supplied admitted catalog. Its ordering is exclusive end, precedence,
then lower declaration ordinal. Exact ties choose the right operand, matching
=scan/lexical.ss:prefer=. This proof assumes neither speculative callback
purity nor completeness of the native catalog. The native producer must still
establish all legal candidates, eligibility masks and payload/ordinal identity.
Character endpoints must not silently become byte endpoints.

*** One shared executable fixture through the engine

[[file:../../formal/quint/GrammarPipeline.qnt][GrammarPipeline.qnt]] uses =S -> A b; A -> a A | epsilon=. It connects nullable
and FIRST publication, literal candidate enumeration/ranking, pending-token
admission, a reference LR graph, nullable and repeated reductions, goto,
acceptance and rejection. Its safety predicate checks graph edges, grammar
frame yields, consumed/scanned token order and complete-publication conditions.
The graph IDs are reference IDs, not an unproved native numeric-state mapping.

The nine directed histories cover a wide lexical match, unit matches, nullable
A, rejection, and missing-FIRST/wrong-goto/advanced-lookahead/reversed-yield/
early-accept mutations. Deliberate mutations are excluded from admitted steps.
The seeded 1,000-trace/40-step exploration is finite sampling, not exhaustive
checking or a generic LR correctness theorem.

The existing [[file:../../t/resolved-grammar-test.ss][resolved-grammar test owner]] supplies an independent finite CFG
chart. Its facts =(lhs, start, end)= are derived from separate grammar clauses;
it reads no lowered productions, nullable/FIRST sets or LR tables. Both native
=canonical-lr1= and =follow-partition-lr1= paths are checked against the chart
for all 31 words of length 0--4 over a/b. The same grammar is instantiated in
=Grammar.Fixture=: nullable A and both FIRST(S) entries have derivation proofs,
and =repeated_S= constructs a derivation of =a^n b= for arbitrary n. That is a
positive semantic family witness, not unbounded native conformance or a proof
that no other words can be accepted by a native backend. Separate actual ranked-scanner calls
check longest/rank/order, mode masks, exact endpoints and the complete prepared
parser with the resulting two-token or three-token stream. These finite checks
bind a real route to the shared fixture; they do not discharge every generic
producer premise in the Lean theorem.

*** Two witnessed correspondence gaps

1. *Table format admission is insufficient.* =validate-lr-tables= checks
   dimensions, vocabulary, indices, row forms and reachable acceptance. A
   deliberate EOF-action mutation still passes it and low-level
   =lr-parse/prepared= accepts =a= for a grammar
   requiring a trailing =b=. The independent derivation chart rejects that word.
   =CellSupported= is a separate obligation. A completed item and a viable
   stack must justify reductions; a start-root/EOF condition must justify
   acceptance. The negative control does not claim that the normal compiler
   produces the mutated table or that arbitrary tables must be recompiled on
   every request. It disproves using schema admission as semantic evidence.
2. *Raw tokens have state-dependent terminal interpretations.* The built-in
   =make-lr-action-selector= tries exact literal, optional casefolded literal,
   then token kind in the current state. The same immutable =word/"if"= token
   selects a literal in one row and a token terminal in another. The new
   =Lookahead.selectRaw= laws and =raw_terminal_is_state_sensitive= witness,
   together with the real selector control, make this difference explicit.
   =Grammar='s fixed-terminal trace cannot be claimed to cover all such paths.
   The raw-request extension below supplies this logical relation and retains
   the pending observation through reductions; native refinement remains open.

The producer obligations require native nullable/FIRST worklist refinement,
closure/goto and conflict construction correspondence, and source-to-raw scanner
observations. The extension below derives RHS agreement and singleton acceptance
from explicit graph certificates. GLR, layout, recovery, edits and ABI remain
later compositions listed in the architecture ledger. Runtime tuning remains
deferred.

*** Viable prefixes, LR construction and state-dependent raw requests

[[file:../../formal/ParserEngine/Viable.lean][Viable.lean]] connects the earlier =Grammar.Predicts= relation, including
=FIRST(beta, lookahead)= and nullable inheritance, to a graph of production/dot
cores. =lr1_closure_erases= preserves production and dot while erasing lookahead.
=lr1_graph_constructed= derives the core graph certificate from LR1 closure/goto
membership and exact item projection. It does not assume a completed item
already describes the runtime stack.

The graph certificate requires initial items to originate in closure of the
augmented seed, and target items to originate in closure of the source items
advanced across that edge. Subset inclusion permits omission of predictions
with no lookahead. No prediction may introduce the augmented production as a
user rule. These are construction obligations, not conclusions from state IDs,
action schemas or an accept state being reachable.

Induction on the actual top-first stack path establishes:

- =item_suffix=: every item's consumed RHS prefix is a suffix of the stack in
  source order, with the dot within the production width.
- =completed_rhs=: the completed production fits the stack and its popped
  symbols, reversed into source order, equal its RHS. Epsilon is included.
- =drop_path=: popping the used prefix retains the earlier graph path.
- =accepting_stack=: a completed isolated augmented production of width one
  implies exactly one start symbol and two physical states. The singleton is
  derived rather than supplied as a request premise.

[[file:../../formal/ParserEngine/RawRequest.lean][RawRequest.lean]] uses these results in one complete deterministic request.
It retains original raw observations separately from chosen grammar terminals.
Only shift commits a terminal and consumes raw input; reduce preserves the raw
suffix and the next query uses the new LR state. Frame derivations, raw input
conservation and the ordered terminal/raw relation are preserved together.
=complete_request= derives a CFG word related to the entire original raw input
from the initial state, a legal trace, exhausted input and a selected accept.
It requires neither a per-reduction RHS premise nor a singleton-root premise.
This is conditional acceptance soundness, not language completeness.

=Lookahead.RowSupported= certifies EOF, exact literal, folded literal and kind
branches. =selected_raw_supported= preserves that certificate through the actual
priority order. =RawRequest.builtin_action_and_terminal= projects it into both
published-cell support and the terminal predicate needed by the request proof.
The certificates remain obligations of the row producer. Mutable Scheme token
fields and effectful custom selectors do not inherit them automatically.

[[file:../../formal/quint/RawRequest.qnt][RawRequest.qnt]] supplies a second connected fixture: =S -> X literal-if |
Y token-word=, =X -> a=, =Y -> b=. The same raw =word/if= observation commits
different grammar terminals in two complete requests. Directed histories cover
retained lookahead through reduction, normal rejection and full acceptance.
Mutations consume lookahead during reduction, commit a state-independent
terminal, accept a prefix or reverse a reduction yield. Each is rejected by the
shared path/derivation/conservation invariant. This is a finite protocol check,
not a proof of native LR table construction.

*** Compiler defect exposed by the construction obligation

The native graph check initially failed on an authored =$accept= nonterminal:
=lower-rules= always named the augmented production =$accept=, so prediction
could reintroduce augmented dot-zero items into goto targets. The same namespace
also allowed authored rules to collide with generated helper names.

The engine now reserves authored rule names and reference targets before
lowering, claims helper names deterministically, and allocates an unused
augmented name. Ordinary non-colliding grammars retain their naming sequence.
No user namespace restriction or compatibility mode was added.

The existing [[file:../../t/resolved-grammar-test.ss][resolved-grammar owner]] now checks four grammars across LR0/LALR,
canonical LR1 and follow-partition LR1 construction. An independent list-pair
closure oracle checks item origins and augmented separation without using the
producer's closure templates or packed increment rule. ACTION checks require a
shift edge and item, or a completed item with its published lookahead; GOTO
checks require an actual nonterminal edge. Invented edge labels and production
zero used as a reduction fail the controls. These checks compare the published
tables to generated graph/lookahead data; they do not independently prove the
native lookahead propagation fixed point. Partitioned LR1, layout guards and
full GLR execution are outside this new control.

Public compile/prepare/parse checks cover =$accept=, =$accept.0= and =$start.0=
collisions, deterministic repeated lowering, valid full input and rejection.
Root aliases follow the public recognition-result contract. The raw selector
check reuses the same token object across two complete requests with distinct
root kinds and verifies the committed literal/kind terminals.

*** Checked native publications and solver correspondence

The earlier table-support check used the producer's own lookahead masks as
premises. The new checks strengthen that boundary in three coordinated layers.
They do not treat agreement between two views of one mask as an independent
lookahead derivation.

**** Executable completion certificates

[[file:../../formal/ParserEngine/Completion.lean][Completion.lean]] implements finite nullable/FIRST derivation rounds and
publication checkers. A check succeeds only when the supplied set equals a
sound finite round *and* is closed under every grammar rule. Rounds retain set
membership rather than duplicate derivation entries. Theorems
=nullable_certificate_exact= and =first_certificate_exact= establish both
soundness and completeness against =Grammar.Nullable= and =Grammar.First= for
arbitrary supplied grammars and certificates. Neither theorem assumes the
native queue has terminated correctly. An inadequate fuel value fails closed;
no theorem treats exhaustion or a locally empty queue as publication evidence.

The sequence operator is proved equivalent to =Grammar.SequenceFirst=.
Nullable closure feeds FIRST leastness, and FIRST remains a terminal-prefix
property when a later suffix is unproductive. Negative kernel checks reject
self-supporting nullable/FIRST cycles, empty-fuel publication missing an epsilon
consequence and omitted FIRST facts. A positive control retains FIRST for an
unproductive suffix.

The same module models the native clause counter as the number of *unresolved
occurrences*, not the number of distinct dependencies. A fresh notification
removes exactly the source's occurrence multiplicity. A duplicate notification
changes no unresolved obligation. A zero counter means every dependency is
known; an undefined name remains unresolved. Here =known= describes delivered
facts, distinct from facts published but still pending in the native queue.
These laws cover the mathematical counter update; they do not prove every
Scheme mutation executes it correctly.

[[file:../../formal/ParserEngine/NativeFacts.lean][NativeFacts.lean]] instantiates the checkers with four typed inputs generated
from the actual native =lower-rules=, =compute-completion= and =compute-first=
outputs. The fixtures cover epsilon/recursion, repeated dependencies and cycles,
an unproductive suffix and undefined reference, and annotated optional/repeat
lowering with a helper-name collision. The exported data retain production
order and consistently encode named symbols into separate terminal/nonterminal
constructors. For each fixture, Lean checks the Boolean certificate with
=by decide= and derives exact semantic membership for all names and terminals.
No =native_decide= trust extension, new axiom or admitted theorem is used.

The existing Scheme owner independently regenerates the entire typed input
module and compares it with the checked source. Thus a stale fixture, changed
native publication, changed encoding or edited certificate declaration cannot
silently preserve the qualification. These are small executable proof fixtures,
not benchmark result reports. The explicit regeneration command is:

#+begin_src sh
gerbil env gxi t/generate-grammar-model-facts.ss
cd formal && lake build
#+end_src

Regeneration alone is not acceptance: both the Lean checker and native
conformance owner must subsequently pass. The encoder and bounded fixture
coverage remain explicit implementation boundaries. This is not a formal
interpreter for arbitrary Scheme source.

**** Authored DSL and lowering meaning

The Scheme =source-dsl-accepts?= oracle evaluates authored expression trees
using span saturation over named references. It does not call lowering,
nullable/FIRST, generated helpers or LR tables. Choice, sequence, optional,
repeat/repeat1, references, literals, fixture token kinds and field/alias/static
precedence wrappers are evaluated directly. Repeat admits only positive-width
iterations after its empty case, preserving finite-word meaning without a
nullable loop.

For eight grammars and all 15 words over =a/b= through length three, the owner
compares this meaning with a separate CFG span chart over actual lowered
productions. The controls include epsilon, recursive cycles, undefined names,
annotations and generated helper collisions. A removed mandatory suffix is
witnessed as a semantic mismatch. This establishes bounded terminal-language
correspondence; AST fields/spans, dynamic precedence, layout, DSL admission and
a universal lowering theorem remain open.

**** LR lookahead provenance independent of native masks

The new symbolic tuple oracle reconstructs LR lookaheads from the augmented
EOF seed and saturates the complete published transition graph. Its prediction
step recomputes =FIRST(beta, inherited)= with independent nullable/FIRST
reference solvers. It uses neither native suffix masks, packed increments,
closure scratch arrays nor dependency queues. Symbolic lookaheads are compared

*** Universal lowering and preparation control flow

This extension moves beyond equality certificates for four publications. Its
main results quantify over arbitrary grammars, recursive derivations and finite
input lengths. Finite Scheme/Quint controls continue to qualify the physical
implementation; they are not the source of those universal results.

The paper anchor is [[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing, sections 2.1--2.2]]: parser
behavior is specified against the grammar's derivation relation, with an
isolated augmented start production. The source DSL must therefore preserve
CFG derivations before an LR algorithm or specialization can be justified.
The new proof is our lowering construction, not a theorem claimed by that
paper, and no PEG ordered-choice law or specialization speed result is used.

**** Recursive source DSL and emitted-rule correspondence

[[file:../../formal/ParserEngine/Lowering.lean][Lowering.lean]] defines source evaluation and a production schema with
intrinsic expression owners. =lowering_exact= and =named_lowering_exact= prove
soundness and completeness for every finite recursive rule list, expression
and terminal word. Constructors include failure/empty, terminal/reference,

annotations. =choice_list_exact= and =sequence_list_exact= connect arbitrary
source arities to the binary induction. Empty choice is failure; empty sequence
is epsilon. Nullable repeated children are permitted in the mathematical
finite-derivation semantics; native admission policy is a separate judgment.

This is a schema with scoped expression owners, not a claim that Scheme's
physical names already have that type. The native bridge uses finite syntactic

and atomic operand erasure. =native_derivation_sound= and =native_root_sound=
quantify over every native CFG and every input word satisfying that structural
bridge. They do not take desired per-input language equality as a premise.

shared left side. =isolated_repeat_origin= and =isolated_repeat1_origin= prove
the native self-recursive rule shape for arbitrary child expressions and

spans, dynamic precedence, lexical layout effects and an executable verifier for

* Cost model: count work before estimating time

For a logical sequence with R leaf/branch records and N emitted children,
=materializeInto= is an executable suffix builder. =copyLeaf= counts one
emission per recursive cell; branches count one structural visit and combine
child counts. The theorem proves both its output and exactly R + N counted
operations, for arbitrary sequence shape and an arbitrary retained suffix.
The append-based =flatten= is only the reference denotation: its own runtime
is not claimed linear. This recursive Lean algorithm does not prove the
bounded control-stack behavior of Scheme's builder/iterative visitor, nor
cover position views or event-program sequences.

=stackSequence= allocates branches rather than copying accumulated prefixes.
A branch has constant logical construction work; =join_allocations_linear=
counts n branch constructions. Repeated singleton append in the reference
list implementation copies 0 + 1 + ... + (n - 1) prefix cells;
=copied_prefix_triangular= proves 2 C(n) + n = n squared. This comparison
formalizes the engine's existing persistent representation; it is not a new
optimization or a measured speedup. Empty-join normalization is abstracted
away, so logical branch counts need not equal Scheme allocations.

Prepared factories make no provider selections in the modeled request
executor. Interpreted action selections equal the action-list length.
Factory-body costs, field/alias boundary walks, allocations and GC are outside
that selection count. They must still be measured on real requests.

=publicationWork= is an explicit contract charging every source byte and flat
event. Its lower-bound theorem is arithmetic under that contract, not a proof
of the SHA256 implementation or event publisher. Full digest and flat output
prevent a sublinear complete-publication claim even when recognition is local.

* Question: why does this design exploit Scheme and its DSL?

The advantage is staging and higher-order composition, not parentheses alone.
Canonical syntax describes actions once. Engine-owned generic selection turns
those declarations into retained functions; each request supplies its own
children and source anchors. Grammar authors need not select storage, dispatch
or traversal strategies. Scheme closures preserve that separation naturally.

The existing engine pattern is illustrated below; this is an implementation
witness, not a new public DSL form:

#+begin_src scheme
;; src/runtime/reduction-plan.ss: select before repeated requests.
;; Each retained action receives request-local children and offsets.
(prepare-operand-actions field-factory alias-factory actions)
#+end_src

The LeanPoo tuple models selection provenance, while the parser model adds the
ordered context-threading law. A generic method may choose the implementation
at preparation time without forcing generic selection into every child visit.
The three language interfaces remain grammar.ss, parser.ss and parser-test.ss.

* Question: how is the design scientifically checked?

Each claim names its counted operation and assumptions, a kernel-checked
semantic law, a Scheme conformance owner and a measurement owner. The
integration theorem connects preparation to reverse-stack reduction instead
of treating local equalities as a complete parser proof. The materializer
counts the operations of a defined algorithm instead of assigning a desired
linear formula to an unspecified traversal.

The remaining proof boundary is explicit: input/span admission, derivation of
nullable offsets, LR table/CFG soundness, GLR ambiguity, arbitrary external
actions, relocation views, Scheme refinement, digest correctness and reuse
validation are not proved. Operands carry already supplied individual anchors.
Stack-depth preservation requires admitted width; it does not validate goto
entries. No theorem establishes P50/P95, heap bytes or hardware performance.

this admission. The original triggering transition and event order remain

admission/lowering policy was restored to the prior baseline. The invariant
checker and directed controls remain verification tooling, not an enabled
runtime optimization. This is one part of the engine execution plan, not whole-engine
performance closure and not a maintained state/text cache.

The architecture audit must account for the complete request, not add up
instrumented leaf durations or mistake fewer guards for fewer executed visits:

Existing =FoldPlan.qnt= owns source/bounds epochs, effect barriers and ordered
consumer histories. Its local-preserving-transition history requires the same
extent and scan basis; unknown transitions still invalidate. =RunPlan.qnt=
owns interval commit/residual ordering. No second grammar or duplicated Lean
semantic proof is introduced in Quint. Neither model proves processor
activation, garbage-collector behavior or Tokio latency.

Real AOT conformance and observer-free complete-request timing remain mandatory.
The latest historical count-only census reports many repeated generated calls,
but its instrumentation and GC prevent treating those counts as exclusive CPU
or allocated bytes. The new architectural model is deliberately not a claim
that the 1000-request 10 ms gate has passed. The compiler-to-model dependency
analysis and complete pipeline cost attribution remain explicit open work.

* Generated call-region fusion

The call planner operates on the complete generated program before module
partitioning. Private expression references are counted across bodies and
value/export references. Only a unique call edge with scalar-reference
arguments and bounded expanded size is spliced. Shared consumers and helper
frame entries retain their boundary; effectful arguments are not moved.
Consumer effects and events retain order. Fresh lexical names preserve let,
let*, single-binding Gerbil let and named-loop scope. Quotes are opaque.
Final reachability prevents a rejected parent from deleting needed callees.

The budget bounds generated code, not request concurrency or runtime dispatch.
No request cache, event representation or runtime graph is added. Production
direct tapes use this pass; list consumers and diagnostic products do not.
Six directed controls cover scope, shared calls, argument effects, skipped
errors, size rejection and mutable owners. Lean splice_call_preserves_order
proves the ordered transition-region contract, not Scheme alpha conversion.
Existing Quint FoldPlan checks a fused-call/frame invalidation history rather
than duplicating the semantic proof. The collector binds the planner, tests,
models and real AOT. Static call reductions are not performance admission.

* Existing interval contracts

=Fold.lean= owns pure transition refinement: =overwrite_run_last= and
=overwrite_run_residual= retain the final overwrite and the original trigger
transition; =run_partition= preserves contiguous source extents. These theorems
do not establish the compiler's eligibility analysis or physical scan cost.

=RunPlan.qnt= owns lifecycle histories, not the same denotational proof:
frame invalidation prevents stale commits, a committed ordinary run must
execute its residual before the next scan, and a mutation witness rejects
stale admission. The seeded 1000-trace/20-step check is bounded testing, not
an exhaustive proof over all executions or a throughput guarantee.

The model collector binds the ordinary-run admission and lowering, generated
module owner, borrowed byte scanner, source-line visitor, event-tape writer,
and implementation controls. Complete real AOT tapes and matched timing remain
separate evidence obligations. Model success never promotes a candidate that
fails the 1000-request <=10 ms preflight.

The foreign ordinary-run leaf experiment passed boundary and complete-tape
controls but did not improve matched whole-call timing and was reverted.
The retained models describe the existing run contract, not a deployed foreign
scanner. Diagnostic =t/benchmarks/parser-throughput/stalls.ss= reads the
installed Gambit header's GC counters and OS resource counters; its extra
probes and cold first call make it diagnostic only, not acceptance timing.

* Explicit Lean and Quint responsibilities

[[file:../architecture/0019-model-responsibilities.org][Model responsibility boundary]] maps paper arguments to separate algorithm,
lifecycle, implementation and performance obligations. Lean's new
=ParserEngine.Reuse= proves whole-result identity admission and counted
preparation amortization including per-request validation. Quint's
=ReuseAdmission= checks source/grammar/plan invalidation, cancelled/failed
completion and superseded ownership with independent mutation witnesses.
Neither qualifies cross-edit subtree reuse or a runtime speedup.

* Lowering proof production and operational LR construction

The terminal-language projection follows the CFG obligations in the research
basis and the LR construction/viable-prefix boundary above. It is not a PEG
ordered-choice law. The actual =lower-rules= engine now has an optional proof
sink after the existing origin observer. It publishes each helper's physical
name and source expression before its productions, and attaches a recursive
schema recipe to the actual emitted production object. The augmentation row is
separate. Ordinary compilation does not request or allocate recipe trees.

The producer covers atomic operands, empty/layout-end rules, n-ary sequences,
n-ary choice inlining, optional branches, isolated repeat/repeat1 loops,
shared-owner forwarding through private helpers, and field/alias/precedence
projection. The recognition projection erases field, alias and precedence
annotations and maps layout-end to epsilon. This does not establish AST,
indentation, priority, conflict-resolution or dynamic-GLR effect preservation.

=Names.Produced= describes syntactic generation, and =produced_recipe_checked=
proves that arbitrary-depth generated recipes check successfully with their
exact endpoints. =sequence_recipe_produced= and =choice_recipe_produced= cover
arbitrary arity, including the empty-sequence base and absent empty-choice
branch. The two repetition constructors require a justified recurrence recipe;
a named recurrence uses =UniqueBody=, while a private helper uses identity.
A sibling alternative cannot supply that unique-body witness. The atomic
operand producer and =native_sequence_recipe_produced= require no supplied
per-operand proof. =admitNative=
consumes both lists completely and rejects missing or excess recipes.
=admitted_native_root_sound= composes an admitted complete publication with
source evaluation for arbitrary finite words and recursive grammars.

The native fixture writer emits source rules, helper decoding, actual native
rules and their generated recipes into =NativeFacts.lean=. Seventeen grammar
families exercise every supported lowering branch, undefined references,
duplicate authored names, reserved helper-looking names, dynamic precedence,
empty choice and nested choices. Lean checks each publication and proves its
source-language implication for all finite words. Native tests compare the
complete generated module, preserve production object identity and order,
check binding-before-use, and require proof-sink failures to propagate. These
are implementation controls, not universal proof of Scheme evaluation.
Negative Lean controls reject a wrong helper binding, changed endpoint,
ambiguous named fold, invalid local schema step and truncated publication.

The LR boundary now includes the actual =make-item-layout= recurrence:
=denseOffset= models prefix offsets, and =denseCoordinates= models the ordered
owner-vector fill. =dense_coordinate_roundtrip= covers arbitrary production
counts and RHS widths, including epsilon productions. =decode_core_roundtrip=
connects those coordinates to the ordered grammar table.
=dense_goto_refines_advance= proves that the native integer increment is a
logical shift precisely when the actual after-dot symbol exists. Native
controls enumerate independent coordinates and symbol catalogs over uneven
width families and check that completed items do not become shift premises.

=ClosureTrace= starts at the kernel and publishes only predictions justified
by an already published item. Its supported/retained-kernel invariants and
=closure_trace_exact= derive least closure from operational history plus
quiescence, rather than assume equality with the desired result.
=goto_kernel_exact= connects executable filtering/increment to =moved=.
=construction_traces_supported= then derives the graph obligations consumed
by the existing viable-prefix proofs from initial/target construction traces.
It permits arbitrary state identifiers and construction order. =LR1Trace= and
=lr1_trace_exact= retain the full =Predicts= suffix-FIRST/nullable/inherited
lookahead relation. =lr1_construction_traces_supported= composes the executable
LR(1) goto-kernel operation and those histories through core erasure with the
same viable-prefix graph theorem; no global FOLLOW approximation is assumed.

The remaining correspondence obligations are explicit: connect every physical
native edge and optimized prediction-template batch to those operational
histories; prove state interning, follow partition refinement and conflict/table
publication; and connect source normalization and fresh-name allocation to the
recipe producer for arbitrary host executions. Existing name/ordinal/counter
proofs and checked publications supply components, not that entire composition.
The unchanged Quint =GrammarPipeline= owns publication/request ordering and the
shared-loop mutation witness; Lean owns the unbounded derivational results.
No performance change or CPU improvement is claimed by this work.

qualification against those native dependencies passed 53 resolved-grammar

These checks qualify the stated boundaries; they do not close physical native
state construction or establish a CPU improvement.
