#+title: Canonical artifact publication cost and ownership
#+startup: overview

Part of the [[file:shared-scanner-staging-and-fusion.org][shared engine study]] and its
[[file:shared-source-projection-publication.org][source publication argument]]. Implementation baseline: PR #13 =11b2cf1=
plus this source slice. This module connects an open cost-attribution obligation
to the existing artifact owner, source tests and cross-language measurements.

* Research question

Which work inside =artifact-materialization= should be optimized first: source
encoding, canonical event publication, or source identity construction? An
inclusive materialization interval could not distinguish those operations.
This prevents using the research proposal to choose a measured implementation
boundary. It is not evidence that hashing or Gambit GC is defective.

[[https://arxiv.org/html/2304.05276#S2.SS8][flap Section 2.8]] excludes user semantic actions from its allocation-free
generated execution claim; Section 5.5 distinguishes recognizer pseudocode from
constructing ASTs or other semantic values. Our inference is that the required
lossless artifact must be measured explicitly before applying staging or fusion
claims. This attribution change implements that measurement obligation, not
flap's DGNF normalization, fusion algorithm or linear-time theorem.

* Engine-owned phase contract

The existing =with-parser-cost-stage= macro now marks three boundaries inside
=src/runtime/artifact.ss=. It retains direct expression evaluation when the
observer is disabled; parameter lookup still has a cost. No language slot,
callback protocol or author configuration is added.

| Stage | Work inside the interval | When absent |
|-------+--------------------------+-------------|
| =artifact-source-encoding= | Convert the source string to UTF-8 bytes | The caller already supplied bytes |
| =artifact-event-publication= | Walk recognition/event programs or resolve a committed raw tape into canonical event vectors and list cells; rejected products publish flat token events | The caller already supplied canonical events, or an uninstrumented specialized constructor owns them |
| =artifact-source-identity= | Hash supplied source bytes and construct the canonical artifact header | Publication failed before reaching identity construction |

The raw-tape resolver is a private named function. Its committed prefix,
trivia resolution, event IDs and completeness checks are unchanged. Identity
construction executes after that function returns, outside the event interval.
Supplying events does not imply that event construction ran in this constructor.
The existing source-validation interval remains a separate caller obligation.
Incremental event rewriting and generated direct sinks are not fully attributed
by this slice; an absent phase is not a zero-cost phase.

The generic stage benchmark now reports =request-samples=, invocation =samples=,
=completed-samples= and =incomplete-samples=. A recovered failure can belong to a
complete rejected artifact while its failed inner interval remains incomplete.
Repeated stage invocations remain separate observations. CPU quantiles use the
reported invocation population; allocation quantiles retain only zero-GC,
nonnegative counter intervals. These populations must not be interchanged.

* Scheme witness and design questions

#+begin_src scheme
;; Engine code; grammar.ss retains syntax and rules only.
(let ((events
       (with-parser-cost-stage 'artifact-event-publication
         (raw-event-tape-events tokens tape committed-count trivia? byte-length))))
  ;; The canonical identity owner reuses bytes and observes its own hash/header.
  (artifact grammar-digest source 'accepted events '() source-bytes))
#+end_src

** Question: why does this design improve the DSL boundary?

Cost ownership follows engine operations. Recognition, event programs and raw
tapes publish through shared canonical contracts, so authors do not need to
write per-language profiling adapters or expose transient event machinery in
=grammar.ss=. =parser.ss= keeps metadata and parser adaptation; =parser-test.ss=
keeps language behavior and workload selection. Scheme macros express the
optional observation at the owner while preserving its normal result.

** Question: why is the design scientifically testable?

An observed constructor must equal its unobserved complete artifact. Source
admission checks Unicode byte coverage and identities independently. Supplied
bytes/events must not generate fictitious construction observations. A failed
tape must preserve its original error, publish =completed=false= for the failed
interval, and never report a later identity stage. The observer's dynamic scope
must be restored. These are executable obligations, not a speed claim inferred
from the presence of a macro or a paper result.

* Consequence for the next optimization

In these measured workloads, event publication allocates far more than source
identity construction. That interval includes required canonical vectors/list
cells and transient traversal storage; the measurements do not separate those
components or justify eliminating the public artifact. A subsequent producer/
consumer change must account for retained versus transient storage, preserve
full event/field/span/diagnostic equality and qualify complete requests. Hash
caching, dropping source admission or reviving a rejected local iterator does
not follow from this evidence. Exact-head platform CI remains a separate gate.

* Executable event-storage control

The shared benchmark now implements =measure-artifact-event-storage=. This
closes the next attribution obligation at the same publication boundary. It
copies an already source-admitted artifact's event list into fresh list cells
and shallow-copied vectors, preserving event order, vector widths and every
payload. IDs, symbols, byte offsets and token lexemes remain shared values.
The control uses the existing canonical representation; it introduces no new
parser backend, language configuration or production storage protocol.

The installed Gerbil runtime uses =vector-copy= in =raw-table-copy= in
=src/gerbil/runtime/table.ss=. Its =src/std/list/list-builder.ss= supplies
=with-list-builder=, and =src/std/vector/vector.ss= composes that macro with
vector iteration. The engine's private =collect-canonical-events= now uses
that same official builder in place of its hand-written queue function. Both
its recognition and event-program sinks retain their existing event constructors
and source-order authority. The independent copy control uses the same builder
with =for-each= and native shallow copying. This is a source-grounded reduction
in duplicated infrastructure, not an inference that a higher-order function or
unchecked mutation always improves parser performance. Builder mutation is
confined to fresh private list cells.

#+begin_src scheme
(import :gerbil-parser/t/benchmarks/parser-stage-cost/benchmark
        :gerbil-parser/languages/arithmetic/parser
        (only-in :std/list/list-builder with-list-builder))

(let* ((source "1 + 2 + 3")
       (artifact (parse-arithmetic source)))
  ;; Complete requests localize the publication interval.
  (measure-parser-stages parse-arithmetic source 20)
  ;; Independent control isolates construction of the existing containers.
  (measure-artifact-event-storage artifact source 20))

;; Shared benchmark implementation: native shallow copies preserve payloads.
(def (copy-canonical-event-storage events)
  (with-list-builder (emit!)
    (for-each (lambda (event) (emit! (vector-copy event))) events)))
#+end_src

** Question: why does this improve the DSL boundary?

The engine's canonical event representation supplies the control without a
second language-specific walker. Authors continue declaring syntax/rules and
public parser metadata; they do not need to describe memory layouts or provide
profiling sinks. Scheme procedure composition expresses the copying operation
directly, while the engine remains the authority for publication and source
admission. Generic dispatch would add no useful type decision to this homogeneous
list of canonical vectors.

** Question: why is the control scientifically testable?

Each copied event vector and list cell must be distinct, each payload must retain
its identity, and mutating a copied vector must leave the original vector intact.
The benchmark reconstructs the complete artifact header around the copied events
outside the measured interval, checks complete equality, then independently
checks source admission. This preserves accepted/rejected status, diagnostics,
fields, Unicode byte coverage and both source/grammar identities. Empty products
and invalid inputs have explicit controls. Allocation observations retain the
same no-GC, nonnegative-counter admission as the stage benchmark.

This is an empirical container-construction control, not a retained-heap census,
an allocation lower-bound theorem, or an alternative parser. Copy-loop and
statistics overhead remain in the interval. Lexeme payloads and artifact-header
construction are outside it. The summary reports event count and total vector
slots alongside CPU/allocation populations; no fixed Gambit object-size formula
is assumed. Subtracting independent medians would not establish recoverable
allocation or a complete-request speedup. A large gap motivates a traversal
experiment with matched complete-request controls; it does not admit that change.

** Rejected attribution shortcut

The initial =map vector-copy= prototype compiled natively in =27.682s= and
passed all =31= source cases in =16.822s=. Twelve profiles with twenty copies
each completed in =9.062s=, with full-product equality and source admission.
At 512 operands, GQL's copy allocation median was =1167728= bytes against
=1168768= publication bytes; Arithmetic's was =1047856= against =1048896=.
FHIRPath's copy counter instead varied: its requested =#f= median was =872448=
and P95 =1789936=, despite all twenty intervals passing the no-GC/nonnegative
counter filter. The requested =#t= median was =872440= with the same P95.

This is negative evidence for treating the prototype's median as a precise
storage budget or the remainder as traversal waste. No allocation saving is
admitted from these values. The installed allocation counter's raw delta and
occupied-object terms are not an object-lifetime census. The builder rerun
checks the construction protocol directly; it does not assert a cause for the
prototype's counter variation or weaken the allocation admission filter.

The builder control's admitted allocation P50 and P95 agree in all twelve

and retains nineteen allocation observations; CPU still includes that sample.
All other copy profiles retain twenty. A separate Scheme report checks each
publication population completes twenty intervals and each copy population
contains twenty samples, with its actual allocation population reported.
An initial temporary report rejected an incorrect summary field index; the
corrected reader completes with =EVENT-STORAGE-REPORT-OK profiles=12=.

Required container construction closely tracks publication allocation in these
workloads. The experiment provides no evidence of a large removable traversal
allocation budget. The small difference is not admitted as recoverable storage;
the observed publication interval includes observer overhead and the copy
interval has its own construction/statistics overhead. The official-builder
migration preserves the reported publication allocation medians. It is not a
complete-request speedup admission, and the two run elapsed times are not a
performance comparison.

The next engine experiment should therefore separate source recognition and
semantic reduction costs, which remain larger request allocations in these
profiles, instead of treating canonical publication vectors as disposable.
Changing the public representation would require a separately reviewed semantic
contract and Rust consumer qualification. No such change is implemented here.
This updates the preceding localization decision with the missing independent
control rather than appending an unrelated language-specific optimization.
