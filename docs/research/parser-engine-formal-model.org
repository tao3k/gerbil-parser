#+title: Parser engine semantics and operation model

* Objective and evidence boundary

This model connects one complete deterministic reduction path: canonical
field/alias actions, retained factories, reverse LR operands, logical AST
children and sequence materialization. Production remains Scheme. Lean checks
universal properties of the reference algorithms; Scheme controls check the
implementation; matched benchmarks measure CPU and allocation. These are
three separate obligations, not interchangeable receipts.

The executable package is [[file:../../formal/ParserEngine.lean][formal/ParserEngine.lean]]. The checked toolchain and LeanPoo revision are recorded in
[[file:../../formal/lean-toolchain][lean-toolchain]], [[file:../../formal/lakefile.toml][lakefile.toml]] and its locked manifest. LeanPoo is a verification dependency only.
Its =Functional.Requirements.Factories= and =Selected= retain typed factories;
=prepare_ok_iff= establishes that successful preparation selected exactly
those factories. Our executor threads transformed children through that tuple:
LeanPoo's independent-result =build= is deliberately not used for sequential
actions. No new Scheme dispatch facility or author interface is introduced.

* Architecture alignment audit and qualification order

The architecture model is *incomplete*. A successful Lean build establishes the
listed theorems; successful Quint runs check their stated finite histories.
Neither establishes coverage of all paper mechanisms, all engine routes or a
refinement of Scheme. Hash-binding a source file only identifies that file.
It does not connect a source transition to a theorem.

The local reduction objective above is historical scope, not a complete engine
specification. This section is the shared coverage ledger. Extend this ledger
and its connected models before another runtime optimization. Do not use a new
local object-count identity as evidence that an architecture gap has closed.

** Responsibilities and shared vocabulary

1. Papers define mechanisms, premises and limits. Transfer to this engine must
   identify both retained premises and differences in algorithm/representation.
2. Quint describes legal histories, invalidation and interleavings. Its bounded
   transition envelope must name the same owners and observations as Lean.
3. Lean defines denotations, representation relations, transition preservation
   and cost recurrences under explicit premises. It must not replace producer
   premises with facts that only a native implementation could establish.
4. Scheme/Rust controls discharge implementation-specific correspondence and
   failure obligations. Complete-request benchmarks measure the resulting CPU,
   allocation and GC behavior. Neither timing nor byte counts prove semantics.

The request state vocabulary is: admitted grammar/IR identity; source identity
and generation; lexical position/mode; pending terminal with its admission
basis; LR states; semantic values; retained recognition yields; branch and
layout context; checkpoint/history owner; public artifact; and FFI owner/lifetime.
A source coordinate, token ordinal, grammar state and object identity are four
different quantities. Mutable tokens need a real producer protocol; an abstract
revision field does not supply one to Scheme.

The common observations are recognition outcome, exact remainder, terminal
order/identity, tree fields and spans, diagnostics, published bytes/events and
ownership after cancellation/edit/retry. Cost observations additionally include
preparation, scanning, selection, shifts/reductions, capture, reuse checks and
failed reuse, materialization, validation/digest/publication, FFI transport,
allocation/GC and scheduling. Counted operations are not CPU weights.

** First connected kernel: retained terminal flow

[[file:../../formal/ParserEngine/Request.lean][Request.lean]] composes the existing =Capture.splitPrefix= semantics with LR
state/value depth. A configuration contains a top-first state stack, top-first
terminal-yield frames and the unconsumed significant-token suffix. Its invariant
is both stack alignment and:

#+begin_example
flatten(reverse(frames)) ++ rest = admitted significant-token input
#+end_example

=shift_valid= consumes exactly one pending token. =reduce_valid= uses an admitted
width, contracts only that prefix in source order, preserves its suffix and
leaves pending input unchanged, including width zero. =trace_valid= composes
these steps over arbitrary finite traces. =root_and_remainder= separates prefix
observation from =complete_root='s explicit empty-remainder premise.

[[file:../../formal/quint/RequestFlow.qnt][RequestFlow.qnt]] uses the same state and observation, with an empty input control and input ordinals
1--3, at most six frames, arbitrary abstract targets and reduction widths 0--3.
Its ten directed controls include full consumption, nullable/repeated
reductions, retained suffix, prefix acceptance, rejection and three deliberate
faults. Seeded 1,000-sample/20-step exploration checks this envelope; it is not
exhaustive model checking. Fault actions are excluded from the admitted step.
Neither model asserts grammar acceptance, scan correctness, AST yield equality,
native identity, progress or complete engine coverage.

Local qualification for this model change: =lake build= completed 57 jobs;
=npm --prefix formal/quint test= passed 137 directed controls across 16 modules
and 15 seeded invariant explorations; the evidence host/input controls passed
four tests. =RequestFlow='s final ten controls and 1,000-sample exploration also
passed independently. These results establish the stated model properties and
input invalidation behavior, not native refinement or model completeness.

The Scheme correspondence obligations are concrete:

- =batch.ss= shift adds the current terminal and advances =rest= once.
- =batch.ss= reduction obtains source-order operands, retains the remaining
  states/values and recurses with the original =rest= after a successful goto.
- =recognition.ss= capture retains a terminal-yield description independent of
  the possibly lossy semantic value. =Request.frames= denotes that description,
  not arbitrary public AST children.
- =batch.ss= accept returns a root and remainder. =parser.ss='s
  =parse-tokenized/with= checks the remainder before success publication.
  Low-level accept checks the top semantic value, not a singleton stack.
  The single-frame premise of =root_and_remainder= must therefore come from
  the start-production/table correspondence; it is not discharged here.
- The direct checkpoint, contextual and generated paths need their own
  transition correspondence. Hash-binding these owners does not prove it.

These obligations are now visible; the source-to-model simulation is still
open. Counterexamples demonstrate that correct depth can coexist with reversed
terminals, and that a valid prefix is not a complete request. They are model
falsifiers, not claims that the production runtime has those faults.

** Completion gates before architecture optimization

1. Specify the admitted DSL/grammar and scanner meaning, including effects and
   invalid declarations. Connect derived facts and tables to that meaning.
2. Extend the shared LR kernel with selected actions/gotos, branch/layout and
   recovery, then connect capture/projection and checkpoint transfer to it.
3. Compose edit/retry/cancellation/history and artifact/ABI observations with
   the same request semantics. Name every unsupported route and premise.
4. Bind executable conformance controls to these abstraction relations; model
   command success and source hashes alone cannot discharge the relations.
5. Derive complete cost recurrences from admitted transitions. Rank optimization
   hypotheses only after the applicable semantic boundaries close, then use
   complete-request Scheme benchmarks for CPU qualification.

The latest =a50882f= Ubuntu CPU trial remains a failed performance gate:
production P90 =0.9724769011= against the unchanged =0.95= ceiling with valid
controls. A passing earlier trial cannot cancel it. The current model changes
make no CPU improvement or runtime repair claim and do not authorize treating
that revision as performance-qualified.

* Papers, obligations and implementation owners

Sperber and Thiemann's [[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing]] separates grammar-static
information from request-dependent execution through partial evaluation.
Our immediate obligation is narrower: retaining selected action functions must
preserve their declaration order and semantics. This is not a reproduction of
the paper's full LR generator or its speed measurements.

Wagner and Graham's [[https://harmonia.cs.berkeley.edu/papers/twagner-parsing.pdf][Efficient and Flexible Incremental Parsing]] motivates
explicit treatment of retained parsing structure. Here persistent child joins
are modeled separately from complete publication. Incremental invalidation,
reuse certificates and grammar recognition soundness remain later obligations;
existing [[file:../architecture/0010-persistent-recognition-snapshots.org][snapshot architecture]] owns those implementation requirements.

| Obligation / Lean theorem | Scheme owner | Implementation controls |
|---------------------------+--------------+-------------------------|
| Prepared action chain equals interpretation: =prepared_plan_equivalent= | =src/runtime/reduction-plan.ss= | =t/fused-reduction-test.ss= |
| Prepared reverse reduction preserves source order and operand anchors: =prepared_reverse_reduction_equivalent= | =src/runtime/reduction-plan.ss= | =t/lr-stack-reduction-test.ss= |
| Field labels survive nesting; empty aliases retain supplied anchors | =src/runtime/reduce.ss= | =t/fused-reduction-test.ss= |
| Materialization preserves children and suffix: =materialize_into_exact= | =src/runtime/funcs.ss= | =t/recognition-sequence-test.ss= |
| Shift/reduction preserve state/value depth relation | =src/runtime/lr-parser.ss= | =t/lr-stack-reduction-test.ss= |
| Full publication has byte and event obligations | =src/runtime/artifact.ss= | =t/artifact-publication-cost-test.ss= |

The table identifies conformance owners, not a proved refinement from Scheme
into Lean. Existing controls must be inspected and extended when either side
changes. =Examples.lean= also checks both action orders, nested fields, distinct
empty-operand anchors, empty leaves, suffix preservation and a prefix-copy
count. They complement the general theorems; finite examples do not prove them.

* Cost model: count work before estimating time

For a logical sequence with R leaf/branch records and N emitted children,
=materializeInto= is an executable suffix builder. =copyLeaf= counts one
emission per recursive cell; branches count one structural visit and combine
child counts. The theorem proves both its output and exactly R + N counted
operations, for arbitrary sequence shape and an arbitrary retained suffix.
The append-based =flatten= is only the reference denotation: its own runtime
is not claimed linear. This recursive Lean algorithm does not prove the
bounded control-stack behavior of Scheme's builder/iterative visitor, nor
cover position views or event-program sequences.

=stackSequence= allocates branches rather than copying accumulated prefixes.
A branch has constant logical construction work; =join_allocations_linear=
counts n branch constructions. Repeated singleton append in the reference
list implementation copies 0 + 1 + ... + (n - 1) prefix cells;
=copied_prefix_triangular= proves 2 C(n) + n = n squared. This comparison
formalizes the engine's existing persistent representation; it is not a new
optimization or a measured speedup. Empty-join normalization is abstracted
away, so logical branch counts need not equal Scheme allocations.

Prepared factories make no provider selections in the modeled request
executor. Interpreted action selections equal the action-list length.
Factory-body costs, field/alias boundary walks, allocations and GC are outside
that selection count. They must still be measured on real requests.

=publicationWork= is an explicit contract charging every source byte and flat
event. Its lower-bound theorem is arithmetic under that contract, not a proof
of the SHA256 implementation or event publisher. Full digest and flat output
prevent a sublinear complete-publication claim even when recognition is local.

* Question: why does this design exploit Scheme and its DSL?

The advantage is staging and higher-order composition, not parentheses alone.
Canonical syntax describes actions once. Engine-owned generic selection turns
those declarations into retained functions; each request supplies its own
children and source anchors. Grammar authors need not select storage, dispatch
or traversal strategies. Scheme closures preserve that separation naturally.

The existing engine pattern is illustrated below; this is an implementation
witness, not a new public DSL form:

#+begin_src scheme
;; src/runtime/reduction-plan.ss: select before repeated requests.
;; Each retained action receives request-local children and offsets.
(prepare-operand-actions field-factory alias-factory actions)
#+end_src

The LeanPoo tuple models selection provenance, while the parser model adds the
ordered context-threading law. A generic method may choose the implementation
at preparation time without forcing generic selection into every child visit.
The three language interfaces remain grammar.ss, parser.ss and parser-test.ss.

* Question: how is the design scientifically checked?

Each claim names its counted operation and assumptions, a kernel-checked
semantic law, a Scheme conformance owner and a measurement owner. The
integration theorem connects preparation to reverse-stack reduction instead
of treating local equalities as a complete parser proof. The materializer
counts the operations of a defined algorithm instead of assigning a desired
linear formula to an unspecified traversal.

The remaining proof boundary is explicit: input/span admission, derivation of
nullable offsets, LR table/CFG soundness, GLR ambiguity, arbitrary external
actions, relocation views, Scheme refinement, digest correctness and reuse
validation are not proved. Operands carry already supplied individual anchors.
Stack-depth preservation requires admitted width; it does not validate goto
entries. No theorem establishes P50/P95, heap bytes or hardware performance.

* Ordered consumer execution: conditional region model

=Execution.lean= models ordered, dependent consumers over one immutable source
extent. The shared recognition fact is source-only; consumers retain their
original order and may observe earlier state writes. State includes the event
owner and rejection outcome, rather than only a Boolean mode. The general
=transition_list_preserves= theorem permits writes that preserve the admission
invariant; requiring every relevant cell to remain untouched is unnecessarily
strong. The source-visit count theorem is conditional logical work, NOT elapsed
time, an allocation estimate or proof that the Scheme optimizer is sound.

The whole-span trial reuses =Fold.count_summary_identity=, rather than adding
a duplicate counter model. =Execution.count_summary_extent= proves that the
summary carry is true exactly when its suffix length equals consumed length;
=count_summary_length_encoding= justifies that ABI representation without
truncating the initial Scheme integer. It does not prove a C implementation or
physical speed. =RunPlan.qnt= separately models the synchronous borrowed phase:
no source invalidation, state commit or residual publication during the borrow,
and ordered commit/consumer execution after release. Directed Scheme tests and
complete actual AOT tapes bind implementation observations. Both span-leaf
implementations were slower and withdrawn despite passing those controls.
The model is an obligation for a future execution-region candidate, not a
claim that the retained production code now uses this foreign span executor.

The rejected implementation derived local completion support after byte-region
classification and reapplies explicit entry facts after unreachable trigger
effects disappear. Literal zero resets preserve unsigned zero support. A
nonzero intermediate write, unknown handoff or observable publication rejects
this admission. The original triggering transition and event order remain
unchanged. Matched timing did not establish a consistent improvement, and the
admission/lowering policy was restored to the prior baseline. The invariant
checker and directed controls remain verification tooling, not an enabled
runtime optimization. This is one part of the engine execution plan, not whole-engine
performance closure and not a maintained state/text cache.

The architecture audit must account for the complete request, not add up
instrumented leaf durations or mistake fewer guards for fewer executed visits:

Existing =FoldPlan.qnt= owns source/bounds epochs, effect barriers and ordered
consumer histories. Its local-preserving-transition history requires the same
extent and scan basis; unknown transitions still invalidate. =RunPlan.qnt=
owns interval commit/residual ordering. No second grammar or duplicated Lean
semantic proof is introduced in Quint. Neither model proves processor
activation, garbage-collector behavior or Tokio latency.

Real AOT conformance and observer-free complete-request timing remain mandatory.
The latest historical count-only census reports many repeated generated calls,
but its instrumentation and GC prevent treating those counts as exclusive CPU
or allocated bytes. The new architectural model is deliberately not a claim
that the 1000-request 10 ms gate has passed. The compiler-to-model dependency
analysis and complete pipeline cost attribution remain explicit open work.

* Generated call-region fusion

The call planner operates on the complete generated program before module
partitioning. Private expression references are counted across bodies and
value/export references. Only a unique call edge with scalar-reference
arguments and bounded expanded size is spliced. Shared consumers and helper
frame entries retain their boundary; effectful arguments are not moved.
Consumer effects and events retain order. Fresh lexical names preserve let,
let*, single-binding Gerbil let and named-loop scope. Quotes are opaque.
Final reachability prevents a rejected parent from deleting needed callees.

The budget bounds generated code, not request concurrency or runtime dispatch.
No request cache, event representation or runtime graph is added. Production
direct tapes use this pass; list consumers and diagnostic products do not.
Six directed controls cover scope, shared calls, argument effects, skipped
errors, size rejection and mutable owners. Lean splice_call_preserves_order
proves the ordered transition-region contract, not Scheme alpha conversion.
Existing Quint FoldPlan checks a fused-call/frame invalidation history rather
than duplicating the semantic proof. The collector binds the planner, tests,
models and real AOT. Static call reductions are not performance admission.

* Existing interval contracts

=Fold.lean= owns pure transition refinement: =overwrite_run_last= and
=overwrite_run_residual= retain the final overwrite and the original trigger
transition; =run_partition= preserves contiguous source extents. These theorems
do not establish the compiler's eligibility analysis or physical scan cost.

=RunPlan.qnt= owns lifecycle histories, not the same denotational proof:
frame invalidation prevents stale commits, a committed ordinary run must
execute its residual before the next scan, and a mutation witness rejects
stale admission. The seeded 1000-trace/20-step check is bounded testing, not
an exhaustive proof over all executions or a throughput guarantee.

The model collector binds the ordinary-run admission and lowering, generated
module owner, borrowed byte scanner, source-line visitor, event-tape writer,
and implementation controls. Complete real AOT tapes and matched timing remain
separate evidence obligations. Model success never promotes a candidate that
fails the 1000-request <=10 ms preflight.

The foreign ordinary-run leaf experiment passed boundary and complete-tape
controls but did not improve matched whole-call timing and was reverted.
The retained models describe the existing run contract, not a deployed foreign
scanner. Diagnostic =t/benchmarks/parser-throughput/stalls.ss= reads the
installed Gambit header's GC counters and OS resource counters; its extra
probes and cold first call make it diagnostic only, not acceptance timing.

* Explicit Lean and Quint responsibilities

[[file:../architecture/0019-model-responsibilities.org][Model responsibility boundary]] maps paper arguments to separate algorithm,
lifecycle, implementation and performance obligations. Lean's new
=ParserEngine.Reuse= proves whole-result identity admission and counted
preparation amortization including per-request validation. Quint's
=ReuseAdmission= checks source/grammar/plan invalidation, cancelled/failed
