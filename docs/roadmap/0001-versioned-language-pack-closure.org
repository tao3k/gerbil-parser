** Stable language modules and metadata

Language editions are data rather than module identity. The seven edition
subdirectories and the two edition-labelled reference-corpus directories are
flattened into stable family paths. Public language/parser bindings omit edition
suffixes; tests, generators, native FFI callers, CI commands and documentation
use those same paths. Upstream grammar/corpus bytes and pinned authority values
remain unchanged. This is an in-place correction of the unreleased loader
contract, with no v3 schema bump and no compatibility aliases.

Loader metadata is an inherited POO value augmented by the engine with
=language=, =version=, =contract=, =digest= and =digest-kind=. The effective
identity is checked against the descriptor; language/user metadata fields such
as grammar format and upstream references remain extensible. Grammar digests
bind Parser IR; source-language digests bind declared source identity and must
not be described as hashes of scanner implementation code.

** Design obligations for each stage

=deflanguage-parser-loader= is the enforcement point, not merely an entry-name
macro. Its descriptor/identity/dispatch slots are sealed; POO extension
contracts validate the effective inherited object. Grammar compiler admission
owns canonical IR, fixture services pre-admit the entire native corpus, and
scanner services require an engine-owned declaration tied to the descriptor.
A row containing an arbitrary procedure is not a scanner declaration.

The remaining source-parser bridge is explicitly named
=declare-language-source-scan-worker= and is admitted only for source descriptors.
It constrains descriptor ownership, factory result type, source identity and
checkpoint isolation. It does not qualify the callback as portable Scanner IR.
S1/S2 remove the remaining callback implementations; they do not grandfather
undeclared downstream callbacks. Test/fixture extensions must retain their
loader-bound admission and conformance checks, and future IR worker services
must use the same declaration boundary rather than a second registry.


- POO remains the extension boundary. =grammars= and metadata are exposed by the
  loader; fixture data uses ordinary POO values; test/worker execution remains explicit. Engine identity, descriptor
  binding and dispatch remain sealed against inherited overrides. Downstream
  users declare options/rules/services rather than maintain scanner drivers.
- Lexical profiles must preserve committed malformed suffix rejection. For
  example, FHIRPath's incomplete =-MM= / =:mm= groups must not quietly fall back
  to a shorter accepted token. HL7 segment ids reject a maximal four-character
  run instead of accepting its first three characters. Preserve Unicode class
  semantics through Scheme-generated classes and exact UTF-8 endpoint tests.
- HL7 source captures are validated once per parse: the five MSH delimiters
  are distinct and non-alphanumeric. The prepared plan retains no source;
  per-source execution owns captures. No global mutable delimiter cache.
- TLA+ module depth is source state rather than repeated scans from offset zero.
  Comments, quoted strings, module borders and proof lexemes keep their existing
  boundaries. Source-sensitive checks become transitions/guards, not arbitrary
  callbacks executed by Rust.
- Bash retains nested Word/WordPart/expansion nodes and stable fields. Generic
  queues/checkpoints and marker-to-body links belong to the engine; an opaque
  balanced-word token does not qualify structured Bash syntax. Traversal and
  child accumulation must avoid repeated copying as input grows.
- Native C ownership and standalone Rust are separate product gates. A common
  loader is not a portable-policy receipt; source descriptors are currently
  rejected by native artifact serialization and standalone Rust generation.
  Runtime creation/FFI handles are reused across calls, not recreated per parse.

one Gerbil parser compiler and runtime.  A language is complete only when its
pinned upstream grammar, admitted corpus, generated artifacts, installed
consumer, negative contracts, and performance receipt are all exercised by the
single native package test entrypoint.
