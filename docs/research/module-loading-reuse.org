#+title: Native Gerbil loading ownership and source admission

* Current ownership
The current design is [[file:../architecture/language-testing-ownership.org][language and testing ownership under Yuanxu]].
Gerbil runtime/loader.ss owns runtime initialization, loaded state, concurrent
waiters and cached runtime failures. The native expander owns source contexts,
source promises and their retry behavior. Parser no longer interprets loader
wrappers or source import forms, chooses compiled interfaces, traverses module
dependencies or replaces live context promises.

Yuanxu init tests.for-directory / for-files and std-make-spec replace the manual
conformance list and support catalog. Native Gerbil owns compilation and Suite
execution through development/CI entrypoints; no Suite starts another runner.
The observational fixture only parameterizes native diagnostic hooks and delegates
requests unchanged. Zero/multiple values and exceptions are preserved.

* Current descriptor boundary
language-module-descriptor selects exactly one language-grammar with optional
#export. For file inputs it remembers only the last attempted canonical source
bytes to choose the native import-module reload flag. It retains no descriptor,
context, exception, loaded flag or approval. Library inputs retain native snapshot
semantics and explicit reload. Core fresh reads and pre/post-effect currentness
admit actual source across initialization; timestamps and an outer pure-read cache
cannot establish currentness. Runtime failures retain native load-module semantics;
source failures are not forced into a custom common exception cache.

* Current correctness controls
just test-module-loading exercises real edits, missing/invalid sources, descriptor
selection and native reload recovery. Native Suites additionally cover actual
initialization once/order, first-child failure, delayed/quoted calls, arity errors,
import/evaluator parameter restoration, zero/multiple values and exception identity
at the native runtime boundary. The original source-rewrite negative control
executes beneath an adversarial outer Core read cache.

* Historical measurement boundary
The old custom-loader CPU results below describe former revisions only. The copied
reference loader is deleted; it is not maintained as a second implementation.
No old warm-preparation result qualifies the new architecture. A native warm-load
versus reload comparison would compare different requests, not equivalent
implementations, and cannot establish an optimization claim. Complete-generation
controls retain identical generated Rust output and the existing bounded protocol.

* Historical observations (prior implementations)
All sections below preserve earlier observations and failure custody. Names such
as SDK, source hashes, wrapper traversal and preloader refer to historical code,
not current ownership, source-admission policy or current-head acceptance.

* Failure restoration model and regression (2026-10-15)

Auditing the official =expander/module.ss= showed that =core-import-module=
installs a new context in its registry before =eval-module= forces its delayed
initializer. A previous successful digest therefore cannot attest that registry
entry after a failed replacement. This differs from committed parse history:
the parser's publication owner can retain an old result, whereas the SDK has
already replaced its current module context.

The new [[file:../../formal/quint/ModuleAdmission.qnt][ModuleAdmission]] protocol separates source bytes, current SDK context,
accepted identity, pending admission and failure. Its mutation witness retains
a historical marker after failure and demonstrates that it incorrectly skips
reload when the original source is restored. Eight directed histories cover
unchanged reuse, changed content, failed restoration/recovery, explicit reload
failure, rejected selection and repeated failure. Its sampled invariant check
runs 1,000 histories of at most 20 steps, seed 1. This does not model the SDK's
internal mutex, concurrent source edits or recursive dependency invalidation.

[[file:../../formal/ParserEngine/Reuse.lean][Lean Reuse]] proves that withdrawal forces a new attempt even for the original
source, failed selection establishes no accepted identity, successful admission
can reuse, and explicit reload cannot be skipped. Source must remain stable
within each admission attempt; identities remain logical collision-free values.
The actual module owner, preloader, controls and CPU experiment are included in
the existing model source binding. Whole-request cost and CPU obligations remain
separate from those lifecycle statements.

The new Scheme control first reproduced the defect: load =second= successfully,
fail a replacement twice, restore the exact =second= content, and observe the
cached =initializer failed= exception. It terminated with =reason error-output=
and no final success receipt. The fixed implementation withdraws identity only
before actual file reload and commits it after successful evaluation/selection.
Warm unchanged calls retain official context reuse. The full controls then
passed in 7.223 seconds, including =MODULE-RESTORED-SOURCE-OK=, source-edit Rust
output changes, repeated runtime failures and official explicit recovery.
