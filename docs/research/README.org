#+title: Parser research

Research documents explain algorithm choices and their relation to the public
Grammar/Parser/Scanner IR. Executable correctness belongs in Scheme test suites;
performance admission belongs in the ASP =benchmark.ss= contracts.

Use the repository's native harness and existing =Justfile= entries. Keep
workloads, samples and thresholds in their Scheme owners. Research documentation
has no generated result snapshots, separate JSON report schemas, source-rewriting
instrumentation or runtime-binding replacement wrappers.

The paper/framework synthesis remains in
[[file:scheme-parser-performance-framework.org][scheme-parser-performance-framework.org]].

Language authoring research, annotated papers and proposed experiments are in
[[file:scheme-language-pack-design.org][Scheme language pack design]]. The document distinguishes the current
authoring interfaces from unimplemented research proposals.

The deeper [[file:scheme-language-pack-semantics.org][binding, field semantics and author task study]] develops namespace
policies, conservative count equations and concrete HCL/arithmetic examples.
