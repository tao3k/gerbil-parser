* Structural cause and implementation

A checkpoint combines an immutable LR prefix snapshot, a source-token cursor
including trivia, and a byte cursor. These must describe the same retained
prefix. The directed resume loop correctly initialized its token count from
=length(prefix-tokens)=, while its initial capture callback unconditionally
recorded zero. A subsequent edit could select a late byte cursor with a token
cursor at the start, omit the prefix token stream, and fail publication.

The failing regression produced a typed resume rejection at byte 2352:
=recognition token does not match source order=. Fresh fallback masked the
checkpoint error by reconstructing the whole source correctly.

The implementation records the retained prefix token count in that initial
capture. It also preserves checkpoints strictly before the chosen snapshot
when a successful short tail emits no replacement samples. It never retains
checkpoints from the edited suffix. Existing LR trace mode now emits the actual
resume rejection diagnostics before fallback; successful requests add no trace
output.

The regression covers canonical and event backends, 400/800 declarations,
tail insertion/deletion and their inverses. It requires complete artifact and
projector equality, no fresh fallback, positive checkpoint reuse and fewer
remaining significant tokens than declarations. Failed parses, full deletion,
Unicode, selective GLR and layout ownership remain in the existing suite.

This removes a history-dependent full-reparse path for the qualified cases.
Full source hashing and full artifact publication still visit the whole output;
no sublinear complete-request complexity claim follows.

* Research connection and next structural experiment

[[https://www.cs.ox.ac.uk/ralf.hinze/publications/FingerTrees.pdf][Hinze and Paterson's finger trees]] provide end access and measured splitting,
with persistence bounds that rely on laziness. Strict Scheme binary carries
cannot inherit that bound without a separate evaluation/branching proof.
[[https://www.cs.purdue.edu/homes/rompf/papers/stucki-icfp15.pdf][Stucki et al.'s RRB vector]] supplies a framework for immutable sequence
concatenation and splitting. These are relevant to future mixed concat/split
workloads; zero observed multi concats makes that replacement an unsupported
priority for the current flat workloads.

For the moved publication phase, the next falsifiable representation experiment
is to coalesce adjacent semantic relocation runs with the same offset action.
Composition must add deltas and OR moved provenance, preserving moved status
when deltas cancel. Node/field/trivia boundaries and token proof must survive.
Measure construction plus complete publication, retained old roots and repeated
branches, and the complete edit/history matrix. A publication-only measurement
with rebinding moved outside the timer cannot qualify the change.

This is a proposed experiment, not an implemented capability. The checkpoint
cursor repair is the implemented structural change in this RFC.

* Rejected native sample observer and remaining gates

The first full 59-module audit terminated three benchmark batches under the
unchanged 5-second silence guard. Those failed receipts are retained. A test
observer prototype resolved private ASP helper bindings and passed a direct
thunk/payload probe. Compiled ASP callers bypassed that runtime wrapper: the
subsequent full audit emitted zero sample completion notices. That observer is
rejected and removed; it is not an implemented native progress capability.
A proper ASP owner callback would need to survive native compilation.

* Verification budget after this audit

The follow-up audit with the restored driver was explicitly stopped after the
user objected to the accumulated eight-minute verification wait. Its partial
output is not a completed qualification. No further test run was started.

For subsequent iterations, compile affected modules once, then run independent
focused test groups concurrently. Keep the 5-second real-output guard and set a
90-second aggregate test-phase budget; native compilation has a separate,
reported budget. Report the specific unfinished gate at the deadline instead
of retrying the full audit. Run the full suite once at an integration boundary,
not after every experiment. Parallel timings cannot qualify a CPU comparison:
performance measurements require an isolated, bounded run.

* Local closure follow-up

No remote push was performed. The follow-up separates the two remaining
admission owners: fifty checked grammar/role constructions and one hundred
complete GQL parses. Checkpoint reuse does not execute either fresh workload.

The five-sample stage diagnostic validates one complete GQL artifact and reports
CPU and wall time separately. Median CPU milliseconds per hundred operations:
complete GQL 17.166, lexing 2.353, significant filtering 0.110, LR execution
13.208, publication 1.449. The phase timings are separate executions, so they
are not additive. Wall time varies substantially; observed host load averages
were 152.54, 133.84 and 117.08. This supports scheduling interference as a
hypothesis, not exclusive causal attribution or a replacement admission metric.

POO role construction takes median 11.180 CPU milliseconds per fifty operations;
grammar construction with a preexisting role takes 20.831. Rechecking a role
costs 9.845 and rechecking a grammar 15.069. The latter stages use already-created
objects; they do not reproduce the complete POO admission workload. The contract
owner regenerates full responsibility evidence during element checks. A future
reuse design must preserve open prototype behavior, current slot values and
obligations; global identity caching cannot be assumed sound.
