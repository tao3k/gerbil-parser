* One design and implementation pipeline

The author boundary remains =grammar.ss=, =parser.ss= and =parser-test.ss=.
Syntax/rules express language intent; checked POO composition selects effective
values and source origins; canonical IR admits target semantics before lowering.
The engine owns recognition, scheduling, publication and FFI transport.
Metadata belongs to the parser entry; ordinary values need no POO wrapper.

This study is organized by engine responsibility. Each module retains earlier
implementation receipts with their original evidence boundaries. Historical
proposals are not automatically current gaps: consult the implementation sections
and current source before proposing another mechanism.

* Why this DSL is preferable

The benefit is a checked composition of syntax, bindings and grammar meaning.
An S-expression by itself only supplies a convenient representation. Gerbil
=defgrammar-syntax= expands reusable syntax through =defrules=; =deflanguage=
admits the declaration vocabulary; POO supports extension where requested;
engine analysis sees the selected rules before choosing a runtime strategy.

#+begin_src scheme
;; Question 1: Why is this design preferable?
;; An author defines a vocabulary once using the existing hygienic macro entry.
;; Both call and array rules reuse the same node/field intention.
(defgrammar-syntax (named token-expression)
  (node Name (field value token-expression)))
;; Within a deflanguage rules section:
;;   (name (named (token identifier)))
;; No generated helper keys, analysis callbacks or cache recipes are authored.

;; Question 2: Why is the design scientifically justified?
;; Existing engine-level admission control: a reference can become nullable
;; after effective composition, so the resolved grammar owns this obligation.
;; This is a diagnostic control, not an author-facing IR assembly recipe.
(compile-lr-spec
 '((start (repeat (reference item))) (item (empty))) 'start)
;; Expected rejection: resolved repetition operand accepts empty input.
;; Consuming recursive grammars remain admissible; LR is not restricted to LL(1).
#+end_src

The first block uses the current =defgrammar-syntax= implementation. The second
is an existing case in [[file:../../t/resolved-grammar-test.ss][resolved grammar tests]]. Native POO override,
nullable cycles, consuming prefixes and productive left recursion are controls
in that same suite. This document does not claim a new local execution receipt
for those cases merely because their sources were inspected.
