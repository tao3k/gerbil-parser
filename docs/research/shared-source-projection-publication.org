#+title: Source projection and publication
#+startup: overview

Part of [[file:shared-scanner-staging-and-fusion.org][the shared scanner study]].
Historical revisions, failed experiments and receipt limits retain their original scope.

The [[file:artifact-publication-cost-boundaries.org][artifact publication cost contract]] implements the event/encoding/identity
attribution obligation below, with independent source controls and a native
cross-language receipt. It does not admit a new fused executor or default.

* Next shared-engine design: direct execution and publication ownership

The evidence motivates a different experiment, not another generic closure
wrapper. flap's staging removes higher-order dispatch through generated direct
code; its fusion removes internal representations. Neither experiment above
performed these transformations. No speed ratio from the paper transfers here.

The implementation milestones are:

1. Lower closed projection IR into generated Scheme constructors with fixed
   capture indexes and direct token/node operations. The engine owns generation;
   the public POO profile remains the declarative authority. Prove catalog,
   capture-order and admission parity before admitting any specialization.
2. Measure projection execution separately from recognition, token lexeme
   materialization and artifact publication, while retaining a complete-product
   control. Inspect generated Scheme/C to verify that opcode dispatch and
   per-operation indirect calls actually disappear.
3. Establish ownership for recognition nodes that exist only until publication.
   Prototype an engine-owned event sink that emits the required canonical
   artifact once, retaining byte coverage, child order, identities, diagnostics
   and rejection semantics. Keep request state private; do not add language
   callbacks or a second public artifact protocol.
4. Admit direct emission only after full public products and Scheme/C/Rust
   consumers preserve their contracts. Analyze unsupported recursion/context
   forms explicitly; deterministic lexer/parser fusion requires properties that
   have not been proved for every supported grammar.

These are design obligations, not implemented AOT or direct-publication claims.
The current engine still uses the original projection executor. Permanent tests
strengthen its admission contract; temporary comparison modules are excluded
from the commit. Future measurements must include the complete publication path
and cannot promote a component allocation saving into an end-to-end speedup.

* Implemented: fuse source publication admission with input identity

The shared SourceLanguage publisher previously validated the artifact by
reconstructing a string from token lexemes and hashing it, then independently
hashed the actual input to check its identity. The publisher already owns that
input. This duplicates whole-source work and constructs a string used only
between two validation steps.

=parse-artifact-valid-for-source?= now binds artifact admission to the supplied
input. The existing event walk still checks schema, digest shape, canonical
IDs, byte coverage, UTF-8 token widths, node/field balance, root count, status and
diagnostics. For each admitted token it compares its characters directly with
the next input range, without a substring or encoding. Complete character
coverage is required, then the actual input is hashed once and compared with the
artifact identity. SourceLanguage uses this entry and retains grammar identity
admission. All language declarations and artifact/FFI schemas remain unchanged.

For lexemes L1 through Ln and input S, the walk proves each Li equals the next
character interval in S and that their combined character count is length(S).
This establishes concat(L1,...,Ln) = S without materializing that concatenation.
Contiguous byte coverage and each lexeme's UTF-8 width remain separately checked.
A forged digest that matches S but disagrees with lexeme content still fails.
Standalone artifact admission and owned roundtrip reconstruction retain their
existing behavior; callers with an actual input use the stronger source-bound
entry. Both paths share the same structural validator.

Both algorithms are O(events + characters). The improvement removes an internal
representation and a repeated input hash; it does not establish a new asymptotic
bound or complete lexer/parser fusion. Recognition trees and canonical event
allocation remain in the current producer.

The original artifact validator was frozen under a temporary native namespace.
Both sides used the same fixed GCC SDK and optimization/diagnostic flags. The
baseline publication obligation includes artifact validation, grammar identity
and a second hash of the input. The candidate includes grammar identity and
source-bound artifact validation. Full controls share the same prepared scanner
and parser and require complete artifact equality with the public entry for

* Complete request attribution and the next representation boundary

The previous complete native controls still allocated about 38 MB per large
request. A shared diagnostic now accepts any public parser procedure and input:
=t/benchmarks/parser-stage-cost/benchmark.ss#measure-parser-stages=. It has no
language imports, scanner replacement, process launcher or alternative parser.
The caller owns workload selection. Each measured request must equal the full
unobserved reference artifact and pass source-bound admission. IO, reference
construction, equality, admission and sample output are outside the request.
The summary includes source and grammar identities, event count, CPU median,
allocation median and the number of admitted allocation observations.

An audit found an observability gap: session parsing already reported source
preparation, scanning and artifact validation, whereas ordinary SourceLanguage
and receipt entries did not. Shared shell and line providers now report the
preparation and scanning boundaries; public source and receipt entries report
validation. Existing disabled-path macro lowering evaluates the expression
without constructing an observation thunk. These additions measure existing
work; they do not implement a runtime speedup. LR and generated direct engines
are different providers and do not acquire source-provider stage names merely
because they support a language such as HL7 or HCL.

Natural GC remains inside the measured CPU interval. Allocation deltas are
admitted only with zero collections and a nonnegative counter delta. Observer
callbacks and statistics calls have a cost, and outer measurements include
that cost. Nested observations are inclusive. Medians from different stages
and different admitted subsets must not be added or subtracted to infer an
unobserved stage. These are localization diagnostics, not an uninstrumented
latency comparison with Tree-sitter.

A scanner exception recovered by the parser can legitimately publish a complete
rejected artifact. The scanner observation must retain =completed=false=;
requiring every stage to complete would misclassify correct rejection. The
benchmark admits a rejected request through full product equality and actual
input admission. Permanent controls cover the public shell entry, its multiple
return-value receipt entry, a POO line provider, Unicode, empty input, lexical
failure and prefix rejection. Dynamic observer scope is restored afterward.

** Paper interpretation and bounded lowering obligations

[[https://arxiv.org/html/2304.05276][flap sections 2.5, 2.7 and 2.8]] distinguish three mechanisms:
deterministic single-token branch selection, lexer/parser fusion eliminating an
internal token representation, and staging away statically known dispatch.
Its generated parser still permits allocation introduced by semantic actions.
Our required lossless artifact is such an observable semantic product. Removing
an internal token stream does not authorize removing lexemes, field events,
trivia coverage, diagnostics or public identities.

A generic lowering must be derived from admitted engine IR. It must establish:

1. Branch selection and lexical priority preserve the original recognition
   language, including maximal-munch behavior and negative lookahead. A FIRST
   set alone is insufficient to prove scanner/parser fusion.
2. Skipped characters remain publishable lossless trivia. A recognizer that
   discards them does not satisfy the complete artifact contract.
3. Deferred delimiters, source modes and speculative branches establish explicit
   commit boundaries. A speculative event cannot escape into canonical output.
4. Source intervals retain byte/character agreement and input ownership through
   Unicode and relocation. A borrowed interval cannot silently outlive its
   request or become a mutable shared input view.
5. ResultPlan field order, token spelling and failure diagnostics remain equal
   to the current public product. The existing event-program and raw-event-tape
   publication mechanisms are the targets; a new language callback protocol is
   unnecessary.

The current shell execution chain still creates scanner tokens, recognition
values and projected word token sequences, then flattens those sequences at
component boundaries, copies them into the parser's emitted stream and finally
publishes canonical events. Some of this storage is transient, but canonical
output is required. Word source preparation already uses an ASCII fast path and
lazily prepares region caches; those mechanisms must not be proposed again as
new work. The earlier generated projection experiment removed interpreter
operation dispatch without establishing a complete-entry allocation or speed
win. That negative result argues for changing producer/consumer representation
and ownership, rather than another wrapper around projection execution.

The next experiment should account for scanner and recognition construction
separately, then lower an admitted deterministic producer/consumer boundary to
existing publication instructions. Request-local source intervals and a single
committed semantic stream are candidate representations, not implemented
capabilities. They require whole-product controls for quoting, substitutions,
here-documents, malformed input, Unicode and another applicable grammar before
any default-path promotion. An implementation should be retained only if it
reduces complete native allocation without a stable runtime regression.

* Owned publication spines in shared Word/result execution (2026-10-10)

** Producer and consumer ownership

After direct materialization bypassed the earlier branch-frame experiment,
the remaining Word producer still built a reversed parts spine and copied it
with =reverse= before projection consumed it. General result projection
execution similarly allocated a private reversed recognition-child spine,
then copied it into publication order. The Scheme projection generator emitted
the same redundant reversal. Neither spine is a caller-owned capture list:
=parts= is assembled by this =parse-parts= invocation, and =children= contains
only cons cells created by this projection's emitter. Nested result nodes,
capture spines, immutable token branches and source text are separate values.

The retained implementation uses =reverse!= on those private spines exactly
at publication. An n-cell temporary list no longer requires another n-cell
copy. Traversal remains linear; this is an allocation and ownership change,
not a new parsing-complexity bound. Public nodes, token values, ordered fields,
source validation and the declared POO projection recipes are preserved. The
single-operation executors are unchanged, since they already construct their
final lists directly. No language grammar, schema version, ABI or language
namespace changes are required.

This follows shipped Gerbil SDK revision =2591dcd= examples:
=gerbil/runtime/c3.ss=, =c4-compute-class-slots=, reverses its private =r-slots=
at publication, and =gerbil/runtime/util.ss=, =string-split=, uses the same
operation for its private accumulator. The SDK's =std/list/list-builder.ss=
is another owned-list construction mechanism; its dummy head and mutable tail
are unnecessary for an existing private reverse accumulator.

[[https://arxiv.org/html/2304.05276][flap]], Sections 2.2 and 2.8, separates materialized intermediary costs from
allocation introduced by semantic actions. Here the lossless public token and
node products remain observable and cannot be removed using a token-free
recognizer's benchmark as justification. The eliminated cells are redundant
publication spines, not public token or node values. This implementation is
not flap fusion and makes no claim to its measured speedups or proof.

** Remaining fusion boundary

This removes one avoidable list copy but leaves the parts list consumed by
projection, the recognition-child list returned by projection, owned lexemes
and lossless nodes/tokens. Eliminating a parts list requires fusing its producer
with the projection's declared field emitter. A future lowering must preserve
validation of node kinds and parent bounds, ordering across optional token,
one-node and many-node operations, and externally supplied capture ownership.
It must also qualify interpreted and generated executors with the same full
products. Moving grammar complexity into a language-specific shortcut or
changing the public capture contract merely to bypass validation would not
address this shared producer/consumer boundary.


* Direct parts projection and bounded DSL expansion (2026-10-10)

** Shared producer boundary

The default unary =many= projection can consume the final child spine directly.
=result-projection-parts-field= derives its field from the admitted operation;
there is no author-facing mode or new grammar declaration. The Word engine's
existing scan loop uses that field to construct =recognition-child= values in
its private accumulator. =result-projection-build-parts= validates the proper
list, exact field and node type, then delegates catalog and parent-span checks
to =result-plan-node=. It publishes that same spine, removing the intermediate
node list, subsequent =map= and temporary capture pair/vector on this path.
Nested mixed projections and assignments retain their existing capture layout.

The private projection record marks only engine-owned unary executors as
eligible. =result-plan-bind-projections= clears that eligibility on a cloned
plan: a supplied procedure is authoritative even if its declared recipe equals
the default recipe. For bound executors, the scanner emits ordinary nodes and
the new build boundary supplies the original capture frame. This preserves
POO override behavior; it does not introduce a legacy schema or language mode.
Generated bindings are tested through this authoritative frame path. This
experiment does not claim a streaming native generated executor or Rust AOT
allocation improvement. Public recipe digests and serialized ABI products
remain unchanged.

[[https://arxiv.org/html/2304.05276][flap]], Section 2.8, explicitly generates code that removes statically known
information and avoids introducing higher-order operations in the parser core.
That motivates specializing the declared field in the producer rather than
assuming a generic callback is free. The retained code removes one semantic
intermediary; it is not DGNF lexer/parser fusion and does not inherit flap's
proof or measured speedups. SDK =2591dcd='s owned-list builders and private
reverse accumulators remain the source model for publication ownership.

* Literal-run invariant staging and bounded source admission

The current Scheme design documents already describe checked public boundaries,
known private calls, and compile-time ownership. Reading the pinned Gerbil SDK
revision =2591dcd=, =src/gerbil/runtime/util.ss= (=string-index= and
=__string-index/char=), provides a concrete example: validate the source range
once, retain invariant input and endpoint, and advance only the cursor. This
change transfers that structure without copying unchecked primitives or type
assertions. The emitted Scheme for the previous parts scanner called the full
context matcher on every character; its context index was not hoisted there.

The shared =part-context-literal-end= now retains the prepared ASCII vector and
Unicode character hash for the entire literal run. Empty initial buckets bypass
rule matching. Candidate initials call the named =match-part-rules= helper also
used by direct matching. Declaration order, prefix bounds, guard rejection,
shorter-prefix overrides, and Unicode keys therefore retain the same matching
algorithm. No extra index, callback, language declaration, compatibility path,
schema version, or FFI surface is introduced.

Range admission requires exact integer endpoints with
=0 <= start <= end <= string-length=. Empty intervals return =end=. The previous
loop started at =start + 1= and stopped only at equality with =end= or a successful
match. With =start = end=, matching returned false beyond the endpoint and the
cursor kept increasing. This nontermination follows from the source; the old
infinite loop was not executed as a benchmark. Tests cover empty intervals,
negative, reversed, escaping and fractional ranges, independent direct-matcher
comparison at every start position, and truncated Unicode guards.
