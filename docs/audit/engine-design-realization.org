* Scope and evidence rules

Source audit baseline: =0a1b3261114406a8564d1f6e90952e77e676976c= on PR #13.

This audit connects the shared engine work to the three author interfaces:
=grammar.ss= declares syntax, =parser.ss= supplies metadata and parser adaptation,
and =parser-test.ss= owns observable language behavior and benchmark contracts.
It does not audit every language-standard production or assert complete package
qualification. Historical research receipts keep their original revisions.

An implemented mechanism, a passed focused control and completed exact-head CI
are separate facts. A research proposal or an inspected test is not a receipt.
Each further change must name its semantic invariant, implementation owner,
independent control and measured phase before a performance claim is admitted.

* One implementation sequence

The architecture remains declaration and POO composition -> canonical IR ->
compiler publication -> prepared machine -> request execution -> artifact.
Shared engine mechanisms belong beneath this sequence. Language authors do not
configure matcher caches, generic registries, opcode lowering or worker lifetimes.

* Scheme witness: declaration, preparation and repeated requests

#+begin_src scheme
;; Engine-owned lowering of an admitted declaration. No new author slot.
(def (prepare-rule-matcher declaration cache)
  (or (table-ref cache declaration #f)
      (let* ((expression (lower-rule-matcher declaration))
             (plan (make-contextual-matcher-plan
                    expression (prepare-matcher expression))))
        (table-set! cache declaration plan)
        plan)))

;; Rule policy is separate from executable configuration. The actual local
;; macro is defined inside decode-rule, where these metadata bindings exist.
(defrule (finish expression executor)
  (make-runtime-scan-rule name mode form expression executor rank action))
#+end_src

** Question: why is this design preferable?

S-expression declarations permit structural equality and engine-owned matching.
Hygienic =defrule= expansion retains lexical rule policy without allocating a
per-rule constructor callback. POO composition selects declared values and
origins; private CLOS preparation methods select backend/capability combinations;
named algorithms implement their execution. Each mechanism has a concrete
responsibility. Authors retain ordinary values unless they need actual extension.

This is deliberately selective: the preparation cache shares expensive immutable
region/guard configuration. It does not intern request state or all Scheme
closures. Rejected broad-cache and multiple-value experiments are retained in
[[file:../research/scheme-reduction-abstractions.org::*Contextual matcher preparation across modes and source sizes][the preparation study]].

** Question: how is the claim scientifically tested?

The falsifiers are changed rule rank/action outcomes, state leaking between
requests, changed Unicode byte boundaries, or preparation cost moved into scan
timing. Shared guard controls exercise independent modes and requests on short
and long sources. Existing region/deferred/source suites exercise the adjacent
semantic obligations. Preparation controls independently declare expected words,
check token kinds, complete lexemes and final UTF-8 byte coverage after timing.

The historical paired region configuration reduces admitted preparation allocation
by approximately 45%. Identifier CPU results are mixed; neither that allocation
result nor the papers prove whole-parser speedup. The papers motivate staging
under explicit assumptions; semantic controls and matched measurements decide
which lowering is retained in this engine.

* Reproducible preparation controls

The existing benchmark exports =benchmark-matcher-preparation=. It exercises
one-mode identifier, sixteen-mode identifier, a 128-literal catalog, a region
configuration and a guarded region configuration. The region source includes
Unicode quotes and nested interpolation. Defaults are eleven samples and three
preparations per sample; both counts must be positive exact integers.

#+begin_src scheme
(import :gerbil-parser/t/benchmarks/contextual-scanner/matched-scale)
(benchmark-matcher-preparation 11 3)
#+end_src

Run this expression through the repository's configured Gerbil environment.
For native cost evidence, compile the benchmark module through the existing
compiler owner and load its native product. Source interpretation is a distinct
control. No new executable, process wrapper or baseline executor is introduced.
Compare revisions through the same caller, toolchain, configuration and sample
order, with explicit loaded-product identities. Each measured interval contains
only plan preparation: IR construction, source encoding and returned-product
validation are excluded. The final plan in each batch is validated; the output
does not assert that every intermediate plan was scanned.

The output records CPU milliseconds per preparation, GC count and admitted
allocated bytes per preparation. Collection or a negative raw delta makes the
allocation value =#f=, not zero. A GC is forced before each interval; this isolated
preparation control does not measure natural application GC, amortized request
latency, scan throughput or complete-language parsing. Existing =scan=,
=prepare-scan= and =plan-batch= entry modes retain those distinct boundaries.

* Complete-request cost admission correction

The [[file:../research/shared-ranked-scanner-execution.org::*Cross-language audit of callback removal][cross-language callback audit]] withdraws the private ranked loop macro.
Reproducible allocation reduction did not establish a complete-request CPU
benefit on GQL, FHIRPath and Arithmetic. The original fold is restored; the
independent order and Unicode test remains. Historical component receipts are
retained with their evidence boundary.

The existing LR request benchmark now exports =benchmark-lr-request-backends=.
It checks twenty-four prepared/public routes against one canonical recognition
artifact, distinguishes requested preference from prepared admission, and records
untimed actual source stages plus generated execution capabilities. GQL rejects
the event executor, FHIRPath admits it, and Arithmetic's public request uses its
generated recognition drive. Enabling an event preference alone therefore does
not certify event execution of the complete public request.

That audit identifies an explicit semantic representation contract for generated
execution as the next obligation. The following section implements the contract;
matched complete-request cost admission remains separate. No default backend is changed on the strength
of prepared allocation or the single-order representation diagnostic. Bash's
contextual route remains independently qualified by its own source products;
these LR controls do not substitute for that qualification.


The [[file:../research/shared-ranked-scanner-execution.org::*Executed interleaved backend qualification][executed paired qualification]] now replaces the single-order diagnostic as
performance evidence. Twenty ABBA/BAAB groups per workload measure 19,200 native
calls in 53.291 seconds, following ten passed measurement controls. Small
prepared event workloads meet the observed-regression criterion. The large GQL
identical-executor control fails, so the executable gate rejects complete-request
benefit admission. Semantic pass and performance rejection are distinct outputs;
no backend default changes on this receipt.
* Installed representation admission

=parser-machine-backend-representation= reports the captured prepared runtime or
an installed drive/source/step/event-step product. The engine owns this closed
domain; language entries retain their existing backend declarations. Missing
optional entries return =#f=; malformed machine/kind queries reject. A retained
event machine continues reporting event-program after the dynamic preference
changes. Its generated drive may still report recognition.

The contract exposed a concrete admission gap: a recognition =step= could be
installed on an event machine. Both the direct machine installer and the
declarative batch precheck now reject that mismatch. A batch with a valid drive
followed by such a step leaves the drive uninstalled. This preserves all-or-nothing
admission and avoids interpreting recognition values with an event reducer.

The cross-language benchmark reports these contracts alongside actual untimed
source stages. Availability and declared representation remain capabilities;
a source specialization can decline. The existing canonical artifact equality
controls qualify known generated implementations, not arbitrary procedure bodies.
The [[file:../research/shared-ranked-scanner-execution.org::*Engine-owned semantic representation of installed entries][research argument]] records the Scheme witness, both design questions and limits.

The shared request executor also reports the actual generated-drive or prepared-
checkpoint branch, rather than relying on the inclusive source-recognition stage.
CI-owned source-contract tests cover generated execution under both preferences
and ordinary accepted/rejected/empty requests. The benchmark requires the expected
branch to complete before admitting its cost samples. Nested child intervals are
not additive to their inclusive source-recognition parent.
