* Shared region opener indexing and Gerbil source review

** Fixed SDK implementation evidence

This review used the source shipped with Gerbil 0.19, revision =2591dcd=,
patch =f5cedd8168cb=. Paths below are relative to that SDK's source tree:

| Source | Mechanism | Consequence for this engine |
|--------+-----------+----------------------------|
| =std/text/parser/ll1.ss=, =ll1-case= | Prepares peek predicates outside the reader lambda | Prepare declaration indexes once; keep input inspection request-local |
| =std/list/list-builder.ss=, =with-list-builder= | Expands collector calls directly into owned list mutation | Use the existing macro when producing lists; do not add a second collector framework |
| =std/text/parser/ebnf/deflexer.ss= and =defparser.ss= | Validate syntax and generate bindings with source information | Keep grammar admission and generated execution separate; preserve hygienic identifiers and error locations |
| =gerbil/compiler/optimize-call.ss= | Specializes calls using known procedure types and checked primitive information | Do not replace proven call specialization with blanket unsafe declarations |
| =gerbil/runtime/util.ss=, =foldl1= | Implements a generic callback-driven tail loop | The engine's repeated callback construction and full declaration walk are the problem, not the generic fold itself |
| =gerbil/runtime/hash.ss= | Provides specialized tables and checked method boundaries | Reuse an eqv table for Unicode codepoints rather than invent another hash implementation |

The LL1 implementation is a source-quality reference, not a replacement for
contextual or LR grammar semantics. Its list peeker still prepares nested
predicates during probing; using a standard library abstraction alone does not
prove allocation or latency improvements. The list builder's mutable chain
belongs to one execution; moving it into shared language state would violate
request ownership.

The binding-time argument in [[https://www.cl.cam.ac.uk/~jdy22/papers/a-typed-algebraic-approach-to-parsing.pdf][A Typed, Algebraic Approach to Parsing]]
(PLDI 2019, Section 6.1) distinguishes static grammar facts from a dynamic
stream. That supports the preparation boundary here. Its benchmark computes
counts instead of constructing AST nodes, so its speed ratios cannot be
transferred to this engine's complete lossless artifact contract.

** Implemented representation and preserved semantics

The shared =RegionPlan= now prepares opener buckets by first codepoint: a
128-entry vector for ASCII and an eqv hash table for other codepoints. Buckets
refer to the same owned declaration rows used by scoped caches, and preserve
declaration order. The public specification view remains a deep copy. Every
probe retains scope filtering and longest-prefix selection. No language
declaration, loader schema, C ABI or compiler selection changes.

Previously, each input position built a capturing callback and walked all P
opener declarations. The generated Scheme for the frozen reference contains
that lambda passed to =foldl__0=. The new named loop walks only its selected
bucket. For T inactive input positions, candidate lookup no longer grows with
P. This is not a trie: a bucket with P colliding first codepoints still requires
a P-row prefix walk, plus the existing allowed-prefix membership checks.

** Rejected experiments and limits

An ASCII class-table experiment passed semantic tests but did not reduce
complete allocation; CPU controls were mixed. It was reverted. Its controller
also failed the idle guard after returning from main, so that run is excluded
from successful native qualification. The retained region controller exits
explicitly only after completing its assertions.

One exploratory GCC compile exceeded the idle guard during optimization
diagnostics. The unchanged source and SDK compiled on a retry. This does not
identify the precise optimizer stall or justify changing the compiler. All
experiments retained the 120-second total and 5-second idle guards. Temporary
frozen-reference modules and experiment controllers are not production code.

Remaining algorithm work is active-bucket prefix discrimination and reducing
word-result intermediate construction. Both require matched complete-product
controls, including negative results; the inactive-input scaling result does
not by itself justify either transformation.

* Rejected dense region-prefix lowering

** Algorithm and source review

This experiment used base =9c4b7635238eeb9f1fc8c8236a345b055589ddea=, the
fixed Gerbil/GCC SDK and unchanged 120-second total / 5-second idle guards.
It investigated the remaining linear walk within a first-codepoint bucket.
The engine's =make-bounded-literal-end-scanner= already follows a character
trie. The experiment adapted that representation to terminals containing the
original owned region rows, preserving cache identity and scope filtering.

The first candidate used a trie for every nonempty bucket. A later candidate
kept buckets of at most eight declarations as lists and compiled larger ones
into tries. The final candidate additionally sorted short buckets by descending
opener length, allowing the first admitted match to commit immediately.
A unique-prefix admission rule ensures that two different terminals of the
same width cannot both match the same source position. A rejected terminal
cannot stop traversal: a longer descendant might still be admitted.

Trie preparation uses memory proportional to its distinct prefix nodes.
Lookup follows the source prefix with expected constant-time hash edge access;
scope membership remains a list search at terminals. This improves dense
first-codepoint collision scaling, but adds representation discrimination and
edge lookups to small catalogs. It does not remove word captures, intermediate
recognition nodes or final token publication.

This distinction agrees with the materialized-token cost discussed in
[[https://arxiv.org/html/2304.05276][flap: A Deterministic Parser with Fused Lexing]], Sections 2.2 and 2.8.
This experiment is static prefix lookup specialization, not lexer/parser
fusion, and does not establish the paper's deterministic grammar assumptions
for this engine.

** Retained contract tests and excluded attempts

The added tests cover sparse and dense catalogs through the existing public
API, shorter admitted terminals beneath longer forbidden ones, unrestricted
queries after scoped cache publication, truncated openers, and Unicode edges
under both ASCII and Unicode first codepoints. A direct query intentionally
selects its unrestricted longest opener rather than reusing the scoped shorter
row. An initial test expected the scoped endpoint for that direct query; it
was corrected to the actual public contract, not by changing the engine.

Early private controller builds used an incorrect import operand order, a
keyword instead of an identifier prefix, a nonexistent optional library path
and a malformed optional-argument definition. Gerbil's shipped
=gerbil/core/module-sugar.ss= defines =prefix-in= as a module followed by an
identifier prefix, and validates =rename-in= identifiers. Those failed builds
are excluded. An initial native run printed its final assertion receipt but
hit the idle guard during normal exit cleanup; it is not a successful
qualification. Subsequent controllers used the existing disposable test-child
exit interface only after every assertion and flushed receipt. Guards were
not relaxed and assertion failures were not bypassed.

The next substantial target remains word-result intermediate construction.
The prior decomposition attributed approximately 15.3 MB to word products
and only 0.53 MB to source-frame preparation on the large fixture. Prefix
lookup is not sufficient to remove that representation cost. Future producer
lowering must preserve the complete artifact, owned source boundaries and
negative-input behavior and demonstrate admitted allocation improvement.

with =TEST-SUITE-OK modules=7=, =OK= and exit 0. This final receipt qualifies

* Sequence continuation reuse rejected after latest-PR integration (2026-10-10)

** Mechanism and source grounding

The experiment targeted the shared =recognition-sequence-for-each= engine,
not a Bash-specific scanner. Existing immutable right subtrees replaced
per-branch =(vector right delta moved?)= frames. A private scope record saved
parent relocation state only when a position view contained another branch or
view. Leaf-only views visited their list directly. The pending-list tail
identity delimited a scope; restoring it also restored the moved flag, even
when nested deltas cancelled to zero. Shared subtrees remained immutable and
visitor exceptions propagated immediately.

[[https://www.brics.dk/RS/01/23/BRICS-RS-01-23.pdf][Danvy and Nielsen, Defunctionalization at Work]], Section 2.1, motivates
using the original tree as the representation of deferred traversal work.
This experiment applied that representation idea to offset-aware sequences;
it does not establish a formal refinement theorem. The existing Gerbil
=std/list/list-builder.ss= collector and standard =for-each= remained in use.
Two explicit leaf-loop rewrites produced no additional admitted native
allocation reduction. A local macro expanding the resume logic also produced
no allocation reduction and higher CPU samples; all three were discarded.

** Artifact admission and experimental controls

The fixed Gerbil SDK revision was =2591dcd=, with GCC and a 3 GiB heap.
The 120-second total and five-second idle guards were unchanged. SDK
=gerbil/runtime/loader.ss=, =__find-library-module=, selects the last
contiguous numbered object version before falling back to source. Merely
replacing an older object does not select it when later versions remain.
Two initial ambiguous runs therefore loaded the candidate on both sides and
are excluded. Subsequent fresh processes asserted the actual loaded object
basename. Only the owned runtime module artifacts changed between variants.

The private Scheme controller measured 11 samples for each 10,000-child
synthetic workload and 31 complete-request samples. Allocation admission
excluded GC-crossing intervals through =admit-parser-allocation=. Complete
request timing included public =parse-bash= and an additional
=parse-artifact-valid-for-source?= check. Full serialized product equality
was checked outside timing for four fixtures plus empty, malformed and
Unicode inputs. No forced GC or simultaneous local builds were used during
timed blocks. The controller and artifact snapshots are not repository
interfaces and were removed from the change set.

* Request-owned region counters instead of replacement frames

The pinned Gerbil SDK revision =2591dcd=, =src/std/struct/queue.ss=, updates
queue links and length under an imperative ownership contract. Its
=queue->list= explicitly copies the externally returned spine. The transferable
mechanism is ownership-directed mutation, not blanket unchecked access. The
current parser design documents likewise require explicit source and execution
ownership. This change uses ordinary checked vector operations.

The region matcher previously rebuilt a pair-frame vector and its top stack
cell whenever a bare delimiter increased or decreased the active pair depth.
These are counter transitions within one region, not new independently
addressable region entries. The matcher now changes only the depth slot in the
active frame. Named nested openers and quote entries still allocate their own
frames. Prepared declaration rows remain immutable.

All callers create initial frames for one invocation. Frames never escape the
match, and completed boundary caches retain numeric endpoints, not frames.
A failed match abandons its local frames. Independent scans sharing a plan
therefore share no mutable depth. This does not grant concurrent-write authority
to one shared source cache. Regression tests exercise deep counter nesting with
other pair kinds and quotes, repeat calls, independent source caches, four
concurrent scans of the same plan, failure followed by reuse, and existing
5,000-frame cache endpoint checks.

** Matched native control

The independent grammar declares =@{ ... }=, with ordinary braces contributing
to its counter. The control has three workloads: 4,096 bare nested braces with
a Unicode payload, a flat region, and 512 explicitly named nested regions.
Plan and source construction occur outside timing. Each of eleven samples
runs ten native matches and checks the summed endpoint. The same interpreted
orchestrator invokes native kernels in every block.

The GCC-backed SDK, 3 GiB heap, 120-second total guard and five-second silence
guard remain fixed. Processes verify actual loaded artifacts: reference
=region-scanner~0.o6= and candidate =region-scanner~0.o7=. Complete owned
artifact snapshots retain contiguous loader suffixes; other clients remain
unchanged. The sequence is reference A, candidate A, candidate B, reference B.

| Workload | Reference A CPU ms | Candidate A | Candidate B | Reference B |
|----------+--------------------+-------------+-------------+-------------|
| Counter depth, ten calls | 3.106 | 2.624 | 2.606 | 2.996 |
| Flat, ten calls | 0.005 | 0.005 | 0.003 | 0.003 |
| Distinct frames, ten calls | 0.533 | 0.471 | 0.464 | 0.462 |

Counter-depth median allocation decreases from 11,799,296 to 2,816 bytes
per ten-call sample; admission counts are 10/11 for each reference and 11/11
for each candidate. This includes identical orchestration overhead. Flat
allocation remains 2,816 bytes and distinct-frame allocation remains 738,656
bytes, with 11/11 admitted samples in every block. All four controls return
=REGION-CONTROL-OK= and exit 0.

An exploratory 100-call control admitted only one of eleven reference
allocation samples because most crossed GC. Its candidate admitted all eleven.
The ten-call protocol improves admission for both versions; the sparse
exploratory allocation receipt is excluded from the table. Guards and allocation
admission rules were not changed, and no forced collection was added.

The repeatable result is elimination of depth-transition allocation in the
shared matcher. Counter-depth CPU improves modestly in these micro controls.
The flat and distinct-frame timings are controls, not claimed improvements.
There is no complete-request or Tree-sitter comparison in this experiment.

The repository-owned =t/benchmarks/region-depth/benchmark.ss= reproduces these
three workloads with configurable positive exact sample/iteration counts,
endpoint validation, per-call CPU/allocation output, and existing GC-aware
allocation admission. It is a Scheme benchmark, not a frozen alternate engine.

** Integration and cache provenance

The candidate scanner build passed in 14.400 seconds. Integration rebased onto
=c1237c5=, including staged LR action vectors and semantic leaf classification.
Changed native dependencies were rebuilt before qualification. Two existing
local interfaces were stale: the IR interface omitted =event-fold-ir= and the

The ABBA micro table remains a control against the earlier =3ba88c7= clients.
