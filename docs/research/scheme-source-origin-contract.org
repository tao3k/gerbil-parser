#+title: Scheme component origins: definition, invocation and generated rules
#+date: 2026-10-06

* Research question and evidence boundary

Can a concise multi-rule component retain both its author invocation and its
macro definition origin, through the existing POO and Bound IR owners?
This follows the [[file:scheme-component-provenance.org][component provenance]] and
[[file:scheme-composition-history.org][composition history]] studies.

The local study runs against committed baseline
=783381f33fa1b309ac4cc4b0012696f24c852d93=. Its syntax is experimental;
no public language API has been selected. All location values come from reader
syntax, not a manually maintained line table.

* Official mechanism and a useful negative result

The [[https://gerbil.scheme.org/reference/gerbil/expander/utilities.html][official Gerbil expander utilities]] document =stx-source= returning a locat
or =#f=. Container and position accessors expose file paths and coordinates;
a location may be a point without an end position. The fixture converts line
and column to one-based values and preserves a missing end as =#f=.

The initial attempt queried =stx-source= on a literal identifier created inside
the transformer with =#'template-origin-anchor=. In this installed Gerbil,
the result was =#f=. The reader location of the author's matched =owner=
identifier survived. A retry reached that check and exited 70 when the driver
incorrectly treated the absent template origin as an alist. This is a limitation
of the attempted collection strategy, not evidence of a parser defect.

The corrected strategy captures the real =defsyntax= declaration while an outer
macro still receives its reader syntax. It binds the resulting inert origin at
phase one, where the component transformer can read it. The invocation origin
is independently read from the component owner's matched identifier.

* Paper interpretation: coordinates do not complete diagnostics

[[https://www2.ccs.neu.edu/racket/pubs/icfp10-cf.pdf][Culpepper and Felleisen, Fortifying Macros (ICFP 2010)]], section 2, explains
that tracking source locations does not suffice when errors expose an expansion's
implementation instead of the author's declaration. Their guard examples also
show that rejecting syntax alone does not explain the reason. This supports
separate obligations for origin capture and author-level error explanation.
It does not establish that Gerbil provides Racket's syntax classes.

Our design consequence is an explicit diagnostic contract: report the component
operation and its author declaration first; retain generated rule identity and
template definition as supporting detail. That presentation remains a proposal;
this fixture checks metadata, not diagnostic rendering or editor navigation.

* Working contract for discussion

| Origin facet | Meaning | Current evidence / remaining work |
|--------------+---------+-----------------------------------|
| Invocation | Component instance chosen by author | Actual owner identifier coordinate checked |
| Definition | Template implementation declaration | Actual defsyntax coordinate checked |
| Generated identity | Rule admitted by current compiler | Existing binding plus owner metadata checked |
| Effective contribution | Declaration selected after composition | Override requires operation-aware selection |
| Expansion chain | Intermediates between definition and invocation | Existing flat lineage does not yet prove this chain |
| Missing source | Explicit unknown, never invented coordinate | Source-free expansion checked; artifact integration pending |

The working recommendation is to collect origins at their actual syntax
boundaries, carry them through existing compilation, and keep these facets
separate. The author should not need provenance bookkeeping in every language
package. Before publishing syntax, qualify missing-source and nested-expansion
cases and complete the bounded actual-language receipt. Author-task experiments
must separately establish whether these origins make diagnostics easier to use.

* Follow-up: declaration diagnostics and absent source

The [[file:scheme-declaration-diagnostics.org][declaration diagnostics study]] now supplies passing real-reader and source-free
