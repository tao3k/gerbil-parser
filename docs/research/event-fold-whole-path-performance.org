* Decision

** Overwrite-only ordinary-byte segments

The =tape-run= candidate changes the execution unit from one byte to one
admitted contiguous ordinary-byte segment. Its static classifier depends on
the actual IR, not a fixed document scenario. Entry zero-mode facts are checked
on every segment; write targets must not change them. A stable skipped-prefix
bound may be admitted only after the cursor reaches it. Only total, pure,
state-independent overwrite families can execute once at the segment's last
byte. Events, queries, helpers, state read-modify-write and frame changes reject
coalescing. Exceptional bytes and active modes retain the original body.

Exceptional-byte cofactoring removes unreachable effect barriers before the
entry facts are reapplied. Facts come from explicit guards, never prior request
values. The actual inline kernels qualify with 16/12 guard cells and seven
overwrite fields; 33 of 285 static loop forms admit runs. This is not a dynamic
frequency or physical performance proof. There is no runtime cache or cache
invalidation maintenance. Lean owns the overwrite-last algebra; Quint retains
separate lifecycle/publication histories. Concrete compiler admission still
requires source regressions and actual native complete-tape conformance.

Five admission controls and all 24 real AOT tapes pass. Two full sequential
control/run/run/control preflight rounds show candidate walls
62.097/65.347/103.421/62.059 ms for 1000 changing requests. Controls are
132.238/76.472/87.628/363.383 ms; the large wall-minus-CPU pauses and host CPU
contention prevent a qualified speedup claim, and one corresponding pair
regresses. Keep every receipt; do not select only the fast candidates or slow
controls. The <=10 ms gate fails in every lane. Baseline promotion, PR push and
the three-load twenty-batch matrix remain prohibited until preflight passes.
No inferred 100000-request time substitutes for an actual measurement.

pure. Unknown predicates, future-line queries and unproved range checks remain

clamped forward steps have ordered in-frame bounds; their discarded results
can be removed. Reversed ranges and =with-source-bounds= invalidate this
admission. No request value cache, global owner or invalidation maintenance.

** Guarded idle-state specialization and request allocation

The new opt-in engine plan derives uint guard cells from admitted IR rather
than Org-specific names. It retains the original body outside the all-zero
guard. Ordered writes invalidate individual facts; opaque, helper and frame
effects invalidate all facts. Known tape appends, cache queries and possible
range errors are observable but do not alias the private slot vector: retain
their evaluation and order without discarding unrelated zero-state facts.
Read-only configuration cells must not enter an idle guard. The initial plan
included nonzero inline policy, preventing that ordinary path from entering
its specialization; the corrected plan intersects guard candidates with
actual loop writes. Tests cover that regression and tape-effect preservation.
The corrected plan passed fresh actual AOT controls but still fails the
physical throughput preflight; it remains opt-in, not the accepted baseline.

A whole-loop common-byte plan combines this zero-state specialization with
necessary-byte regions. Only the common fallback region is generated as a
fast kernel; exceptional bytes retain the complete original body. The validated
current-byte membership table is reused, not a new source scan. Current native
Ascent evidence binds model/source controls and 24 actual AOT tape controls;
matched-performance remains missing and executionAuthorized=false.

model. =LibraryAdmission= requires preservation of order, observable effects,
and ownership, plus a matched runtime performance gate. Its theorem rejects
a failed runtime gate regardless of the library-selection flag. The ordered
builder sequence contract is modeled with Lean's =List.flatten= and proved

not refinement of the Gerbil macro or a GC/time guarantee.

** Direct-consumer experiment, not performance admission

The current engine candidate emits OEV1 directly from the same admitted Fold.
The grammar fixes numeric kind IDs at generation. Request-owned byte storage
reserves once per event and seals before publication; no event descriptor list
or canonical-list materialization sits between production and the consumer.
The existing canonical product remains an independent control. Ordinary Org
request/batch source wiring selects the generated tape product and passes an
admitted byte slice, avoiding a string decode/encode round trip; this wiring
has passed focused native Rust/FFI integration controls, not performance
acceptance. Diagnostic operations 5/7
still measure the older decomposed canonical path, not this ordinary path.

The tape specialization prepares ordered byte decision regions before private
procedure expansion. Only a validated loop byte and a total guard prefix may
select a region; duplicate rules preserve order and residual state conditions.
Errors, query-cache effects and opaque prefixes prohibit bypass, while nested
source bounds discard the proof. The actual Org product has 59 such regions;
the immutable old product has none. This is structural evidence, not a claim
that all repeated source scans or generic state work have been removed.

The current compiler also reuses the dominating validated byte for equality
and singleton byte-set predicates. This removes repeated offset arithmetic,
source reads and range checks without removing their admission: the enclosing
loop proves start <= cursor < limit <= end. Safe total state guards can move
behind a byte test to reject irrelevant branches before slot reads. Queries,
opaque operations and errors retain their order; a nested source frame drops
the proof. Ninety-two predicate references in the real generated Org product
use this refinement. Whole-range LaTeX/trigger prescan fusion remains open.

** 1. Stage grammar knowledge; preserve execution semantics

Build-time admission should produce dependency/read/write/effect information
for Fold expressions and transitions. The generated request should consume
that prepared plan, not repeatedly interpret or structurally hash grammar data.
Intern equivalent static future-query specifications once into compact product-
local identifiers; dynamic heading levels remain a separate key component.
The scope is the request, including nested parse restoration, not a global
content cache. Different query semantics must never share an identifier.

The present prefix-family lowering already builds a trie for a restricted pure
alternative family. Extend shared classification only where precedence and
effect analysis permit it; reuse this facility rather than introduce a second
dispatcher. Ordered alternatives, state mutation, source-bound changes and
helper effects must retain their original order.

** 2. Eliminate repeated work, not merely procedure calls

Construct a typed execution DAG with source-only computations separated from
state-dependent predicates. Compute shared line bounds, whitespace ends,
prefix classification and other admitted scans once per applicable frame.
Use dominance and dependency information for reuse; changing start/end,
helper parameters or a written slot invalidates dependent values. A global
memo table or text snapshot is not a substitute for this analysis.

Represent small state values in the owning lexical frame when they do not
escape or cross procedure joins. Keep explicit slots where aliasing is needed.
Bound specialization by generated size and compilation/retained-code cost;
making all 3746 procedures inline is not the design. Inspect emitted SSXI/SCM
and the actual call graph to qualify the intended compiler optimization.

** 3. Fuse event production with its admitted consumer

Current token transitions allocate token lists and an outer event spine;
later consumers traverse the materialized result. Establish event counts,
bytes and traversal costs before selecting a representation. Evaluate an
engine-owned compact event builder consumed directly by publication/projection,
with immutable kind metadata and request-owned output storage.

Use the existing event/sequence architecture and its ownership contracts; RFCs
0013 and 0015 already record producer/consumer fusion and slower consumers.
Do not build a competing event framework or assume a packed representation is
faster. A changing-input complete-result oracle must compare every event, kind,
offset, ordering and recovery decision. The old representation may remain a
test oracle during evaluation, not a permanent second production parser.

Offsets select physical width only after admitted bounds; overflow must reject
or use an already-supported wider representation, never truncate. Publication
requires a frozen owner/lease; cancellation, errors and retained results must
not permit reuse of live mutable storage. No per-token FFI callback is allowed.

** 4. Keep one admitted source representation and bounded storage

Map the full lifecycle: Rust input -> byte ownership/validation -> Fold scans
-> events -> metadata/projection -> output ownership. Remove only demonstrated
decode/encode/copy duplicates. Encoding a required result is not redundant.
Borrowing bytes does not authorize bypassing UTF-8 validation or retaining a
Rust pointer after its lease. Buffers and pools must have explicit reset,
retention and high-water policies rather than unconditional worst-case reserve.

Measure Scheme natural GC and Rust live length/reserved capacity together.
Prefer a supported bulk primitive over hand-written per-byte FFI. Any retained
memory reduction must be evaluated with CPU, wall and tail latency; lower GC
without better total cost is not a throughput improvement.

* Attribution before transformation

Use one upstream diagnostic case containing the actual admitted Org Fold
product; no Rust queues or Python runtime participate in this gate. Count
dynamic predicate/helper calls, repeated source ranges, future-key lookups,
index-build visits, emitted events and output bytes. Separate encoding,
Fold evaluation, future-index construction and event publication intervals.
Parent/child intervals overlap; never sum them as exclusive costs.

Optional observers are diagnostic-only. Preserve observer-free immutable
control/candidate executables for admission; do not qualify performance with
instrumentation enabled or compare incompatible harnesses. Sampling overhead,
clock resolution, CPU totals and GC counter limitations must be reported.
Never modify installed SDK/kernel code to add attribution.

* Acceptance order and stop rules

1. Preserve the exact baseline executable, grammar/compiler identities, corpus,
   SDK, configuration and resource conditions. Rebuild rejected diagnostic
   libraries before reuse; revision pins alone do not identify loaded code.
2. Validate complete semantic equality, Unicode/CR/LF/CRLF, malformed UTF-8,
   empty slices, helper reentrancy, overrides, ownership and overflow paths.
3. Run the upstream actual-Fold 1000-request preflight. Require at least
   100000 requests/s and at most 0.010 s batch wall. Reject grossly inadequate
   candidates before repeating long matrices. Tail values are reported only.
4. Only after preflight passes, run changing input for twenty batches EACH of
   1000, 10000 and 100000 requests. Hard walls are 0.010/0.100/1.000 s.
   Report request P95/P99 in us or ms, batch wall in s, throughput in requests/s,
   process RSS in MiB, capacity in bytes and explicitly scoped GC/allocation
   counters. Do not present percentiles of twenty batch totals as request tails.
5. Reject slower candidates conservatively; retain negative receipts and revert
   only owned changes. Promote nothing based on a small synthetic grammar,
   fewer allocations, one faster sample or a compiler flag change.
6. Admit accepted upstream changes to the existing parser PR, then align
   immutable GitHub revisions and actual compiled consumers. Qualify Orgize
   publication/projection, FFI and asynchronous delivery separately. Rust queue
   concurrency is not Scheme parsing parallelism. Unsupported SMP remains an
   explicit skip, not a successful acceptance result.

The 100000 requests/s objective gives an inclusive average budget of 10 us per
request, not a P95/P99 standard. No phase budget or memory limit is silently
invented. Output size and fixture complexity remain explicit; constant-size
bridge calls and tiny line grammars cannot satisfy the real workload gate.
