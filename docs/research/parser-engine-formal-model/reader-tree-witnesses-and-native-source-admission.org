* Reader-tree witnesses and native source admission

The next source-refinement audit separates parser obligations from external
compiler and host assumptions. The earlier hybrid proof was universal over a
manually specified control machine; source hashes and finite callback comparisons
did not connect its direct-call plans to the actual Scheme procedure.

[[file:../../../t/fixtures/event-walk-source.ss][The reader adapter]] now locates exactly one =event-program-walk/inline=
definition, validates its macro pattern, lexical procedure scope and initial call,
and serializes the complete =walk= declaration. It does not extract selected
calls while dropping other expressions. Unknown datum types, duplicate macros,
additional scope expressions and changed macro envelopes fail closed.
[[file:../../../t/generate-walk-source-witness.ss][The generator]] emits [[file:../../../formal/ParserEngine/SourceData.lean][typed reader data]]. This is generated source for
kernel checking, not a textual output snapshot used as an assertion. Regeneration
reads the current Scheme file. Check mode compares fresh serialization with the
committed proof input, so a source or generator change cannot reuse stale syntax.

** Restricted syntax kernel and universal scheduler correspondence

[[file:../../../formal/ParserEngine/WalkSource.lean][WalkSource]] consumes the raw tree inside Lean. It validates all ten ordered
=cond= clauses, exact callback operands, local =kind/node-state= bindings and
saved footer context. Compositional decoders extract child routes, depth
increments, relocation/provenance parameters, chunk index progression and the
append block reversal. No unrecognized expression or trailing effect is accepted.
The extracted cutoff is a parameter; the current-source witness separately
proves that the production literal is 64.

The extracted call schedule has an executable interpretation independent of
=HybridIterator.plan=. Calls and sequential loops retain distinct activations.
=admitted_plan= proves equality with that model for every projected record,
signed translation, moved flag, depth, outer continuation, existing observation
prefix and counter. =admitted_advance= and =admitted_run= transport it through
direct dispatch and arbitrary finite runs. =checked_syntax_execution= constructs
the decoded source program as well as the graph extraction witness, a completed
run, event meaning and retained callback contexts from Boolean syntax and graph
admission. The Lean =extracted_execution= specializes that theorem to the
actual reader tree, rather than supplying a hand-authored direct-control trace.

Eight mutations of the actual tree must be rejected: wrong child depth,
discarded moved provenance, duplicated branch route, missing append reversal,
lost opening context, incorrect chunk index progression, an extra effect and
fallback-before-empty priority. A changed cutoff of 63 remains admissible to the
general model, while the separate production-cutoff theorem requires 64. This
positive variation distinguishes semantic schedule admission from equality with
one entire source-text golden. All decisions use Lean kernel reduction; no
=native_decide=, custom axiom or =sorry= is introduced.

This extends the direct-control/CPS correspondence described in the
[[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][LR paper, section 4]] with parser-owned extraction obligations. It does not
turn that paper's control transformation into a theorem about arbitrary Scheme
programs, macro expansion, compiler code generation or host runtime behavior.
The restricted decoder defines the admitted source idioms; equivalence between
those idioms and execution by the installed compiler is an external premise.

The packet fallback remains a service obligation in =advanceSource=, backed by
the existing typed executor proof and real controls. It is not silently promoted
to a source-certified implementation. Likewise, the reader and macro-envelope
adapter is tested Scheme code, not a formally verified reader. This matrix is
the parser closure backlog; it prevents further host-model expansion from being
mistaken for progress on parser-owned extraction. Model closure is still open,
and no parser performance optimization is authorized by this evidence.

** Complete explicit-mutation extraction and storage laws

[[file:../../../formal/ParserEngine/SourceEffects.lean][SourceEffects]] defines a structural mutation collector over reader trees.
Its occurrence relation includes descendants under lambdas and branches; quoted
values are data. =occurrence_retained= proves that every explicit =set!= or
=vector-set!= occurrence in that relation is retained. Malformed mutation forms
are collected too. =extracted_site_decodes= proves that successful extraction
cannot silently omit an undecodable explicit mutation. This is a universal
syntax property, not a search for two expected strings in the current source.
It does not inspect the implementation or side effects of called procedures.

Kernel checking establishes that the actual iterative procedure contains two
explicit mutation sites: the chunk-frame index write and the local =frames=
assignment. The actual row indexer also has two vector-write sites. Their raw
syntax is serialized before Lean decodes it; reader, symbol conversion and
serialization fidelity remain adapter premises.

The store model preserves object identity. A write is visible through every
alias of its target, preserves all different objects and all other slots,
and preserves vector length. In-bounds reads of the written slot return the
new value. Local assignment rebinds only its named variable. Primitive vector
bounds, allocation, identity and integer arithmetic are explicit host contracts;
they are not inferred from the equations or reimplemented in Gambit.

** Source-derived assignment and chunk-resume correspondence

The append decoder consumes the complete source setup, =for-each= body and
subsequent register transfer. It checks tail-first construction, the actual
=set! frames= expression, original block order and the prefix continuation.
=source_append_assignment= interprets repeated lexical assignments and derives
=pushed_blocks_order= for arbitrary blocks, translations, provenance and prior
environments. =assignments_other= preserves all unrelated variable bindings.
It does not assume that a caller already supplied reversed blocks.

The resume decoder consumes the initial six-register binding, pending-pop
scope, chunk classification, both restoration alternatives, index read,
last-element comparison, conditional =vector-set!= and all six next-call
operands. Read/write slots, step and translation/provenance slots are extracted
parameters and admitted against the packet contract. =source_chunk_write=
connects that source-derived write to exact frame decoding for every reference,
signed index/translation and moved flag.

=last_guard_from_suffix= derives the source's =i + 1 = vector-length= condition
from the remaining item suffix. =source_resume_step= combines that guard with
the source-derived pop/retain decision and register parameters to prove the
corresponding =IteratorExecutor.advance= transition for arbitrary stores,
remaining items, pending suffixes, observation prefixes and counters. The write
is the non-final branch; the final branch pops its continuation without writing.
No source execution trace is supplied as a premise.

These are restricted source-idiom correspondences over typed projections. The
complete iterative dispatch loop is not yet source-certified. In particular,
physical continuation ownership must ensure that a write to the current frame
does not alias another pending frame. The generic alias law makes that condition
visible; fresh primitive allocation alone does not prove that parser control
never duplicates a frame reference. Remaining dispatch branches and ownership
are parser obligations, not compiler assumptions that can be silently waived.

** LR source admission and stable row order

[[file:../../../formal/ParserEngine/RowSource.lean][RowSource]] decodes the complete real =index-state-rows= declaration. It consumes
allocation, state extraction, pure key/value callbacks, cons insertion, the
zero-based unit-step finalization loop, slot reversal and final return. It
rejects additional expressions or a changed result binding. =accumulate_slot=
proves the arbitrary-row cons pass; =reverse_slots= proves ascending physical
slot updates using the current store. =checked_rows= composes them and preserves
original per-state order, including duplicate keys.

Every input row must have a state below the allocated vector length. This is an
explicit theorem premise and executable admission check; the total functional
store is not used to hide an out-of-bounds source access. Key/value functions
are arbitrary pure projections whose normal return is assumed. Exceptions or
mutation in those callbacks are outside this source schema's contract. The
proof covers all row lists and state counts meeting those premises, not a fixed
grammar or bounded enumeration. Other LR construction and grammar-lowering
procedures still need their own checked source correspondences.
