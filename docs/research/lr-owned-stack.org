#+title: Request-owned LR stacks and immutable parser frontiers

* One engine implementation unit

This study follows [[file:engine-record-access.org][closed engine record access]] and
[[file:parser-evidence-chain.org][the model and implementation evidence chain]]. It concerns the actual LR
executor and semantic operand access, rather than a language-specific adapter.
Grammar declarations, canonical IR, field/alias meanings and public artifacts
retain their existing contracts.

The optimization hypothesis is to remove the driver's two list-spine allocations
per admitted shift/reduction and its two reduction-prefix traversals. Complete
unobserved requests may own state/value vectors. Checkpoints, arbitrary stack
observers, generated reductions and the event backend retain immutable list
frontiers. These are execution domains with different ownership obligations,
not language interfaces or legacy grammar versions.

* Measured cost and rejected approaches

A fresh statistical continuation profile at =e6cebe9= sampled 30,000 prepared
representative GQL requests at a one-millisecond interval. Of 3,982 top-frame
samples, =lr-run-checkpoint= contributed 1,901 (47.7%), =##table-access= 453
(11.4%), the prepared action selector 287 (7.2%), alias construction 187 (4.7%),
and sequence-for-action 90 (2.3%). These are sampled frames, not additive causal
CPU shares. Among 631 selected table/hash frames, 488 also contained the action
selector. Attribution identifies a hypothesis; it cannot establish its benefit.

A finite literal-ID/request-classification candidate passed selector identity
and Unicode controls but did not meet the long complete-request CPU margin.
Its first implementation retained about 9 MB more live heap; compact/selective
variants still lacked the required long-request benefit. Gambit string-key
specialization, Gerbil's string-table owner, and directly expanded AST kernels
also lacked the declared complete-request benefit when evaluated separately.
None of those isolated candidates has an admitted published performance claim.
The subsequent combined candidate
stages the shared AST constructor bodies together with owned stack execution;
its independent earlier failure is retained.
Their failed, timed-out and completed exploratory receipts remain ignored study
data. A source-load timeout and a test expecting the wrong resume return shape
are retained as failures, separately from later passing checks.

This redirects work to the executor itself. Its old recognition path borrows
semantic operands but still walks both list prefixes to pop them and allocates
two new stack pairs for each successful transition. The vector policy changes
those operations without removing semantic children or postponing publication.

A complete-source continuation profile of the owned-stack candidate sampled
30,000 representative GQL requests. Among 2,608 top-frame samples, the owned LR
driver contributed 919 (35.2%), the streaming source driver 304 (11.7%),
recognition-event publication 280 (10.7%), table access 211 (8.1%), the lexical
scanner closure 175 (6.7%), and the action selector 130 (5.0%). Inclusive stacks
overlap and are not additive CPU shares. In particular, the lexical closure's
=prepare-generated-lexer= enclosing name does not mean preparation runs per
request: source inspection shows retained scanners prepared at machine creation.

The source candidate also carries lexical winner selection through a direct
ordered loop, and publishes ordinary child lists through a direct visit loop.
These preserve candidate order, length/precedence/declaration ties, token
identity and event order. Emitted Scheme confirms the lexical request loop
rather than a newly captured fold callback. Neither this emitted-code observation
nor sampled frame counts establish CPU benefit.

* Official Scheme implementation study

[[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][Sperber and Thiemann, The Essence of LR Parsing]] separates grammar-static work
from dynamic execution through specialization. This study uses that principle;
it does not reproduce their generator or inherit their performance results.

Gerbil =2591dcd= =std/io/bio/input.ss= stages a finite operation protocol with
=defrules __bio-read=. Its =std/struct/pqueue.ss= grows owned vector storage by
copying a bounded range. The parser uses checked public =subvector-move!= and
=subvector-fill!=. No unchecked primitive, compiler-metadata override or global
request buffer is introduced. Inactive semantic cells are cleared to immediate
zero; only the active prefix is meaningful, and discarded heap references are
not retained until the next growth or request.

* Shared transition body and storage ownership

=lr-stack-storage.ss= owns the static storage operations and the explicit
token-only observer capability. =lr-parser.ss= expands one transition body into
the two policies. =reduction-plan.ss= expands one right-to-left operand algorithm
with either a list cursor or a vector index. Generic backend/action selection
remains in preparation; no new generic dispatch occurs per semantic child.

#+begin_src scheme
;; One semantic traversal, specialized by its cursor expressions.
(def (reduce-lr-stack-plan actions stack offset)
  (reduce-lr-cursor-plan actions offset
    (cursor stack (car cursor) (cdr cursor))))

(def (reduce-lr-vector-plan actions storage top offset)
  (reduce-lr-cursor-plan actions offset
    (cursor top (vector-ref storage (fx- cursor 1)) (fx- cursor 1))))

;; One transition definition; the boolean is a compile-time storage choice.
(define-lr-driver #f lr-run-persistent-checkpoint)
(define-lr-driver #t lr-run-owned-checkpoint)
#+end_src

** Question: why does this exploit Scheme and Gerbil's strengths?

Hygienic rules stage representation operations into a shared semantic algorithm.
There is no second hand-maintained interpreter and no per-transition storage
object dispatch. Private buffers are lexical request state; field/alias factories
continue receiving ordinary child values and offsets, never buffer views.
Named records express the observer's capability. Direct checked calls let the
compiler retain argument/type knowledge instead of passing an optional-arity
driver through an opaque procedure variable.

** Question: how is this scientifically checked?

The claim is bounded by independent artifact equality, model invariants, native
semantic controls and matched complete-request measurements. A sampled hotspot,
a Lean theorem, or fewer source-level allocations cannot substitute for the
matched result. The first vector trial also exposed small-grammar dispatch
regression; it was corrected before confirmation, rather than widening the
control margin.

* Frontier and proof obligations

Owned state/value buffers are never stored in a checkpoint or returned to a
caller. Fork/failure handoff copies only the active prefixes into newest-first
lists. Selective GLR receives the existing exact frontier and cumulative counts,
without replaying deterministic work. Generated steps and arbitrary stack
observers keep their list protocol. Token-only observers cannot access buffers.

=ParserEngine/OwnedStack.lean= proves active-prefix length, roundtrip projection,
state/value depth alignment, prefix-preserving growth/clearing extensionality,
and the push/frontier relation. It reuses the existing reduction/LeanPoo
preparation model. The native bulk operations, mutation correspondence, GC,
compiler correctness and concurrent foreign-call lifetime are implementation
obligations, not silently proved by the abstract Array model. Quint's existing
finite publication protocol remains a separate source-generation/cancellation
obligation.

Scheme controls cover empty/unary/wide/deep decorated productions, nullable
anchors, position views, independent declaration trees and GLR, generated/event
execution, frontier resumption after an intervening request, token-only versus
arbitrary stack observers, and source ABI publication. An independent raw-rule
scan checks literal action identity, first duplicates and fresh Unicode strings.

publication alone, LR plus publication, and the actual source entry. It requires

* Admitted symbolic lookup and private storage obligations

Canonical production admission requires a Symbol nonterminal. The transition
can therefore use the native =assq= protocol for short goto rows, preserving
the first original pair. General-purpose association indexes retain their
existing equality contract. A hygienic rule expands this finite protocol into
the transition without an intermediate generic association procedure call.

#+begin_src scheme
(defrule (goto-target gotos-expr state-expr lhs-expr)
  (let* ((gotos gotos-expr) (state state-expr) (lhs lhs-expr)
         (index (vector-ref gotos state))
         (entry (if (or (pair? index) (null? index))
                  (assq lhs index) (hash-get index lhs))))
    (and entry (cdr entry))))
#+end_src

This exploits the DSL's admitted symbolic domain and Scheme's native identity
lookup. The grammar author supplies no dispatch IDs, caches or extra metadata.
The independent GLR and declaration-derived semantic oracles remain controls.

The installed SDK's =std/struct/pqueue.ss= combines typed boundaries with a local
array invariant. The private LR storage follows the same ownership principle:
initialization admits aligned frontiers, reductions check width against active
depth, and pushes grow before writing. Only accesses to request-owned state/value
buffers lower their repeated native checks. Borrowed frontiers, checkpoint export
and bulk growth/clearing remain checked. No module-wide unchecked declaration or
compiler metadata replacement is introduced. Lean discharges natural-number
index inequalities conditional on admitted capacity; it does not certify native
allocation, fixnum limits or machine code. Scheme controls exercise empty, unary,
wide/growing frames, nullable aliases, failure snapshots and fork handoffs.

The goto candidate's boundary preflight measured prepared LR at 49.240 ms and
complete source at 93.661 ms per 1,000 calls. Admission uses the separate repeated
request study below. The boundary workload remains in the existing evidence
request owner; CI has no additional lane or budget.
