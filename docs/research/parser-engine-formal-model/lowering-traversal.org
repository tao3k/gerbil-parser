#+title: Recursive lowering generation and construction correspondence

* Position in the unified contract

[[file:lowering-publication.org][Publication]] accepts an ordered pending list. That list is now generated by
[[file:../../../formal/ParserEngine/LoweringTraversal.lean][LoweringTraversal]] from a finite native-shaped syntax tree and an ordered
authored rule list. The generic producer covers arbitrary recursive depth and
n-ary width. It constructs origin recipes during traversal; callers do not
supply recipes or assume that every emitted recipe already passed verification.

The paper-level target remains =Lowering.Eval= and =Lowering.Expansion= from
[[file:../../../formal/ParserEngine/Lowering.lean][the derivational grammar model]]. =declarations_language_sound= composes recursive
generation, complete physical realization and =Names.admitted_native_root_sound=
for every finite word. The paper grammar semantics and the native representation
obligations remain distinct, explicit parts of the same statement.

* Recursive branch contract

| Native owner in =src/compiler/lr.ss= | Producer operation | Required emission order |
|-------------------------------------+--------------------+-------------------------|
| =lower-symbol= atomic cases | =operand= terminal/reference | No helper production |
| =lower-symbol= complex case | =operand= isolated recursive call | All private helper rows before use |
| =lower-operand= field/alias | =operand= transparent descent | Preserve helper rows and operand origin |
| =lower-to= sequence | =operands= | Left-to-right helper rows, then one parent row |
| =lower-to= choice | =choices= | Alternatives in source order, each with its own context and isolation disabled |
| =lower-to= optional | =lower= optional | Empty row, child helper rows, singleton row |
| =lower-to= isolated repeat | =lower= repeat | Empty row, child helper rows, recursive row |
| =lower-to= isolated repeat1 | =lower= repeat1 | Child helper rows, base row, recursive row |
| =lower-to= shared repeat/repeat1 | =lower= unisolated loop | Private isolated helper, then parent singleton row |
| =lower-to= precedence | =rebase= and recursive descent | Preserve lhs/context/recurrence; no wrapper row |
| Precedence in operand position | =operand= complex case | Retain the helper barrier even for an atomic child |
| Empty/layout-end | =lower= empty/layoutEnd | One empty recognition row |
| Authored rule loop | =declarations= | Ordered declarations; isolation from actual declaration count |

The three loop phases have ranks two (unisolated lowering), one (operand),
and zero (isolated helper lowering). Together with expression/list size this
gives a well-founded lexicographic measure. The same-expression
unisolated-loop/operand/helper path therefore terminates without supplied fuel
or a depth bound. Recursive nonterminal references remain symbols; lowering
does not recursively unfold authored grammar references.

=single_declaration= derives the unique named recurrence from the authored row
count. Identical duplicate declarations still take the shared-lhs route. A
choice context cannot manufacture a reverse recurrence from one alternative.
Helpers restart with an identity context and their own recurrence witness.

* Physical representation and LeanPoo integration

[[file:../../../formal/ParserEngine/LoweringBranches.lean][LoweringBranches]] contains the common context and emission witnesses.
=every_emission_checked= follows from the constructors used by the executable
traversal. =RealizedRows= relates every generated row, in order, to its complete
physical native counterpart; there is no zip-based truncation. Each occurrence
can have a different fresh name decoding to the same expression owner.
=realized_native= derives the existing whole-list =Names.admitNative= gate.

[[file:../../../formal/ParserEngine/LoweringTraversalPublication.lean][LoweringTraversalPublication]] sends the generated list into the existing
callback/publication executor. Materialization supplies physical values only;
recipes and grammar rules come from recursive generation. =published_recipes=
preserves the complete recipe order. =complete= retains the exact dependent
construction product and the original =ConstructionConsumer.certified= LeanPoo
factory, physical FIFO execution, actions and readiness. It creates no second
factory or independently validated automaton.

* Native controls and rejection controls

The existing =parser-source-data= macro and shared renderer publish 23 complete
native runs. The source adapter preserves n-ary shape and operand barriers.
The observations retain actual production order, physical helper bindings and
every recipe. [[file:../../../formal/ParserEngine/LoweringTraversalWitness.lean][LoweringTraversalWitness]] compares the generated owner/RHS/recipe
triples with the whole native trace, including duplicate declarations, reserved
name collisions, nested loops, layout and precedence wrappers. A separate
length equality rules out truncated recipe/production pairs. Kernel-checked
=decide_cbv= evaluates these finite controls; it is not a native evaluator axiom.

The controls reject removal of any first physical row from a nonempty trace.
An explicit precedence control distinguishes its operand helper from an atomic
operand. Scheme tests use =defparser-check= and =deflanguage-parser-tests= for
data freshness, depth-first callbacks through depth 32, and n-ary width 32.
They do not introduce a handwritten serializer or test output protocol.

* Remaining obligations and external premises

This is a universal theorem about the recursive producer model, with actual
native controls. It is not yet a universal operational theorem about arbitrary
Scheme evaluation. In particular:

- Native mutable fresh-name allocation, binding callbacks, raw syntax extraction
  and the complete Scheme call stack must still generate =RealizedRows= for all
  admitted inputs. The 23 comparisons establish that fact only for their inputs.
- The source correspondence for the shared emitter remains source-schema checked;
  it does not automatically admit the recursive bodies of =lower-to=,
  =lower-symbol= and =lower-operand=. Their complete operational extraction is
  still a parser-model obligation, not a host assumption.
- AST actions, field/alias labels, layout effects and precedence policy are not
  certified by recognition erasure. The traversal retains their dispatch shape,
  while this source adapter projects labels and precedence payloads away.
- Dynamic-precedence rejection, malformed DSL inputs and exceptions during
  helper binding require rejection/prefix correspondence. This producer models
  admitted syntax under normal-return, nonmutating callbacks.
- Allocation, primitive arithmetic/storage, symbol identity, compiler behavior
  and GC remain external premises. No Gambit source or SDK build is required.

Whole-engine model closure and CPU improvement are not claimed. Runtime
optimization remains gated on the remaining construction/request obligations.

* Qualification

The complete Lean package passes 206 build jobs. The axiom audit reports only
the standard Lean logical axioms; no =sorry=, =native_decide= or host axiom is
introduced. The 23 native comparisons include all existing origin fixtures and
five additional recursive/barrier/declaration-collision controls.

Five Scheme owners pass 99 cases with four workers and natural exit zero under
the existing 90-second total and 5-second idle watchdogs. Matrix combinations
are exercised within those cases, not counted as additional suites. The shared
generator's check mode independently reproduces the complete typed proof input.
