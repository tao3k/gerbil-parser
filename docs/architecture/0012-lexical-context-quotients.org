#+title: RFC 0012 — Compiled lexical context quotients at incremental boundaries
#+startup: overview

* Connected pipeline and proof boundary

RFCs 0010–0011 connect source provenance, certified recognition, original
production replay and canonical ParseArtifact publication. This experiment
addresses the lexical boundary in that same pipeline. It does not add another
parse authority. Its implementation is in compiler/machine.ss; ordinary
suffix convergence and certificate probing consume it in incremental.ss and
reuse.ss. The request-owned probe slot keeps the actual requested LR mode.

An LR mode names a set of admitted declared lexical rules. Numeric mode identity
is sufficient for reuse but can reject equivalent scanner behavior. Declared
rule ordinals retain token identity, expression, precedence and declaration
order. Longest consumption wins; equal consumption uses precedence, then order.
Within one prepared machine, equal complete admission vectors therefore permit
sharing one prepared scanner closure. Arithmetic has eight modes and three
such plans; HCL has 33 modes and ten plans.

This proves lexical behavior, not equivalence of LR stacks or original production
semantics. Fragment admission still checks the prepared runtime, state/stack,
original production transfer, lookahead and its existing lexical context. The
single request-owned probe slot retains its exact mode-object guard, including
its cross-runtime veto. External scanners that may consult changed source
prefixes still exclude ordinary suffix convergence. These guards are required
at their respective interfaces.

** Conservative first-transition projection

This projection still missed the common all-rule fallback. When the directed
mode has no matching candidates, generated-lexer scans with all rules to produce
the offending token or failure frontier. One mode can admit a newline directly,
while another obtains the same newline through that fallback. Candidate-mask
identity alone is too conservative for this actual executor.

** Effective scanner projection with fallback dominance

The final certificate normalizes the executor's effective candidates:

1. Project admitted rules through P(c). If the result is empty, no directed
   rule can match, so use the machine's common all-rule projection instead.
2. Separately derive G(c), a lower bound on guaranteed nonempty acceptance.
   Closed run scanners and matching one-character literals can guarantee a
   match. Incomplete strings/comments, numeric prefixes and external expressions
   cannot supply this guarantee. P and G have opposite proof directions.
3. A pure fallback consumes exactly one character. Remove it only when an
   admitted guaranteed nonfallback rule consumes at least one character and
   wins a length-one tie by higher precedence or earlier declaration order.
   Keep every other competitor, including possible longer matches.
4. Intern the normalized vectors. Equal canonical identities prove equal
   scanner outputs and next character positions at this boundary. Any failed
   directed scan that remains possible reaches the same all-rule scanner.

First-character classes include both P and G, so characters with different
acceptance guarantees cannot accidentally share a normalization class. The
best guaranteed rule is computed in one traversal; dominance is not a quadratic
pairwise rule search. For M LR modes, C unique complete masks, D ASCII classes
and R rules, certificate preparation costs O(MR + 128R + CDR); metadata stores
shared per-class vectors for C masks and references them from M modes. Scanner
preparation itself occurs C times when sharing is enabled, instead of M times.
All certificates belong to one machine. No cross-machine numeric IDs are compared.

Ordinary old-token reuse remains outside the changed byte interval and at an
exact shifted byte boundary. The old lexeme supplies c from an unchanged suffix.
Successful indexed reuse records the actual new LR mode when it differs; the
certificate does not claim historical mode IDs are identical. Fresh parsing,
full artifact equality and the independent original projector verify results.

* Carrying the proof through speculative probes

Ordinary source convergence alone did not reduce measured scanner work, even
when all HCL modes were proved equivalent at newline. The grammar reuser had
already scanned boundaries while certifying fragments, before ordinary source
convergence could supply a token. The same lexical proof must therefore be
consumed at that earlier source interface.

A closed-source owner now admits old-source tokens to those speculative probes.
The byte must be after the new changed interval, map to an old token start after
the old changed interval, and have a compatible lexical certificate. Prefix
reuse is excluded: changing later characters can extend a longest match that
formerly ended before the edit. Source bytes after the suffix boundary are
unchanged; external prefix-dependent scanners remain excluded.

=fragmentCertificateProbeByteCount= counts successful fresh scanner probe bytes.
=certifiedLexicalProbeTokenCount= counts old-source-certified probe requests,
including speculative requests; it is not a count of distinct published tokens.
The existing relex receipt describes source-stream coverage and is not replaced
with a fabricated zero when speculative scanning is avoided. The shared policy
parameter independently enables both consumers for matched controls.

* Native qualification and matched measurements

An attempted scanner-row extension failed because generated-lexer's ranked
normalization copied only the original seven fields from bare-rules. The added
metadata was dropped before certificate construction. The initial stale-cache
hypothesis was incorrect; a separately compiled nine-element vector also
preserved all nine elements. The final design places pure-fallback flags and
guaranteed-acceptance predicates in a separate AOT certificate column aligned
by declared rule ordinal, preserving the scanner's existing internal layout.
There is no legacy-row adapter.

* Remaining structural limit and next experiment

The source/provenance index in RFC 0011 stays experimental. Its balanced storage
and chunk sharing did not produce a matched whole-edit gain. Lexical equivalence
cannot repair that representation cost, and scanner equivalence cannot authorize
a different semantic reduction order.

The current complete-result boundary still copies source, publishes a flat event
sequence with absolute byte positions, and computes the standard whole-source
SHA256 in artifact.ss and incremental receipts. A changed prefix changes SHA256's
subsequent chaining state; a cached suffix hash cannot preserve this contract.
An insertion before a flat event suffix changes all its absolute positions.
Returning that entire materialized suffix retains a cost proportional to its
output size. Recognition-local bounds must therefore be measured separately
from complete publication, without substituting a Merkle digest or dropping
canonical events.

The next structural experiment belongs at original production replay and
publication: retain immutable recognition children and original fold order,
represent translated event windows internally, and materialize canonical rows
only at the existing publication boundary. Measure accepted local recognition,
original fold, event materialization and digest separately on the established
first/middle/last and sequential-history cases. Admit a new public local-result
interface only with an explicit contract and a full-artifact compatibility path.
This RFC implements lexical certificates; it does not claim that local-result
API or sublinear complete publication already exists.
