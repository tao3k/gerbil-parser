#+title: Gerbil macro binding experiments for language pack design
#+date: 2026-10-06

* Question and evidence boundary

The [[file:scheme-language-pack-semantics.org][semantic study]] separates grammar identities, public labels, macro bindings
and host expressions. This experiment asks a narrower executable question:
what happens to a macro's private host reference when its syntax is preserved
versus converted to datum and reconstructed in a caller's context?

Baseline examined: =a99b3646e7ee68c1010ca47985c762d658fef611=.
The experiment executes ordinary Gerbil macros across two source modules. It
does not import =deflanguage=, construct Grammar IR, or execute a parser.
Its results establish host expansion behavior for vocabulary composition.
All executable research fixtures are Scheme.

* Official and paper basis

The official [[https://gerbil.scheme.org/tutorials/languages.html][Gerbil custom languages tutorial]] uses contextual expanders, syntax
construction and renamed exports. It demonstrates intentional contextual
construction; =datum->syntax= is a tool whose context must match the intended
binding policy, not an operation to prohibit everywhere.

Matthew Flatt's [[https://www-old.cs.utah.edu/plt/scope-sets/general-macros.html][Binding as Sets of Scopes, section 3]] discusses syntax objects,
identifier comparisons, procedural macros and module phases. Our experiment
uses Gerbil's own expansion and evaluation. It does not assume that Racket's
scope representation or edge cases are Gerbil's implementation.

* Reproducible Scheme controls

Files:

- [[file:../../t/fixtures/language-pack-research/fragments.ss][fragments.ss]] defines a private =private-value= and exports three macros.
- [[file:../../t/fixtures/language-pack-research/consumer.ss][consumer.ss]] imports one macro under a new name, declares its own same-spelling
  value, and runs assertions including local shadowing.
- [[file:../../t/fixtures/language-pack-research/binding.ss][binding.ss]] is the executable entry.

The preserving control returns the definition-context identifier through an
ordinary =defrules= template. The parameter control returns syntax provided by
the caller. The reconstructing control deliberately performs:

#+begin_src scheme
(datum->syntax #'anchor (syntax->datum #'private-value))
#+end_src

Here =anchor= is the caller's identifier. The source reference and caller
reference have the same spelling, so equality of their datum names cannot
establish equality of their binding.

From the repository root:

#+begin_src sh
GERBIL_LOADPATH=.. GERBIL_PATH="$PWD/.gerbil" gerbil env gxi t/fixtures/language-pack-research/binding.ss
#+end_src

The local research run used a ten-second external =gtimeout= bound around this
command. It completed with exit status 0 and six =BINDING-CASE-OK= lines followed
by =BINDING-RESEARCH-OK: 6 checks passed=. Each case prints only after its actual
assertion succeeds. The experiment adds no dependency and requires no native
parser build. It is independent of compiled parser cache contents.

* Observed results

| Case | Observed value | Interpretation |
|------+----------------+----------------|
| Imported and renamed preserving macro | =definition-site= | Import renaming retains the macro's private reference |
| Reconstructed reference at module use site | =use-site= | Caller context changes resolution of the same spelling |
| Explicit caller parameter | =use-site= | Supplied syntax refers to the caller's value |
| Preserving macro inside local shadow | =definition-site= | Definition context survives local same-spelling bindings |
| Reconstructing macro inside local shadow | =local-shadow= | Reconstruction can select the caller's local binding |
| Parameter macro inside local shadow | =local-shadow= | Preserving a caller argument retains its local binding |

The last two rows intentionally have the same value but different origins.
One accepts an argument whose meaning belongs to the caller; the other discards
a definition-context reference and adopts a caller context. A useful language
implementation must know which transformation it intended.

* Applying the result to composable DSL vocabulary

=src/language/grammar.ss= expands grammar fragments before converting expression
atoms to datum. It constructs backend rows from datum using the language prefix
as the syntax anchor. These are different information classes:

| Value crossing elaboration | Binding obligation | Candidate treatment |
|----------------------------+--------------------+---------------------|
| Node/field label | Intentional published symbolic identity | Extract datum; validate identity and catalog ordering |
| Rule/token reference | Declared DSL namespace identity | Resolve before losing relevant origin; retain canonical core names |
| Macro constructor reference | Host compile-time binding | Expand while its original syntax context is available |
| Backend digest/procedure expression | Host expression with lexical references | Preserve original expression syntax through assembly |
| Generated public parser binding | Deliberate API name derived from the pack prefix | Construct in the documented export context |
| Generated private helper | Implementation binding | Preserve private definition scope or use host-generated fresh identity |

The experiment explains why a grammar vocabulary should document the intended
context of each parameter and introduced name. Public labels, caller grammar
references and implementation helpers have distinct roles. This classification
supports predictable composition using the existing Gerbil macro facilities.

* Follow-up vocabulary studies

1. Compare an explicit binary production with a parameterized infix template.
2. Compose separated-list and delimiter templates while preserving the intended
   node and field shape.
3. Import vocabulary from ordinary Scheme modules and rename it at the use site.
4. Explain expanded productions in terms of their original arguments and source.
5. Admit the expanded grammar through the current engine and compare its products
   with the explicit rules before evaluating compiler or runtime cost.

The primary design synthesis is
[[file:scheme-deflanguage-design-synthesis.org][scientific grammar vocabulary under deflanguage]]. These six host controls are
supporting evidence for that design study. Runtime, schema and target-product
qualification remain distinct experiments.
