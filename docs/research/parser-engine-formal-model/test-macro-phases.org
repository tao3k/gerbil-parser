#+TITLE: Test Macro Phase Ownership

* Unified contract

Test declarations select capabilities before constructing a Suite. Generic
engine and fixture declarations require constrained assertions. Basic loader
clauses additionally require source assertions; development clauses require
their fixture, strategy or product services. Missing capabilities and invalid
declarations must not become empty successful suites.

This is a preparation contract within [[file:native-product-publication.org][native publication]], not a parser
algorithm optimization. [[file:lowering-physical-execution.org][The lowering ledger]] remains authoritative for complete
Scheme-evaluation obligations.

| Obligation | General model | Scheme owner | Real controls |
|------------+---------------+--------------+---------------|
| Ordered demand for arbitrary declaration batches | TestPhase.requests, generic_requests | deflanguage-parser-tests | generic fixture and matrix |
| Unrequested providers cannot affect preparation | batch_independent, source_independent, loader_independent | engine/source/development branches | captured module-registry observations |
| Requested failure remains an error | loader_missing | selected helper import | loading failure and retry |

The model reuses LeanPoo Requirements.prepare, prepare_congr and build. It does
not add a provider resolver. Repeated case demands remain ordered; SDK module
initialization deduplication is a separate contract.

=import_absence= requires the transitive closure of each requested capability.
=generic_effect_counterexample= proves that provider independence alone does
not imply module isolation: the assertion provider could itself import
development services. =caller_import_survives= retains the caller's explicit
parser imports. These laws prevent a framework selection theorem from being
misreported as a bound on the entire parser startup.

* Author-time service boundary

The previous grammar frontend imported parser-ir, bound-ir and concise-language
at phase plus one. Reading a compiled grammar's interface therefore initialized
the author compiler even when the caller only wanted its runtime parser.

The frontend now retains an explicit for-template dependency on
src/compiler/language-declaration.ss. This preserves the ordinary build graph
without requesting the service runtime at interface phase. An actual lexical
declaration calls the SDK import-module with evaluation enabled, resolves its
export using the SDK and obtains the original expansion procedure. No private
module-state cache, generated-interface rewrite or runtime-binding replacement
is introduced. The service invokes the existing compiler with the same syntax
and hygienic runtime operands; lowering and parser algorithms are unchanged.

The same boundary now covers canonical, ANTLR4, ISO BNF and shell author
entries. A shared expansion-service resolves their selected SDK export;
compiled consumers retain the build dependency without initializing those
author services. Existing compiler algorithms and artifact schemas remain.
Runtime scanning and parsing operations are still requested normally.

Moving the two source-vocabulary matchers exposed a genuine hygiene defect:
a runtime service's syntax-case literals have a different definition context.
A clean build rejected the real GQL declaration. The corrected service receives
literal identifiers from the facade as operands and compares them with the
SDK free-identifier=? relation. Spelling-only matching would accept a captured
keyword and is rejected by both the model counterexample and Scheme control.
The arbitrary-list transport theorem assumes preservation of the SDK binding
relation; it does not prove the SDK expander itself.

AuthorPhase reuses LeanPoo Requirements. Its counterexample shows why eager
compiler admission can fail an interface that does not need that capability.
The general laws preserve the expansion context and required-service failure.
Quint AuthorPhase exercises the ordered interface/request/resolve/expand
protocol, including missing services, invalid input and negative eager-admission
controls. Seven controls and one thousand sampled traces pass. These finite
controls complement the arbitrary-context Lean laws; they are not a general
Scheme execution proof.

SDK export extraction, Scheme evaluation and transitive metadata effects remain
explicit premises. In particular, a dormant runtime dependency does not mean
that no compiler metadata is read.

The loader fixture captures absence of the three compiler runtimes before any
development owner is prepared. The separate source author fixture expands a
real declaration with defgrammar-syntax, checks acceptance and rejection, and
requires an invalid declaration to fail. This is a phase contract, not a claim
of parser-request CPU improvement or a complete Scheme simulation.

* SDK-selected evaluation

The former raw-source walk missed imports emitted by test macros. A concrete
failure reached evaluation of the arithmetic test owner: its expanded helper
import was present, but the runtime dependency batch produced no module
progress and crossed the five-second idle fence. The installed SDK's runtime
import path calls core-eval-module directly; observing only the public module
evaluation parameter for compiled contexts cannot cover this path.

The suite now reads the SDK's resolved import directory, including generated
imports, before constructing that source owner. It restores declaration order
from the reverse directory and prepares the supported zero-phase runtime
subset. A wrapper is admitted only when its canonical interface and sibling
SCM match the selected context. Source overlays, foreign interfaces, missing
wrappers and other phases remain with the SDK. Positive-phase recursive import
semantics are not reimplemented.

The duplicate raw-source graph walk is removed from the suite-owner path.
Explicit source-generator entry points retain their separate preloading API.
The SDK still owns source expansion, module promises, failed states and owner
evaluation. The observer delegates the prelude first, then selected admission,
then the original evaluator, preserving its returned values and exception.
It does not replace runtime bindings or rewrite compiler output.

This is the test preparation policy, not an equivalence theorem for arbitrary
interleaved, effectful Scheme module initializers. Complete source evaluation
and the extraction of SDK fields remain explicit obligations. General laws
cover arbitrary import lists and integer phases; actual controls additionally
exercise source/foreign rejection, zero/multiple values and exact exception
identity from prelude, admission and body.

The phase fixtures run in an explicitly ordered fresh suite process. The
first owner captures Boolean registry observations before preparing the loader
owner. Later admission cannot mutate that captured value. Both share the same
SDK expander and runtime. They stay outside recursive test discovery because
arbitrary aggregate ordering would invalidate the absence observation.

* Closed loading and construction phases

** Defects and semantic ownership

The old dependency observer searched arbitrary Scheme data for =load-module=.
It could execute quoted or deferred code, or run a child before an earlier
opaque parent failure. The shared =src/modules/loader.ss= now recognizes a
closed executable language: exact load calls, proper nested =begin= sequences,
and the pinned compiler's exact declaration. An unsupported sibling rejects
the entire extraction before any speculative effect.

A second defect crossed declaration and execution phases. Grammar loader
identity imported the complete source-language declaration owner merely to
recognize its descriptor type. That imported source strategy binding,
result/scanner profiles and contextual compilation even for Arithmetic.

| Owner | Responsibility |
|-------+----------------|

| =src/language/source-parser.ss= | Execution, receipts and sessions of admitted descriptors |
| =src/language/source.ss= | Declaration admission and source strategy construction |
| =src/runtime/result-plan.ss= | Owned construction storage and copied public catalog views |
| =src/language/result-profile.ss= | POO profile admission and executable projection compilation |

Loader identity, development metadata and FFI consumers now import the needed
owner. The declaration API exports the same underlying descriptor and request
bindings; there is no second class family or compatibility implementation.
Schemas, declaration values and parsing algorithms are unchanged.

The original =loader-controls.ss= captures eight source-construction modules
before execution and requires them all to be absent. Existing accepted and
rejected requests still run. This checks the actual prepared language closure,
not only a source-text dependency diagram.

** SDK cache and evaluator contract

The SDK remains authoritative for selected paths, module states, exceptions,
initialization, reloads and concurrent loading. The observer does not replace
its registry or force a directory of declared imports. Promise observation
reports actual SDK invocations; installation itself does not force them.
Repeated diagnostics may be suppressed for qualified identities, but SDK
lookup is never skipped. Relative requests and explicit reloads remain visible.
Failures clear diagnostic suppression and preserve the original exception.

Speculative child failure does not bypass the parent SDK request: the parent
must retain its own first failure even after child recovery. Quoted data,
deferred calls and unsupported opaque code retain their original execution
boundary. Source and macro-generated imports use the SDK's actual contexts.

Compiled interfaces may themselves call =load-module= before returning an
expander context. A later promise observer cannot retrospectively report those
calls. The runner therefore observes its bootstrap and real completed GC work
as well. A single opaque operation with no observable progress still fails the
silence fence; no periodic heartbeat is introduced.

** Compiler products and source replay

Native wrapper images duplicate a closed loader program already present in
=.scm=. The publication writer now omits only such package-owned wrapper
objects. It retains interfaces, source, native implementation sidecars and
foreign libraries. The shared loader and native child launcher retain native
bootstrap objects. Unknown source, missing interfaces, quoted/deferred code and
raw executable products are ineligible.

Classification uses a hash index over wrapper identities. Retained product
bytes are checked before and after removal, under the existing publication
lock. The final receipt records the actual products. Standard clean/build
remains the owner; there is no copied library tree or custom SDK cache.

GXI's ordinary Gerbil evaluator rejects a raw compiled =declare= form. The
shared loader uses the SDK's existing Scheme source parameter only for an
admitted package wrapper whose dependencies form a settled prefix: cached
successes, optionally ending at the first cached failure. Fresh initializers
run in the original evaluator. A cold/loading prefix cannot authorize replay.
The parameter is restored on both success and failure; a cached failure skips
the remaining suffix and preserves its exception identity.

These are parser capability and execution-trace contracts. Physical selected
paths reflect the new product representation; no equality of native filenames,
SDK internals, host scheduling or compiler implementation is asserted.

** Publication identity and compiled host capabilities

Nested SDK environment invocations can repeat the first PATH entry. Publication
identity collapses only consecutive copies of that entry. Unset PATH remains
distinct from empty PATH; trailing empty components, relative entries, later
duplicates, remaining search order and every other compiler flag are retained.
Stable filesystem lookup is an external premise.

Compiled host test products initialize their module through the shared loader
and resolve its qualified runtime procedure. They do not evaluate a Gerbil
=import= form in a host Scheme evaluator. A non-procedure export fails admission.
Canonical Rust fixture regeneration also restores the descriptor hashes owned
by the Scheme producer, rather than adjusting assertions to accept stale data.

The FFI build owner declares its dynamic producer and language-test closure.
The ABI recipe still invokes SDK gxtest, all twenty original native cases and
the exact-byte assertion. Build dependencies are actual named recipes. Native
helpers are not substituted with source-only test entrypoints.

** Transitive phase correspondence

The direct-key =LanguagePhase= contract has an important limit: narrowing a
root import does not prove that its transitive runtime closure excludes a
constructor. =PhaseDemand.direct_import_counterexample= exhibits precisely
that leak. The generic assertion facade is a concrete remaining audit target:
it imports =parser-ast= even when a declaration contains no AST clause. The
current generic control does not claim artifact/CST absence. Its existing
language-execution isolation result remains valid.

The reusable =PhaseDemand.Cut= contract requires both admitted roots and closure
of every admitted owner's selected runtime edges. Selection reuses the existing
=TestPhase.ResolvedImport= projection, preserving import and source phases.
Template-only dependencies are distinct from runtime requests; their author
service execution belongs to the expansion graph. Cycles and repeated requests
do not require an acyclicity or deduplication assumption.

=record_dependencies= proves correspondence when an actual owner records its
ordered dependency list. =stopped_requests= retains correspondence for a stopped
prefix, including first-error termination. =extracted_wrapper_requests= composes
arbitrary recursive closed-wrapper encoding/extraction with phase selection,
using the existing =ModuleWrapper.raw_execution= proof. =Recording= derives
request correspondence from roots, dependency records and stopped prefixes. It does not enumerate
fixture names or replace the SDK reader.

For any request transcript corresponding to this graph, a closed capability cut
bounds its requests. LeanPoo's =Requirements.prepare_congr= and the existing
consumer theorem then preserve factories, first missing-key errors and arbitrary
prepared consumers when providers agree inside the cut. Constructor absence is
valid only after establishing the cut, not from direct root inspection.

These results establish a protocol obligation for the real module graph. Source
graph completeness, dynamic imports, SDK cache/reentry behavior and compiler
phase interpretation remain external premises. The complete native controls
exercise actual imports and retained parser behavior; they do not discharge
those premises for all Scheme programs. No parser runtime optimization or CPU
speedup is claimed by this dependency work.

** Extracted lexical dependencies and runtime cells

=SourceEnvironment= composes LeanPoo's typed =Requirements.factoryAt= selection

requested names, caller order, repeated keys and heaps, it proves:

- Every retained lexical factory resolves against the invocation heap.
- A requested missing binding prevents successful preparation.
- A successful retained read supplies the actual variable-evaluation rule.
- A bound cell may still be uninitialized; name admission alone is insufficient.
- A later write to that cell is visible through the retained factory.

This guards against freezing callback state while preparing source witnesses.
The theorem does not establish completeness of arbitrary Scheme free-variable
extraction, closure conversion or host primitives. Those remain explicit
premises; they are not discharged by successful finite source controls. The
unified construction audit imports the module and reports each theorem's axioms.

** Startup output and consumer backpressure

The macOS process-control failure occurred before the flood target created its
ready marker. The old control waited for that marker without reading stdout;
qualification admission can write more than the pipe capacity before launching
the target. Thus the test's own consumer could stop initialization. An unchanged
local run passed, but the old consumer with a fixed 64 KiB startup prelude failed

without attributing every historical startup timeout to the same cause. An
earlier revised control also missed the readiness fence without a captured
startup trace; that failure remains unattributed. The retained failure diagnostic
now reports reader completion, process status and captured byte count.

The control now drains initialization output immediately. After the real target
creates its marker, the reader pauses for the existing 1.2 seconds to exercise
backpressure beyond the unchanged 0.8-second idle fence. Both ordinary and padded

qualification, not a production heartbeat. The six-second completion bound and

Generated Rust remains byte-identical to the pinned IR compiler's output. Its

when observed. An earlier outer-idle failure is retained separately; no periodic
