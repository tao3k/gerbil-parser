Documents and authored proof/control files have a 1,000-line maximum. Split at
semantic boundaries before reaching that limit. Use responsibility or fixture
names, never numbered continuation modules. Imported grammar originals and
machine-generated Rust fixtures retain their upstream or generator identity;
changes to their layout belong in the importer or generator.

The input catalogue discovers compiler, runtime and control owners rather than
copying filenames into collectors and tests. This conservative binding can
invalidate both model observations after an implementation change. It does not
claim that Lean or Quint proves every discovered source file.

* Composable parser tests

=deflanguage-parser-tests= accepts a private =(fixture)= profile with the same
closed clause admission as =(engine)=. An engine declaration composes a fixture
with =(suite "description" fixture-name)=. The engine registers its checks into
the current suite in declaration order; fixtures are not exported as independent
suites. A private owner tag rejects an arbitrary procedure used as a fixture.

Lexical fixture fragments use semantic =.ssi= names. The source-style contract
checks those fragments as well as test entry files. Fixture contents still pass
through the parser test macros; moving a scenario does not bypass admission.
The composition control checks that a child runs exactly once. The historical
rejection matrix checks each result directly, without a manually maintained
expected list length.

* Current semantic frontier

The parser model remains incomplete. The [[file:parser-engine-formal-model/lr-state-suffix-correspondence.org][LR state and suffix correspondence]]
now proves reverse suffix execution, physical after-dot reads, ordered LR0
closure publication and universal propagation-to-paper composition. The [[file:parser-engine-formal-model/prediction-interning-coordinates.org][construction protocol correspondence]] adds multi-seed prediction replay,
grammar-row decoding, state-store preservation and two-pass coordinate
extraction. The [[file:parser-engine-formal-model/template-materialization-publication.org][generated witness and publication composition]] now derives name coverage,
completed queue replay, materialized templates and published closure meaning.
The [[file:parser-engine-formal-model/physical-sparse-goto.org][physical extraction and sparse goto composition]] derives bounded advances,
symbol-index injectivity, group membership and published target closure.
The same contract now integrates earliest-item ordering, borrowed scratch, FIFO
termination and complete row publication through =ConstructionProtocol.construct=.
=CachedConstruction.construct= now consumes retained templates and selected
traversal in that same complete queue, deriving cache coverage for every plan and
identifying its final machine with this canonical paper contract.
The selected LeanPoo traversal capability now supplies direct/field callback
order to the complete queue through =traversal_finish_exact=. Its paper target
theorem applies to final edges; concrete host primitives and compiler lowering
remain external to the restricted source model.
No parser performance or compiler/host correctness claim follows from it.
