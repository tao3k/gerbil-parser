** One effective grammar, several target obligations

The typed algebraic parsing paper's Section 3 defines separate conditions for
alternative apartness and sequence separability. Its concatenation facts require
those preconditions; they cannot be copied as universally valid CFG equations.
Our design inference is to keep common facts separate from a predictive backend's
proof obligations. A legal LR grammar may fail the predictive proof.

The existing nullable/FIRST analysis remains the common authority. A proposed
analysis result also records productivity, reference components, declaration
origins and conservative scanner effects. These are private records computed by
named engine functions. An unknown effect is explicit, not an empty effect set.

#+begin_example
Effective declarations + selected origin rows
  -> common resolved facts
  -> LR admission: supported constructs, conflicts and policy
  -> predictive admission: supported constructs + determinism proof
  -> scanner/Command admission: progress, state and result obligations
  -> Scheme / Rust emission from the admitted target plan
#+end_example

A failed predictive proof rejects that requested target with an author-local
reason; it does not change choice semantics, silently select another backend or
reject an otherwise valid LR target. Conflict witnesses and proof failures must
identify the target and relevant expression occurrence.

Productivity is distinct from nullability: =A -> A= has no finite terminal
word, whereas =A -> A a | b= is productive left recursion. Productivity may be
computed monotonically with terminals/epsilon productive, choice as any child,
and sequence as all children, with repeat/optional admitting epsilon. Admission
must separately reject repeat of a nullable operand. This is a proposed analysis,
not an additional implemented fixed point. Unreachable rule policy must remain
explicit; it is not a reason to label every reference cycle invalid.

POO override invalidation follows semantic dependencies. Editing only release
metadata must not reconstruct LR states; replacing a rule or scanner policy
invalidates its dependent analysis and target admission. Cached facts must bind
the effective grammar and policy identity. A semantic digest must include all
recognition-affecting declarations; a hash alone does not replace equality or
resolve ownership. No new public schema version follows from this proposal.

** Preserve expression occurrences through transformations

Langcc's Section 2.3 explains delayed intermediate reductions in terms of the
surrounding continuation. Section 2.4 bounds XLR execution by simultaneous
branches; unbounded branching loses its stated bound. We infer that helper
transforms need both origin records and measured conflict witnesses here; adopting
a numeric branch cap does not prove that our admitted grammar belongs to XLR.

Start from =effective-grammar-row= and assign each expression occurrence an
internal identity: selected rule, child path, selected contribution and available
reader coordinates. Equal expressions at two paths remain distinct occurrences.
Generated repetition helpers point back to that identity and their lowering
operation. This avoids exposing generated helper names in DSL diagnostics.

The proposed next origin test extends the current owner/operand diagnostic:
base role -> nullable override -> inherited repeated reference. Require the
selected override and reference path in the diagnostic; restoring a consuming
override must produce a fresh admitted plan. Source coordinates unavailable in
current syntax data remain unknown rather than fabricated.

** Resume Source through the existing Command VM

=execute_initial= currently holds local frames/tasks while =step= calls
=host.command()= or =host.list()= synchronously. Both Source host methods increment
=Cursor.depth= and re-enter Source parsing. The architectural change is to retain
the VM state across these calls and return a typed request to the outer engine.

Proposed private request/result vocabulary:

#+begin_example
Command execution -> Completed(node) | NeedCompound(field) | NeedList(field, until, allow_empty)
Outer engine      -> push Source continuation + suspended Command execution
Source completion -> resume Command execution with exactly one owned result
Failure           -> unwind all suspended state and pending result ownership
#+end_example

The actual names and representation remain open. Store program counters, repeat
progress checkpoints, ordered node frames and the target field in private typed
records. Command call/node/repeat/balance already have task semantics and should
retain them. Word/Region need suspension only if their actual call graph also
re-enters Source; do not turn every leaf operation into a scheduler request.

Source continuations own pipeline/and-or/list assembly and the stop trigger.
A single request-local cursor owns token position, byte position, pending heredoc
FIFO and links. Preserve today's deferred-body behavior before considering
scoped queues. Parent result publication happens once after child completion;
trivia and significant ranges retain source order. No state is shared mutably
between independent parses.

The scheduler must account for the entire live request: pending tasks, retained
frames/captures, deferred markers, consumed input and produced output. Removing
=256= alone is insufficient. Check actual storage/work limits with structured
failure; do not add a new user-written host callback or scheduler slot.

Private result storage may require an arena or iterative destruction. Decide
using a deep lifecycle test before changing the representation. A deep parse that
succeeds but overflows during artifact release is not a successful migration.

** Incremental reuse needs boundary validation

Wagner and Graham's Sections 4–5 reuse shiftable subtrees while validating their
right edge against lookahead. A parser-state equality check is sufficient but
can be overly restrictive. Their sequence bounds also exclude unbounded context
effects. The design inference is to separate scanner restart checkpoints from
parser subtree admission, and to test context-sensitive sequences explicitly.

Tree-sitter's scanner contract stores the complete lexical state so edits and
ambiguities can restore it. The corresponding engine proposal must include
pending deferred markers and parser-induced context changes, not only the
scanner's mode. Existing immutable Scheme checkpoints are the starting point.

An edit must map both byte and character offsets and preserve UTF-8 boundaries.
A candidate retains old source ownership until an explicit mapped result is
constructed for the new source. Reusing an old =ProjectedNode= directly violates
its current source-identity contract. Reuse diagnostics should distinguish
changed content, scanner context mismatch, parser boundary failure and unsupported
effects. Do not expose those internal states as required language author data.

* Dependency-driven nullable closure (2026-10-09)

The selected grammar still flows through the existing =compute-nullable= owner
in =src/compiler/lr.ss=. This change replaces repeated complete production scans
with occurrence obligations; it adds no author slots, schemas or backend-specific
analysis. Resolved repetition diagnostics and their selected POO source map keep
using this same completed nullable index.

Krishnaswami and Yallop's [[https://www.cl.cam.ac.uk/~nk480/parsing.pdf][A Typed, Algebraic Approach to Parsing]], sections 3, 5.2
and 6, motivates deriving static grammar facts before parser specialization.
Their restricted predictive grammar result does not establish a complexity bound
for our LR parser. The worklist below is our implementation of the existing
nullable equations, rather than a claimed reproduction of their parser.

** Invariants and work bound

Each terminal-free production owns a private =nullable-clause= containing its
lhs and unresolved occurrence count. Register one reverse edge for each rhs
nonterminal occurrence, including duplicates. An empty production publishes its
lhs immediately. A terminal anywhere in a production blocks that entire clause;
it cannot become nullable through its prefix. Marked operands are unwrapped by
the existing =base-symbol= operation.

After all clauses are registered, drain newly published names. Each name is
published at most once. Each reverse edge decrements its clause once; reaching
zero publishes its lhs. Multiple alternatives can publish the same name only
once. Pure cycles and references without a definition remain false. A cycle
with an empty alternative propagates normally.

Soundness follows by induction on publication: an empty clause is nullable, and
a discharged clause has only nullable rhs operands. Completeness follows at
worklist exhaustion: every clause whose rhs operands are nullable has reached
zero, so no additional nullable lhs can be derived. With expected constant-time
table operations, graph construction and propagation cost O(P + R), for P
productions and R rhs occurrences, with O(P + R) auxiliary storage. In contrast,
a reverse-ordered chain required repeated full production scans.

The public list still follows first lhs occurrence in production order; the
lookup table contains exactly those names. These are nullable facts, not
productivity facts. Nonempty-language analysis and FIRST remain separate
obligations, and the author grammar/tree is not rewritten by this change.

* FIRST propagation: contract and implementation

The current =compute-first= owner remains in =src/compiler/lr.ss=. Its consumer
is LR lookahead/state construction and target analysis. A dependency candidate
must register rhs nonterminals only through the nullable prefix, include the
first terminal/nonnullable operand and stop afterward. Cyclic prefixes require
least-fixed-point propagation. Nullable membership must be complete before these
edges are constructed; no incremental partial index may escape admission.

FIRST's result contract includes canonical terminal order from the production
terminal catalog, not the order in which worklist facts arrive. Duplicate edges,
marked symbols, nullable cycles, nonnullable blockers and dead tails need matched
controls. Multiple terminal facts can update the same nonterminal, so nullable's
one-publication bound does not automatically apply to FIRST. Measure dependency
construction, mask propagation and result materialization together, then compare
complete LRSpec and real full-construction cost at the same compilation tier.
The implementation below applies this contract to the existing owner. It changes
analysis evaluation and storage; it introduces no public DSL vocabulary or
choice/admission policy. Productivity still requires its separate semantic
consumer and policy decision before it can change target admission.

** Implementation and fixed-point argument (2026-10-09)

The baseline is =2feaa26727dddc379a066c6b991cd1a48c9f5504=. The implementation
assigns dense indices in first-lhs order and stores FIRST/pending masks and
reverse targets in private vectors. A source/target edge is registered once,
even when several productions or rhs occurrences induce it. References without
a defining lhs retain the existing empty FIRST lookup behavior; their admission
belongs to the existing reference validator.

Build every nullable-prefix dependency before draining work. Direct terminals
seed lhs masks. A newly admitted bit enters that nonterminal's pending mask; an
empty-to-nonempty pending transition queues the index once. Popping an index
clears its pending mask and propagates only that delta to its reverse targets.
Facts arriving while queued are coalesced. A self cycle has no seed of its own.

Each seed is justified by a terminal with a nullable preceding prefix. Each edge
is justified by a nonterminal at such a prefix. Propagation is therefore sound
for the existing FIRST equations. At queue exhaustion, every admitted terminal
has reached every dependent lhs, establishing the same least fixed point as
repeated scans. Termination follows from finite monotone terminal membership;
this is not a proof that every grammar derives a completed terminal word.

Materialize public rows only afterward using the existing terminal catalog and
first-lhs name order. Queue order and delta arrival order cannot change canonical
rows. Every lookup row is derived from that same completed mask. Epsilon remains
a nullable fact rather than a FIRST terminal.

For N nonterminals, T terminal identities and E unique prefix dependencies,
each index can publish at most T nonempty batches and each edge transmits a
particular terminal bit at most once. Graph discovery and deduplication visit the
prefix occurrences; propagation work is bounded by those fact/edge updates.
Account separately for arbitrary-width mask operations and ordered result
materialization: neither nullable's one-publication bound nor a constant-time
bignum assumption applies. Dependency storage is O(N + E), alongside masks,
catalogs and the required public output rows.

** Paper transfer and semantic boundary

[[https://www.cl.cam.ac.uk/~nk480/parsing.pdf][Krishnaswami and Yallop, Figure 2 and section 3]] give compositional Null/First
transfer for concatenation. We apply the familiar nullable-prefix recurrence to
our existing syntactic CFG FIRST facts. The paper's complete type algebra,
FLast/separability obligations and predictive-parser theorem do not certify our
LR construction. In particular, our FIRST facts are not a productivity proof:
a terminal followed by a dead nonterminal can retain that leading terminal.
We preserve this behavior and the separate completion admission contract.

Let F[i] and N[i] summarize the rhs suffix beginning at position i. For the
empty suffix F[n] = 0 and N[n] = true. With completed per-symbol facts H[i]
and Q[i], the recurrence is:

#+begin_example
F[i] = H[i] union (if Q[i] then F[i+1] else 0)
N[i] = Q[i] and N[i+1]
#+end_example

A terminal has a singleton H and false Q; a missing reference has empty H and
false Q. Before incorporating position i, the builder publishes F[i+1] and
N[i+1] at its core-item slot only if that item is a nonterminal. Completed,
terminal and padding slots retain the previous zero/false values. The existing
core-symbol catalog has already unwrapped operand marks, so aliases/fields do
not change this analysis. An empty production makes no publications.

Induction backwards from n shows that each published suffix agrees with the
independent forward scans. Every rhs position is visited once; nonterminal FIRST
lists are converted to masks once per distinct referenced name. This removes
quadratic suffix traversal. It does not remove the existing padded vector
allocation, whose size is production-count times layout-width. Big-integer mask
operations also depend on terminal count; no constant-time bitset assumption or
whole-parser linear bound is claimed. The analysis adds no language-author slot,
loader schema, public grammar rewrite or admission restriction.

** Position contract and compositional argument

The producer receives the completed FIRST and nullable tables, one terminal
index and the existing core-symbol/layout catalog. Slot i stores facts for the
suffix beginning at dotted position i. Every valid position is published,
including terminal positions and the completed core: the empty suffix is
FIRST=0 and nullable=true. Padding remains zero/false. The backwards recurrence
in the preceding section is unchanged; induction now covers all valid slots.
Marked operands still use the unwrapped core symbol. Undefined references
retain empty FIRST and false nullable; FIRST does not establish productivity.

| Consumer | Fact position |
|----------+---------------|
| LALR closure propagation | core + 1, after the predicted nonterminal |
| Canonical LR(1) closure | core + 1 |
| Forward reachable FOLLOW edges | core + 1 |
| Initial backward compatibility partition | core, including completed cores |
| Follow-core NFA metadata | core + 1 |

All five consumers read the same fact meanings. Static masks are read once per
occurrence rather than re-converted for every child alternative in the FOLLOW
edge construction. Existing follow/state/terminal order and conflict policies
remain unchanged. Each catalog invocation still allocates its own padded

* SCC epsilon-closure experiment: rejected for complete construction

** Paper transfer and invariant

[[https://www.cs.cmu.edu/~cdm/resources/Tarjan1972-sccs.pdf][Tarjan, Depth-First Search and Linear Graph Algorithms (1972), section 4]]

** Indexed successor accumulation and invariant

After the forward quotient is complete, the engine indexes each shift-bearing
block's label once. Let M contain precisely the blocks whose shift target mask
is nonzero. For a DFA state S and label a, the original target is:

=epsilon-closure(union { shift(q) | q in S, label(q) = a })=.

Intersecting S with M before enumeration gives the same union, since blocks
outside M contribute zero. A dense local vector accumulates target masks by
indexed label; the first visit to a zero slot records the label for this state.
Only touched slots are cleared before processing the next state. Blocks are
visited in ascending original index order, and first-seen labels retain their
order. The engine therefore interns successor states in the original order.

The full epsilon-closed state S remains the state identity and the input to
output-item publication. Completed/nonshifting items, lookahead masks and reduce
behavior remain present. The epsilon-closure algorithm, its cache admission,
partition boundaries, conflict policy and output materialization are unchanged.
Each complete compiler invocation owns its scratch row; concurrent invocations
share no mutable row. This introduces no language-author metadata or POO slot.

Static label hashing and core/symbol lookup happen once per shift-bearing NFA
block. The hot state loop scans only those blocks and uses vector accumulation;
it no longer creates a symbol hash table per state or hashes each visited block's
symbol. Extra storage is one block-label vector, one shift-source mask, one
label catalog and one target row. Bigint operations and subset state growth
retain their existing costs; allocation and GC counts require separate evidence.

* Immutable indexed-set traversal with local fixnum fields (2026-10-09)

** Research boundary and design

Chambi, Lemire, Kaser and Godin, /Better bitmap performance with Roaring
bitmaps/, [[https://arxiv.org/pdf/1402.6407][arXiv:1402.6407v10]], Sections 1--2, motivate partitioning a
bitmap's range and choosing work according to local density. Their Roaring
representation combines sparse arrays and dense bitmap containers. This engine
change adopts the bounded-field traversal idea; it does not implement Roaring,
change the integer set representation, or inherit the paper's measured speedups.

The [[https://gambitscheme.org/4.9.7/manual/#Bitwise_002doperations-on-exact-integers][Gambit integer-operation contract]] defines =extract-bit-field= as a fixed-width
field shifted to index zero, and =first-set-bit= as the lowest present index.
The engine derives field width from =integer-length(##greatest-fixnum)= rather
than assuming a 64-bit host. Every extracted nonnegative field fits a positive
fixnum. Per-bit subtraction and clearing operate on that field; field extraction
may still allocate internally. The original bigint remains immutable and remains
the identity used in state interning, union, difference and equality.

The previous traversal clears the lowest present bit by subtracting one and
ANDing the complete remaining integer. Dense wide masks repeat bigint arithmetic
for every callback. The new private traversal starts at the field containing
the first bit and visits fields in increasing order until the last bit. Within
each field it emits the lowest present index plus the field offset. Disjoint
fields and ascending local indices preserve each callback exactly once in its
original order. No mutable global cursor, list conversion, POO slot or author
API is introduced. Nested traversals have independent local state; callback
exceptions propagate without admitting later callbacks.

A naive field-only experiment substantially regressed the two-bit mask spanning
4096 positions: 1000 traversals, median 0.762 -> 4.323 ms. It passed full artifact
equality but is rejected as the final algorithm. Empty fields count as work.
The retained algorithm selects direct clearing when cardinality is smaller than
the number of fields between the first and last bit. Fixnum masks retain the
original loop without offset arithmetic. This density choice uses input facts,
not a grammar filename, language count, runtime cache or benchmark threshold.
No asymptotic claim ignores field extraction, bigint cost or cardinality setup.

* Delta expansion for shared indexed reachability (2026-10-09)

** Paper transfer and engine boundary

Gertjan van Noord, /Treatment of Epsilon Moves in Subset Construction/,
[[https://aclanthology.org/J00-1005.pdf][Computational Linguistics 26(1), 2000]], Section 3.2 and Figure 4, separates
per-state closure memoization from per-subset closure, and computes reachability
by expanding only newly reached states. The paper also identifies the union cost
of memoized singleton closures. This revision retains the existing integrated
closure strategy and cache admission; it does not reintroduce the rejected
whole-graph SCC precomputation or claim that the paper establishes our timings.

The engine derives a bitset delta implementation of the Figure 4 worklist:
for an expanded node u, compute =delta = edges[u] \ reached=, mark all delta
nodes reached with one union, and enqueue just that delta. The reached set is
reflexive in the initial set and monotonically grows. Every node is queued only
once, so self loops, cycles, multiple initial roots and overlapping neighborhoods
terminate without repeated expansion. When the queue is empty, every reached
node's outgoing row is included, proving closure; each inserted node has an
initial-to-node path, proving no spurious reachability. Bigint difference/union
and queue costs remain part of complete-call measurement.

=compiler-index-set-reachable= belongs to =src/compiler/funcs.ss=. It accepts
an initial integer mask and a vector of immutable adjacency masks in the same
valid finite index domain. It returns an immutable reached mask and keeps its
queue local to the invocation. This is a named reusable engine algorithm, not a
language-specific closure model or an author-defined scanner. The former private
FOLLOW BFS is removed; both singleton-cache misses and uncached subset closure
use the shared owner. Grammar DSL, POO loader slots, state interning, publication,
conflict policy and the 3500-block singleton-cache admission remain unchanged.

The old BFS creates a singleton mask and checks membership for every outgoing
edge, including already reached neighbors. The new algorithm performs set
operations once per expanded nonempty row and enumerates only unseen neighbors.
Sinks skip the difference step. This is an implementation transfer of the
worklist invariant; dense and overlapping rows supply the opportunity, while
complete construction controls determine whether the added row operations pay.

** Retained cache invariant and bound

The cache maps an immutable target seed mask to a canonical state ID that has
already been assigned by =intern!=. A hit reuses that ID without recomputing
singleton unions or hashing a newly produced closure into the state index. A
miss retains the original closure/intern path. Because entries are admitted only
after interning, a hit cannot change first-discovery order or skip a queued new
state. Identical seeds in one fixed graph have identical closures; every stored
ID therefore names exactly the original transition target.

The index lives inside one complete determinization invocation. It is admitted
at the existing large-quotient threshold (3500 nodes). It retains at most one
entry per quotient node and does not evict admitted entries; once full, uncached
seeds still use the original exact computation. Small quotients retain no subset
index. No cache crosses a language, source revision or compiler invocation.

For a quotient with V nodes, each key contains at most V meaningful bits and
there are at most V keys. Thus additional logical key payload is bounded by
V squared bits plus integer alignment; table/object overhead is not included in
that arithmetic bound. The 3984-node TLA+ bound is 1,984,032 logical bytes before
alignment/headers. Canonical output masks are already owned by the existing
state index/vector; subset values are only state IDs, not duplicate closure
objects. The existing LR trace reports completed cache hits and admitted entries.
No DSL declaration, POO slot, public schema or compatibility route is added.
