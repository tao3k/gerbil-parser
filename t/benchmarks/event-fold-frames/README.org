#+title: Native EventFold frame benchmark

* Boundary

This engine-owned native executable compares dynamic string frames, explicit
string frames, and explicit byte frames using the same prefix primitives and
request-owned event publication. It includes whole-source encoding, source
traversal, frame creation, 32 prefix tests per line, and complete event output.
It is not a full Org grammar, FFI scheduler, filesystem query, or end-to-end
100ms admission gate. The dynamic route uses the current primitive defaults,
not an executable from a historical revision. A fourth, benchmark-only
generic byte walker freezes the pre-fixnum algorithm, allowing the cursor
change to be compared inside the same native process. It is not a runtime
fallback and cannot be selected by parser consumers. A fifth route borrows
absolute byte spans without creating a per-line byte vector or decoded string.

Each batch contains 1,000, 2,000, or 10,000 distinct documents with mixed UTF-8,
CR/LF/CRLF, prefix hits, rejected boundaries, blank lines, and an unterminated
last line. Every document's complete output is compared before timing. Ten
samples balance all five route positions; every sample verifies the full event count.
Compilation and conformance checks are excluded from measured request time.

* Native entry points

Use the package's compiled library as =output= and supply its dependency load
path. No Rust executable, JSON exchange, or per-document process is needed.

#+begin_src sh
just build-event-fold-frame-benchmark OUTPUT LOAD_PATH
just benchmark-event-fold-frames OUTPUT/event-fold-frame-benchmark 10
#+end_src

CPU and wall time are distinct. GC count and the raw allocation-counter delta
are retained; =allocated-bytes= is admitted only for a nonnegative delta with
no collection. GC-dependent raw deltas are not proven allocation totals.
Host contention and heap growth prevent a portable wall-time or GC ranking.

* Initial observation

Before the fixnum-cursor change, the 2,000-document CPU medians were 45.808ms
(dynamic), 21.452ms (explicit string), and 22.940ms (explicit byte). This
supports removing dynamic frame/prefix allocation, but shows that byte
traversal was not automatically the fastest route. The subsequent cursor
optimization borrows Gerbil's typed buffered-I/O and fixnum arithmetic style:
one guarded byte read per cursor, a cached next position, and fixnum cursor
operations. Bounds checks remain in place; no kernel or heap changes.

* Same-process cursor control

A subsequent eight-sample run rotates all four routes. Complete parity passes
for every document at every scale. CPU medians (milliseconds per batch):

| Documents | Dynamic string | Explicit string | Generic byte reference | Fixnum byte |
|-----------+----------------+-----------------+------------------------+-------------|
|      1000 |         19.877 |          10.639 |                 11.368 |      10.354 |
|      2000 |         41.654 |          21.453 |                 23.271 |      20.965 |
|     10000 |        192.046 |         109.844 |                116.198 |     106.596 |

The cursor-only CPU differences are approximately 8-10% in this diagnostic
workload. Dynamic-to-explicit differences also include prefix/view allocation
removal; neither comparison is a whole-parser throughput claim. At 10,000
documents the generic/fixnum wall medians are 131.927/172.467ms, respectively:
the wall-time regression is retained, not promoted as a latency win. All rows
had collections, so allocation totals are not admitted from raw deltas.
Original stdout is retained as =event-fold-frame-benchmark-matched.log= next
to the local executable, with all 96 timed rows, not selected best samples.

* Borrowed spans and functional traversal

Generated folds now pass the immutable source buffer and absolute bounds to
helpers and predicates instead of decoding, slicing and re-encoding each
frame. Nonempty helper/slice bounds still reject UTF-8 continuation endpoints;
empty spans remain valid at any offset, matching the independent decoder.

The engine also shares a pure =byte-span-skip= combinator: callers supply a
predicate instead of reimplementing cursor loops for whitespace, keys, ordered
list markers and list content starts. This follows the official LL(1) pattern
of named higher-order procedures around a shared traversal mechanism, not a
replacement grammar or a new macro language. Original checked reads remain.

A ten-sample, same-process run compares all five routes, with complete output
parity at every scale. CPU medians (milliseconds per batch):

| Documents | Dynamic string | Explicit string | Generic byte | Copied byte | Borrowed span |
|-----------+----------------+-----------------+--------------+-------------+---------------|
|      1000 |         22.414 |          12.069 |       12.373 |      11.449 |        10.949 |
|      2000 |         45.464 |          23.713 |       24.858 |      23.756 |        22.076 |
|     10000 |        215.509 |         122.228 |      132.829 |     114.004 |       106.170 |

Borrowed spans reduce CPU approximately 4-7% against copied byte frames in this
workload; this is not a large whole-parser gain. The prefix workload does not
isolate the new skip combinator's cost, so it cannot establish that higher-order
scanning is faster than hand-written loops. All 150 rows collected garbage;
raw allocation deltas are not admitted allocation totals. Local stdout is
retained as =event-fold-frame-benchmark-borrowed.log= beside the executable.
The 100ms complete consumer gate remains a separate, unpassed qualification.

* Native engine control caller

=t/engine-controls.ss= compiles the existing Fold-source, regular-DFA
and parser-runtime suites into one =std/test/base= harness. This is an
alternative qualification caller, not an additional default test matrix or
runtime process framework. =just build-engine-controls= prepares and
links the caller against an already built SDK; =just test-engine-controls=
requires all three modules, all 18 cases, final =OK= and the native exit status.

After rebasing onto =bb53704=, the generated native Fold passed 100 controls,
including decoder-oracle checks for split UTF-8 bounds and empty mid-character
spans. The native suite caller passed all 18 source-owned cases; the complete
local Just invocation took 0.789 seconds, including receipt checks. This is not
a parser-throughput measurement and excludes the cold AOT build.

Source GXI attempts hit the unchanged five-second idle gate before harness
output, including an LR attempt using the compiled interface. Gerbil's
=tools/gxtest.ss= prepares/evaluates modules before running the harness.
The native caller removes this interpretation/loading stage, but does not
prove that the source GXI startup issue itself is repaired. Failed attempts
are excluded from successful qualification; no timeout or heap increase is used.
