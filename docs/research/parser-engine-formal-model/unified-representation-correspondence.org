* Unified representation correspondence

This ledger retains the previously studied representation and host adapters.
It is not a requirement to implement, rebuild or prove the host inside the
parser project. Parser closure is governed by the parser completion gates
below, with host behavior named as an external premise. An unresolved host
premise still prevents an unconditional physical-execution claim; it does not
expand this work into compiler, collector or synchronization repairs.

** Ticket polling and visibility before forwarding-link decode

This section supersedes the earlier four-event slice for the selected ordinary
AArch64 ticket path. It does not supersede the remaining compiler, C language,
collector ownership or root-discovery obligations. The source owner remains
Gambit's ticket macros and =mem.c= at the baseline recorded below. The source
order and the current GCC-generated fixture are checked together.

The [[https://www.cl.cam.ac.uk/~pes20/armv8-mca/armv8-mca-draft.pdf][ARMv8 MCA paper]] separates read observations from ordering. We therefore
keep three distinct layers: source-loop observations, actual selected instruction
effects and the full selected [[https://diy.inria.fr/www/][herd7 AArch64 model]]. A matching volatile
poll does not acquire visibility by definition in any of these adapters.

| Native source operation | Inspected GCC AArch64 effects | Correspondence and boundary |
|-------------------------+-------------------------------+-----------------------------|
| Allocate a ticket | =ADD +8; MOV #8; LDADDAL= | =TicketMachine.prefix_registers= covers arbitrary incoming scratch registers and history; actual SDK FIX/field offsets are tested |
| Volatile current-ticket loop | =LDR; CMP; B.NE= | =poll_block= and =failed_prefix= preserve every observation for any finite failed prefix; =pollRun_eq_run= connects blocks to the same small-step interpreter; no termination or fairness is assumed |
| Exit and protected payload read | Matching branch followed by =LDR +16= | =successful_read= retains the oracle's observed payload; it does not replace it with a newer publication |
| Queue empty recheck | =LDP +24; CMP; B.EQ= | =empty_queue_no_link= excludes link decode on the equal branch; paired reads remain subject to the full ISA model |
| Forwarding-link decode and head update | =LDR [head]; SUB #3; STR +24; DMB ISH= | =queue_link_before_fence= retains this exact read/write/fence order; =forwarding_sub= proves modular tag cancellation separately from pointer validity |
| Unlock | =MOV #8; LDADDAL [current]= | Both threads' actual release/acquire RMWs are included in the external programs; their later position cannot retroactively order the earlier link load |

=host-ordering-layout-control= checks 64-bit words, =FIX(1)= equal to eight, the null
forwarding encoding =3=, current/next offsets =0/8=, payload offset =16= and
queue head/tail/chunk offsets =24/32/40= against the actual compiled SDK.
This is a layout control, not a complete C or compiler correctness theorem.

*** Admission consequence and remaining work

The selected plain-poll AArch64 instruction protocol admits stale protected
reads in the full selected model. Consequently a universally positive ordinary
acquire refinement cannot be completed for that protocol as it stands. The
existing acquire theorem remains conditional on imported visibility. Do not
admit this path by interpreting a successful native handoff as that premise.

The C source uses legacy atomic extensions and a volatile poll, so this result
is not a C11 data-race-freedom theorem or a whole-GCC translation theorem. Native
pointer provenance, all GC object/queue lifecycles, compiler reordering and the
other ISA/backends remain separate obligations. A host correctness repair must
first establish the before-decode import and then rerun these controls with the
actual changed SDK. No local engine optimization is justified by this result.

Local qualification: the locked Lean package builds all 72 jobs with explicit
axiom listings and no admitted host axiom; Quint has 133 directed controls.
The final Scheme/native/style run passes 32+6=38 cases with two workers and
natural exit zero in 15.1316 seconds under unchanged 90/5-second budgets.
The evidence-input binding control also passes. The prior missing-module import
failure is retained in local logs, followed by correction to the SDK's existing
core string API. These are correctness controls, not CPU optimization evidence.
At inspection, PR revision =7ee122e= has passed all scheduled Ubuntu, Rust
and macOS jobs (run =38912571057=). A new commit needs its own remote CI result.

** Forwarding, pointer scans and GVM dispatch composition

The seven-family inventory below remains the current closure boundary. This
extension adds general producer/consumer proofs for switch, ifjump routing and
simple/task-entry labels, and derives movable-header forwarding and pointer-slot
rewrites. It does not certify the entire compiler or collector from finite
controls. The source baseline, SDK patch metadata and ABI boundary remain those
recorded in the source reading section.

*** Switch generation and its native C consumer

=SwitchEmission.accumulated= and =stable_group= connect the native cons/reverse
accumulators to stable filtering for all five kinds. Small fixnum and character
groups have the exact source normalization order: character cases precede
fixnum cases, followed by other cases. Symkeys instead concatenate symbols
before keywords. Hash buckets preserve that order after the producer's reverse
step; hash equality never substitutes for key identity.

The target protocol now includes each group boundary, equality cascade,
hashed type guard, bucket, case transfer and default transfer. Every bucket,
even an empty one, contains a default exit. Only the final default transfer may
be elided when the next block is the default label.

There is a distinct generator/consumer obligation: Scheme computes hash modulo
capacity, while =BEGIN_SWITCH_SYMKEY= uses =hash & (capacity-1)=. The actual
capacity producer starts at one and doubles until strictly above the case
count. =capacity_loop_terminates= derives a finite successful source trace for
arbitrary counts, using a mathematical fuel bound rather than changing the
runtime. =capacity_power= proves the result is a power of two;
=mask_matches_generator= connects the C mask to generator modulo;
=native_bucket_retains= derives case coverage with that produced capacity.
Native hash decoding, key identity, C widths/literals and full source-to-C
expression semantics remain imports.

The installed GSC control checks 56 complete switch streams: five kinds,
zero/one/two/three-case boundaries, the 20/21 symkey threshold, symbol-only,
keyword-only and mixed guards, a deliberately colliding bucket, Unicode names,
poll checks and default fallthrough. The compiler's =targ-hash= is independently
compared with the installed runtime's =##symbol-hash= and =##keyword-hash=
fields for those names. This is not an all-Unicode proof of hash compatibility.
All checks call the real emitter and object/label tables; no generator is
replaced by an expected-output callback.

*** Branch and label generation

=IfJumpEmission.routing_exact= proves branch inversion and fallthrough preserve
both successor routes for arbitrary labels, next-block choices and predicate
results. =clear_result_once= covers result clearing on the source-selected
side of =END_IF=. The primitive-specific predicate semantics and fused
apply/ifjump producer are still separate obligations.

Thirty-six installed-compiler controls use real primitive metadata supplied by
=target-select!=. They cover FALSEP generation, inversion, optional result
assignment, poll/fallthrough, and known-flonum fixnum/flonum branch folding.
The latter is native producer coverage; a general soundness proof of its cache
type premise is not inferred from it. Eight more controls enter through the
actual =targ-gen-gvm-instr= dispatcher for simple/task-entry labels, checking
label identity, TASK_PUSH, frame size, cache-region clearing and all three
basic-block budget resets. =LabelEmission.complete_simple_task_entry= gives
the corresponding general state/code result. Predecessor value preservation,
entry arguments and other return/task constructors remain in the inventory.

Two control preconditions were discovered by negative runs. Constant operand
construction requires the official =virtual.begin!= operand table; optional
comments use =#f= or =make-comment=, not the truthy empty list. Violating either
internal API precondition caused a signal-139 control process. Those receipts
are retained, not admitted as compiler correctness results. The accepted
control uses official environment/target/operand initialization, valid comments
and unchanged SDK generators. Receipt output is flushed at actual completed
phases so a future signal identifies its last completed producer. The operand
initialization guard now runs before generator invocation; removing the official
initialization in a disposable negative control produces a typed rejection,
exit 70, instead of entering the unsafe generator.

*** Movable forwarding and complete pointer-slot scans

The =Forwarding= owner has two placement interfaces. The contiguous-region
adapter derives allocation bounds and uniqueness from an initially empty
forwarding view and header-derived positive widths. =native_scan_from_empty=
consumes no caller-provided alias-uniqueness or copied-object certificate.
The separate =HeaderTrace= interface admits any fresh physical target, including
a lower-address section. =header_trace_unique= and =header_trace_retains= do not
assume globally increasing physical addresses. Fresh target identity alone is
not full body-range ownership; native section allocation must still establish
that stronger premise for the physical copying proof.

The header map denotes decoded per-object forwarding headers, not a new hash
table in the parser. An already forwarded source reuses its target and retains
allocation state; a new source records the selected target. =scanned_slot=
connects each rewritten pointer slot to the final header view, and
=same_alias_destination= preserves sharing under arbitrary scan histories.
Widths include the copied header; =extent_bounded= additionally covers the
whole reserved object in the contiguous adapter.

Native pair scanning has a composition requirement: =mark_array= tail-marks
the first copied field; later pair/chunk scanning starts with the remaining
fields. =native_split_scan= joins the two scans for arbitrary field arrays.
Skipping the first field is justified only by that preceding tail phase.
=mixed_scan_projection= connects movable/immediate word scanning to the pointer
history; =immediate_slot_retained= preserves each immediate slot's exact bits.
Every reference in that slice must classify as MOVABLE0/FORW. STILL, PERM,
weak and special-object references are not silently treated as immediates.

A fresh GCC fixture builds a pair/vector graph with car and cdr cycles plus
shared children. Four actual collections preserve the cycles, both pair arms,
shared identity and payload values, with collection counters advancing. It runs
alongside the prior bit-pattern, closure, continuation and physical-placement
controls. This tests real collector behavior, not a copied collector loop.

The later entry/GC refinement below adds the forwarding codec, failed-CAS
rollback and special-field selection/forwarding composition. Remaining native
obligations include complete word/tag/header decoding, section/range ownership,
nonmoving classes, frame-link mutation, complete work scheduling and C/ISA
publication. A forwarded address is not proof that its body is ready to read:
the copy loop and subsequent chunk-publication/scan history must compose.
The existing repeated-collection theorem still requires a full relocation
contract per cycle; this extension does not claim to have derived that whole
contract for the native collector.

Invalid-header behavior is not silently strengthened. The actual diagnostic

**** Publication is not a global writer-side visibility flag

The earlier =Publication= owner is now explicitly documented as an admitted
snapshot interface. Its =fence= transition imports visibility; executing one C
writer barrier does not automatically construct that transition. The new owner
separates each reader observation rather than changing the definition to make a
native pass appear stronger.

Pinned source order in =scan_movable_objs_to_scan= and the stealing path is:

#+begin_example
tail/head recheck -> load and decode *head -> update head
                  -> SHARED_MEMORY_BARRIER -> unlock -> scan body
#+end_example

Consequently, a later barrier may protect the body scan while leaving the
previous link decode outside that ordering. =late_import_retains_link= and
=ordinary_reader_gap= prove that even granting a full published-view import
afterward cannot change the already sampled link. =acquire_before_link=
instead derives the link observation from a complete admitted ownership
history, without taking final visibility as a caller-provided certificate.

Fresh GCC ARM64 lowering of the owned reader agrees with the source order:
ordinary ticket =ldr= polling, =ldp= head/tail recheck, =ldr= link decode,
head update, =dmb ish=, unlock RMW, then body/marker reads. The earlier ticket
allocation is =ldaddal=. The original simple waiter still has no post-poll
acquire before its protected payload load. These are controls on the installed
macros; neither object proves every C/ISA execution of the collector.

**** Paper ordering slice and ordinary contended acquire

The [[https://www.cl.cam.ac.uk/~pes20/armv8-mca/armv8-mca-draft.pdf][ARMv8 paper]] separates observations from dependency, atomic and barrier
ordering. =ChunkOrder= records a four-event message-passing slice: data write,
writer-ordered tail write, tail read from that publication, and a stale data
read from initialization. The stale read contributes a from-read edge back to
the published data write. Adding tail-read-to-data-read ordering closes an
external ordered-before cycle and rejects that candidate under acyclicity.
Without that edge the slice has an explicit increasing rank, so this particular
cycle argument cannot reject it.

The source fence occurs between link decode and body scan. The same general
cycle theorem therefore distinguishes the two reads: it rejects stale body
observation under the admitted external-order contract, while leaving the
link-read slice open. Acyclicity of this subgraph is not a proof that the whole
ARM candidate is allowed; full dependencies, coherence, LSE, C race admission

has been chosen. Reusing indices from the original order is not justified.

itself or any live captured variable retains it. The successful result is the
closed-variable list, including the Scheme-truthy empty list. The model records

=future_capture_root= connects any future captured use to environment retention
and the existing map producer/root consumer; =future_capture_signed= extends
that chain through serialized fields and the signed C cursor. Its explicit
slot-to-word premise is now discharged in =Slots.future_capture_stored= by source layout operations and physical address
identities. Native context validity, pointer bounds and actual spill/cache
behavior remain distinct obligations, not certificates inferred from testing.
The compiled =closure-frame-roots= control retains two closure
environments across an opaque GC callback and collects again before accessing
them in both orders. The existing wide compiled-frame and actual continuation
controls remain in the same suite.

For concurrency, the research basis is the authors' project overview for
[[https://www.cl.cam.ac.uk/~pes20/cpp/][Mathematizing C++ Concurrency]]: concurrent semantics must account for compiler
and hardware relaxed-memory behavior. This reading covers that overview, not a
transfer of its complete C11 formalization or x86 validation to Gambit.
The actual inspected route uses GCC legacy =__sync= operations, rather than
assuming C11 relaxed atomics. GCC documents
[[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fsync-Builtins.html][old-value fetch-add/CAS and the full synchronize barrier]]. Its
[[https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html][volatile documentation]] explicitly does not order nonvolatile memory through a
volatile access. These source-specific contracts remain below the logical
linearization boundary; no new axiom asserts compiler correctness.

=Publication= distinguishes initialized chunk epochs, observer-visible payloads
and the published tail. A write can advance initialization without visibility.
An unfenced atomic tail update has a checked unsafe counterexample. The first
=end_heap_chunk= barrier flushes chunk content, end marker and link before the
tail update. The second barrier follows that update; it stutters in this
payload-safety projection. Visibility progress and condition-variable wakeups
are not proved by a stuttering safety projection. =end_chunk_safe= derives the
producer branch without assuming its resulting invariant. =trace_safe= then
preserves the invariant through arbitrary admitted finite histories, and
=reservation_visible= connects a published queue head to both visible payload
and the existing queued/held ownership permutation.

The steal path's optimistic head check is not a reservation. The current head
must be read again after obtaining the lock. =distinct_reservations= proves
adjacent removals cannot claim the same chunk when the queue has unique IDs.
It does not establish that native allocation and queues preserve global ID
uniqueness. The collector's strong and weak phases use distinct counters; this
strong-root proof does not silently combine those phases.

The ticket macros require a separate boundary. Fetch-add returns the old ticket;
unlock uses another fetch-add. =bounded_tickets_unique= only admits physical
modulo tickets inside an explicit no-wrap window. The normal lock then waits
using a volatile load of =current=, with no explicit post-wait barrier in that
macro. A full barrier on ticket allocation before waiting is not, by itself,
a proof of acquire ordering after a later owner's unlock. Architecture/compiler
ordering for that ticket path and patched-binary identity remain open adapters.
The POSIX mutex alternative is modeled below relative to its successful-call
synchronization contract. This is an identified proof gap, not a demonstrated native
race, and no runtime synchronization change is made on that basis.
