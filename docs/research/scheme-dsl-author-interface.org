* Closed author contract and migration gate

The author grammar has exactly two blocks: =syntax= selects a vocabulary and
its recognition policy; =rules= supplies local productions. Release metadata and
validated execution backends belong to =parser.ss=. The former flat declaration,
its release =identity= clause, the old source-adapter macro exports and authored
canonical =alias/sequence/precedence= constructors are removed from this API.
Engine IR still has its own closed encoding; it is not an alternative author DSL.

#+begin_src scheme
;; grammar.ss: names and fields are collected through hygienic expansion.
(defgrammar-syntax (named kind item)
  (node kind (field value item)))
(deflanguage example
  (syntax (lexical
    (root name)
    (lex (identifier Identifier (identifier)))))
  (rules (name (named Name identifier))))

;; parser.ss: release identity is owned by the public parser entry.
(deflanguage-parser-loader example-language
  (grammar example-language-grammar example-syntax)
  (parse parse-example)
  (metadata '((language . "example") (version . "1")
              (contract . "example.v1"))))

;; Question 1: Why is this design better?
;; The author declares token recognition, node construction and release identity
;; once under their respective owners. Defsyntax/rules express reusable grammar
;; abstractions; the compiler derives consistent catalogs and admitted products.
;; POO extends values where inheritance is needed; ordinary values need no wrapper.
;; Question 2: Why is this scientifically defensible?
;; Old declarations must fail before publication. The new declarations must keep
;; independently specified acceptance, fields, spans, diagnostics and roundtrip.
;; A shared wire format or a successful import alone cannot establish alignment.
#+end_src

The strict macro boundary, all production grammar declarations, native source
vocabularies and test declarations are migrated together. Qualification of the
previous contextual IR commit establishes engine-product admission only; it does
not qualify this new author-contract migration. Current migration receipts are
recorded only after their actual tests finish. No timing improvement is inferred.

* Historical public API audit before the closed author migration

The three-file topology is implemented, but it is not evidence that the entire
public DSL is minimal. On 2026-10-07 the eight grammar.ss modules contain neither
=setq= nor =set!=. Their =(seq ...)= forms express grammatical sequence, not
Scheme assignment. Sequence is a necessary semantic distinction; requiring every
author to spell every lowered sequence, reference and token wrapper is a separate
interface decision that must be justified with complete examples.

The current public boundary has concrete remaining leaks:

| Current surface | Responsibility | Design direction |
|-----------------+----------------+------------------|
| Grammar exports of grammar IR, parser IR and generated parser bindings | Compiler products | Keep diagnostic inspection explicit; ordinary parsing must not require these bindings |
| Whole grammar re-export from parser.ss | Consumer API | Publish the checked language entry, parse operation and deliberate metadata; keep compiler products out of that ordinary entry |
| Arithmetic/HCL imports of generated direct drivers and digest bindings | Backend admission | Derive or bind validated backend products behind the compiler/library boundary |
| GQL lexical recognition and token bindings | Source adapter and lexical semantics | Catalogs are derived from one lexical declaration; token policy stays explicit |
| Repeated literal/reference/token/sequence wrappers | Grammar vocabulary | Use existing hygienic grammar syntax to express recurring constructs and preserve their source origins |

These are design obligations, not changes already shipped. Removing an export
without tracing generators, semantic tests and artifact inspection would merely
hide a dependency. Moving language-specific semantics into the generic engine
would also violate the engine/library boundary. The source adapter owns source
format translation; the engine owns canonical admission and compilation.

The compiler already implements these shorthand rules in
[[file:../../src/compiler/concise-language.ss::175][surface-body and surface-expression]]:
strings lower to literals; unambiguous declared names lower to token/reference
forms; multiple rule/node body expressions lower to a sequence. Explicit token
or reference forms remain required for a token/rule name collision. Therefore
removing those redundant wrappers needs no new DSL constructor or parser runtime.
The complete call/array package below now uses these existing facilities; its
inline control, accepted/rejected expectations, field counts and exact AST/span
test remain independently authored. Language-specific lexical and conflict
policies remain explicit.

The existing =defgrammar-syntax= example below is an executable starting point:

;; It removes duplicated implementation of the separated-list policy while
;; keeping the author-visible field, item and separator choices explicit.
;; Hygienic expansion preserves binding and origin; parentheses alone do not.
;; Question 2: Why is this scientifically defensible?
;; The inline and macro forms must agree on accepted/rejected strings, exact
;; AST fields and spans, source roundtrip, diagnostics and published identity
;; rules. Those independent observations can falsify the proposed abstraction.

The next design comparison must cover complete arithmetic and GQL packages,

** Native Scheme abstraction is the author baseline

The previous contribution/owner/compose candidate is withdrawn. It introduced
public bookkeeping without establishing a language-author task that required it.
Checked POO roles are existing engine capabilities; they do not justify making
ordinary authors learn a contribution protocol. No new author form is selected.

The design starts from the complete existing package above: grammar.ss declares
language meaning, parser.ss declares the checked entry, and parser-test.ss declares
observable expectations. A reusable grammar idiom can use the existing
=defgrammar-syntax= template or ordinary Gerbil =defrules/defsyntax=. More powerful
macro facilities are useful only when they make a concrete declaration or change
clearer. A new name or shorter expansion is not a sufficient improvement.

#+begin_src scheme
;; Existing author vocabulary: an expression abstraction with language meaning.
(defgrammar-syntax (required-items label item separator)
  (seq (field label item)
       (repeat (seq separator (field label item)))))

;; Existing grammar expression. No contribution owner or compiler metadata.
(node Call
  (seq (field callee (token identifier)) (literal "(")
       (optional (required-items argument (reference name) (literal ",")))
       (literal ")")))

;; Question 1: Why is this DSL design better?
;; Compared with repeated list productions, a named grammar idiom centralizes
;; list policy while leaving the node, fields and delimiters visible to the author.
;; The engine derives catalogs and compiles the result through the existing entry.
;; Question 2: Why does this DSL design have a scientific basis?
;; Compare the complete explicit and macro-based packages using independent tree,
;; event, span and rejection expectations, then evaluate real edit/diagnosis tasks.
;; Falsifiers: hidden policy changes, worse diagnosis or manual metadata required.
;; Limit: native package controls establish stated semantics, not measured author
;; effort, universal superiority or a completed source-aware POO admission path.
#+end_src

Keep the engine dependency order explicit: preserve syntax during elaboration;
resolve effective declarations; derive and validate catalogs; finalize canonical
data and receipt; compile and publish consistent runtime inputs. These are engine
obligations, not a sequence users must configure. Host macro availability and
language-domain reference validation remain distinct. The engine must diagnose
errors in terms of authored rules and parameters rather than internal role names.

Existing keyed POO operations remain available at their current lower-level API.
The concise DSL does not acquire new composition forms by implication. If a
complete language-package task later needs multi-rule reuse, first express its
before/after declarations and observable contract with normal Scheme facilities.
Only a demonstrated limitation can justify another public form. The same rule
applies to helper identity, registration and inspection protocols.

The paper-to-source rationale is in [[file:scheme-dsl-research-basis.org][the research basis]]. The corresponding
selection/finalization/publication responsibilities are in
[[file:scheme-dsl-engine-admission.org][engine admission]]. The checked entry and test declarations below complete the
same author package; they do not depend on the withdrawn candidate.

** Three files are responsibility boundaries, not frozen implementations

The complete migration changes the contents of all three author modules. Keeping
three interfaces does not require preserving the old declarations, assembly or
test layout. The compiler route is:

#+begin_src scheme
;; Architecture, not a new author syntax:
;; grammar.ss -> hygienic expansion and POO composition -> canonical IR
;;            -> binding, compilation and publication -> generated machine
;; parser.ss -> checked public entry over the accepted descriptor and machine
;; parser-test.ss -> independent obligations across the complete route
#+end_src

The arrows express product dependencies. parser-test.ss is authored conformance,
not a generated final compiler stage. It must independently test semantics,
fields, effective origins, immutable products and public entry behavior. Likewise,
parser.ss consumes the machine but need not implement parsing algorithms.

** A concrete duplication with a concrete owner

At baseline =783381f33fa1b309ac4cc4b0012696f24c852d93=, the grammar module repeats upstream version, commit and digest in exported
metadata constants, the =antlr4 vocabulary= declaration and the separate
=defsyntax-antlr4-source= declaration. Both macros resolve/read the source and call
=parse-antlr4-source/expected=. Source inspection therefore identifies two source
processing sites when both declarations expand. It does not establish two parses
per request or per module load: compiled products and cached expansion can avoid
executing transformer code on those paths.

The separate catalog has a real consumer. The
[[file:../../t/antlr4-source-test.ss][source catalog tests]] assert total/parser/lexer rule counts, known rules and
canonical lowering. Deleting it simply to shorten grammar.ss would remove an
existing contract. Likewise, parser-test.ss deliberately repeats expected identity
literals: changing implementation identity must not silently change its oracle.

Both declaration macros require literal string syntax for identity and digest.
Replacing those literals with existing runtime constants does not satisfy their
current transformer contract. Ordinary Scheme values and transformer inputs are
different stages; an apparent deduplication must specify how it crosses that
boundary before claiming the complete module remains valid.

;; GQL uses (deflanguage gql (syntax (antlr4 ...)) (rules)).
;; The complete checked declaration is languages/gql/grammar.ss.
;; Question 1: Why is this DSL design better?
;; A declaration expresses source identity and language policy; Scheme expansion
;; can derive consistent definitions and compiled products from that accepted input.
;; Compared with synchronized declarations, an engine-owned common source result
;; removes repeated source pins while retaining the Loader, catalog and test contracts.
;; Question 2: Why does this DSL design have a scientific basis?
;; Trace one source identity into source catalog, Grammar/Bound/Parser IR and Loader.
;; Keep independent identity, structure, precedence and rejection expectations.
;; Test mismatched digests before publication and compare complete package behavior.
;; Falsifiers: a removed consumer, stale metadata/origins, changed recognition/tree
;; policy, or tests whose expected values are regenerated from the changed input.
;; Limit: bounded local conformance does not measure author effort, compilation
;; speedup, standalone generated products or parse-latency improvement.

** Local implementation through the existing declaration

The refactor is now implemented locally in
[[file:../../language-support/antlr4-language.ss][antlr4 vocabulary]] and [[file:../../languages/gql/grammar.ss][the GQL declaration]]. The macro serializes its already
validated catalog and emits =prefix-antlr4-source= alongside the existing grammar,
Parser IR, machine and descriptor. The runtime constructor binding is imported
by the macro module, preserving hygiene; the public generated name uses the prefix
syntax context, following the existing generated binding convention.

GQL keeps its existing =gql-antlr4-source= export and removes its separate
=defsyntax-antlr4-source= invocation. Its source-version, commit and digest metadata
now come from that catalog; edition and syntax contract come from the descriptor.
The pin is declared once. Its parser.ss entry and parser-test.ss declarations retain
their existing contracts and independent expected identity literals. The standalone
source macro remains available for separate resources such as FHIRPath's normative
catalog. No contribution, owner or compose interface was added.

| Before | After | Semantic obligation |
|--------+-------+---------------------|
| Two GQL source-processing macro invocations | One accepted catalog in the grammar macro | Digest validation occurs before canonical emission |
| Independent typed catalog materialization | Typed catalog emitted from that accepted catalog | Existing source export and consumers remain usable |
| Metadata pins repeated in runtime constants | Constants derived from catalog/descriptor | Independent literal expectations retain their values |
| Existing checked Loader and grammar compiler | Same Loader and compiler owners | Recognition, precedence, corpus, origins and rejection remain qualified locally |

The existing [[file:../../t/antlr4-source-test.ss][source suite]] now additionally compares all lowered catalog rule rows
with the published Grammar IR's rule rows. This is a cross-product consistency
assertion, not an independent recognition oracle; it supplements the unchanged
independent source identities, rule counts and language semantics.

This implements a concrete use of Scheme macros: one accepted declaration expands
into consistent definitions and compiled products. The common-core principle in
[[https://www2.ccs.neu.edu/racket/pubs/icfp24-bgh.pdf][Compiled, Extensible, Multi-language DSLs]] motivates that boundary; dependent
validation in [[https://www2.ccs.neu.edu/racket/pubs/icfp10-cf.pdf][Fortifying Macros]] motivates rejecting invalid pins before downstream
emission. Their Racket mechanisms and miniKanren algorithms are not runtime
dependencies or GQL performance evidence.

This distinction completes the research argument: the declaration and macro can
be simpler only if the compiler and published products retain the same contract.
The semantic controls answer whether the current source behaves correctly; the
compiler gate answers whether that source can produce a consistent reusable
package. Neither establishes a quantitative author-effort or performance result.
No LR or runtime parser algorithm was changed by the refactor.
