* Public language and declaration entry

The package selects its own =prelude: :tao3k/parser/prelude= in =gerbil.pkg=,
whose base is =:tao3k/yuanxu/prelude=.
=init.ss= invokes the public =yuanxu!= declaration supplied by that prelude;
consumers do not import =module-system/selection/init-syntax= directly.
The prelude provides the shared Gerbil/POO language and a deferred declaration
entry, while Yuanxu retains selection, source admission and native build
ownership. Importing the prelude alone does not load Parser subsystems or
execute a generator. Parser runtime and grammar APIs keep their existing module
identities; the prelude does not reexport the entire parsing engine.

The shared-prelude candidate completed native =gerbil build --optimized= with
2 GiB/600 seconds on the installed macOS ARM64 SDK. Native runtime,
graph-query and source-grammar Suites passed 19 cases under 1 GiB/120 seconds.
The separate language-source-contract Suite could not load its test benchmark,
which requires the independently declared ASP development dependency; that
attempt is not counted as a pass. Full development/benchmark and remote CI
qualification remain separate gates.

* Product language and reviewed downstream interfaces

The Parser prelude owns the Parser language entry. It inherits Yuanxu's common
Gerbil/POO/Module declaration surface and exposes =deflanguage=,
=defgrammar-syntax= and =deftext-profile= through deferred native imports.
Declaring a grammar keeps the caller's source and lexical context; ordinary
prelude import initializes neither Parser engines nor the Module System.

Runtime products are imported through =artifact-support=, =text-support=,
=source-line-support=, =graph-projection-support= and =graph-query-support=.
The immutable Fold program protocol uses =event-fold-program-support=;
generation and compilation use =language-build-support= and
=rust-syntax-support=. Tests use =language-test-support=. =only-in= still
selects the required names. Downstream code does not depend on =src/= paths.

Pure text functions now have one implementation in =text-support.ss=.
Rust lowering imports those same functions rather than owning runtime text
behavior. This keeps a runtime text import from initializing compiler modules.
Existing published roots discover these interfaces through the native import
closure; no extra hand-maintained source catalog is added.

The product-entry candidate completed native build within 2 GiB/600 seconds,
including the owned =tao3k/parser/prelude= products. Its public-interface,
runtime, graph-query and source-grammar Suites passed 22 cases in 4 Suites
within 1 GiB/120 seconds. The three new controls run independent consumers:
ordinary prelude import plus inherited macro phases, an actual grammar using
the deferred public declarations, and pure text behavior without compiler
initialization. These are local installed-SDK results, not full remote CI.

* Remove the duplicate API umbrella (2026-10-29)

compiler, runtime and native-scanner interfaces through one eager aggregate,
and Language's Build retained that aggregate as a publication root. Delete
both. The existing independent catalog now refuses the retired =src/api=
target, retaining its complete source-discovery comparison and all ABI options.

=source-line-support= entries, whose previous publication edge was the
removed umbrella. Scanner implementation
and foreign compilation stay with Runtime; no wrapper replaces =src/api= and
no complete runtime is imported into the prelude. Installed stale outputs must
be removed with the native clean/build lifecycle before catalog qualification.
