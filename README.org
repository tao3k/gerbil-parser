#+title: gerbil-parser

A programmable syntax engine in Gerbil Scheme, with declarative language packs,
lossless parse artifacts, and Rust integration.

Languages declare syntax and metadata; the engine owns scanning, grammar
normalization, LR construction, parsing and result publication. Hygienic macros
and POO prototypes provide constrained extension points. Gerbil remains the
compiler authority for generated Rust products.

This is an active implementation and research project. Supported syntax and
portable products are qualified per language and target; a shared authoring
interface does not imply complete language coverage or backend parity.

* Native package dependency

The one direct production dependency is Core. Its native declaration owns the
inherited POO revision; Parser does not repeat that pin. Runtime imports and the
installed dependency closure retain both public owners.

* Native package build

Gerbil is the default compiler and standard build toolchain. =init.ss= selects
Parser with =yuanxu!=; its Scope publishes the existing =build-modules.ss=
catalog. =build.ss= hands the complete catalog and all three FFI specifications
through the same init-owned =std-make-spec= to Core's =defbuild-script= adapter.
Core owns selected-source preparation, normalization and required-product
checks; Gerbil =std/make= owns scheduling and compilation.

=gerbil pkg build github.com/tao3k/gerbil-parser= uses this entry. The
=qualify-library= recipe also invokes =build.ss= directly. Optional command,
FFI and test build entries keep their existing Gerbil declarations and compiler
options. No Parser publication wrapper or package-input policy sits around them.
Ordinary build completion is not a separately issued review or delivery approval.
Qualification records actual command results and required test markers.

The prefix-wide library snapshot, reverse-dependent/namespace policy,
reader/writer publication barrier, separate qualified-build wrapper and copied
conformance cache are removed together. There is no scan of all installed
packages to manufacture Parser input ownership. Conformance preparation invokes
the existing declared module and link owners; source-only test classification
belongs to =scripts/test-plan.ss=. That script does not manage a cache.

=src/build-support= retains compiler options and the necessary native-object
link adapter. The shared byte/text output pump is owned by existing Core Ops;
Gerbil =run-process= retains process execution and failure propagation. No
Gerbil/compiler source or installed toolchain is modified.

Two workers and the existing heap limits remain. Parser package/helper/catalog
build entries have no 180-second cutoff; focused test, idle and failure-evidence
limits remain unchanged. Failure archives preserve the original status and
cannot be restored as successful prepared products. CI's existing transport
identity remains distinct from compiler correctness and review authorization.

* Explicit callable and data boundaries

Native POO Types and Functions check each invocation. Graph callers choose their
Row, Id and Kind Types; the Context retains these choices and a TypeValuePair
for its admitted view. Its accessors return Id, OrFalse(Id), and Kind. False is
reserved for no parent. Query arguments and targets use the same chosen Types.

#+begin_src scheme
(import :gerbil-parser/graph-query-support
        (only-in :clan/poo/object .o .ref)
        (only-in :clan/poo/type Record Symbol OrFalse))
(def Row (Record id: [Symbol] parent: [(OrFalse Symbol)] kind: [Symbol]))
(def context
  (make-graph-query-context Row Symbol Symbol
    (.o records: (list (.o id: 'root parent: #f kind: 'section))
        id-of: (lambda (record) (.ref record 'id))
        parent-of: (lambda (record) (.ref record 'parent))
        kind-of: (lambda (record) (.ref record 'kind)))))
(graph-query-map context 'section (lambda (_) #t))
#+end_src

=make-source-scanner ContextType ModeType source initial-context step= installs
=SourceScannerStepOf(ContextType, ModeType)=. It accepts source/UInt offset/
ContextType/ModeType and returns exactly optional Symbol, UInt end, ContextType.
A caller-owned defstruct works through its POO Type, including field predicates.
Initial and replacement Contexts are checked. Progress, EOF, span bounds and
worker ownership remain algorithmic invariants. Original callback exceptions
propagate. The contextual IR executor retains its own nominal scanner structs.

=ActionSelectorFactory= validates raw action rows, indexed row structs, and a
returned selector of UInt/optional-token -> optional LRActionEntry. Entries have
concrete terminal/action structure; malformed operands and cyclic branches fail
Type admission. Types do not establish parser transition correctness.

Utilities publishes concrete string services plus
=list-operations-for(RowType, KeyType) -> TypeValuePair=. It has no default row/key
Type. Compiler accepts structural Grammar or schema-bound GrammarIR. IR headers,
row carriers and grammar/lexical expression data are checked by their existing
validators; semantic resolution remains the compiler's responsibility. Grammar
family prototypes are stable across Contract refinements within their own module
realization. Structural compiler inputs permit source/compiled interoperability.

** Remaining Any sites

These seven declarations retain their actual universal semantics; none is renamed
to a nominal alias to conceal a weak signature.

| Location | Position | Reason |
|----------+----------+--------|
| grammar/types.ss grammar-expression? | Candidate | Malformed arbitrary candidates must return false |
| grammar/types.ss lexical-expression? | Candidate | Same recognition boundary for lexical syntax |
| runtime/types.ss parse-artifact-valid? | Candidate | Classification returns false; consuming methods require ParseArtifact |
| modules/types.ss graph-query-view? | Candidate only | Row/Id/Kind parameters are explicit; a malformed candidate still returns false |
| testing/types.ss parser-test-form-admitted? | Inspected reader/form data | Syntax inspection does not evaluate the supplied datum; name lists are List Symbol |
| modules/parser/graph-query-types.ss GraphQueryPredicateOf | Result only | Scheme true values include strings/member tails; Row input remains checked |
| build-support/types.ss BuildSpecification | Native option/metadata tail | Source names are String; std/make owns nested option/submodule payload semantics |

The emitted Rust =Guard::Any= string in rust-scanner.ss is an enum variant, not a
POO Type. SourceScannerStepOf, Graph accessors and GrammarIR contain no Any.

Scope/API checks (=t/library-init-test.ss=) and external native entry checks
(=t/library-build-entry-test.ss=) have distinct owners. Both retain total90/idle5;
the Source Scope owner declares its existing exclusive expander capability and
reports actual source reads/parses/evaluations through Ops. Timers, cached check
replays and unconditional heartbeat output do not count as progress. The Worker
pool remains two. Native entry tests clear inherited GERBIL_LOADPATH and validate
one noisy spec against the complete public/ABI requirements; the development
native inventory gate independently checks the ordinary spec.

The exact source association during native Make belongs to Core's existing
compiler-input owner. Its private dynamic source index preserves the selected
inputs while std/make temporarily changes the search path for timestamps. Byte
and package guards still run, and outside-owner/unselected sources use canonical
native lookup. No Gerbil/SDK edits or alternate build environment are required.

=parser-actor-support.ss= is the public facade for explicitly created local
Gerbil actors. Applications own worker count and lifecycle; imports start no
background service. =spawn-parser-actor= accepts an already prepared machine,
=parser-actor-parse= returns the same lossless artifact as synchronous parsing,
and =parser-actor-stop!= joins the worker. Timeout bounds reply waiting rather
than preempting an active parse. Keep the shared machine immutable after
initialization; actor scheduling does not change the LR algorithm.
* Language authoring

A language pack exposes three Scheme interfaces:

| File | Responsibility |
|------+----------------|
| =grammar.ss= | Declarative syntax and pinned grammar resources |
| =parser.ss= | Production POO Loader, metadata and parse entry |
| =parser-test.ss= | Development Loader, fixtures and declarative conformance tests |

Grammar sources and corpus files remain resources beside these interfaces.
Versions, contracts and source digests belong to metadata, not versioned module
names. Scanner implementations, parser state and C/Rust bridge code belong to
the engine.

For example, a small identifier language declares its syntax in =grammar.ss=:

#+begin_src scheme
(import (only-in :gerbil-parser/language-support/grammar deflanguage))
(export example-syntax)

(deflanguage example
  (syntax
    (lexical
      (root name)
      (lex (identifier Identifier (identifier)))))
  (rules (name (node Name (field value identifier)))))
#+end_src

Its =parser.ss= publishes the entry through the Loader:

#+begin_src scheme
(import (only-in :gerbil-parser/language-support/entry
                 deflanguage-parser-loader)
        ./grammar)
(export example-language parse-example)

(deflanguage-parser-loader example-language
  (grammar example-syntax)
  (parse parse-example)
  (slots metadata: '((language . "example")
                    (version . "v1")
                    (contract . "example.syntax.v1"))))
#+end_src

The Loader is a POO object. Inheritance, value overrides and extension contracts
are admitted before publishing the parse entry. Fixture values are ordinary
slots; the engine owns evaluation, catalog construction and service binding.
=deflanguage-parser-tests= constrains test declarations and checks acceptance,
lossless source, identities and structural expectations.

See the [[file:languages/README.org][language authoring guide]] and
[[file:docs/architecture/0018-downstream-language-products.org][downstream product guide]] for development Loaders,
POO extensions, fixtures and product generation.

* Execution and integration

| Product | Execution boundary |
|---------+--------------------|
| Scheme library | Prepared engine parser returns a lossless ParseArtifact |
| Independent Rust AOT | Generated immutable scanner/parser tables run in the generic Rust runtime; no Scheme VM at request time |
| C ABI and Rust FFI | A reusable Gerbil runtime and language handle execute Scheme parsing; Rust owns result buffers and borrows indexed views |

Parse artifacts preserve source text, syntax structure and spans, with source
and grammar identities. The artifact is the shared publication boundary for
traversal and downstream tooling.

The language-independent C ABI initializes the runtime once and reuses handles
across requests. Its optional Rust Tokio integration queues requests to a
persistent Scheme owner thread. Applications own queue limits and lifecycle.
See [[file:rust/gerbil-parser-ffi/README.org][Rust FFI and Tokio ownership]] and
[[file:rust/gerbil-parser-artifact/README.org][Rust artifact admission and navigation]].

Independent AOT uses the same admitted Grammar/Parser IR through a separate
product gate. It does not automatically support every Scheme source parser or
POO policy. See [[file:docs/architecture/0006-rust-aot.org][Rust AOT design]] and the
[[file:t/fixtures/runtime-record-assignments/README.org][standalone record-language consumer]].

* Bounded package diagnostics and failed-product custody

The strict writer retains two workers and a2GiB maximum, with no180-second
build cutoff. Elapsed time is measured, never treated as an admission receipt.
=COMPILER-INTERFACES= retains real completed imports and now reports cumulative
admission and reporting cost. =COMPILER-COST= reports the union of active evaluation intervals
without counting nested or concurrent evaluations twice. The fields are diagnostic and are
not an additive cost partition, admission receipt or liveness heartbeat.
Checks still precede imports; compiler values/exceptions and trace restoration
are preserved. The direct source API control passes; the latest four-module
source-contract attempt reaches its120s boundary without completing and is not
reported accepted. Complete native/CI validation remains required.

On strict failure, the original status is retained. A separate bounded custody
action records source/revision metadata and archives installed lib/bin/products,
excluding checkout credentials and Gerbil files. The failure archive has no prepared
restore identity and cannot be loaded by the prepared-products restore action.
The always-run CI log artifact also retains these failed products. Archives and
raw logs remain execution artifacts, never source-control or reuse credentials.

Compiler cost counters use short locks around updates only; no lock is retained
across an importer, evaluator or output operation. The crossed-worker synthetic
control keeps the trailing active interval after the first worker returns.
