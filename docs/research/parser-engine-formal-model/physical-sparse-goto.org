#+title: LR construction lifecycle: paper, source and model

* Paper and implementation boundary

The closure and goto definitions in [[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing]], Section 2.2,
are the semantic target. The implementation uses raw production records,
a dense core-symbol vector, interned symbol IDs and sparse bit masks. This
composition derives group meaning and layout bounds from those representations;
it does not require a final group-correctness certificate.

* Constructed representation

[[file:../../../formal/ParserEngine/PhysicalOperandExtraction.lean][PhysicalOperandExtraction]] projects actual operand base fields, discarding
annotations and actions. Induction over the native vector-write recurrence
proves every bounded read, including the untouched completed slot, equals the
constructed grammar's after-dot symbol. A fresh zero-filled vector is required.
[[file:../../../formal/ParserEngine/PhysicalCoreExtraction.lean][PhysicalCoreExtraction]] inverts arbitrary physical addresses and proves that
a symbol-bearing core advances to address plus one inside the same production.
Duplicate semantic productions retain separate physical addresses.

[[file:../../../formal/ParserEngine/PhysicalSymbolDiscovery.lean][PhysicalSymbolDiscovery]] derives the nonterminal discovery stream from the
physical vector. [[file:../../../formal/ParserEngine/SymbolDiscovery.lean][SymbolDiscovery]] separately constructs terminal and nonterminal
symbol IDs from an empty registry and proves index injectivity. Completed slots
contribute neither kind of symbol; terminal and nonterminal namespaces remain
distinct even when their numeric payloads agree.

* Sparse groups and publication

[[file:../../../formal/ParserEngine/SparseGroupMasks.lean][SparseGroupMasks]] follows accumulation, own/shared mask union and the
skip/merge recurrence. Its membership theorem identifies the origin of every
output bit in either the kernel or prediction items. [[file:../../../formal/ParserEngine/SparseGoto.lean][SparseGoto]] combines this
origin with physical symbol discovery and bounded advance. Every returned mask
is bounded without a caller-supplied bound; every decoded target is exactly a
paper goto-kernel item from the generated closure.

[[file:../../../formal/ParserEngine/KernelConstruction.lean][KernelConstruction]] starts at augmented physical core zero and derives
bounds for every successor in its construction history. Composing group meaning,
registry publication and the concrete closure factory gives the target closure
of each returned symbol/target pair. The theorem quantifies over arbitrary
grammars, histories, masks and published groups, rather than a fixture catalogue.

[[file:../../../formal/ParserEngine/SparseGroupSource.lean][SparseGroupSource]] independently describes the complete native symbol-catalog
and sparse-group declarations. The existing source extractor generates both
witnesses, and Lean rejects a declaration mismatch. Its checked adapter exposes
the proved mathematical group implementation only after schema equality.
Source equality identifies the supported procedure; it alone is not a proof of
arbitrary Scheme execution or of all mutable primitive behavior.

* One construction contract

The public model entry is [[file:../../../formal/ParserEngine/ConstructionProtocol.lean][ConstructionProtocol.construct]]. It starts at the
augmented dot-zero kernel and returns registry validity, complete published-row
ownership and an exhausted queue. Consumers use =complete= and =paper_target=;
they do not assemble local certificates for an arbitrary final table.

#+end_example

This is a maintained contract map, not a diary of proof additions. A producer
change must preserve its output law and revalidate the named consumer. The
existing source generator checks complete declarations, the axiom audit imports
the public entry, and model-input discovery binds the native fixtures and this
topic to qualification. A theorem or an added file alone does not close a row.

* Sorting and borrowed storage

[[file:../../../formal/ParserEngine/DiscoveryOrder.lean][DiscoveryOrder]] proves first-occurrence order for arbitrary sorted physical
core streams and repeated symbols. [[file:../../../formal/ParserEngine/GroupOrder.lean][GroupOrder]] derives template order from
production offsets, proves the actual accumulator/skip/merge order and shows
that equal earliest addresses identify equal rows. Any sort with the ordinary
sorted-permutation contract therefore gives the same own rows; stability and
a particular sorting algorithm are unnecessary.

[[file:../../../formal/ParserEngine/GroupScratch.lean][GroupScratch]] follows the native zero-test, first-slot write, bit insertion,
touched-list insertion and cleanup. The touched list is a permutation of the
constructed keys. Every selected first slot is initialized before use and then
retained. Cleanup restores every mask to zero while leaving first slots stale.
=native_group_call= combines these mutable facts with sorting and sparse merge,
proving equality with the group producer consumed by the goto proof.

* Complete queue and publication

[[file:../../../formal/ParserEngine/ConstructionQueue.lean][ConstructionQueue]] models dequeue before discovery, processed-count
increment and interning/enqueue of novel kernels. The FIFO invariant identifies
pending IDs with the exact unprocessed interval. The finite physical kernel
universe minus processed states strictly decreases each nonempty iteration.
This is a termination bound, not a practical estimate, timeout or test fuel.

[[file:../../../formal/ParserEngine/ConstructionRows.lean][ConstructionRows]] proves that each processed ID owns a complete row.
Later interning preserves source and target IDs. Exhaustion publishes every
discovered state. =paper_target= composes the final table with generated
prediction, physical extraction and paper goto/closure for every final edge.

* Ordered bit traversal and LeanPoo consumption

[[file:../../../formal/ParserEngine/BitTraversal.lean][BitTraversal]] proves that =rest & (rest - 1)= removes exactly the least
selected bit, including arbitrary-precision borrow chains. The direct loop
terminates and produces a strictly ascending list with exact bit membership.
The field loop finishes each local traversal before advancing its offset. Empty
fields and a partial final field preserve that order. Aligned start and integer
length bounds derive the same complete callback list as the direct loop for
any positive field width. Population-count accuracy affects branch selection,
but either selected branch has the same callback sequence.

The relational =DirectRun= and =FieldRun= rules describe recursive source
control flow without assuming final sortedness. Their soundness laws derive
the sequence above. [[file:../../../formal/ParserEngine/BitTraversalSource.lean][BitTraversalSource]] independently checks the complete
traversal declaration and the SDK-derived field-width binding, including the
fixnum loop, direct loop, field visitor and branch arithmetic. Reordering the
callback and clear operations or changing offset advancement invalidates the
source witness. The reader handles both procedure and value declarations.

[[file:../../../formal/ParserEngine/TraversalCapabilities.lean][TraversalCapabilities]] reuses the pinned LeanPoo APIs instead of defining
another family/certificate mechanism:

- =Requirements.certify= retains direct, field and selected factories with a
  joint equality contract at the exact mask/width context.
- =Certified.entails= derives ordered callbacks while retaining those factories.
- =Certified.project= narrows the family to the selected capability.
- =Certified.consume= constructs the proof-aware callback interface. It applies
  the selected factory, not every strategy in the broad proof family.

Pure integer/loop proofs remain mathematical functions. Capability retention,
contract consequence, projection and consumption use LeanPoo. Existing parser
preparation also uses LeanPoo Requirements and lookahead uses DictionaryBridge;
this adds the same contract discipline to construction traversal.

=callback_cores= derives equality with the grammar's physical =coreItems=.
=traversedGroups_exact= substitutes the selected callback sequence into scratch
accumulation, and =traversal_tick_exact= connects that producer to append/enqueue
and publication. Finally, =traversal_finish_exact= proves equality of the entire
terminating queue drain with the canonical construction. Classification and
population are functions of each mask, so a run may switch traversal paths
between states. This is a consumer
connection, not a certificate attached to an unused traversal implementation.

The external primitive boundary states the ordinary meanings of first-set-bit,
integer-length, extraction, bitwise arithmetic and a positive SDK field width.
=least_unique= relates a primitive satisfying the least-bit specification to
the model. Source execution explicitly requires zero to classify as a fixnum,
so it never admits a nonzero-path first-set-bit invocation on an empty mask.
It neither inspects nor rebuilds Gambit. Normal callback order can
be consumed by any order-sensitive fold; native controls separately exercise
nested callbacks and immediate exception propagation.

* Cache ownership in the unified construction

[[file:../../../formal/ParserEngine/CachedConstruction.lean][CachedConstruction.construct]] executes the combined construction model.
It threads one initially empty grammar-owned cache through initial installation,
novel kernel interning, ordered transition publication and the terminating FIFO
drain. It also consumes the selected LeanPoo traversal capability in each group
call. =construct_exact= identifies the whole resulting machine with
=ConstructionProtocol.construct=, so its complete-row and paper goto/closure
contracts apply without a supplied final-state semantic certificate.

The cache key is the aggregate prediction mask, not the kernel mask or state ID.
[[file:../../../formal/ParserEngine/TemplateCapabilities.lean][TemplateCapabilities]] retains the fetching factory through LeanPoo
=Requirements.certify=. Its joint contract includes both exact template data and
validity of the next cache. =Certified.consume= uses those data to build the
kernel-specific closure and next cache. Hits share predictions, never the complete
closure of distinct kernels. The grammar indexes the retained factory/cache;
there is no cross-grammar reuse or label-only admission.

=build_stored= proves installation at the requested aggregate key and
=build_retained= preserves earlier entries. =construct_covered= carries cache
coverage through the complete queue. [[file:../../../formal/ParserEngine/PlanStorage.lean][PlanStorage]] now gives the retained data
an explicit representation: a directory maps aggregate masks to logical object
references; objects hold immutable templates; physical plan slots contain
=(kernel, reference)= pairs. A miss allocates the next fresh reference, while a
hit retains its reference. =fresh_separates= and =objects_retained= exclude writes
to previously reachable objects. =shared_reference= proves that equal prediction
keys in different plan slots refer to the same object.

=decode_install= derives a new plan's decoded template. =decode_other= proves
that installing another plan preserves older pair/reference reads, including
when allocation occurs. The bounded =vectorize= producer and =vector_decode=
connect plan slots to vector indices; =grow_decode= composes prefix copying with
reference dereference. The addresses are logical identities, not numeric claims
about host pointers or GC placement.

The LeanPoo factory now constructs that memory operation. Its joint certificate
contains exact template data, validity of the next memory and the exact install
operation. =Certified.consume= uses the memory validity evidence to construct the
next owned cache. =construct_aligned= derives agreement of every installed plan
with the canonical grammar factory through initial installation, every target
append and the complete queue. The queue reads =Cache.readTemplate= by following
the physical plan reference and supplies the returned template directly to
=runGroup=. It does not substitute a key-catalog read or rematerialize a template.

The same owned cache carries scratch masks, firsts and touched order. =runGroup=
scans that actual preceding state and resets its touched masks before returning
it. =tick_scratch= proves that subsequent target installations and publication
preserve precisely that returned scratch; =publish_scratch= derives the frame
law for an arbitrary number of targets. Firsts remain stale by design, but their
values now come from the preceding scan rather than an externally supplied
function. =runGroup_memory= proves the converse frame: scratch operations retain
all template objects and physical plan slots. The source's fresh vectors and
immutable template layout justify their separate model fields; host allocation
and alias encoding remain explicit premises, checked by native identity controls.

The native three-slot template also has a group hash index. Its physical hash
operations are represented extensionally by the ordered rows; their primitive
implementation remains external. =source_current= independently checks the
complete builder, materializer and aggregate-key cache declarations. Source
admission is separate from the universal representation and lifecycle proofs.

LeanPoo's =ContextSlot= is deliberately not used: it retains only one context,
whereas this builder retains multiple aggregate masks. =ConstructionCache=
materializes dependency graphs; the LR prediction dependency graph has already
been completed before this cache is constructed. Reusing either with a different
lifetime or key protocol would misrepresent the source. Capability retention,
joint certification and proof-aware consumption reuse LeanPoo directly; mask
arithmetic and FIFO induction remain ordinary functions and proofs.

** Maintained obligation map

| Obligation | Producer and consumer evidence | Boundary |
|------------+--------------------------------+----------|
| Paper prediction, closure and goto | =PredictionMaterialization=, =PublishedClosure=, =ConstructionProtocol.paper_target= | Arbitrary constructed grammar; physical production identity retained |
| Ordered direct/field callbacks | =TraversalCapabilities.callbacks= consumed by =CachedConstruction.runGroup= | Integer primitives and positive SDK field width |
| Sparse order and scratch lifecycle | =groups_exact=, =runGroup_memory= and =tick_scratch=; persistent native vector controls | Prior scan supplies firsts; touched masks reset before reuse |
| Aggregate-key cache lifetime | =construct_covered=, =cache_hit=; native object identity and factory counts | Per-builder grammar/layout; no cross-builder admission |
| Physical plan/reference reads | =decode_install=, =decode_other=, =grow_decode= and =construct_aligned= | Logical references; primitive pointer/vector encoding external |
| Interning, FIFO and final rows | =construct_exact= and returned =Product= | Hash equality and queue primitives |
| Source authority | Complete independent declaration schemas and fresh extraction; forwarding native execution | Restricted schemas, not a general Scheme execution theorem |
| Compiler, GC and host memory | Explicit external premises | No Gambit modification or build; no native compiler correctness claim |

This table is the integration checklist. Adding an isolated theorem does not
close a row until the complete constructor consumes its evidence and a native
control exercises the corresponding source boundary. The combined model now
closes cache population, reference/plan decoding and the persistent scratch
lifecycle. Concrete pointer encoding and primitive host realization remain
explicit premises. No runtime performance claim follows from this map.

* External premises and remaining source boundary

These are universal algorithm-level lifecycle proofs. Ascending callback order
is now derived from the direct/field recurrence and supplied through LeanPoo's
selected capability to the complete queue. It is no longer an unproved parser
enumeration premise. The remaining boundary is primitive arithmetic/storage
semantics and their host/compiler implementation.

The restricted schemas
identify complete supported Scheme declarations; forwarding native observers
execute those declarations. They are not a universal Scheme interpreter.
Concrete heap/vector/hash/queue primitive implementations and compiler lowering
remain external; the host sorting premise is explicitly sortedness plus
permutation. Source equality and finite native agreement do not establish
arbitrary native execution. The construction contract is the integration
boundary for subsequent work; remaining representation-to-host simulation must
not be presented as an algorithm theorem. Gambit is neither modified nor built.
No runtime performance optimization or CPU claim is included.
