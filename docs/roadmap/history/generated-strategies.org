* Generic POO fused reductions and Loader build slots — 2026-10-05

The HCL fused reduction producer is now the reusable engine
=FusedReductionStrategy.= prototype, exposed by =language-build-support.ss=.
It derives actions from a descriptor's exact Parser IR and admits the complete
production/action algebra before emission. POO inheritance supplies effective
binding names and metadata; stale digest, invalid names and foreign descriptor
bindings fail admission. No generator branch selects a builtin language.

HCL and Arithmetic both declare =fused-reductions= in their public Loader
=build-strategies= slot. The Loader contract checks unique declared names and
exact descriptor identity. Empty strategies remain the default for other
languages; the existing Loader schema version is unchanged. All build work is
outside source parser dispatch.

The HCL generated step moved to =src/compiler/hcl-reductions.ss=, and the old
benchmark generator was deleted. CI uses =scripts/generate-reductions.ss= with
the grammar's module identifier. A second generated native fixture is produced
from Arithmetic's actual IR through the same engine. Existing event tests and
incremental benchmark imports follow the new engine product path.

Seven independent native controls cover deterministic interleaved generation,
POO names/metadata inheritance, stale and malformed overrides before any output,
Loader duplicate/foreign binding rejection, both languages' full artifact parity
in recognition and event program backends, and malformed-source rejection.
They compare against the indexed runtime without replacing installed routes.

The initial generator compiler run rejected an unimported list utility; the
name check now compares the three slots directly. Two initial test runs caught
binding-group/closing-parenthesis errors and remain failures. Initial plain
script launchers hit the unchanged five-second idle gate after imports; those
receipts were not admitted. The producer was exercised through the existing
native child harness with explicit main-return/exit propagation, using module
identifiers rather than repeated source imports. No timeout was widened and no
compiler/profile was replaced.

This closes fused reduction generation and HCL step ownership. The remaining
HCL recursive generator and its fast lexical/source corridor must become a
separately admitted reusable strategy; moving those HCL assumptions into a
nominally generic module would not establish reuse. TLA+ scanner/proof policy
and Bash source/word state remain the following runtime convergence work.

* Common POO build protocol across provider kinds — 2026-10-05

The previous registry admitted only =FusedReductionStrategyContract= and called
its emitter directly. That restriction is replaced by =BuildStrategyContract=
and =emit-build-strategy=. Identity/digest/metadata/target checks now live in the
common prototype; concrete providers refine admission. The Loader has no
concrete backend import and no language/kind dispatch branch.

Both HCL and Arithmetic now declare fused Scheme reductions and canonical
Rust output through the same =build-strategies= slot. Rust output is
produced by the existing producer; its source and portable-policy gates remain
unchanged. Public recipe values remain ordinary POO inheritance/override values,
and the Loader schema remains v2.

Eight controls cover two languages and two real provider kinds, exact canonical
Rust output, renamed downstream declarations and inherited metadata, registered
writer dispatch despite a recipe method override, provider/target/digest forgery
rejection, additional constrained engine recipe/format registration without
changing common dispatch, foreign-descriptor rejection and Scheme/Rust policy
admission differences. The extension control also checks eight actual parser
calls cause zero extra provider admission or emission invocations.

The first consumer compiler attempted to load the provider's generated macro
SCM before its native phase product existed. The next consumer used a cached
facade export set; after moving the convenience method out of the Loader, that
old interface referred to a removed internal export. The specific generated
facade interface/optimizer files were saved and rebuilt, then consumed in a
fresh compiler process. These failed phases remain failures; SDK/GCC and bounded
native gates were retained. No package uninstall, compiler switch or timeout
extension was used.

This establishes a common constrained POO capability protocol and two real
implementations. It does not close HCL recursive/source strategies, TLA+ policy
portability, Bash word/source scanning or the three-file language layout.

* HL7 scanner removal through shared closed header rules — 2026-10-05

Removed =languages/hl7/scanner.ss= and all six language-owned external callback
references. HL7's concise grammar now declares shared =header-delimiter= and
=header-data= operations. The lexical algebra validates their prefix/count/index
or stop data; execution now belongs to =src/runtime/lexical-source.ss= and the
Rust lexical engine. The count is bounded to 1..32 and headers require distinct non-alphabetic,
non-numeric delimiter characters. The engine compares/borrows source characters
without constructing delimiter lists or hash tables. At this scanner-removal
baseline, header validation still occurred per lexical-rule invocation. The
request-owned preparation described below supersedes that execution path; no
measured speedup percentage is claimed.

The second actual POO Loader is a test language with prefix ="記"=, two dynamic
separators and =";"= stops. It parses accepted/rejected sources with the same
engine operations. This is an independent language declaration used as a reuse
control, not a second production language pack. POO metadata extension preserves
its descriptor-bound identity. No old HL7 entry alias or external fallback is
retained, and Loader/IR schema identifiers are unchanged.

The common Rust build strategy emits both complete specs from canonical Scheme
IR. Rust executes the real HL7 ADT A08 corpus, a custom-delimiter message,
and the independent record sources; malformed header recipes reject at spec
admission. The two generated source files are executable compiler witnesses,
not benchmark/result snapshots. CI compiles the Scheme declaration, regenerates
both Rust files with required per-product markers, formats them and compares
exactly. The existing Rust workspace gate runs the new native controls.
