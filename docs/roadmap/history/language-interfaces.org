#+title: Historical language interfaces receipts

This module preserves prior design and qualification records. Its status notes
are historical; the active execution plan is [[file:../0001-versioned-language-pack-closure.org][the convergence plan]].

* Three-interface language pack contract

Every language converges to =grammar.ss=, =parser.ss= and =parser-test.ss=.
=parser.ss= is the only public entry. Grammar identity, upstream digests and
corpus declarations stay with =grammar.ss=; the loader binds their values to
POO metadata and fixture services. No separate =source.ss= or =fixtures.ss=
authoring module is required. Test consumers import the public entry.
Upstream grammar/corpus resources remain source files, not Scheme interfaces.

Pure declaration consolidation removes seven extra modules across arithmetic,
HCL, openCypher, FHIRPath and GQL. It changes neither language identity nor
loader schema. FHIRPath and openCypher have three Scheme interfaces after this
step. The other languages still contain execution or specialization modules;
they need the shared-engine migrations above before this contract is closed.
File consolidation alone does not qualify portable Rust/C execution.

** Native verification of declaration consolidation

BNF when the public loader is loaded. The actual new native openCypher product
contains =iso-bnf-source-from-datum=, with no BNF parse call at that binding.
Full catalog field parity and malformed materialization controls passed.

* Shared closed regions and Bash caller migration — 2026-10-05

The first step of the whole Bash migration now has production callers. The
public =defregion-plan= accepts stop values, quote escape/scope values and paired
region values. =languages/bash/grammar.ss= declares the actual Bash plan;
=scanner.ss= and =word.ss= consume the engine matcher. The 103-line procedural
=scan-words.ss= and all its imports are removed. This is generic region
execution, not a language-name dispatch or a copied Bash scanner under =src/=.

The engine prepares and owns a copied plan and operator trie once. It traverses
with one forward cursor and explicit frames rather than recursively invoking
region scanners. Longest declared openers select arithmetic expansion before
command substitution; process substitutions shield overlapping operator stops;
quotes constrain visible nested regions. Initial-stop consumption is explicit
so transitional marker scanning retains its existing behavior. The closed
=region-word= operation is additive within Scanner IR v1; loader schema stays
=gerbil-parser.language-entry.v2=.

The existing Scheme producer emits the Rust region tables and nine source
traces. Its final native output is byte-identical, after rustfmt, to the checked-in
Rust fixture. The Rust executor admits the same scalar-depth constraints and
uses explicit frames with UTF-8 byte offsets. No Scheme callback executes in
that consumer.

Fixtures are now declarative values in Bash =grammar.ss= and the unchanged

* Constrained parser-test syntax — 2026-10-05

=deflanguage-parser-tests= is now the public test declaration through the
=language-test-support.ss= facade. It admits the POO Loader with the existing
=LanguageLoaderContract=, evaluates the Loader once, and uses its effective
=.parse= and named fixture-test service. Syntax rows own source/expected values;
the engine owns evaluation and artifact validity/status/roundtrip/digest checks.
Node/token membership, node counts, absent nodes, diagnostics, exact AST fields
and byte spans, and projection values are typed clauses. Property extensions
have explicit bindings and equality assertions; arbitrary test-case statement
bodies, unknown sections and empty properties are rejected during expansion.
Duplicate labels also reject before publishing a suite.

Bash's two source-digest admission and UTF-8 checkpoint tests moved intact to
=t/language-source-contract-test.ss= because they exercise engine contracts.
The regression corpus, ordered marker/body checks, word/node kinds and rejection
inputs were preserved. Tests now additionally check valid lossless artifacts and
source digests for every ordinary syntax row, including rejected source rows.
No parsing implementation, schema, dependency or backend selection changed.

Native GCC-compiled test support qualified all five migrated consumers. Bash,
Arithmetic, HL7 and FHIRPath bounded runs completed in 5.19, 5.08, 4.55 and 4.11
seconds respectively. Engine controls cover ten expansion-time negative forms,
single Loader/source/parser evaluation despite multiple expectations, macro
hygiene, and effective inherited fixture override. Records and the retained
source-contract controls also pass. These are qualification timings from
concurrent runs, not performance comparisons.

The first native support import failed because its newly emitted macro module
had not yet been compiled. The first consumer batch exposed an empty generated
=let= for syntax rows without extra structure expectations and one unmatched
Arithmetic source delimiter. Both source defects were corrected; the exact
failed logs remain separate from passing reruns. No timeout was relaxed and no
interpreter/toolchain fallback was used. Full migration of the remaining
advanced suites is still an open owner obligation; a bare suite wrapper is not
accepted as completion.

* Advanced graph-query tests and TLA+ layout migration — 2026-10-05

GQL and openCypher now use only the public test facade and their =parser.ss=
entry. Their local CST walkers, metadata/IR access helpers, token-driving loops,
source generators and raw test-case bodies have been removed. Existing pinned
identities, Parser/Bound IR counts and ordered references, compatibility and
precedence overlays, digest prefixes, syntax sources, corpus structure and
rejection controls remain declarations. GQL's selected comparison operands
must retain their order; an additional reversed-operand query must fail.
openCypher retains 1,317 states, 321 fork cells, absent nullable-prefix helpers,
initial shift checks and the actual 300-item LR receipt with zero speculative
branches and one completion.

TLA+ layout's eight controls migrated to =parser-test.ss=; the old
=layout-test.ss= was removed and the native suite owner/build exclusion updated.
Field cardinality, source ordering, CRLF/tab layout, nine concurrent requests,
fresh/incremental artifact equality and disabled recovery rejection all remain.
Parallel scheduling and source-bound result selection belong to the engine;
all workers join before a captured parser exception propagates. Incremental
text selection uses the shared prefix matcher and converts character positions
and deletion lengths to UTF-8 bytes. A Unicode HCL control exercises both a
multibyte prefix and a multibyte replacement.

* HCL strategy and corpus test execution migration — 2026-10-05

HCL's 27 raw cases migrated to 29 =deflanguage-parser-tests= declaration rows.
The two added rows split the numeric boundary/generated-source checks and the
Loader identity check; no former obligation was removed. =parser-test.ss= now
imports only the public test facade and =parser.ss=. It has no local function,
LR checkpoint loop, CST walker, random state, thread, scanner execution callback
or free-form test-case body. Its source literals and five seed streams retain
the original input ordering, string/comment terminators, number bounds and
Unicode values. The 1,024-line attribute sources, two 256-block label variants,
256 nested blocks and 128 compact lines keep exact indexed-reference artifacts.

The engine's =language-strategy.ss= owns the ranked/indexed reference driver,
closed source template interpreter, named generated recognizer routes, lexical
parity and fast/fallback admission counts. The =native-test-profile= Loader slot
is an ordinary extensible POO value. =LanguageLoaderContract= checks its profile,
exact machine digest, source procedure identity and declared lexer procedure.
The profile is optional; arbitrary recognizers do not acquire recursive-source
parameter semantics merely by having a parse entry. This uses the existing
=language-entry.v2= schema and adds no per-call runtime admission.

Seven engine controls independently compare all 1,024 sources from the original
five port-writing generators, require one lexer call per coverage input, admit
an effective inherited profile and reject a stale digest, foreign recognizer,
unknown profile, absent lexer or profile for another grammar. The public macro
now rejects 35 malformed declaration forms, including unknown/duplicate routes,
invalid bounds, unknown bindings and incomplete coverage obligations. Coverage
uses the candidate lexical result once rather than running the scanner again.

limits. Native compiler phases retain 90/30 limits. These times are qualification
