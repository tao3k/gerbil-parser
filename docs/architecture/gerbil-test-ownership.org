#+TITLE: Gerbil Test and Build Ownership
#+LANGUAGE: en

* Execution boundary

CI and development commands invoke gerbil test and gerbil build. A test module
publishes Suite, Case and Fixture values. It must not launch another test round.
Process fixtures which exercise a product subprocess or the compiler's stream
API are different subjects; they do not select or execute test suites.

Core already publishes TestingScript, module-test-file-source,
module-test-execution and Fixture lifecycle policy. Use those existing facilities
when a selected Module requires source admission or resource policy. Do not
invent a Parser equivalent, synthetic source guard, evaluator launcher or harness.

* Removed responsibilities

- compiler-policy-output and its generated gxi expressions, data files and forced
  child exit are removed. Two policy Cases live in t/fixtures/compiler-policy.ss,
  explicitly executed by the CI/development native test command.
- test-suite.ss, suite-runtime.ss, private Worker scheduling/affinity/exclusivity
  fixtures and execution metadata are removed. Ordinary declarations lower to
  native std/test values; the native harness owns discovery and execution.
- run-observed-sdk-tests! no longer wraps gxtest in a Parser function. Preparation
  no longer deletes test interfaces to force a private source execution route.
- CI and development source-test callers use gerbil test. The native build.ss
  still declares the actual Core/std-make projection; no new builder is added.

* Native inputs and policy

Native qualified test imports require the package's source parent in
GERBIL_LOADPATH, or correctly compiled dependencies. A checkout whose leaf is
not gerbil-parser must not be concealed by a custom module loader. Use a normal
checkout/worktree with the package name and the existing native package prefix.
This is source-layout alignment, not a second compiler environment.

Compilation remains configured for two workers and its existing2GiB heap. The
native complete test entry retains the existing3GiB process ceiling. The three
modules with Core-profiled Cases declare native test-setup!/test-cleanup! Fixture
hooks which select the same shared-process Case heap ceiling; Core continues to
own duration, growth, sampling, cancellation and failure policy. The existing15-minute full-entry wall limit remains. Native gxtest has
no Worker option; do not emulate one in Parser. Historical shared-Worker and
per-Worker90/idle5 results are archived, not relabeled as native harness results.
External product/process idle controls remain at their existing owners.

Native gxtest loads selected modules before reporting the harness. Applying the
old dispatcher's output-idle rule to that pre-harness phase refuses cohorts108
and110, even after standard Suite compilation. Those refusals are retained;
no heartbeat/preloader is restored. Native total deadlines and explicit final
OK/error admission apply at CI/development entry boundaries.

* Complete executor removal
Ordinary tests and research fixture tests only declare Suites, Cases and Fixtures.
No Parser test module calls test-suite!, test-run! or constructs TestHarness.
The private conformance Suite executor, timer threads, manually linked Engine/
event-fold runners, research Suite launchers and runtime-organization harness are
removed. Existing development recipes invoke gerbil test against those original
Suite modules. Compiler/product subprocess Fixtures remain SUT execution, never a
second test/build harness. Research standalone programs have a separate entry and
retain their existing process budgets; they no longer embed semantic Suite runs.

The former conformance import/export/Suite partition validator and duplicate
Suite catalog are removed. Native Gerbil discovers exported Suite values. The
remaining build catalog selects helper compilation and research Suite inputs; it
does not reimplement module discovery, test execution, Case policy or scheduling.
The old conformance runner success/failure/timeout receipts are historical only.
Native failure controls must be invoked from development/CI and rejected using
actual harness diagnostics plus final OK, since process exit zero alone is not
sufficient for native Gerbil test acceptance.
