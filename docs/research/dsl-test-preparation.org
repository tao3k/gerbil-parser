#+title: Shared test runtime and preparation ownership
#+date: 2026-10-09

Part of [[file:dsl-engine-contracts.org][the integrated DSL and engine study]].
Existing dated receipts retain their original revision and scope.

* Implementation: single-runtime Scheme test preparation and Workers

The Scheme Suite entry starts one =gxi=. A single preparation owner admits the
native FFI dependencies and expands each source test module once before any
Suite executes. Its loaded-module and interface caches survive the whole run.
The runtime must finish module initialization before Worker execution; runtime
loading and source expansion are not concurrent test jobs.

=GERBIL_TEST_CORES= configures the bounded Scheme Worker queue. CI selects two
Workers with a shared 3 GiB heap budget. Loading the full source suite exceeded
the previous 1 GiB budget before execution; this budget covers all loaded modules
and both Workers. The inherited POO Case profile uses the same absolute heap
cap because its sampler measures process-wide memory; its growth, sampling,
failure, and duration policies remain inherited unchanged. Each module owns its
=std/test= harness and thread-local test parameters;
shared-runtime barrier controls require two modules to rendezvous in one process.
Modules may export a symbolic =test-worker-affinity= for runtime thread ownership.
Declared owners execute on the same persistent Worker; independent modules use
the shared queue. The output supervisor never moves a test onto another thread.
Failures stop new admission, join active Workers, and return a failing status.
The original five-second silence and ninety-second module budgets remain;
preparation time is deducted from the execution budget. A timed-out thread ends
the runtime rather than continuing with partially mutated state.

The conformance build has one content-admission owner. Its S-expression receipt
covers project sources, dependency products/sources, SDK, compiler/environment,
and the native executable plus loadable helpers. SHA-256 and file modes are
checked, failed or input-mutating builds cannot publish a usable receipt, and an
OS file lock releases on exit. Source-only test interfaces removed by
=prepare-gxtest!= are deliberately outside the retained output identity.

CI restores an isolated conformance product store. Only an exact content match
can copy its declared executable/helper products into the working library;
dependency/package cache restoration remains a separate owner. Scheme controls
exercise unchanged inputs, changed/corrupt/missing products, corrupt receipts,
failed preparation, store recovery/corruption, and mutation during preparation.
These changes remove repeated process startup and unchanged preparation work;
no end-to-end speedup is asserted without a matched complete-call measurement.

* Implementation: disjoint compiled and source execution ownership

The compiled conformance semantic entry runs every declared Suite in one process,
checks Suite object identity for repetition, and enforces the original ten-second
budget for each group. The outer supervisor retains its five-second idle fence.
Research commands with process-owning entrypoints remain separate.

=scripts/test-plan.ss= compares the build catalog, imported Suite names and actual
Suite execution declarations. Missing owners, omitted Suites and repeated execution
fail admission. Following a successful compiled gate, CI passes
=--remaining-conformance= to the source runner. Fully covered modules are excluded before
source preparation; the remaining modules share the existing runtime and Workers.
The default source runner still qualifies every source module when requested.

GQL support is compiled as one union for local diagnostics, while CI consumes the
products of its prior preparation owners. Missing products fail before execution.
Workspace Rust qualification includes its source-policy integration test, so CI
no longer pays for a separate invocation of that same test.

Compilation also compares each module's actual phase-zero =-test= exports with
its imported conformance Suites. Public expander metadata is inspected with
runtime evaluation disabled. This catches additional exported Suites even when
all handwritten import declarations are internally consistent. Current-head
source-versus-compiled Case names are compared before admitting the partition.

Source-only Suite declarations cover genuine source admission boundaries. The
SANY closure Suite needs dynamic module loading for its portable-build rejection
control. It runs in the source runtime; other Suites from the same file run in the
compiled runtime. Declared ownership has a complete union and an empty intersection,
checked against actual exported Suite names during compilation. Source selection
uses the same validated ownership and does not repeat the compiled Suites.

Python process/compiler controls run once per Scheme CI platform. Ubuntu coverage
is retained there; the Rust-only Ubuntu job no longer repeats the same discovery.
macOS controls remain separate platform evidence.

The old =t/versioned-language-pack-test.ss= forwarding module is removed. It had
no Cases of its own and re-exported language leaf Suites already discovered from
=languages=. Source admission now requires each test binding to belong to its
module and each Suite object to have one owner. Re-exporting leaf Suites or
admitting one Suite object twice fails instead of multiplying execution costs.
