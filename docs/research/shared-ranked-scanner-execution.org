* One argument from declaration to complete product

This is the integration entry for lexical specialization, prepared execution and
performance evidence. Its four responsibility modules preserve the original
experiments; they are parts of one implementation sequence, not separate author
interfaces or optimization roadmaps.

The sequence is =grammar.ss= -> macro expansion and POO composition -> canonical
IR -> compiler publication -> prepared machine -> =parser.ss= request -> canonical
artifact -> =parser-test.ss= qualification. Static decisions belong to preparation;
request values and mutable execution state belong to the request. A cheaper
component is not sufficient evidence for a cheaper complete product.

* Scheme witness

#+begin_src scheme
;; Authors declare a grammatical value; preparation derives immutable execution.
;; This is an illustrative ownership boundary, not another public DSL slot.
(let* ((declaration '(literal "λ"))
       (execute (prepare-matcher declaration)))
  (values (execute "λx" 0 #f)       ; => 1
          (execute "xλ" 0 #f)       ; => #f
          (execute "xλ" 1 #f)))     ; => 2

;; Scientific admission consumes the complete observation and its controls.
;; A component allocation result cannot imply complete-request CPU improvement.
(equal? candidate-artifact reference-artifact)
#+end_src

** Question: why does this exploit Scheme beyond S-expression notation?

The inspectable declaration gives the engine a static value to admit and lower.
Hygienic syntax retains caller bindings; lexical closures capture prepared data;
POO composes extensible declarations and policies; structural matching handles
closed IR alternatives. Their responsibilities are explicit. Authors need no
matcher cache, dispatch loop, opcode, storage visitor or measurement reader in
=grammar.ss=. The detailed studies show where these mechanisms helped and where
additional abstract calls or traversal transfers were rejected by execution.

** Question: how is the design scientifically justified?

The [[file:shared-scanner-staging-and-fusion.org][paper-to-engine argument]] states the assumptions of staging and fusion.
Independent token/field/span/artifact controls test semantics, while paired
native observations with unchanged controls decide performance admission. A
changed result, invalid source ownership, unstable control, incomplete receipt
or failed process gate falsifies the corresponding claim. Papers motivate the
mechanism; their proofs do not certify this LR/GLR implementation. Rejected
candidates remain visible and the current defaults follow the retained decisions.
