#+title: Physical placement and acquire composition

[[file:../parser-engine-formal-model.org][Model and evidence index]]

* Physical placement and acquire composition

=Slots.extend= follows both branches of the target's =extend-vars=: prepend
empty variables when growing, drop leading variables when shrinking. After
reversal, =physical_exact= derives the retained low slots followed by high-slot
padding for arbitrary lists and requested sizes. =physical_retained= and
=physical_padding= establish indexed readback, rather than assuming a correct
final permutation. The compiler stores frame size separately from its slot
list; =Context.Valid= makes their agreement explicit. =push_valid= and
=shrink_valid= prove the corresponding frontend mutations preserve it, and
=declared_adapter= connects that validity to the target operation. Other native
context constructors, replacement and restoration still need admission to this
same invariant; the existence of a size field alone is not proof.

The generated stack operand is =STK(slot - targ-proc-fp)=. =FP_STK= subtracts
that operand from the current pointer. =emitted_scanned= derives agreement with
physical scanner slot =index + 1=; =collector_base= derives the frame-base
recovery in =mark_continuation=. =emitted_byte_address= retains arbitrary word
width instead of silently treating words as bytes. The model uses mathematical
addresses, so C object bounds, alignment and overflow remain native premises.
=stored_word_read= derives actual readback from a modeled generated write;
=future_capture_stored= composes this with resize/reversal, liveness, serialized
map fields and the signed GC cursor. The former read/placement certificates are
not additional inputs of this theorem.

Internal returns concatenate aligned ordinary slots, saved GVM registers in
register order, the return variable and trailing padding. The register source
list is reversed before applying =extend-vars= and reversed again afterward;
ordinary slots have only the latter reversal. =saved_register_at= and
=return_variable_at= retain this distinction and the inclusive live band.
=alignment_covers= and =internal_size_matches= derive agreement with
=RETI_CFS_TO_FS= for arbitrary positive alignment and reserve constants. These
proofs do not certify every native register push or dirty-cache flush.

The research basis additionally includes the abstract, introduction and scope
statement of [[https://www.cl.cam.ac.uk/~pes20/weakmemory/cacm.pdf][x86-TSO: A Rigorous and Usable Programmer's Model for x86 Multiprocessors]].
It separates processor-family memory behavior and compiler effects; its x86
spinlock result is not transferred to this AArch64 SDK. The normative interface
for the modeled mutex route is POSIX
[[https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap04.html#tag_04_15_02][Memory Synchronization]] and
[[https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_mutex_lock.html][pthread mutex lock/unlock]]. The indexed synchronization clauses were available;
direct full-page fetches were denied, so no full standard reading is claimed.

=Acquire= tracks per-location write versions, released views, each worker's
observed view and the mutex owner. An owned write advances its location in both
the memory and owner view. Release exports the owner's view; a successful
mutex acquire imports the released view. The invariant states that an owner
observes every current protected location, or that an unowned mutex retains
those versions for the next owner. =complete_handoff= derives visibility from
the empty initial state through arbitrary finite write/release/acquire histories.
It takes no final visibility certificate. This is a refinement relative to the
POSIX synchronization contract, not a proof of a libc mutex implementation,
condition-variable wakeup progress or arbitrary racing C reads.

=plain_poll_counterexample= shows why merely observing a later ticket does not
supply this import operation in a weak observation model. It does not prove that
the native ticket lock fails on a particular processor. Backend classification
keeps single-thread execution, successful POSIX synchronization and unresolved
ticket polling separate; =no_smp_inference= prevents treating the first or last
as a qualified SMP acquire. No compiler flag or synchronization primitive was
changed to make this result pass.

The compiled host metadata control reports =spin-backend=0= and
=max-processors=1= for the currently tested SDK. Earlier two-Scheme-worker GC
receipts must therefore not be read as multi-processor collector acceptance.
The new OS-thread mutex control is separate: while holding the actual Gambit
=___MUTEX=, the producer creates a waiter, then writes 32 C-owned words and
unlocks. The waiter reads them only after successful lock acquisition. Thread
creation precedes the tested writes and cannot publish them. No Scheme pointer
or VM entry is shared with this C waiter. A second control invokes actual
=FP_SET_STK=, =FP_ADJFP= and =FP_STK= macros across 128 pointer adjustments and
96 slots, preserving the metadata slot and checking address/value agreement.

* Context, cache and ticket lifecycle composition

This extension follows the same reported Gambit source baseline and the active
forms of =gsc/_front.scm= and =gsc/_t-c-2.scm=. The latter also contains a quoted
experimental representation-analysis block; its definitions are not used as
proof of the active flonum-cache implementation. The research obligations remain
root reachability plus explicit compiler/hardware ordering from the sources
above. No x86 result is imported as an AArch64 acquire guarantee.

=Contexts.Context= retains all six context fields. Entry construction creates
empty slot/register rows; its poll budget is a parameter, not a fabricated zero
for the native =entry-poll= result. Assignment requires a physical cell that
exists and is empty. =assignments_valid= handles arbitrary sequences, including
rejection of duplicate locations, and =Constructed= composes entry, assignment
and bounded task/parent constructors. =constructed_layout= supplies the slot
validity needed by the target layout adapter without requiring an arbitrary
validated input context. Snapshot/restore retains the full context; the cleared
machine state is separate and has no frame. A task split requires a bounded
frame start and a nonempty register row, matching the native =cdr= operation.
The join law proves the final drop has the selected length, but still takes the
displacement producer's full-width row as a premise.

The inspected entry assignment checks =reg <= target.nb-regs= before dropping
that many cells and taking =car=. The endpoint equal to the row length has no
cell. Our adapter therefore also requires successful indexed readback; it does
not claim that the source's numerical comparison alone establishes safety.
This identifies an input-admission obligation for =target.label-info=, not a
reproduced malformed native compilation or an upstream repair. =put-var='s
return-address uniqueness and its extending register replacement are not
silently identified with bounded initial pcontext assignment.

=Cache.flush= follows the physical vector's early-return scan: it writes back
the first matching dirty entry, preserving its stamp and clearing its dirty bit.
=lookup= probes the first matching entry regardless of dirtiness. A clean alias
before a dirty alias would break their correspondence; this has a negative
Quint control. =invalidate= scans all cells, including malformed duplicate keys.
=insert= reuses the first hole; a full vector of capacity n grows to 2*n+1.
The source writeback uses =F64BOX= and =targ-loc-no-invalidate=, so it must not
remove its own entry as an ordinary boxed overwrite would.

The cache history starts empty with stamp counter zero. Cold entry is admitted
only after a probe miss; dirty replacement invalidates its old location first.
Allocation increments the procedure-local stamp counter, while invalidation and
flush retain it. =trace_unique= derives key uniqueness through every admitted
history, =trace_bound= bounds all retained stamps, and =new_stamp_fresh= excludes
reuse of a retained stamp. =history_dirty_read= then derives the emitted boxed
value from that history rather than assuming a fresh uniqueness certificate at
each read. =dirty_spill_signed= composes the writeback event, generated physical
slot store, signed GC-map cursor and root retention. Its explicit boxing pointer
and compiler live-decision premises remain allocator/liveness interfaces; it is
not a proof of IEEE arithmetic or arbitrary native operand identity.

=Spill.choose= projects =lowest-dead-slot= into increasing physical slot order:
select the first nonlive slot, or exactly the next new slot when none exists.
=chosen_bound= and =chosen_dead= derive those branches. =saved_read= proves the
written copy is available at the selected destination; =live_read_preserved=
keeps every previously live indexed value. =all_live_retained= lifts this to
arbitrary sequences of register copies, including repeated frame extension.
Its liveness predicate must include closure-environment promotion. The copy
sequence still needs native register/operand decoding, and return-address
metadata movement is not identified with an ordinary payload write. This keeps
the general destination proof separate from those remaining source interfaces.

=Ticket.tryObserved= follows the current-read/next-CAS split in the actual
try-lock macro. It admits any past decoded current value: observing the latest
value is not assumed across an intervening unlock. A successful CAS plus the
counter ordering derives an empty queue and imports the released view through
the GCC full-barrier contract. A stale comparison fails without changing the
lock. =try_preserves_valid= and =unlock_valid= preserve the ticket/owner relation.
The invariant is one-way: an empty ticket queue is unowned. Its converse is
false between unlock and the next queued waiter's entry; the model and a Quint
negative control retain that ownerless, nonempty-queue intermediate state.

This CAS result does not qualify the normal contended poll loop. In particular,
matching the first poll does not establish that unlock preceded ticket
allocation: unlock can occur between allocation and that first read. The normal
macro has no explicit post-poll acquire barrier. The debug macro contains extra
history RMW/barrier operations; debug observations cannot certify normal mode.
No mutex backend, debug mode or compiler option was substituted for the active
runtime. A universal import proof for ordinary polling still requires the
actual compiler/ISA contract or a separately justified upstream correction.

** Operand identity, closure aliases and copies

Native operands use =index * 8 + tag=: register, stack, label, global,
closure and constant occupy tags zero through five. Scheme false is an absent
source; integer register zero is a valid source. The operand table retains its
argument-pair distinction, including global =#t= versus constant =#f=.
=intern_read= and =intern_preserves= prove selected and existing rows survive
arbitrary insertions; =encode_decode= covers all six constructors, not a fixed
corpus of register indices. The adapter rejects missing rows, mismatched kinds
and tags six/seven rather than certifying malformed target inputs.

Closure field addresses must use the resolved base pointer. Two different raw
base operands can alias the same closure. =closure_aliases= proves equality of
those physical destinations; =destination_read= connects each admitted target
to its memory read. Recursive base decoding has an explicit fuel bound and
requires a reference value and positive field index. Fuel sufficiency and
native object/name-table extraction remain interfaces, not consequences of a
successful finite decoder test.

=executeCopy= composes target decoding/resolution, source decoding/read and the
resulting store. =decoded_copy_readback= proves the destination contains the
source word and every other place is retained, for arbitrary admitted operands,
tables and memory. Label/constant sources are read values, not destinations.
A missing source still permits metadata assignment. The separate
=suppressed_copy_names= theorem preserves the frontend rule that an equal
source/destination suppresses the data move while updating variable metadata.
This is a denotational copy proof: it does not certify native emitted instruction
counts, target cache invalidation, stack extension or return-address movement.

** Actual boxing writes and retained roots

The qualified SDK branch uses 64-bit words, one flonum payload word, no handles,
no self-tagging and no NaN boxing. Its header is 2288, heap tag is seven and
reference-to-body offset is one word. These are qualification metadata;
=Boxing.ABI= carries header/tag parameters in the theorem. =allocate= advances
hp by two, writes the header at old hp and the exact =BitVec 64= payload at
old hp plus one. The tagged pointer denotes the header; untagging plus one
selects the payload. Earlier allocated cells are retained.

=Fresh= describes ownership of the current section tail, not physically zeroed
memory or all addresses above hp. The later section-composition extension below
corrects the former globally monotone ownership scope. =Ready= bounds the two-word write by the physical segment capacity,
not by a GC trigger threshold. =trace_fresh= derives ownership for arbitrary
admitted allocation histories. =tagged_fits= separately requires a representable
capacity. =cache_allocation_root= combines the existing dirty-cache history,
fresh/within-segment writes, actual tagged-header decoding, emitted stack stores
and signed frame-map scanning. It no longer asks the caller for an arbitrary
boxing function plus a matching pointer-readback certificate. Compiler live
flags, segment reservation, slow-path GC, raw address correspondence and other
boxing branches still need their own source adapters. No IEEE arithmetic
correctness or complete allocator theorem is claimed.

** Ordinary contention is a distinct ordering obligation

The normal macro allocates a ticket using GCC's full-barrier =__sync= operation,
then polls volatile current-ticket storage. The ARM relax macro is empty.
A full barrier before the previous owner's release is not a later acquire of
that release. GCC's [[https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html][volatile contract]] does not order independent nonvolatile
payload storage; the [[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fsync-Builtins.html][legacy atomic contract]] belongs to the atomic operation.
The inspected portions of Pulte et al.'s
[[https://www.cl.cam.ac.uk/~pes20/armv8-mca/armv8-mca-draft.pdf][ARMv8 MCA model]] distinguish load-acquire/barrier ordering from plain
control dependence. Its instruction coverage is not imported as a complete
proof of GCC's LSE atomics or this SDK binary.

=ordinary_poll_stale_history= constructs, for arbitrary positive tickets and
publication epochs, a history that satisfies a payload read before unlock,
observes the matching ticket afterward and consumes the stale value. Logical
poll-before-consume order is retained. =ordinary_poll_not_universal= proves the
negative import result in that explicit weak-observation projection. It is an
obstruction to deriving acquire solely from ticket equality, not an ISA
refinement theorem or a reproduced hardware failure. The corresponding GCC
ARM64 fixture disassembly has =ldaddal= for ticket allocation, ordinary =ldr=
for polling and an ordinary payload =ldr= immediately after the matching branch;
no extra post-poll acquire instruction is present. The normal path is kept
separate from debug history barriers and successful try-lock CAS.

** Physical operand table and actual cache representation

=Operand.Table.Atom= observes booleans, nonnegative numeric operands and opaque
canonical identity keys. =observe= interprets the native pair's second field:
=#t= selects global, =#f= selects constant, and a numeric field selects a closure
only when its base is numeric. Numeric zero is not Scheme false. This scalar
observation boundary still requires a correct native tagged-datum/eqv? adapter;
the theorem does not implement Gambit's entire object decoder.

=extract= reads exactly the allocated vector prefix and fails on a missing or
malformed allocated row. Spare capacity is ignored. =extract_size= derives the
prefix bound; =extract_read= connects every admitted row back to the indexed
physical pair and its scalar observation. =grow_size= proves the native
=floor(3*n/2)+1= capacity law. =grow_snapshot= and =append_snapshot= prove that
copying the old vector, incrementing allocated count and writing the new row at
the old count preserve the complete decoded prefix for arbitrary sizes. These
are general storage proofs, not tests of a few fixed grammar tables. Native
search-loop/eqv? correspondence and symbol/object identity extraction remain
separate obligations.

The active =targ-fp-cache-enter= entry has three vector fields: location,
dirty flag and stamp. Payload is not a fourth physical field. Source inspection
also confirms =targ-use-fresh-fp-vars?=#t=: =targ-unboxed-loc->code= selects
=F64V<stamp>=. =CacheExecution.decodeEntry= therefore gets its payload from the
stamp-indexed unboxed store. The inactive register/stack reuse mode is not
qualified by this adapter. =decodeRows= checks every actual three-field entry
and preserves false slots. =physical_flush= proves that mutating the first dirty
field and emitting its writeback agrees with the logical flush.
=physical_invalidate= covers clearing every matching vector slot;
=physical_copy_rows= composes both observed vector operations with the executed
copy state. Embedding observed fields in the actual Scheme heap, including entry
object ownership, is still a native scalar/read/write interface.

=CacheExecution.read= executes the first dirty writeback event as a real
=Boxing.allocate= and updates boxed source storage before returning its value.
=dirty_copy= composes a history-derived source with the destination store and
subsequent invalidation. It derives fresh bounded heap writes, exact payload,
target cache absence and a valid resulting cache history. =copy_other= preserves
every unrelated source/destination location; =clean_read_no_allocation= excludes
spurious boxes on clean/missing entries. This denotation covers emitted direct
register/stack copies. Frontend self-copy elision, nested closure-target
materialization, source emission extraction and return metadata remain distinct.

The cache-size field also needs its own correspondence. In the inspected
producer it is assigned =old-vector-length+1= on growth; insertion into a hole
does not update it. =reported_size_is_not_occupancy_bound= constructs three
valid distinct locations with reported size two and actual occupancy three.
A matching Quint control retains the same producer history. This refutes the
proposed identification of reported size with an occupancy upper bound; a
finite witness is sufficient for that negative result. Since
=targ-heap-reserve-and-check= uses the reported field, its reservation proof must
retain this distinction. The following reservation extension resolves the
qualified 64-bit no-check budget using the actual six-word compiler charge; the
reported-size counterexample alone is not evidence of insufficient reservation. This is not yet a native out-of-bounds witness:
compiler flushing, reserved words, section fudge and physical capacity must be
composed before making a memory-safety conclusion. No counter or runtime gate
is changed to conceal the discrepancy.

** Correcting the heap ownership scope

The previous global =Fresh= tail was too strong for Gambit's msections. A newly
selected section can have a lower address while a live boxed object remains in
a higher section. =Fresh= now quantifies only over =[hp, physical-limit)=.
=set_heap_msection= changes active pointers to the selected tospace; it does not
impose global address monotonicity. =selectSection= models that pointer change
under =SectionFree= ownership. Old bytes in an unallocated section are not
assumed to be physically zero; the cell projection tracks ownership.

=allocated_cell_retained= now proves preservation of every already-owned cell,
including addresses above current hp. =Trace= includes allocation and section
selection. =trace_fresh= derives local ownership, and =trace_retains= preserves
all existing cells across arbitrary such histories. A separate whole-heap
=extent= is retained monotonically by =trace_extent= while hp can move backward.
The collection snapshot ranges over that extent, not the current hp;
=selected_snapshot_retains= proves that selecting a lower section cannot omit
an older high-address object from the snapshot. Free-list validity and
nonoverlap are explicit native allocator premises, not facts inferred from a
passing section fixture. Collection relocation is a different transition and
is not incorrectly required to preserve old physical addresses.

** Heap-limit dispatch and collection composition

The native [[https://github.com/gambit/gambit/blob/dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813/lib/_kernel.scm][kernel heap handler]]
saves all GVM registers and a separate return address before =##check-heap=.
The strict =hp > heap_limit= check then short-circuits
=heap_limit() && garbage_collect()=. =heap_limit= in
[[https://github.com/gambit/gambit/blob/dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813/lib/mem.c][the native allocator]] may reuse/select a section or arrange more space and
return zero, without collection. Nonzero requests GC. Overflow is reported only
when collection also returns nonzero; a returning overflow handler retries the
check. No successful continuation is inferred from the overflow result.

=HeapCheck.overflow_exact= and =no_gc_on_reuse= preserve that control flow,
including equality at the trigger threshold. =saved_register= includes every
saved reference, independently of ordinary caller liveness flags. =snapshot=
retains the boxed object's full =BitVec 64= payload as an atom, unlike the older
pointer-only root projection. =allocated_object= derives that atom from actual
header/payload writes. =boxed_register_survives= connects it to saved roots and
relocation. =CacheExecution.copy_collection= composes the dirty source, copied
register root and exact-bit post-collection object in one theorem.

This composition still consumes the existing =Collection.Relocation= contract.
It is not a proof of native forwarding/copying, complete free-list operations,
soft-limit reservation, register push/pop implementation or every heap-limit
branch's memory effects. Those remaining source imports are visible in the
unified ledger; they cannot be removed by treating a GC success flag as proof.

** Ordinary contended acquire: identified missing import

The newly compiled GCC ARM64 fixture retains this instruction sequence:
=ldaddal next_ticket=; ordinary =ldr current_ticket= / compare / branch; ordinary
payload =ldr=; =ldaddal current_ticket= on unlock. The earlier atomic accesses
and later matching poll are different events. A ticket allocation before the
previous owner's release cannot acquire that later release. The matching poll
has no acquire instruction or post-poll barrier, and the branch alone does not
order the subsequent independent load in the cited ARM model. GCC volatile
access also does not supply a general compiler barrier for payload storage.

Thus the gap is an absent ordering import for the normal poll, not a missing
induction over ticket numbers. A positive theorem needs a source/backend rule
that orders the payload read after an acquire observing the matching release,
plus the existing no-wrap/ownership conditions. An acquire load for the normal
poll is a possible upstream correctness repair; no such repair or backend
substitution is made here. Mixed volatile/legacy-RMW accesses also need an
explicit compiler contract. The abstract negative history and successful native
handoff remain separate evidence; no native hardware failure or complete ARM
execution certificate is claimed. The paper's published errata were checked;
the [[https://www.cl.cam.ac.uk/~pes20/armv8-mca/errata.html][coherence-footprint and exclusive-instruction corrections]] do not
supply the absent acquire in this binary.

** Four quantities and two word ledgers

=Reservation.occupancy= counts actual present entries; =dirtyCount= counts the
subset needing boxing. Capacity counts every physical vector cell. Reported
size is the independent native record field. =Trace= covers initialization,
entry, invalidation and dirty writeback. =trace_shape= proves either the empty
initial state or =capacity+1=2*reported=. =reported_bound= then derives
=dirty <= occupancy <= capacity <= 2*reported= for arbitrary histories. These
are source-producer properties, not assumed equalities between counters.

The previous three-entry example remains valid: reported two does not bound
occupancy three. It does not establish a reservation defect. The installed
GSC reports minimum word size four bytes and two portable header words;
=targ-vector-of-64-bit-elements-space= rounds its conservative allocation
allowance to eight-byte alignment. =compilerFlonumCharge 4 2= is therefore
six words. The already qualified 64-bit non-handle =F64BOX= writes only two.

Let A denote actual emitted heap words, R compiler-charged emitted words,
D dirty entries and r reported size. =Accounting= generates both emitted
ledgers and the separate floating charge counter; =accounting_bounds= derives
=A<=R=. The qualified no-check proof is:

#+begin_example
D <= 2*r
2*D <= 4*r <= 6*r
A + 2*D <= R + 6*r <= 4096
#+end_example

The last comparison is the actual strict native trigger's untaken branch.
=qualified_no_check_safe= proves it for arbitrary producer histories, including
hole reuse and invalidation. A negative control using an equal two-word charge
refutes that incorrect unit substitution; it is not a counterexample to the
real six-word compiler charge. Other ABIs and the inactive boxing branches need
their own size ratio and are not admitted automatically.

** From potential to executed allocations

=flush_conservation= derives a one-unit dirty decrease for each emitted boxing
event. =batch_conservation= covers arbitrary live-location sequences, including
repeated and missing locations; already-clean entries do not emit another box.
=batch_potential= conserves emitted words plus remaining dirty potential for one
chosen word ledger. Compiler charges and actual words are never silently mixed.

=executeReads= uses the earlier =CacheExecution.read=, not a separate abstract
allocator. =read_preserves_potential= derives the exact hp/dirty conservation;
=dirty_event_ready= supplies physical room before every real two-word allocation.
=execute_reads_safe= constructs the complete =Boxing.Trace= for a batch.
=prepared_accounted_reads= composes generated charge counters, reported-size
history, C threshold geometry and all executed boxes, then derives freshness
and retention of every previously owned cell. It does not request a supplied
occupancy identity or an arbitrary emitted/reserved inequality at each step.

For the triggering unboxed assignment, =dirty_replacement_growth= derives at
most one additional dirty result from actual invalidate/insert algorithms.
=triggering_dirty_reads= admits the resulting flush sequence using a maximum
two-word potential increase. Thus this emitted operation is covered before the
post-materialization heap check. =triggering_flush_fits= exposes the general
bounded-instruction envelope for other opcodes; those bounds are still required.
No native gate or compiler threshold is changed.

** Physical fudge, resumption and synchronization

The reported native source has =MAX_NB_FRAME_SLOTS=8192= and
=MSECTION_FUDGE=MAX_NB_FRAME_SLOTS+1+SUBTYPED_BODY=. In the qualified non-handle
branch this is 8194 words; it is distinct from the compiler threshold 4096.
The physical allocation limit has already excluded end-of-chunk marker space.
=prepare_mem_pstate= computes:

#+begin_example
soft = hp + min(heap_available, physical_limit - hp - physical_fudge)
#+end_example

=prepared_bounds= derives =hp<=soft= and =soft+fudge<=physical_limit= under the
explicit physical-room premise. =prepared_accounted_reads= permits any compiler
reset cursor below that soft threshold. The GC return path guarantees fudge by
selecting another section when required, then calls =prepare_mem_pstate=;
=heap_limit= can also return after section reuse without GC. The kernel only
raises overflow when both the limit handler requests collection and collection
reports overflow, and may retry if the exception handler returns. A numeric
heap request of zero is truthy in Scheme; it must not be decoded as =#f= in the
remaining emission adapter.

The physical-room proof, free-list ownership, full instruction-size coverage,
register restoration and collector byte-copy relation remain native imports.
The new reservation result does not itself prove those implementations.

Ordinary ticket acquire remains a separate import. Source call-site inspection
shows =ALLOC_MEM_LOCK= is elided under =SINGLE_THREADED_VMS=; chunk publication
and stealing also guard their spinlock calls with that condition. In SMP,
=USE_MUTEX_FOR_SPINLOCK= selects the mutex path; otherwise the normal ticket
poll is used. Primitive locks have their own single-thread guard. Current SDK
metadata reports the single-thread branch, while the existing C contention
control explicitly exercises the normal ticket macro. Neither elided GC locks
nor a successful C handoff supplies the missing acquire rule. The cited GCC
volatile/legacy-atomic contracts and ARM ordering distinction remain unchanged;
no compiler switch, mutex substitution or debug barrier is used to hide the gap.

* Responsibilities and shared vocabulary

1. Papers define mechanisms, premises and limits. Transfer to this engine must
   identify both retained premises and differences in algorithm/representation.
2. Quint describes legal histories, invalidation and interleavings. Its bounded
   transition envelope must name the same owners and observations as Lean.
3. Lean defines denotations, representation relations, transition preservation
   and cost recurrences under explicit premises. It must not replace producer
   premises with facts that only a native implementation could establish.
4. Scheme/Rust controls discharge implementation-specific correspondence and
   failure obligations. Complete-request benchmarks measure the resulting CPU,
   allocation and GC behavior. Neither timing nor byte counts prove semantics.

The request state vocabulary is: admitted grammar/IR identity; source identity
and generation; lexical position/mode; pending raw token with its admission
basis; state-selected grammar terminal; LR states; semantic values; retained recognition yields; branch and
layout context; checkpoint/history owner; public artifact; and FFI owner/lifetime.
A source coordinate, token ordinal, grammar state and object identity are four
different quantities. Mutable tokens need a real producer protocol; an abstract
revision field does not supply one to Scheme.

The common observations are recognition outcome, exact remainder, terminal
order/identity, tree fields and spans, diagnostics, published bytes/events and
ownership after cancellation/edit/retry. Cost observations additionally include
preparation, scanning, selection, shifts/reductions, capture, reuse checks and
failed reuse, materialization, validation/digest/publication, FFI transport,
allocation/GC and scheduling. Counted operations are not CPU weights.
