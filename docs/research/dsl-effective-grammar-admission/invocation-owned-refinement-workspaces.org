* Invocation-owned refinement workspaces (2026-10-09)

** Resource transfer from the partition refinement design

The [[https://arxiv.org/pdf/cs/0612120][generalized Paige-Tarjan study]] separates correctness of stable refinement
from algorithmic scheduling improvements. This implementation retains the
previous affected-group schedule, exact signatures, first-seen numbering and
termination. It changes resource ownership within the shared Scheme algorithm,
not splitter selection or its asymptotic time bound.

Each invocation allocates two ID vectors and two affected-group vectors, alongside
the existing sizes and first-child workspace. Every next ID slot is assigned
before publication; the next affected frontier is cleared before propagation.
Only after all signature reads and successor visits complete are current/next
roles exchanged. Original initial IDs are never overwritten. A signature
callback borrows current IDs during its call; it must not retain that internal
view. The final returned vector survives other invocations, and no buffer is
global or retained by the language descriptor.

For =r= completed rounds, the previous algorithm allocates =2r + 2= indexed
vectors, including initial dirty flags and size/first-child storage. This version
allocates six, independent of =r=. One-round calls therefore allocate two extra
vectors, two-round calls the same number, and longer calls fewer. Table/signature
allocation, vector reset work and maximum live bytes remain separate costs.
This is a deterministic workspace allocation count, not a total allocation-byte
or latency claim. Language author declarations and ABI contracts are unchanged.

* Group cardinality and propagation frontier experiment (2026-10-09)

** Paper transfer and candidate proof

[[https://arxiv.org/pdf/cs/0612120][Ranzato and Tapparo]] separates stable refinement correctness from scheduling
improvements. The existing engine still sizes every current group in a separate
node pass, and scans all nodes when propagating split-source dependencies.
Two candidates were implemented and tested with identical synchronous rounds,
exact signatures, first-seen IDs and termination:

- Compute next-group cardinalities during ID publication and carry them into
  the following round. Initial membership is counted only once.
- Record each affected nonsingleton member in an invocation-owned source vector.
  Only those groups can split, so propagation scans that recorded prefix and
  visits successors only for members whose old group actually split.

Candidate one retains separate size/dirty arrays and needs eight indexed
vectors rather than six. Candidate two stores affected status in the sign of
each cardinality: negative affected, positive clean, magnitude exact group size.
All next sizes are counted positively before propagation; marking an already
negative size is idempotent. This returns the workspace to six indexed vectors
and eliminates the separate boolean frontier reset. Zero denotes an unused
slot, never a populated group. Both preserve input and output lifetime contracts.

For =r= rounds on =n= nodes, the separate membership-sizing pass would drop
from =r*n= node reads to =n= initial reads. Publication still performs =r*n=
node assignments and additionally counts next-group membership, including the
last unused next size map. Propagation would inspect the affected nonsingleton
prefix rather than =n= nodes per continuing round. These are traversal bounds,
not total operation or complexity improvements; synchronous publication remains
linear in every round. Neither candidate implements full Paige-Tarjan scheduling
or establishes its logarithmic bound.

* Persistent group identity experiment (2026-10-09)

** Paper transfer and implementation

[[https://arxiv.org/pdf/cs/0612120][Ranzato and Tapparo, Introduction, pp. 1-2]] distinguishes correctness of
stable refinement from the scheduling changes that earn its logarithmic bound.
The next candidate implements the preceding structural obligation: retain group
identities and intrusive membership chains across synchronous rounds, process
only queued nonsingleton groups, and canonicalize once at final publication.

All signatures read the same immutable round IDs. Planned target IDs are
recorded first; member links and IDs are committed only after every signature
read completes. The first child retains the parent identity and other children
receive fresh dense internal IDs. Only successors of members of actually split
source groups are queued, with group-level deduplication. Singleton targets are
excluded. Final publication assigns first-seen IDs without mutating the input.
Signature equality must be invariant under bijective renaming; dependency
visitors must include every shift/epsilon edge, including self edges.

The candidate uses ten invocation-owned vectors rather than six. Group
cardinalities and membership are initialized once. Per-round sizing and global
publication scans disappear; visited member reconstruction replaces them.
Internal IDs and chains need not follow node order, so final publication is a
separate semantic obligation. The final ID map reuses the member-head workspace.
This is still synchronous signature refinement, not smaller-half splitter
scheduling, and establishes no =O(m log n)= bound.

* Stable FOLLOW edge publication and indexed FIRST reuse (2026-10-09)

** Ownership and semantic obligations

The backward refinement owner already computes successor signatures. The old
[[file:../../../src/compiler/lr-follow-automaton.ss][FOLLOW construction owner]] then recomputes every lookahead vertex's edge
before determinization, checking that each member agrees. The implemented
handoff publishes the final shift/epsilon vectors from backward refinement and
passes them directly to determinization. These are the same two vectors that
determinization previously allocated, with no new public language slot or ABI.

A no-split final round preserves block order and IDs. Its active nonsingleton
keys were computed against that round's final index and can be reused. Inactive
and singleton keys may contain earlier round IDs: they are never reused. One
representative is evaluated against the final index for each such stable block.
The stable-partition invariant guarantees that all block members have equal
successor signatures. Reordered production controls and independent canonical
construction qualify this invariant instead of a duplicate production traversal.

The first native experiment implements only this handoff. On actual TLA+,
=stable-edge-reuse= reports zero reused keys out of 8888 backward blocks: the
last round has no active nonsingleton block. Eliminating the final per-member
pass alone is insufficient to infer meaningful complete cost reduction.
The retained TLA+ FOLLOW median changes 1712.9290 -> 1705.1450 ms (0.45% lower),
with the same invocation-order sensitivity as preceding experiments; its
controller exits 0 in 58.587 seconds. No independent speed claim is admitted
for that variant.

The next implementation decomposes each vertex's epsilon targets:

#+begin_example
fixed(core, index) = union over children and FIRST(tail) terminals
                    of singleton(index[child, terminal])
epsilon(core, follow, index) = fixed(core, index)
                              union nullable follow targets
#+end_example

Set union distributes over the FIRST/follow union and is idempotent, including
when follow is already in FIRST(tail). The fixed portion is translated once per
queried core into block IDs, using one lazy vector local to the current round.
=#f= means uncomputed; an empty set (=0=) is a valid cached result. A new round
gets a fresh vector because splitting can renumber targets. Final publication
uses the same last-round vector; it cannot carry stale targets across rounds or
invocations. Fixed FIRST expansion changes from repeated work per vertex to
once per queried core per round; dynamic nullable follow targets remain exact.
No smaller-half scheduling or logarithmic complexity bound is asserted.

* Covered-root elimination in memoized epsilon closure (2026-10-09)

** Paper transfer and shared algorithm candidate

[[https://aclanthology.org/J00-1005.pdf][Van Noord, Treatment of Epsilon Moves in Subset Construction (2000),
Section 3.2, pp. 66-68]] compares per-state and per-subset closure strategies.
Per-state memoization still pays to union the cached results for each seed;
whole-subset memoization avoids repeated complete queries. The engine already
has both a graph-sized singleton cache and a bounded seed-to-state cache.
This experiment studies redundancy inside a remaining seed-query miss.

The following additional elimination is our derivation from reflexive
transitive closure, rather than a scheduling theorem stated by that paper:
if =u= is already in a computed closed set =C=, then =closure({u})= is a subset
of =C=. Select one pending seed, union its cached closure into the result, and
subtract that closure from all pending seeds before selecting the next one.
The selected seed is removed by reflexivity, so the loop terminates. Each
omitted seed's entire closure is already covered by transitivity. Therefore
the result equals the union of all singleton seed closures in the old engine.

The candidate moves the language-specific epsilon memo helper into the shared
indexed-set engine as =compiler-index-set-reachable/memo=. Graph edges are
immutable; the caller owns a graph-sized cache and must never reuse it with a
different graph. Cache entries remain exact singleton closures and only roots
actually queried are populated. Empty seeds return zero. No SCC graph, extra
closure table, unbounded subset retention, public language slot or compatibility
path is added. The existing large-quotient admission cutoff remains unchanged.

The canonical reachability Case adds cold and warm memo controls for all 512
directed three-node graphs and all eight seed sets, using its independent list
graph oracle. Populated cache entries are also checked against independent
singleton results. A 1024-node chain/cycle control covers high-bit seeds and
checks that already covered chain roots need no cache entries. Source counts
remain 58 Cases (37 + 21); these controls are added inside the existing Case.
