#+title: Native prefix-family staging

* Engine boundary

The existing homogeneous =or= of four to 32 nonempty =line-starts-with= or
=line-starts-with-ascii-ci= predicates is staged into shared byte decisions.
The aggregate encoded prefix length is bounded at 512 bytes. The compiler
uses pure grouping, mapping and folding over immutable build-time values;
requests allocate no trie. Mixed predicates retain ordinary short-circuit
lowering. No grammar, admitted IR, ABI, runtime cache or public DSL changes.

This follows the engine scanner's prepared-literal approach and Gerbil's
named functional combinators: factor repeated traversal into one mechanism,
not more nested handwritten loops in downstream grammar declarations.

* Matched controls

The rich family uses Org's six TITLE/SUBTITLE/AUTHOR/DATE/CAPTION/DESCRIPTION
prefixes. A separate 32-prefix family is a stress control. The linear route
uses equivalent nested single-prefix conditions, generated by the same
current compiler, not a historical executable. All routes include encoding,
line traversal and complete event publication, with identical hit/miss actions.

The generator embeds independent =run-event-fold= interpreter expectations
for each route: every prefix, lowercase variants, UTF-8 payloads, CRLF and
blank lines, truncated prefixes, empty source and EOF. Before timing, every
document's complete output is compared across both native routes. Eight
samples rotate route positions and verify all 20 events per document.

#+begin_src sh
just generate-prefix-family-benchmark OUTPUT LOAD_PATH
just benchmark-prefix-families OUTPUT/prefix-family-benchmark 8
#+end_src

Link the generated source with the project's native executable recipe against
the same compiled engine library. Generation and compilation are outside
request timing; requests do not launch processes or exchange JSON.

* Local observation

CPU medians in milliseconds, eight samples per route at each scale:

| Documents | Rich linear | Rich staged | Stress linear | Stress staged |
|-----------+-------------+-------------+---------------+---------------|
|      1000 |       2.298 |       1.107 |         8.769 |         0.998 |
|      2000 |       4.816 |       2.076 |        17.503 |         2.034 |
|     10000 |      20.277 |       8.596 |        84.867 |         7.652 |

All 96 timed rows and complete parity controls passed. Original stdout is
retained as =prefix-family-benchmark.log= beside the local native executable.
At 10,000 documents rich wall medians were 20.395/9.686ms; stress medians were
85.357/7.670ms. Individual stress wall samples reached 319.606ms (linear) and
83.401ms (staged), so host scheduling noise is retained rather than hidden.
Every sample collected garbage: raw allocation-counter deltas are retained
but not admitted as allocation totals.

These are engine mechanism measurements, not full Org grammar, Rust/Tokio or
Scheme actor scheduling, FFI packets, query, or filesystem measurements.
They do not close the complete consumer's separate, still-unpassed 100ms gate.

The subsequent interpreter-qualified repetition also passed all 96 rows.
Rich CPU medians were 2.243/1.121ms, 4.441/2.083ms and 20.302/8.929ms
at 1,000/2,000/10,000 documents. That receipt is retained separately as
=prefix-family-benchmark-oracle.log=; it does not replace the first run.
