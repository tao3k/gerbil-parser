#+title: Upstream caller-owned UTF-8 admission in complete parser requests

* Ownership and integration

Both =gerbil.pkg= and the Rust IR dependency pin
=gerbil-scheme-rust= revision =345b172765e5607b09049614d10520c2439dcac3=.
The parser imports the actual upstream =scheme/utf8= module; it does not copy
its encoder or initialize a second Scheme VM. The public Rust and C parse
signatures, GPA1 format and language declarations remain unchanged.

[[file:../../src/ffi/language-abi-context.ss][Prepared ABI contexts]] own a source-admission procedure. The default decodes
incoming bytes and calls upstream =gerbil-rs-encode-utf8-into= to compare the
canonical encoding against the original bytes. [[file:../../src/ffi/language-artifact-codec.ss][Both fresh and session publication]]
use that admission before parsing. [[file:../../src/ffi/language-handles.ss][Prepared context registration]] gives each
handle its existing independent history; it adds no process or VM isolation.
The private context record is an engine protocol, not a new language DSL slot.

Each nonempty admission allocates stable C storage with capacity four times
its decoded character count. Upstream writes bounded 256-character chunks,
retaining Scheme polling and strict Unicode scalar checks. The consumer passes
a typed =void*= foreign object, not an integer address. Its no-allocation
comparison leaf borrows the Scheme bytevector body only during that call.
No Scheme body pointer survives a poll, callback or allocation. =dynamic-wind=
frees C storage on success and exceptions; empty input requires no allocation.
Allocation failure and malformed/noncanonical UTF-8 remain errors before result
publication and history commit. This changes temporary encoding storage, not
the original source copy or the owned C result lifetime.

The upstream encoder and its pointer contract are primary implementation inputs:
[[https://github.com/tao3k/gerbil-scheme-rust/blob/345b172765e5607b09049614d10520c2439dcac3/scheme/utf8.ss][Pinned Scheme encoder source]]. Existing parser transport already uses bulk
=memcpy= for source and GPA1 bytes; reimplementing those copies would not consume
a missing upstream optimization.

* Complete request experiment

[[file:../../t/benchmarks/language-abi/utf8-cpu.ss][The Scheme Benchmark]] registers two prepared contextual record parsers. The
reference context independently reproduces the former =utf8->string= plus
=string->utf8= equality admission. The candidate uses the production upstream
caller-buffer admission. Grammar, scanner, parser, catalog, byte source and
expected complete GPA1 payload are shared in meaning. Workloads must be accepted.

Both timed thunks call the actual length-bearing public C parse ABI through
[[file:../../t/benchmarks/source-edits/abi-call.ss][the existing owned C caller]]. Timing includes input allocation/copy, callback,
strict admission, contextual parsing, GPA1 encoding, C result allocation/copy,
readback and all releases. Complete payload equality is checked by the common
sampler; initialization and context preparation are outside both timed lanes.
This is a Scheme measurement of the public C path also used by Rust callers,
not a measurement of Rust wrapper instruction costs.

Twenty groups retain complementary paired order and equal request budgets.
Every natural collection remains charged to CPU. Identical reference controls
run before and after the production comparison. Both control P10/P90 bounds
remain 0.90--1.10; positive benefit additionally requires production P90 below
0.95 and every timed sub-batch to resolve at least one millisecond. Each fresh
proof child retains 120 seconds total, five seconds of real-output idle time,
three GiB maximum heap and typed nonzero rejection. No collection is forced
between sub-batches, no sample is dropped and GC CPU is not subtracted.

These receipts qualify the specified complete contextual requests. They do not
prove every grammar faster, solve the Bash/Tree-sitter gap, or attribute a gain

CPU contribution of UTF-8 admission visible when parsing/publication dominates.

* Complete 64-record publication algorithm

The UTF-8-only 64-record result above remains a negative benefit result. The
next experiment changes the shared GPA1 publication algorithm independently
of source admission. A request-local diagnostic measured 100 accepted ASCII
64-record C ABI calls: complete CPU was 54.732 ms, contextual scan/LR drive
21.860 ms, event validation 2.528 ms and event publication 27.962 ms. The
publication stage was approximately 51% of complete CPU. These inclusive
observer measurements locate costs; they are not a paired speedup proof.

The fixed Gerbil SDK's =std/vector/u8vector= integer setters dispatch byte
order and check each scalar span before shifting/storing each byte. GPA1 rows
have an invariant 24-byte layout. The shared engine now packs that whole row
through one bounded synchronous leaf instead of five generic scalar writes.
The leaf converts unsigned integers before accessing storage, checks the
bytevector and complete remaining span without offset-addition overflow, and
writes explicit little-endian bytes. It requires neither aligned stores nor
host endianness. The Scheme buffer body is borrowed only during the leaf;
there is no callback, allocation, poll or retained pointer inside it.

Both deferred contextual publication and already materialized Source artifacts
use the prepared context's row writer. Parsing, two-pass event validation,
source ownership, canonical IDs, descriptor lookups, publication error
classification, exact buffer sizing and history commit ownership are preserved.
No language declarations or scanner rules change. Invalid integer widths and
short output spans fail before writing any part of the row.

The =events= Benchmark registers two independent public C ABI handles with
identical production UTF-8 admission and parsing. Its reference context owns
the former five-setter row writer; its candidate uses whole-row packing. Both
produce the entire 15,488-byte GPA1 for 64 accepted assignments, including input
copy, parsing, source hash, publication, C result copy, readback and release.
Empty, rejected, quoted, CRLF, Unicode and field-bearing products are compared
byte-for-byte outside timing. The existing 20-group paired CPU admission,
resolution, natural GC and before/after controls remain unchanged.

The initial ASCII experiment passed with CPU P10/P50/P90
0.624346/0.642045/0.683865, a 35.80% median decrease. Before-control P10/P90
were 0.928303/1.037129 and after-control 0.928605/1.047672. The child completed
in 66.762 seconds with exit zero and =ABI-EVENT-CPU-PROOF-OK=. This receipt
predates the extra internal bytevector guard; final receipts are recorded below.
A guard compilation rejected a missing Gambit predicate temporary, and the
premature Unicode child was stopped. Neither is admitted as final evidence.

addition to the existing UTF-8 obligations. A gain here proves the specified
complete multi-record requests faster; it does not establish an arbitrary
language speedup or close the separate Bash/Tree-sitter performance gap.
