#+title: Working decision

[[file:../scheme-parser-performance-framework.org][Model and evidence index]]

* Working decision

Keep the Scheme-owned compiler as the authority, and evaluate two algorithmic
paths against distinct workloads. For fresh, whole-source parsing and grammar
generation, test conflict-directed LR state partitioning and generated lexer
design. For small edits, Tree-sitter's
contextual lexing and reusable syntax subtrees remain the stronger reference.
Both preserve deterministic LR execution on the ordinary path and admit
generalized parsing only where the grammar requires it. This is a research
direction, not an adoption or performance claim. Neither external runtime
would be embedded as the parser authority.

The isolated Scheme prototype uses canonical LR(1) as a semantic reference.
It has two compact-table candidates: a canonical-state quotient and a direct
LR(0)-derived forward/backward follow partition. The direct route does not
enumerate canonical DFA states, but uses conservative potential-conflict
lookaheads rather than langcc's exact Definition 3.24. Generation and parse
cost must be measured before any product cutover. The existing LALR route
remains the production default.

The current engine already has important pieces: =src/compiler/lr-automaton.ss=
builds an interned LR(0) automaton; =src/compiler/lr-lookahead.ss= propagates
LALR lookaheads; =src/runtime/lr-parser.ss= executes deterministic actions and
selective GLR; =src/compiler/machine.ss= generates parser-directed lexical modes;
and =src/runtime/incremental.ss= resumes sparse LR checkpoints and reuses
tokens only under matching parser-directed lexical modes. The LR executor
still feeds the changed suffix and publishes a complete artifact.
These are source observations; measured costs appear below.

The 2026 comparison and the langcc results address different questions. The
former compares algorithm families under a shared Rust harness; the latter
measures generated full frontends against language-specific standard parsers.
Neither supplies a matched result for this repository's Scheme grammar,
scanner, lossless artifact, or incremental edit workload.

The focused direct-route test now also compares LALR and follow-partition LR
roots for all 12 accepted embedded HCL v2.24 specsuite fixtures. Both tables
have 133 states in this language, so this extends real-language equivalence
coverage but does not exercise a necessary LR(1) split. The existing mixed
fixture exercises that split (20 direct states versus 23 canonical states),
while the 16-region family checks scale (211 states on both routes). A local
20-run benchmark completed, but short batches had large warmup/GC variance;
state counts and products are firmer evidence than its throughput ratios.

The closed-form lexer DFA is now in Scheme. It preserves the
existing parser-directed modes and scanner fallback; =t/ranked-regular-scanner-test.ss=
compares every offset of mixed ASCII/Unicode sources, including complete and
incomplete numeric exponents, with the old individual
scanners; =t/grammar-composition-test.ss= also checks that LR modes distinguish
two regular rules with the same spelling. The pure Scheme
=t/benchmarks/regular-mode/benchmark.ss= compares the old ASCII-prefiltered
mode scan against the combined scanner: a 100,000-call sample improved all
four selected sources, while a shorter 20,000-call Unicode sample reversed
direction. A later 100,000-call number sample also favored the combined
scanner, but these local microbenchmarks do not establish stable Unicode or
whole-parser throughput gains. A matched full ParseArtifact comparison now
uses =t/benchmarks/versioned-languages/matched-batch.ss=, with independent

60 timed batches, with GC outside each timed region. Against the pre-number-DFA

the two baseline medians were 17.54 and 29.61 ms. Fastest samples in all four
processes were 10.67--11.00 ms. The second pair and p95 values varied widely,
so this corpus does not establish an end-to-end gain from the number DFA. These
numbers measure a complete batch, not process import or compilation; they also
do not establish per-language scalability. Keep the DFA for its lexical
semantics and focused speed evidence, but measure phase costs before adding
more rule forms. The language-pack and generated Rust conformance gates
remain required. Add subtree certificates and edit-local LR actions where edits
justify them. The follow-partition route remains an
explicit construction choice until a real conflict-bearing language corpus
justifies switching a scene from LALR.

The generated lexer now also uses each LR mode's ASCII first-character table
to skip the regular scanner or shared literal trie when the first transition
is impossible. Unicode retains the existing scanner path; longest match, rank,

not establish a stable end-to-end gain. The pure Scheme
=t/benchmarks/arithmetic-scale/matched-stream.ss= makes the long-input
comparison reproducible before widening this dispatch further.

The local minute-scale wait seen during this slice was qualification time:
the package-only scanner import took 2.9 seconds, while isolated lexical,
composition, and HCL test commands took about 5, 7, and 9 seconds. A full
suite through the interpreted =gerbil env gxi= test entry took about 46 seconds;
the same suite through native =gerbil test= took 25.6 seconds with the same

The root =justfile= exposes a focused =test-lexer= gate (about 4 seconds with
native =gerbil test=) and a separate full suite gate; CI uses the native entry.

* Scheme prototype and measured boundary

=src/compiler/lr-lookahead.ss= now exposes an optional canonical LR(1)
construction. =src/compiler/lr-partition.ss= groups states with equal LR(0)
cores only when their union adds no raw parser conflict, then repeatedly
splits groups until transition targets are congruent. It uses Gerbil's
=:std/struct/queue=, =:std/vector/extensible=, =:std/hash/misc=, standard
tables, and the existing indexed-set masks. The partition code does not
rebuild groups with =append=. =src/compiler/lr-follow-automaton.ss= now builds
a second experimental path directly from LR(0): it refines follow blocks
backward, coarsens and refines them forward, determinizes the quotient NFA,
and publishes the ordinary LR table contract. =compile-lr-spec= selects these
routes through an explicit fifth argument. =compile-parser= forwards an
optional construction choice from canonical Grammar IR to that Scheme
compiler; both defaults stay LALR.

The focused Scheme test includes the classic LR(1)-but-not-LALR(1) grammar:
LALR reports a reduce/reduce conflict, while canonical, canonical-quotient,
and direct follow-partition LR(1) compile and produce identical parse results
across all 125 three-character
strings over the fixture alphabet; exactly four are accepted. On the
shared-lookahead LALR grammar, canonical construction has 11 states and both
compact routes have 8, matching LALR. The direct path also matches canonical
parse products for a precedence grammar. The benchmark itself is pure Scheme
at =t/benchmarks/lr1-partition/benchmark.ss=; compile the compiler modules and
shared fixture into a clean Gerbil path before invoking it with =gxi=.
The focused Grammar IR test constructs complete v1 IR from the LR(1)-only and
precedence fixtures, calls =compile-parser= with the direct and canonical
choices, and compares their LR parse products. Under the pinned v0.19 build,
it also compares both routes on the generated arithmetic language using its
actual lexer and three source expressions. It does not exercise Rust syntax.

** Bounded canonical trial at medium grammar size

The direct follow constructor has a bounded canonical trial for large
grammars. For a medium family of independent LR(1) contexts, the previous
512-production entry threshold instead built the LR(0) seed first. At 48
contexts (290 productions), it then entered follow refinement, although the
canonical automaton has only 627 states and needs no follow compression.
The entry threshold is now 256 productions. The trial still stops at three
times the production count and falls back to direct follow construction when
canonical states exceed that budget. The later LR(0)-conflict lower-bound
check and all table contracts remain in place.

The pure Scheme =t/benchmarks/lr1-partition/route-threshold.ss= prepares the
grammar once, alternates canonical and follow construction, runs =##gc=
before each sample, and reports CPU time, state count, and follow-block
count. Invoke it as =gerbil env gxi
t/benchmarks/lr1-partition/route-threshold.ss 48 20= under the built package.
In separate 20-pair local runs, the 48-context follow-route CPU median fell
from 12.715 to 3.280 ms; the canonical reference medians were 2.880 and
2.873 ms. At 64 contexts (386 productions), the follow-route median fell
from 5.828 to 5.196 ms; that case already used a late canonical trial, so
the gain is limited to avoiding the LR(0) seed. Both results report zero
follow blocks, and the focused reference test checks parse products for all
accepted and rejected context fixtures at 48 and 64 contexts. This is a
construction-time route choice, not a measured runtime parse gain.

** Mapping langcc's direct construction to the Scheme compiler

Construction 3.27 of /Practical LR Parser Generation/ partitions k-follow
strings *per dotted production*. It first computes forward-reachable follow
strings, then uses LR(0) DFA co-reachability to identify lookaheads on which
actions could conflict. Compatibility with those lookaheads defines the initial
backward partition. Backward edge refinement runs to a fixed point, followed
by a forward refinement over the resulting blocks. Only then does it build the
quotient NFA and determinize it. Theorem 3.28 states equivalence of conflict
existence with the canonical LR(k) NFA; it does not state equality of generated
tables or parser throughput. Source: https://arxiv.org/pdf/2209.08383,
Definitions 3.12, 3.19, 3.22--3.25, Construction 3.27, Theorem 3.28.

| Paper object | Existing Scheme asset | Required new object or check |
|-
| Dotted production and LR(0) co-reachability | =make-core-item= and =build-lr0-automaton= already index dotted items and intern LR(0) states. | Expose a stable item-to-state membership index for potential-conflict pairs. |
| Forward-reachable 1-follow strings | =make-core-lookahead-catalog= already caches FIRST tails and nullability; =propagate-lalr-lookaheads= propagates masks on LR(0) item nodes. | Track follow sets per dotted production/partition, preserving context; a LALR union mask alone loses the distinction the paper refines. |
| Potentially conflicting lookaheads | The LR(0) state contains jointly reachable dotted items. | Calculate raw shift/reduce and reduce/reduce overlap before precedence, associativity, or selective GLR changes the action set. |
| Backward then forward refinement | =make-lookahead-propagation-graph= resolves closure and shift edges. | Refine follow-string blocks across both edge directions until stable; use standard queue, table, vector, and set operations rather than hand-built collection machinery. |
| Quotient NFA then DFA | =compile-lr-spec= already publishes action/goto tables. | Determinize the partitioned NFA and prove its conflicts and parse products against the canonical reference before comparing runtime throughput. |

The older =lr-partition.ss= operates on *already materialized canonical
LR(1) DFA states*. The direct path instead uses
=src/compiler/lr-conflict-candidates.ss=: a standard-library queue computes
forward-reachable 1-follow masks per production without canonical states, and
raw action overlap on the LR(0) propagation graph produces conservative
potential-conflict cells. Compatibility signatures then seed the initial
backward follow-string partition.

The forward follow worklist now propagates only newly discovered terminal bits
through nullable tails, while each static FIRST(tail) mask is applied once when
its parent production first becomes reachable. This is the k=1 fixed point of
Definition 3.22; the focused test compares its masks with LR(0) propagation
on recursive, mixed-context, and 16-context grammars. The pure Scheme
benchmark reports this phase separately with a follow-mask sum so its cost is
not conflated with LR(0) construction or backward refinement. The 16-context
phase is below a millisecond locally, but this does not establish a gain for
the complete parser generator.

The candidate stage uses LALR union masks,
so it may include more lookaheads than Definition 3.24 and split more blocks
than the paper's exact initial partition. The seed now intersects each LR(0)
state candidate mask with the dotted item's possible raw actions: completed
items reduce on reachable follows, terminal-dot items shift on their terminal,
and nonterminal-dot items have no action. An inactive-core witness reduces the
seed from 42 to 41 blocks and from four to three split cores while preserving
full follow masks and canonical conflict coverage. This remains a conservative
approximation of Definition 3.24 because the candidate stage does not compute
exact follow-specific co-reachability. =lr-follow-automaton.ss= refines
those blocks by shift and closure successors until stable, groups the
backward blocks by dotted core, refines by predecessor reachability, then
determinizes the quotient NFA. If there are no raw conflict candidates, it
reuses the already computed LALR states and lookaheads. This implements the
paper's forward/backward framework for k=1 with a conservative candidate
stage; it is not an exact port of langcc's implementation.
The backward fixed point now tracks reverse dependencies between dotted cores.
When a follow block splits, only cores whose shift or closure targets that core
are checked in the next round; each round still rebuilds the global block
index so identifiers remain consistent. This preserves the partition rule of
Definition 3.19 while avoiding successor-signature work for unaffected cores.
The generated 16-context LR(1) family retains the canonical reference's 211
states and matching accepted and rejected parse products across all regions.
Small local construction timings vary enough that this change does not yet
establish a stable end-to-end speedup.
The focused test compares follow masks with all LR(0) completed-item
lookaheads and checks that every canonical raw conflict projects into a
candidate cell, including a grammar with a genuine reduce/reduce conflict.
Raw candidate detection now records the first action per terminal and marks
only a distinct second action, avoiding production-sized bignum action masks.
The pure Scheme benchmark reports this candidate phase separately, with its
conflict-state count. Focused equivalence tests pass; full construction
timings remain noisy and do not establish an end-to-end speedup.
It also checks that initial blocks cover every reachable follow string and
that the LR(1)-but-not-LALR fixture yields a real initial split. A mixed
grammar exercises the full path: the direct table has 20 states versus
23 canonical states, and parse products agree over all 775 strings of lengths
2--4 from the five-character alphabet. Generated language module qualification
and representative parser throughput measurement remain. Keep each phase's
state/block count and elapsed time separate;
a smaller table is not by itself a faster parser.

** Stop forward refinement at singleton blocks

The direct follow constructor's forward partition previously ran one more
global signature pass after every block had become its own group. No further
split is possible once =group-count= equals =block-count=. It now materializes
the result immediately at that fixed point. This follows the same monotone
partition rule as Construction 3.27 and changes neither the partition nor the
published LR table.

The new =mixed-context-family-rules= fixture joins independent LR(1)-only
regions with a shared recursive component. Unlike the independent family, it
requires direct follow construction and compresses the result: at 32 regions,
canonical has 489 states, while follow has 486 states and 1,033 blocks for
1,161 output items. The reference test compares accepted and rejected parse
products at 4, 16, and 32 regions. The existing pure Scheme
=t/benchmarks/lr1-partition/route-threshold.ss= accepts =mixed= as its third
argument, for example =gerbil env gxi
t/benchmarks/lr1-partition/route-threshold.ss 32 20 mixed=.

For a controlled 30-pair, same-process A/B at 32 regions, a temporary switch
alternated the old confirmation round and the new termination rule. The full
LR specs were =equal?= for every pair. The old and new CPU medians were 10.516
and 8.636 ms; the new path won 25 pairs. The 16-region effect was smaller:
4.093 versus 4.039 ms and 18/30 paired wins. Static predecessor grouping and
epsilon-closure caching did not show stable whole-construction gains on this
same direct-route fixture, so they were removed. These are grammar-construction
measurements; parser runtime throughput is unchanged by this experiment.

** Skip singleton backward follow blocks

Backward refinement previously recomputed a successor signature and created
a grouping table even for a block containing only one lookahead. Such a block
cannot split under Definition 3.19, regardless of later changes to its
successors. The direct constructor now carries it into the next partition
unchanged. Multi-lookahead blocks retain the existing signature refinement.

The independent 32-context family takes the direct route and ends with 900
singleton follow blocks. In a temporary same-process A/B with 30 alternating
pairs, the complete old and new LR specs were =equal?= in every pair. The
construction CPU medians were 7.455 and 6.486 ms; the shortcut won 25 pairs.
At 16 contexts the medians were 3.295 and 2.994 ms, but only 17/30 pairs
favored the shortcut. On the compressing mixed 32-context family the change
was small (9.179 versus 8.953 ms; 17/30 wins), so this experiment does not
claim a gain there. The checked-in =route-threshold.ss= benchmark continues
to report the direct route's state, block, and item counts for both shapes.

** Refine forward groups only while they can split

The forward pass used to rebuild predecessor signatures for every block in
each round. A group containing one block cannot split under Construction 3.27,
so the Scheme constructor now counts current group members and computes a
signature only for blocks in groups with at least two members. It still assigns
new group IDs in block traversal order, preserving the published LR spec's
state and transition numbering. At 32 independent contexts, the initial
partition has 772 groups for 900 blocks; the next two rounds reach 836 and
900 groups. The mixed family has 905 initial groups for 1,033 blocks and
reaches 969, then 1,033.

A temporary switch compared the old and new paths in one process, alternating
order with GC before each construction. Each of 30 pairs compared the entire
LR spec with =equal?=. Median CPU time in ms (old to new, paired wins) was:

| Contexts | Independent | Mixed |
|----------+-------------+-------|
| 16       | 2.914 to 2.497, 24/30 | 3.794 to 3.225, 22/30 |
| 32       | 6.741 to 5.698, 24/30 | 8.187 to 6.415, 28/30 |

The temporary switch was removed from the production module after the
comparison. These are in-process Scheme grammar-construction measurements on
one host; they do not imply a fresh-parse throughput change. Lowering either
canonical-trial threshold improved the independent fixture but slowed the
compressing mixed fixture, so those threshold experiments were reverted.

A later bounded-route experiment tried canonical construction for 128--255
productions only when the nonterminal dependency graph was acyclic. It cut
the independent 32-context family's median from 5.283 to 2.270 ms in 30/30
paired runs, while the recursive mixed family stayed on direct follow. The
new =acyclic-mixed-context-family-rules= fixture is the counterexample to
that admission rule: it shares a finite component across 32 regions, has no
recursive dependency, and needs 485 follow states versus 487 canonical
states. The canonical trial therefore falls back, but raises the full
construction median from 7.050 to 9.923 ms (only 7/30 wins). The route change
was reverted. The fixture, reference test, and =route-threshold.ss=
=acyclic-mixed= mode retain this performance and semantic boundary for the
next routing algorithm.

Several local signature and fixed-point refinements were also rejected after
same-process full-spec comparisons: direct comparison within small forward
groups, propagation only to groups reached from a split, sparse predecessor
signatures, and an extra backward singleton confirmation guard. Canonical
closure queue deduplication, lookahead-delta propagation, and eager closure
edge caching likewise lacked consistent paired wins. None of these temporary
switches remains in the compiler.

A subsequent phase profile under ASP Scheme =v0.1.2.1= measured the full
direct constructor for 32 recursive shared contexts. Over 10 local CPU
samples, LR(0) construction took 1.321 ms median, raw conflict detection
0.109 ms, initial backward partition 0.540 ms, metadata 0.139 ms,
backward refinement 0.319 ms, and quotient-NFA determinization 3.230 ms.
The latter includes roughly 1--2 ms each for forward refinement and DFA
state expansion. These are compiler-construction costs, not parser runtime.

Two reversible determinization experiments preserved the complete LR spec
in every paired sample but did not retain a stable gain. Replacing the
standard queue in epsilon closure with a bitset worklist changed the
recursive shared 32-context median from 6.937 to 7.167 ms (12/30 wins).
Indexing symbols once and reusing a vector of transition targets initially
changed that median from 7.451 to 7.101 ms (23/30 wins), but a repeat was
6.769 to 6.936 ms (15/30 wins) and 64 contexts were 22.579 to 22.792 ms
(11/30 wins). Both candidate edits were reverted. The existing benchmark
fixtures and full-spec equivalence checks remain the gate for another
representation change.

The lower-bound canonical trial now also admits medium grammars (at
least 64 productions and eight raw conflict states) when each nonterminal
occurs in at most two production right-hand sides. This static sharing
measure screens out the recursive and finite shared-component families;
it is a route heuristic, not a correctness premise. The exact LR(0)
state-plus-conflict lower bound remains the final admission test, and a
canonical trial that exceeds it falls back to direct follow partitioning.
The bounded trial leaves small grammars unchanged. On this host, alternating in-process 30-pair CPU runs
measured the independent 16-context family at 2.392 to 1.486 ms (29/30
candidate wins) and independent 32 at 5.600 to 3.045 ms (28/30 wins).
The recursive mixed 32 family was 7.363 to 7.324 ms (16/30); the finite
shared 32 family, after reversing the scan to reject sharing early, was
7.245 to 6.897 ms (17/30). Those latter differences are not treated as

** Grammar-wide prediction and sparse LR graph construction

The implementation now factors LR(0) closure into a grammar-wide reachability
solution and kernel application. For each referenced nonterminal A, a dense
production-id mask starts with A's own dot-zero productions. A production
whose first symbol is nonterminal B adds a dependency on B's mask. A reverse
edge work queue propagates only new production bits until these masks reach
their finite fixed point, including recursive grammar components. Each goto
kernel unions the completed masks of its after-dot nonterminals and merges
the resulting dot-zero items with the sorted advanced items. It no longer
runs a prediction queue, item hash table, or full item sort for every goto.

State identity is the advanced-item kernel bitset. Closure adds only dot-zero
items, so distinct noninitial kernels identify distinct closed states. The
augmented dot-zero initial kernel has a disjoint key. The state index is
queried before closure; closure is computed only when a new state is
published. Symbol discovery order and the canonical sorted state items retain
the existing state numbering. Each state's transition row is assembled once.

LALR propagation nodes occupy sorted contiguous slices in the node-item
vector, located by state offsets. Binary search resolves graph edges without
a packed (state,item) hash index. Symbol IDs resolve shifts through scratch
arrays; each state/nonterminal shares one immutable prediction target list.
Static FIRST(tail) evidence is delivered once when a node becomes reachable;
later queue entries carry only new follow bits through nullable tails.

Action construction uses the existing terminal catalog's numeric IDs for
scratch cells and shift targets, retaining action installation order and
precedence/conflict policy. Only touched scratch cells are cleared after row
publication. Both graph and action scratch storage are reused across states,
so these arrays do not allocate a state-by-symbol or state-by-terminal matrix.
All indexes belong to one construction call; no mutable grammar cache or
runtime selection flag was added.

grammar families on LALR, canonical LR(1), and direct follow construction
(36 comparisons). TLA+ and the three larger scale fixtures are additionally

unique, and that each goto target has exactly the source items advanced over

** Shared LR(0) prediction templates

The next audit used the existing TLA+ default-LALR construction benchmark.
Temporary phase-statistics instrumentation observed about 4--6 ms of
lookahead propagation, with substantial GC time in slower complete calls.
On the 390-state automaton, the sorted state items contain 6,224 dot-zero
prediction occurrences and 977 advanced kernel occurrences. Only 63 distinct
dot-zero item sets occur; their unique templates contain 876 items in total.
This count includes the augmented initial dot-zero item. It identifies
repeated prediction grouping across states as a structural reuse opportunity.

=src/compiler/lr-automaton.ss= now interns a template by the completed dense
production-id prediction mask. A template owns its sorted predicted item
list, goto groups, and sparse symbol-id group index. Each goto group stores
its earliest item and immutable advanced-kernel mask. A new state's closure
merges its kernel with this shared list, retaining an unchanged template
suffix when the kernel is exhausted. Its transitions group only its own
kernel items, merge overlapping template groups, and combine the two rows
by earliest item. This reproduces sorted-closure symbol discovery order
without regrouping every closed-state item. Only the small kernel group row
is sorted; the shared prediction group row is already ordered.

Template ownership lasts for one construction call. Numeric symbol IDs and
scratch vectors belong to that same call. Scratch masks are cleared for
kernel symbols only; template groups remain immutable after construction.
Every template is requested by a newly admitted state, so the template count
is bounded by the state count. The automaton still publishes the same item
lists, state IDs, transitions and visit count. Complete LRSpec comparisons
also retain lookahead masks, conflict actions and diagnostic counters.

The baseline is =9d6d32f=, following the prior structural migration and latest
PR rebase. The same complete construction benchmark measured a 20-call CPU
median of 46.5365 ms before this change. A clean 12-core production rebuild
of the template implementation measured 15.229 ms; an independent 20-call
repeat measured 15.567 ms. All use a 2 GiB heap and explicit pre-call GC,
with imports, pre-call GC and equality checking outside CPU timing; in-call
GC stays inside. The complete serialized before/after TLA+ specs are
byte-identical, at 280 productions and 390 states. This is about a 67 percent
complete-call reduction on this host and workload.

Separate four-call process-statistics samples observed in-call collection
counts of =(0 1 1 1)= for the baseline, with roughly 25--29 ms GC CPU in the
three collecting calls, and =(0 0 0 0)= for the template implementation.
The existing =construction.ss= benchmark now reports per-call collection
count and GC CPU time plus their medians, using Gambit's statistics slots
3/4 for GC user/system time and slot 6 for collection count. Its 20-call
qualification measured 14.908 ms and median in-call GC count zero. GC is a
material contributor to this speedup; these samples do not establish that
all heaps or workloads avoid collections.

** Shared literal recognition across lexical modes

=generated-lexer= now builds one trie for all complete =(literals ...)= rules,
including precedence-wrapped literal catalogs. Every interned LR lexical mode
keeps a rule-admission vector; the trie filters terminal candidates by that

initialization.
