Source and runtime failure semantics differ. import-module owns source promises
and retry behavior; load-module retains failed runtime exceptions until explicit
reload. Parser must not invent a common exception cache. The former diagnostic importer/evaluator bindings and private promise mirrors
are removed. Parser loading/recovery Cases call the real native APIs. Compiler
stream zero/multiple-value and exception controls remain with their actual owner.

* Controls and failure custody
Positive controls cover descriptor selection, same-size edits, Core post-effect
source admission, real helper initialization once, native order, and typed init
services. Negative controls retain malformed imports/arity, invalid selectors,
initializer failures, source rewrite under an outer read-cache, deferred/quoted
loads, and a first failed child preventing a later cold suffix.
