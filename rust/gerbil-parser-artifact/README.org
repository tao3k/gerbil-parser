#+title: Scheme parser artifacts in Rust

* Authority and ownership

=gerbil-parser-artifact= admits the Scheme-owned GPA1 result and the inert
native descriptor from the same language handle. It contains no language
recognizer and depends on neither the Rust AOT executor nor Rowan.
=gerbil-parser-native= obtains and caches this catalog through its handle;
callers use =parsed.view()= without passing a generated parser specification.

#+begin_src rust
let parsed = language.parse(source)?;
let view = parsed.view()?;
if let Some(root) = view.root() {
    for field in root.field("body") {
        for child in field.children() {
            // Node and token kinds, spans and source text come from Scheme.
        }
    }
}
#+end_src

The descriptor uses the existing bounded =(object ...)= / =(list ...)= Scheme
metadata wire. Its reader accepts inert values only, rejects duplicate object
keys and trailing forms, and enforces the producer's depth limit. It does not
evaluate Scheme. =rootKind= is published by the parser product, rather than
inferred from catalog order. Node fields are checked against their owner's
published declaration.

* Borrowed AST contract

The view borrows both the original C result bytes and source. A flat index
records matching scope boundaries and node parents. Navigation preserves
producer order, token trivia, UTF-8 byte spans, named field scopes, repeated
fields and zero-width fields. Node and token text are slices of the original source.
Field scopes remain associations; they are not converted to anonymous nodes.
Rejected syntax exposes =view.tokens()= but no accepted root. The same borrowed
token API is available for accepted input: =id()= is the scanner ordinal,
=class()= is the original terminal class, and =kind()= is its published syntax
kind (or the class for unmapped source tokens). These identities remain distinct;
for example, an =item-token= scanner class can publish an =Identifier= syntax
kind. Iteration preserves all trivia and returns slices of the original source,
with no token-text allocation or recognition replay. Accepted tokens expose their
owning node; rejected tokens have no invented node parent.

Admission checks grammar and source digests, complete source coverage, catalog
indices, node/token identities, nesting, field ownership and UTF-8 boundaries
before navigation. The native wrapper's lifetimes retain the result allocation,
language handle and owner-thread runtime until borrowed access ends.

* Independent Rust execution

The =syntax= module stores an owned source allocation plus a validated flat
preorder index for the independent Rust AOT backend. It is not used to convert
native Scheme artifacts. AOT execution remains in =gerbil-parser-runtime=;
its generated tables and semantic controls remain independent of native FFI.
Both access paths avoid per-token string storage and GreenNode construction.

* Evidence boundary

Canonical and contextual Scheme fixtures are regenerated by
=t/fixtures/shared-scanner/generate-native-artifact.ss=. Native AST shape, token
order, spans and source borrowing are compared with independent AOT results.
Truncation, header/record mutation, product mismatch, rejection, UTF-8 and field
identity controls remain executable. Field traversal additionally checks actual
published field names and values. This separation establishes ownership and
representation contracts; it makes no end-to-end performance claim.
