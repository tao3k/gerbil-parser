* LR fragment transfer admission is a correctness contract

Here, parser state matching concerns a current LR continuation and an actual
retained grammar nonterminal. It is not support for an obsolete framework or
language interface. The shared engine keeps exact prepared-runtime and reducer
identity, entry-state matching and the admitted nonterminal goto/exit state.
There is no old-architecture adapter or alternate grammar declaration path.

The source owner still certifies unchanged source and lexical entry/exit
boundaries. The LR injection boundary now independently checks the significant
terminal yield: kinds, lexemes and relocated UTF-8 start/end coordinates must
match retained terminal leaves in order. The first transferred token must also
match the current input token. Equal token count alone is insufficient.
Private relocation views accumulate offsets without mutating retained fragments.
Validation completes before a new checkpoint is constructed; rejection leaves
the original continuation usable.

#+begin_src scheme
;; Source ownership and lexical boundary checks precede this engine operation.
;; The fragment represents a grammar production, not an AST kind.
(def next
  (lr-checkpoint-inject-fragment current fragment byte-delta significant-tokens))
(lr-checkpoint-resume next)
#+end_src

Why is this preferable? Language authors retain declarative syntax/rules; the
engine validates the transfer using its own grammar structure and continuation.
They do not write per-language reuse callbacks or repeat parser stack logic.
Why is it justified? A state/goto match certifies the grammar transition, while
exact terminal comparison prevents a caller from attaching a retained semantic
value to different token contents or coordinates. Source and lexical admission
remain separate obligations; this check alone cannot admit an arbitrary edit.

The validator uses an explicit pending work list over recognition fragments and
views, including nested relocation. Its work is proportional to visited
recognition structure plus terminal comparison; lexeme comparison includes text
length. It adds validation work to each accepted transfer. This is a conservative
engineering guard motivated by the context/reuse distinction in
[[https://harmonia.cs.berkeley.edu/papers/twagner-parsing.pdf][Wagner and Graham]], not their optimal reuse algorithm or complexity bound.
Rust currently exposes no LR fragment injection API; this change does not claim
a cross-backend incremental session or AST/CST identity-preserving edit API.

ParseArtifact publication against fresh parsing, exercises a multibyte terminal

* Source scanning sessions consume the convergence proof

=make-source-scan-session= retains private token and checkpoint sequences. On a
new source it reads the longest common suffix from the scanner-owned snapshots,
scans the prefix from the initial state, and binary-searches old boundaries at
the translated character position. It checks plan identity, the fixed parser
position and full delimiter context before admitting the suffix. It never
restarts from an old matching-prefix checkpoint.

An opaque =contextual-scan-suffix= binds the independently reached boundaries.
Only checkpoints from that old source at or after the admitted boundary can be
rebound to the new owner; character and UTF-8 byte deltas are distinct. The worker
copies token records and marker text stays shared inside private immutable
checkpoints. Public token snapshots are copied, so consumer mutation cannot
change later reuse. Rebound checkpoints support a second edit without rescanning
the old suffix merely to populate the next cache.

=parse-source-language/session= integrates this scanner cache into the existing
Source language parser. It owns the input, retains the declaration identity and
runs the original recognition/publication path with the new token stream. Every
published artifact is validated against the declaration and new source identity.
Lexical rejection uses the original parser diagnostic path and retains no cache;
ordinary Source engines call their original declared scanner so projection and
mode handling are preserved; they retain no cache and cannot admit lexical reuse.

Matched Bash controls now demonstrate one scanned token after a Unicode command
prefix edit with the remaining lexical records reused. Changing an unquoted
here-document marker to a quoted marker scans all seven tokens through the
marker close before reusing the four-token footer. Both artifacts equal complete
fresh parses, and a subsequent edit consumes the rebound checkpoints. Source
mutation, published token mutation and unclosed quote recovery have executable
controls. These counts measure skipped scanner recognition, not preserved token
object identity, parser-state reuse or measured end-to-end latency.

This implementation retains O(tokens) checkpoint storage, reads source suffixes
linearly and copies/relocates the admitted tail. Recognition and canonical CST
publication still execute fully. Rust/native incremental Source transport and
parser-stack/subtree reuse remain separate implementation work; no ABI, schema
version or language declaration changes are introduced here.

* Shared terminal yields for LR fragment transfer

Captured LR fragments now retain a private shared terminal-yield rope. A shift
contributes its existing terminal reference. A reduction concatenates child
yields without flattening descendant tokens; empty and unary grammar wrappers
share the existing yield instead of adding nodes. Relocated children contribute
coordinate views, whose repeated moves collapse their deltas. The original
grammar children, cached semantic value, entry/exit state and lookahead remain
available to the source owner and independent recognition projection.

The LR transfer validator now walks this yield instead of every retained grammar
production. It still compares each significant terminal's kind, complete lexeme,
relocated UTF-8 start/end, exact count and current first input token. Runtime,
reducer, goto, source ownership and lexical boundary admission remain separate
checks. No digest-only acceptance or grammar/publication schema change is added.

For an unrelocated yield of T nonempty terminals, the binary representation has
T leaves and T-1 branches. Validation therefore visits 2T-1 nodes regardless of
unary grammar wrapper depth. Coordinate views add explicit visits. The traversal
is iterative; this is not a balanced tree or a logarithmic edit algorithm.
Construction adds one reference per captured grammar fragment and shared branch
records for concatenation, plus relocation views. Capture has extra work and
retained storage; a flat token list is never copied for each ancestor. Ordinary
parses without recognition capture do not construct the yield index.

The optional =current-lr-transfer-yield-observer= reports the actual visited yield
node count once per validation attempt. It is observational and is disabled by
default; source/grammar certificates do not use its output. The retained fixture
freezes the f21204f grammar-tree traversal as an independent admission control.
A 64-layer grammar with two multibyte-source terminals visits 67 grammar-tree
nodes in that reference and 3 yield nodes in the indexed validator; complete
canonical ParseArtifact publication equals a fresh parse. A 512-terminal
left-recursive control visits 1,023 yield nodes, rejects a changed last terminal,
and reuses the original checkpoint after rejection. Epsilon reduction and a
recaptured relocated child plus a fresh sibling have canonical fresh-parse and
independent projection controls, including another relocation of the new root.
