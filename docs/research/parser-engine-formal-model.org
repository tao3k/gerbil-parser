#+title: Parser engine semantics and operation model

* Objective and evidence boundary

This model connects one complete deterministic reduction path: canonical
field/alias actions, retained factories, reverse LR operands, logical AST
children and sequence materialization. Production remains Scheme. Lean checks
universal properties of the reference algorithms; Scheme controls check the
implementation; matched benchmarks measure CPU and allocation. These are
three separate obligations, not interchangeable receipts.

The executable package is [[file:../../formal/ParserEngine.lean][formal/ParserEngine.lean]]. The checked toolchain and LeanPoo revision are recorded in
[[file:../../formal/lean-toolchain][lean-toolchain]], [[file:../../formal/lakefile.toml][lakefile.toml]] and its locked manifest. LeanPoo is a verification dependency only.
Its =Functional.Requirements.Factories= and =Selected= retain typed factories;
=prepare_ok_iff= establishes that successful preparation selected exactly
those factories. Our executor threads transformed children through that tuple:
LeanPoo's independent-result =build= is deliberately not used for sequential
actions. No new Scheme dispatch facility or author interface is introduced.

* Architecture alignment audit and qualification order

The architecture model is *incomplete*. A successful Lean build establishes the
listed theorems; successful Quint runs check their stated finite histories.
Neither establishes coverage of all paper mechanisms, all engine routes or a
refinement of Scheme. Hash-binding a source file only identifies that file.
It does not connect a source transition to a theorem.

The local reduction objective above is historical scope, not a complete engine
specification. This section is the shared coverage ledger. Extend this ledger
and its connected models before another runtime optimization. Do not use a new
local object-count identity as evidence that an architecture gap has closed.

*** Research and source reading boundary

The existing LR paper and abstract-interpretation basis supply the grammar,
finite-domain and least-closure obligations recorded below. Appel's
[[https://www.cs.princeton.edu/~appel/papers/143.pdf][Simple Generational Garbage Collection and Fast Allocation]] supplies the
root-pointer reachability premise in its introduction. Only that indexed
introductory passage was available for this reading; the PDF fetch was denied.
No generational allocation, write-barrier, throughput or full-paper correctness
result is transferred to this engine. Gambit source inspection supplies the
concrete root and object descriptors; it is distinct from the paper argument.

The strong-mark phase includes VM, symbol/keyword, reference-counted foreign
roots, globals, active continuations, registers, saved registers, type caches
and processor roots. =Roots.Banks= names these sources separately. Captured
continuation handles are roots; the saved frame and dynamic environment are
then object edges. Closure code metadata is excluded from its free-variable
payload; frame maps exclude return/link metadata. Typed numeric arrays,
strings and other pointer-free payloads are opaque in this pointer projection.
The projection does not establish their byte-content preservation. Weak keys,
weak values and wills require separate reachability rules and are excluded.

Qualification metadata: the tested Gerbil SDK identifies revision =2591dcd=
with local patch identity =f5cedd8168cb=; its compiler reports Gambit baseline
=dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813= and GCC 16. The GC root/scanner and
probe branches were re-read from that baseline's =lib/mem.c=. The corresponding
=gsc/_t-c-3.scm=, =gsc/_t-c-2.scm=, =lib/_system.scm= and
=include/gambit.h.in= supply the target map generator, frame decisions, generic
hash dispatch and physical macros. A matching
reported baseline is not proof that all installed patch bytes equal that
source. The modeled map generator and frontend liveness adapter do not prove AST
free-variable extraction, physical variable placement, C compilation, FFI
pinning or the full SMP memory model. No complete Gambit
collector correctness claim follows from the source inspection.

*** GVM liveness, atomicity and weak observation

The host adapter follows the reported Gambit baseline's
[[https://github.com/gambit/gambit/blob/dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813/gsc/_front.scm][frontend]] and
[[https://github.com/gambit/gambit/blob/dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813/gsc/_gvm.scm][GVM frame decisions]].
This is a recursive expression-boundary calculation, not an invented CFG
use/kill solver. Its result has one more boundary than expressions. Every
nonfinal boundary adds =force-live=, including a false placeholder. A return
placeholder adds =ret-var= only for a tail reason; an ordinary expression adds
its bound free variables. The final boundary is exactly the incoming live set.
Lists represent varsets extensionally by membership; duplicate/order identities
are not claimed. =boundary_suffix= applies after the actual argument schedule
has been chosen. Reusing indices from the original order is not justified.

=frame-live?= treats the closure environment specially: either the environment
itself or any live captured variable retains it. The successful result is the
closed-variable list, including the Scheme-truthy empty list. The model records
this truth value without confusing an empty list with false.
=future_capture_root= connects any future captured use to environment retention
and the existing map producer/root consumer; =future_capture_signed= extends
that chain through serialized fields and the signed C cursor. Its explicit
slot-to-word premise is now discharged in =Slots.future_capture_stored= by source layout operations and physical address
identities. Native context validity, pointer bounds and actual spill/cache
behavior remain distinct obligations, not certificates inferred from testing.
The compiled =closure-frame-roots= control retains two closure
environments across an opaque GC callback and collects again before accessing
them in both orders. The existing wide compiled-frame and actual continuation
controls remain in the same suite.

For concurrency, the research basis is the authors' project overview for
[[https://www.cl.cam.ac.uk/~pes20/cpp/][Mathematizing C++ Concurrency]]: concurrent semantics must account for compiler
and hardware relaxed-memory behavior. This reading covers that overview, not a
transfer of its complete C11 formalization or x86 validation to Gambit.
The actual inspected route uses GCC legacy =__sync= operations, rather than
assuming C11 relaxed atomics. GCC documents
[[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fsync-Builtins.html][old-value fetch-add/CAS and the full synchronize barrier]]. Its
[[https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html][volatile documentation]] explicitly does not order nonvolatile memory through a
volatile access. These source-specific contracts remain below the logical
linearization boundary; no new axiom asserts compiler correctness.

=Publication= distinguishes initialized chunk epochs, observer-visible payloads
and the published tail. A write can advance initialization without visibility.
An unfenced atomic tail update has a checked unsafe counterexample. The first
=end_heap_chunk= barrier flushes chunk content, end marker and link before the
tail update. The second barrier follows that update; it stutters in this
payload-safety projection. Visibility progress and condition-variable wakeups
are not proved by a stuttering safety projection. =end_chunk_safe= derives the
producer branch without assuming its resulting invariant. =trace_safe= then
preserves the invariant through arbitrary admitted finite histories, and
=reservation_visible= connects a published queue head to both visible payload
and the existing queued/held ownership permutation.

The steal path's optimistic head check is not a reservation. The current head
must be read again after obtaining the lock. =distinct_reservations= proves
adjacent removals cannot claim the same chunk when the queue has unique IDs.
It does not establish that native allocation and queues preserve global ID
uniqueness. The collector's strong and weak phases use distinct counters; this
strong-root proof does not silently combine those phases.

The ticket macros require a separate boundary. Fetch-add returns the old ticket;
unlock uses another fetch-add. =bounded_tickets_unique= only admits physical
modulo tickets inside an explicit no-wrap window. The normal lock then waits
using a volatile load of =current=, with no explicit post-wait barrier in that
macro. A full barrier on ticket allocation before waiting is not, by itself,
a proof of acquire ordering after a later owner's unlock. Architecture/compiler
ordering for that ticket path and patched-binary identity remain open adapters.
The POSIX mutex alternative is modeled below relative to its successful-call
synchronization contract. This is an identified proof gap, not a demonstrated native
race, and no runtime synchronization change is made on that basis.

*** Physical placement and acquire composition

=Slots.extend= follows both branches of the target's =extend-vars=: prepend
empty variables when growing, drop leading variables when shrinking. After
reversal, =physical_exact= derives the retained low slots followed by high-slot
padding for arbitrary lists and requested sizes. =physical_retained= and
=physical_padding= establish indexed readback, rather than assuming a correct
final permutation. The compiler stores frame size separately from its slot
list; =Context.Valid= makes their agreement explicit. =push_valid= and
=shrink_valid= prove the corresponding frontend mutations preserve it, and
=declared_adapter= connects that validity to the target operation. Other native
context constructors, replacement and restoration still need admission to this
same invariant; the existence of a size field alone is not proof.

The generated stack operand is =STK(slot - targ-proc-fp)=. =FP_STK= subtracts
that operand from the current pointer. =emitted_scanned= derives agreement with
physical scanner slot =index + 1=; =collector_base= derives the frame-base
recovery in =mark_continuation=. =emitted_byte_address= retains arbitrary word
width instead of silently treating words as bytes. The model uses mathematical
addresses, so C object bounds, alignment and overflow remain native premises.
=stored_word_read= derives actual readback from a modeled generated write;
=future_capture_stored= composes this with resize/reversal, liveness, serialized
map fields and the signed GC cursor. The former read/placement certificates are
not additional inputs of this theorem.

Internal returns concatenate aligned ordinary slots, saved GVM registers in
register order, the return variable and trailing padding. The register source
list is reversed before applying =extend-vars= and reversed again afterward;
ordinary slots have only the latter reversal. =saved_register_at= and
=return_variable_at= retain this distinction and the inclusive live band.
=alignment_covers= and =internal_size_matches= derive agreement with
=RETI_CFS_TO_FS= for arbitrary positive alignment and reserve constants. These
proofs do not certify every native register push or dirty-cache flush.

The research basis additionally includes the abstract, introduction and scope
statement of [[https://www.cl.cam.ac.uk/~pes20/weakmemory/cacm.pdf][x86-TSO: A Rigorous and Usable Programmer's Model for x86 Multiprocessors]].
It separates processor-family memory behavior and compiler effects; its x86
spinlock result is not transferred to this AArch64 SDK. The normative interface
for the modeled mutex route is POSIX
[[https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap04.html#tag_04_15_02][Memory Synchronization]] and
[[https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_mutex_lock.html][pthread mutex lock/unlock]]. The indexed synchronization clauses were available;
direct full-page fetches were denied, so no full standard reading is claimed.

=Acquire= tracks per-location write versions, released views, each worker's
observed view and the mutex owner. An owned write advances its location in both
the memory and owner view. Release exports the owner's view; a successful
mutex acquire imports the released view. The invariant states that an owner
observes every current protected location, or that an unowned mutex retains
those versions for the next owner. =complete_handoff= derives visibility from
the empty initial state through arbitrary finite write/release/acquire histories.
It takes no final visibility certificate. This is a refinement relative to the
POSIX synchronization contract, not a proof of a libc mutex implementation,
condition-variable wakeup progress or arbitrary racing C reads.

=plain_poll_counterexample= shows why merely observing a later ticket does not
supply this import operation in a weak observation model. It does not prove that
the native ticket lock fails on a particular processor. Backend classification
keeps single-thread execution, successful POSIX synchronization and unresolved
ticket polling separate; =no_smp_inference= prevents treating the first or last
as a qualified SMP acquire. No compiler flag or synchronization primitive was
changed to make this result pass.

The compiled host metadata control reports =spin-backend=0= and
=max-processors=1= for the currently tested SDK. Earlier two-Scheme-worker GC
receipts must therefore not be read as multi-processor collector acceptance.
The new OS-thread mutex control is separate: while holding the actual Gambit
=___MUTEX=, the producer creates a waiter, then writes 32 C-owned words and
unlocks. The waiter reads them only after successful lock acquisition. Thread
creation precedes the tested writes and cannot publish them. No Scheme pointer
or VM entry is shared with this C waiter. A second control invokes actual
=FP_SET_STK=, =FP_ADJFP= and =FP_STK= macros across 128 pointer adjustments and
96 slots, preserving the metadata slot and checking address/value agreement.

*** Context, cache and ticket lifecycle composition

This extension follows the same reported Gambit source baseline and the active
forms of =gsc/_front.scm= and =gsc/_t-c-2.scm=. The latter also contains a quoted
experimental representation-analysis block; its definitions are not used as
proof of the active flonum-cache implementation. The research obligations remain
root reachability plus explicit compiler/hardware ordering from the sources
above. No x86 result is imported as an AArch64 acquire guarantee.

=Contexts.Context= retains all six context fields. Entry construction creates
empty slot/register rows; its poll budget is a parameter, not a fabricated zero
for the native =entry-poll= result. Assignment requires a physical cell that
exists and is empty. =assignments_valid= handles arbitrary sequences, including
rejection of duplicate locations, and =Constructed= composes entry, assignment
and bounded task/parent constructors. =constructed_layout= supplies the slot
validity needed by the target layout adapter without requiring an arbitrary
validated input context. Snapshot/restore retains the full context; the cleared
machine state is separate and has no frame. A task split requires a bounded
frame start and a nonempty register row, matching the native =cdr= operation.
The join law proves the final drop has the selected length, but still takes the
displacement producer's full-width row as a premise.

The inspected entry assignment checks =reg <= target.nb-regs= before dropping
that many cells and taking =car=. The endpoint equal to the row length has no
cell. Our adapter therefore also requires successful indexed readback; it does
not claim that the source's numerical comparison alone establishes safety.
This identifies an input-admission obligation for =target.label-info=, not a
reproduced malformed native compilation or an upstream repair. =put-var='s
return-address uniqueness and its extending register replacement are not
silently identified with bounded initial pcontext assignment.

=Cache.flush= follows the physical vector's early-return scan: it writes back
the first matching dirty entry, preserving its stamp and clearing its dirty bit.
=lookup= probes the first matching entry regardless of dirtiness. A clean alias
before a dirty alias would break their correspondence; this has a negative
Quint control. =invalidate= scans all cells, including malformed duplicate keys.
=insert= reuses the first hole; a full vector of capacity n grows to 2*n+1.
The source writeback uses =F64BOX= and =targ-loc-no-invalidate=, so it must not
remove its own entry as an ordinary boxed overwrite would.

The cache history starts empty with stamp counter zero. Cold entry is admitted
only after a probe miss; dirty replacement invalidates its old location first.
Allocation increments the procedure-local stamp counter, while invalidation and
flush retain it. =trace_unique= derives key uniqueness through every admitted
history, =trace_bound= bounds all retained stamps, and =new_stamp_fresh= excludes
reuse of a retained stamp. =history_dirty_read= then derives the emitted boxed
value from that history rather than assuming a fresh uniqueness certificate at
each read. =dirty_spill_signed= composes the writeback event, generated physical
slot store, signed GC-map cursor and root retention. Its explicit boxing pointer
and compiler live-decision premises remain allocator/liveness interfaces; it is
not a proof of IEEE arithmetic or arbitrary native operand identity.

=Spill.choose= projects =lowest-dead-slot= into increasing physical slot order:
select the first nonlive slot, or exactly the next new slot when none exists.
=chosen_bound= and =chosen_dead= derive those branches. =saved_read= proves the
written copy is available at the selected destination; =live_read_preserved=
keeps every previously live indexed value. =all_live_retained= lifts this to
arbitrary sequences of register copies, including repeated frame extension.
Its liveness predicate must include closure-environment promotion. The copy
sequence still needs native register/operand decoding, and return-address
metadata movement is not identified with an ordinary payload write. This keeps
the general destination proof separate from those remaining source interfaces.

=Ticket.tryObserved= follows the current-read/next-CAS split in the actual
try-lock macro. It admits any past decoded current value: observing the latest
value is not assumed across an intervening unlock. A successful CAS plus the
counter ordering derives an empty queue and imports the released view through
the GCC full-barrier contract. A stale comparison fails without changing the
lock. =try_preserves_valid= and =unlock_valid= preserve the ticket/owner relation.
The invariant is one-way: an empty ticket queue is unowned. Its converse is
false between unlock and the next queued waiter's entry; the model and a Quint
negative control retain that ownerless, nonempty-queue intermediate state.

This CAS result does not qualify the normal contended poll loop. In particular,
matching the first poll does not establish that unlock preceded ticket
allocation: unlock can occur between allocation and that first read. The normal
macro has no explicit post-poll acquire barrier. The debug macro contains extra
history RMW/barrier operations; debug observations cannot certify normal mode.
No mutex backend, debug mode or compiler option was substituted for the active
runtime. A universal import proof for ordinary polling still requires the
actual compiler/ISA contract or a separately justified upstream correction.

**** Operand identity, closure aliases and copies

Native operands use =index * 8 + tag=: register, stack, label, global,
closure and constant occupy tags zero through five. Scheme false is an absent
source; integer register zero is a valid source. The operand table retains its
argument-pair distinction, including global =#t= versus constant =#f=.
=intern_read= and =intern_preserves= prove selected and existing rows survive
arbitrary insertions; =encode_decode= covers all six constructors, not a fixed
corpus of register indices. The adapter rejects missing rows, mismatched kinds
and tags six/seven rather than certifying malformed target inputs.

Closure field addresses must use the resolved base pointer. Two different raw
base operands can alias the same closure. =closure_aliases= proves equality of
those physical destinations; =destination_read= connects each admitted target
to its memory read. Recursive base decoding has an explicit fuel bound and
requires a reference value and positive field index. Fuel sufficiency and
native object/name-table extraction remain interfaces, not consequences of a
successful finite decoder test.

=executeCopy= composes target decoding/resolution, source decoding/read and the
resulting store. =decoded_copy_readback= proves the destination contains the
source word and every other place is retained, for arbitrary admitted operands,
tables and memory. Label/constant sources are read values, not destinations.
A missing source still permits metadata assignment. The separate

**** Actual boxing writes and retained roots

The qualified SDK branch uses 64-bit words, one flonum payload word, no handles,
no self-tagging and no NaN boxing. Its header is 2288, heap tag is seven and
reference-to-body offset is one word. These are qualification metadata;
=Boxing.ABI= carries header/tag parameters in the theorem. =allocate= advances
hp by two, writes the header at old hp and the exact =BitVec 64= payload at
old hp plus one. The tagged pointer denotes the header; untagging plus one
selects the payload. Earlier allocated cells are retained.

=Fresh= describes ownership of unallocated addresses, not physically zeroed
memory. =Ready= bounds the two-word write by the physical segment capacity,
not by a GC trigger threshold. =trace_fresh= derives ownership for arbitrary
admitted allocation histories. =tagged_fits= separately requires a representable
capacity. =cache_allocation_root= combines the existing dirty-cache history,
fresh/within-segment writes, actual tagged-header decoding, emitted stack stores
and signed frame-map scanning. It no longer asks the caller for an arbitrary
boxing function plus a matching pointer-readback certificate. Compiler live
flags, segment reservation, slow-path GC, raw address correspondence and other
boxing branches still need their own source adapters. No IEEE arithmetic
correctness or complete allocator theorem is claimed.

**** Ordinary contention is a distinct ordering obligation

The normal macro allocates a ticket using GCC's full-barrier =__sync= operation,
then polls volatile current-ticket storage. The ARM relax macro is empty.
A full barrier before the previous owner's release is not a later acquire of
that release. GCC's [[https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html][volatile contract]] does not order independent nonvolatile
payload storage; the [[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fsync-Builtins.html][legacy atomic contract]] belongs to the atomic operation.
The inspected portions of Pulte et al.'s
[[https://www.cl.cam.ac.uk/~pes20/armv8-mca/armv8-mca-draft.pdf][ARMv8 MCA model]] distinguish load-acquire/barrier ordering from plain
control dependence. Its instruction coverage is not imported as a complete
proof of GCC's LSE atomics or this SDK binary.

=ordinary_poll_stale_history= constructs, for arbitrary positive tickets and
publication epochs, a history that satisfies a payload read before unlock,
observes the matching ticket afterward and consumes the stale value. Logical
poll-before-consume order is retained. =ordinary_poll_not_universal= proves the
negative import result in that explicit weak-observation projection. It is an
obstruction to deriving acquire solely from ticket equality, not an ISA
refinement theorem or a reproduced hardware failure. The corresponding GCC
ARM64 fixture disassembly has =ldaddal= for ticket allocation, ordinary =ldr=
for polling and an ordinary payload =ldr= immediately after the matching branch;
no extra post-poll acquire instruction is present. The normal path is kept
separate from debug history barriers and successful try-lock CAS.

** Responsibilities and shared vocabulary

   failure obligations. Complete-request benchmarks measure the resulting CPU,

*** Viable prefixes, LR construction and state-dependent raw requests

[[file:../../formal/ParserEngine/Viable.lean][Viable.lean]] connects the earlier =Grammar.Predicts= relation, including
=FIRST(beta, lookahead)= and nullable inheritance, to a graph of production/dot
cores. =lr1_closure_erases= preserves production and dot while erasing lookahead.
=lr1_graph_constructed= derives the core graph certificate from LR1 closure/goto
membership and exact item projection. It does not assume a completed item
already describes the runtime stack.

The graph certificate requires initial items to originate in closure of the
augmented seed, and target items to originate in closure of the source items
advanced across that edge. Subset inclusion permits omission of predictions
with no lookahead. No prediction may introduce the augmented production as a
user rule. These are construction obligations, not conclusions from state IDs,
action schemas or an accept state being reachable.

Induction on the actual top-first stack path establishes:

- =item_suffix=: every item's consumed RHS prefix is a suffix of the stack in
  source order, with the dot within the production width.
- =completed_rhs=: the completed production fits the stack and its popped
  symbols, reversed into source order, equal its RHS. Epsilon is included.
- =drop_path=: popping the used prefix retains the earlier graph path.
- =accepting_stack=: a completed isolated augmented production of width one
  implies exactly one start symbol and two physical states. The singleton is
  derived rather than supplied as a request premise.

[[file:../../formal/ParserEngine/RawRequest.lean][RawRequest.lean]] uses these results in one complete deterministic request.
It retains original raw observations separately from chosen grammar terminals.
Only shift commits a terminal and consumes raw input; reduce preserves the raw
suffix and the next query uses the new LR state. Frame derivations, raw input
conservation and the ordered terminal/raw relation are preserved together.
=complete_request= derives a CFG word related to the entire original raw input
from the initial state, a legal trace, exhausted input and a selected accept.
It requires neither a per-reduction RHS premise nor a singleton-root premise.
This is conditional acceptance soundness, not language completeness.

=Lookahead.RowSupported= certifies EOF, exact literal, folded literal and kind
branches. =selected_raw_supported= preserves that certificate through the actual
priority order. =RawRequest.builtin_action_and_terminal= projects it into both
published-cell support and the terminal predicate needed by the request proof.
The certificates remain obligations of the row producer. Mutable Scheme token
fields and effectful custom selectors do not inherit them automatically.

[[file:../../formal/quint/RawRequest.qnt][RawRequest.qnt]] supplies a second connected fixture: =S -> X literal-if |
Y token-word=, =X -> a=, =Y -> b=. The same raw =word/if= observation commits
different grammar terminals in two complete requests. Directed histories cover
retained lookahead through reduction, normal rejection and full acceptance.
Mutations consume lookahead during reduction, commit a state-independent
terminal, accept a prefix or reverse a reduction yield. Each is rejected by the
shared path/derivation/conservation invariant. This is a finite protocol check,
not a proof of native LR table construction.

*** Universal lowering and preparation control flow

This extension moves beyond equality certificates for four publications. Its
main results quantify over arbitrary grammars, recursive derivations and finite
input lengths. Finite Scheme/Quint controls continue to qualify the physical
implementation; they are not the source of those universal results.

The paper anchor is [[https://www.deinprogramm.de/sperber/papers/lr-essence-pepm.pdf][The Essence of LR Parsing, sections 2.1--2.2]]: parser
behavior is specified against the grammar's derivation relation, with an
isolated augmented start production. The source DSL must therefore preserve
CFG derivations before an LR algorithm or specialization can be justified.
The new proof is our lowering construction, not a theorem claimed by that
paper, and no PEG ordered-choice law or specialization speed result is used.

**** Recursive source DSL and emitted-rule correspondence

[[file:../../formal/ParserEngine/Lowering.lean][Lowering.lean]] defines source evaluation and a production schema with
intrinsic expression owners. =lowering_exact= and =named_lowering_exact= prove
soundness and completeness for every finite recursive rule list, expression
and terminal word. Constructors include failure/empty, terminal/reference,
choice/sequence, optional, repeat/repeat1 and terminal-language-transparent
annotations. =choice_list_exact= and =sequence_list_exact= connect arbitrary
source arities to the binary induction. Empty choice is failure; empty sequence
is epsilon. Nullable repeated children are permitted in the mathematical
finite-derivation semantics; native admission policy is a separate judgment.

This is a schema with scoped expression owners, not a claim that Scheme's
physical names already have that type. The native bridge uses finite syntactic
=Expansion= witnesses for emitted productions, including legal unit inlining
and atomic operand erasure. =native_derivation_sound= and =native_root_sound=
quantify over every native CFG and every input word satisfying that structural
bridge. They do not take desired per-input language equality as a premise.

Folding a named source rule into its defining expression additionally requires
=UniqueBody=. One branch of a choice cannot supply that witness for the entire
shared left side. =isolated_repeat_origin= and =isolated_repeat1_origin= prove
the native self-recursive rule shape for arbitrary child expressions and
recursive source contexts when the unique-body premise holds. AST fields,
spans, dynamic precedence, lexical layout effects and an executable verifier for
every native origin/name witness remain outside these terminal-language laws.

**** Arbitrary finite worklists and CFG preparation

[[file:../../formal/ParserEngine/Worklist.lean][Worklist.lean]] models complete publication and dependent notification,
with separate =known=, =delivered= and =pending= lists. Publication admits a fact
once. Initial scanning seeds empty-dependency clauses. Delivery removes pending
work, records it as delivered and scans exactly the affected registered clauses.
The invariants preserve sound known facts, pending/delivered accounting and
closure over delivered dependencies. Queue order does not establish semantics.

=quiescent_exact= derives least Horn meaning for an arbitrary finite program
from its operational history and an empty final pending queue. The caller does
not supply final closure, a successful equality certificate or a fact-set
soundness assumption. The theorem does not prove a termination bound or turn
fuel exhaustion into quiescence.

[[file:../../formal/ParserEngine/Solver.lean][Solver.lean]] compiles the source-shaped programs from any =Grammar.CFG=:

- Nullable clauses retain every nonterminal occurrence, discard terminal-blocked
  nullable clauses and keep undefined references as unsatisfied dependencies.
  =nullable_horn_exact= connects those clauses to =Grammar.Nullable=.
- =notification_enables_exactly= connects native per-occurrence counter decrements
  to the operational enabled test using the existing multiplicity theorem.
- FIRST scans each nullable prefix, emits a seed for the encountered terminal
  and propagates each nonterminal dependency over the finite terminal catalog.
  =prefix_sequence= connects those edges to =Grammar.SequenceFirst=.
- =named_first_in_catalog= proves that the catalog derived from grammar RHS
  terminals covers every semantic FIRST fact. The caller need not guess a
  bound on terminal ordinals.
- =preparation_pipeline_exact= composes both operational histories in native
  preparation order: FIRST consumes the completed nullable publication. Both
  semantic conclusions follow without external final-fact certificates.

These are algorithmic control-flow results for all grammars, rather than a
finite execution of one example. Native bit masks, coalesced two-domain queue
payloads, physical counters, table indexing and shared mutable records still
need representation adapters to the proved transitions. Productive-domain
shortcuts and native termination are not silently included in the nullable and
FIRST claims. The independent native solver/LR controls remain the executable
boundary checks for those adapters.

* Cost model: count work before estimating time

For a logical sequence with R leaf/branch records and N emitted children,
=materializeInto= is an executable suffix builder. =copyLeaf= counts one
emission per recursive cell; branches count one structural visit and combine
child counts. The theorem proves both its output and exactly R + N counted
operations, for arbitrary sequence shape and an arbitrary retained suffix.
The append-based =flatten= is only the reference denotation: its own runtime
is not claimed linear. This recursive Lean algorithm does not prove the
bounded control-stack behavior of Scheme's builder/iterative visitor, nor
cover position views or event-program sequences.

=stackSequence= allocates branches rather than copying accumulated prefixes.
A branch has constant logical construction work; =join_allocations_linear=
counts n branch constructions. Repeated singleton append in the reference
list implementation copies 0 + 1 + ... + (n - 1) prefix cells;
=copied_prefix_triangular= proves 2 C(n) + n = n squared. This comparison
formalizes the engine's existing persistent representation; it is not a new
optimization or a measured speedup. Empty-join normalization is abstracted
away, so logical branch counts need not equal Scheme allocations.

Prepared factories make no provider selections in the modeled request
executor. Interpreted action selections equal the action-list length.
Factory-body costs, field/alias boundary walks, allocations and GC are outside
that selection count. They must still be measured on real requests.

=publicationWork= is an explicit contract charging every source byte and flat
event. Its lower-bound theorem is arithmetic under that contract, not a proof
of the SHA256 implementation or event publisher. Full digest and flat output
prevent a sublinear complete-publication claim even when recognition is local.

* Question: why does this design exploit Scheme and its DSL?

The advantage is staging and higher-order composition, not parentheses alone.
Canonical syntax describes actions once. Engine-owned generic selection turns
those declarations into retained functions; each request supplies its own
children and source anchors. Grammar authors need not select storage, dispatch
or traversal strategies. Scheme closures preserve that separation naturally.

The existing engine pattern is illustrated below; this is an implementation
witness, not a new public DSL form:

#+begin_src scheme
;; src/runtime/reduction-plan.ss: select before repeated requests.
;; Each retained action receives request-local children and offsets.
(prepare-operand-actions field-factory alias-factory actions)
#+end_src

The LeanPoo tuple models selection provenance, while the parser model adds the
ordered context-threading law. A generic method may choose the implementation
at preparation time without forcing generic selection into every child visit.
The three language interfaces remain grammar.ss, parser.ss and parser-test.ss.

* Question: how is the design scientifically checked?

Each claim names its counted operation and assumptions, a kernel-checked
semantic law, a Scheme conformance owner and a measurement owner. The
integration theorem connects preparation to reverse-stack reduction instead
of treating local equalities as a complete parser proof. The materializer
counts the operations of a defined algorithm instead of assigning a desired
linear formula to an unspecified traversal.

The remaining proof boundary is explicit: input/span admission, derivation of
nullable offsets, LR table/CFG soundness, GLR ambiguity, arbitrary external
actions, relocation views, Scheme refinement, digest correctness and reuse
validation are not proved. Operands carry already supplied individual anchors.
Stack-depth preservation requires admitted width; it does not validate goto
entries. No theorem establishes P50/P95, heap bytes or hardware performance.

sources. =event_row_publication= composes those facts: every selected published
action has an origin for that cell, the frozen row is retained, and every
scratch slot is empty for the next state. Neither a final trace nor final
scratch coverage is supplied as a premise. Duplicate touches are permitted;
the native first-install-only catalog satisfies a stronger uniqueness rule.

The model's frozen row is an immutable value. Native =build-actions= copies
entries into a row list before clearing touched action/reduction/shift slots.
Proving that the Scheme vector operations, list allocation and all three
scratch catalogs refine this transition remains a host implementation bridge.
The existing native table-support and injected unsupported-cell controls,
together with repeated complete parsing and the new identity control, test
this bridge; finite tests do not turn it into a universal Scheme proof.
Layout-guard fallback publication and quotient lookahead transport remain
separate composition obligations. No local performance optimization is made.

* Finite storage, retained layout fallback and lookahead transport

** Model composition and actual storage operations

[[file:../../formal/ParserEngine/Construction.lean][Construction.lean]] now refines the earlier function-valued scratch model with
finite =Array= storage. =vector_write_refines= proves a bounded write has the
same read behavior as the logical update; its bound is explicit. In particular,
reading an out-of-range slot as an empty default cannot justify an invalid
write. =vector_clear_refines= proves arbitrary touched-key clearing, including
duplicates, and =vector_clear_covered= derives empty storage from coverage.
This law is polymorphic: action slots use an absent value, raw reductions use
an empty list, and shift targets use absence. Native state/terminal zero
remains a valid present identity.

=vector_event_projection= proves, for every bounded event sequence, that the
finite producer projects to =buildEventScratch=. =vector_event_publication=
then derives action origins from copied-list reads and empty vector storage
for the next state. No completed trace or coverage certificate is supplied.
The finite model represents array reads/writes and immutable row values; it
does not mechanize the Scheme heap, Gambit allocation or the C backend.
Native correspondence still requires the producer's bounds, catalog ordering
and copy discipline. The actual =build-actions= allocates each row with
=map/cons= before clearing its three reusable vectors.

** Layout fallback is a separate origin channel

Ordinary precedence resolution can select a shift and suppress a reduction.
[[file:../../src/compiler/lr-compiler.ss][build-actions]] retains every raw reduction for that terminal when layout is
enabled. A selected shift and a nonempty raw list publish a =layout-guard=.
[[file:../../src/runtime/layout.ss][layout-ordinary-entry]] chooses its primary shift when indentation permits it,
and the retained reduction or reduction fork otherwise. An ordinary fork is
filtered to exclude shifts when shifting is blocked.

=publishLayout= and =selectLayout= express these actual branches.
=raw_reductions_origin= derives fallback provenance from raw reduce events;
it does not assume that fallback survived ordinary precedence resolution.
=layout_replay_supported= composes event admission, concrete policy replay
and either layout outcome into semantic cell support. =cellEvents= restores
chronological order from the newest-first catalog before fallback publication;
=cell_events_origin= retains terminal ownership. =vector_layout_publication= combines finite storage,
resolved primary actions, same-cell raw fallbacks and scratch clearing in one
arbitrary-event-sequence contract. Substituting =CellSupported= for its origin
predicate connects the result to the existing table/request boundary.

This origin theorem holds for both eligibility outcomes. It does not prove
that native source columns, marker priority, frame push/pop or branch-local
restoration compute the correct eligibility outcome, nor that precedence and
layout preserve every canonical derivation. Those are separate language and
request-context obligations.

** Lookahead: activation, shift and quotient positions

The LR paper's =FIRST(beta, inherited)= premise is retained by
[[file:../../src/compiler/lr-lookahead.ss][propagate-lalr-lookaheads]]. Static suffix FIRST is emitted at first activation;
a nullable suffix additionally forwards new inherited bits on every activation.
=suffix_evidence_exact= proves the per-activation law, and
=suffix_delivery_exact= proves its union for arbitrary finite delta histories.
An empty history emits nothing. A nonnullable suffix never forwards an
inherited EOF merely because its parent has one. =suffix_evidence_allowed=
connects the masks to =Grammar.LookaheadAllowed= under explicit completed
FIRST/nullable and terminal-decoding premises. =suffix_prediction_supported=
then composes it with the real parent item, child production/lhs and zero dot
into =LR1Closure=. =shifted_lookahead_retained= covers the distinct shift edge,
which advances the dot without changing production or lookahead.

[[file:../../src/compiler/lr-partition.ss][materialize-partition]] unions member masks at the same item position after
choosing a group's representative core row. =union_masks_exact= proves the
actual accumulator recurrence bit-for-bit for arbitrary masks and member
counts. =quotient_lookahead_origin= additionally retains core-order alignment
and CSR-style offsets: every merged bit has a canonical member with that same
physical core at that position. Equal lengths or equal unordered core sets
are insufficient. The alignment premise is therefore explicit, alongside the
separate refinement/interner contracts; it is not inferred from a source hash.

These results discharge transfer safety and exact finite union, not native
fixed-point termination or a complete quotient/canonical language-equivalence
proof. The existing worklist/quiescence theorems remain distinct owners of
least-fixed-point completion. Canonical closure's full-mask queue and the
forward/backward follow-partition graph producers still require their own
whole-execution refinements.

* Operational heap, finite scheduler progress and dynamic layout

** Shared operational boundary

[[file:../../formal/ParserEngine/Operational.lean][Operational.lean]] collects the operational adapters for the existing
construction and request models. It adds one shared primitive vocabulary,
not another language-author entrypoint. The paper obligations remain separate:
finite monotone publication needs an actual progress argument; heap identity
is distinct from structural equality; and dynamic context must be restored
when a branch exits. These adapters refine those obligations under explicit
primitive and ownership protocols. They are not a Scheme interpreter or a
proof of the Gambit compiler, collector, FFI or machine-code backend.

** Heap addresses, tags and publication

=Heap.Store= contains addressed atom, pair and vector objects. Allocation
appends a fresh object, and =allocation_identity= / =allocation_is_fresh= prove
its readback and freshness. =writeVector= checks the object tag and slot bound;
wrong-tag and out-of-range operations fail without changing storage.
=failed_write_atomic= proves that error boundary.

=Heap.Frozen= describes the recursively readable pair/atom graph of a published
row, including shared subgraphs. It excludes a mutable vector at any node.
=vector_update_retains= and =publication_survives_trace= prove that arbitrary
allocation/vector-write histories preserve the same published tree. They do
not assume that all objects at different addresses are unaliased: vectors can
point to shared actions, while actions have no path back to their vector owner.
A checked counterexample shows why retaining a vector alias is different.

The native bridge is the actual =map/cons= publication in
[[file:../../src/compiler/lr-compiler.ss][build-actions]], followed by =vector-set!= cleanup. The new Scheme control
retains actual compiled action rows, clears their mutable vector owner,
checks the pair graph and contents survive, and checks wrong-tag/out-of-range
setters leave it unchanged. A live-vector alias is a negative control.
The trace protocol does not allow pair/string mutation through external
aliases. Logical addresses represent object identity; allocator address reuse,
moving GC, cycles and arbitrary foreign mutation remain outside this model.

=Heap.PrivateTrace= supplies a separate ownership law for request-local mutable
objects. New request allocations start at a heap frontier; writes/replacements
must target objects owned at or beyond that frontier. The replacement case
also covers private packed-buffer updates without pretending their scalar
slots are Scheme pointers. =private_trace_retains= proves every older object's
contents remain readable, including mutable outer column objects. An arbitrary
callback that mutates an older object violates this explicit protocol.

** Progress is distinct from quiescent correctness

The existing =Worklist.quiescent_exact= proves correctness at an empty queue.
The new =Scheduling= adapter adds a finite progress measure:

#+begin_example
rank = 2 * remaining unpublished facts + queued owners
#+end_example

A publication must remove at least one fresh finite-domain fact. It can add
at most one queue owner; an already queued owner is coalesced. A drain removes
one queue entry. =step_decreases= proves strict decrease in either case, and
=trace_length_bound= bounds any such execution by its initial rank.
=native_delta_progress= connects a nonzero native mask difference to an actual
fresh catalog fact using =Encoding.difference_fresh=, the terminal bound and
the current mask/catalog representation. Old evidence returns the unchanged state by =stale_publication_noop= and
cannot be admitted as a progress transition. =finish= is well-founded recursion without timeout fuel;
=finish_stopped= proves it returns at the scheduler's stop condition, and
=finish_quiescent= derives an empty queue when nonempty queues enable progress.

The exact forward-partition guard also receives its own proof.
=partitionRounds= recurses only when the new group count strictly increases
and remains below the node count. =partition_round_bound= proves at most
=nodes - initialGroups + 1= rounds, including empty and singleton domains.
This matches [[file:../../src/compiler/funcs.ss][compiler-index-partition-refine]], rather than treating an arbitrary
changed flag as progress. Its native control checks chain sizes 0, 1, 2, 3, 8
and 16. The native LALR delivery control checks that actual dequeues do not
exceed the physical item-node/terminal domain on three grammar families.
These are operation bounds, not CPU measurements.

Finite callback execution and the mask/catalog representation are still
producer obligations. The backward follow-block changed flag and canonical
state-interning queue have separate producers; the forward round theorem is
not silently applied to them. Completing those source-level refinements and
their relation to semantic quiescence remains distinct from termination of
the finite operational model.

The installed Gerbil source was checked at =gerbil/runtime/control.ss=:
=call-with-parameters= delegates one parameter to =##parameterize1= and nests
multiple bindings. The model follows those scoped bindings and stack unwinding;
it does not substitute an exception-only cleanup combinator for parameter
restoration. Runtime source requests bind fresh columns and empty frames in
[[file:../../src/runtime/parser.ss][parse-tokenized]], and layout shifts/ends bind branch-local frames in
[[file:../../src/runtime/lr-parser/batch.ss][the materialized driver]].

=Layout.shiftAllowed=, =nextEligible=, =afterShift= and =afterEnd= model the
actual column/lexeme rules in [[file:../../src/runtime/layout.ss][layout.ss]]. The frame stores the marker's final
byte column, not its exclusive end. =token_final_byte_in_bounds= retains the

with the actual frame/column eligibility computation. An eligible next marker
cannot close a frame, even if its lexeme is a declared closing boundary.

** Reachability, relocation and suspended roots

=Collection.Reachable= follows pair edges and vector slots from an explicit
root set. =Relocation= requires each reachable cell to be copied with renamed
references and the address map to be injective on reachable objects.
=frozen_survives= preserves a published immutable tree by induction over its
heap representation. =identity_survives= preserves equality of live references;
=private_owner_survives= preserves separation from retained live owners.

A numeric allocation frontier is not invariant under a moving collector.
The post-collection ownership statement therefore uses renamed live reference
sets, rather than comparing relocated addresses with the old frontier.
=suspended_publication_survives= explicitly includes captured continuation
roots alongside active roots. Omitting a suspended root prevents application
of the theorem; Quint includes that invalid-root-set control.

This is a collector contract, not a verification of Gambit's collector,
root discovery, foreign-pointer pinning or concurrent collection. Opaque atom
values carry no modeled heap references. The theorem does not permit foreign
mutation of a published tree.

** Dynamic extent and repeated reentry

=Reentry.commonPath= compares activation identities along the two wind paths.
Equal parameter values do not establish a shared activation. =resume= checks
and exits departed activations from inside to outside, preserves the shared
prefix, then enters target activations from outside to inside.
=resume_captured_path= derives the resulting stack through these operations;
=repeated_resume= admits repeated use of the same captured path without a
one-shot flag. =captured_context_restored= selects the captured layout context.
=captured_column_survives= connects its column reference to the relocation
contract and the captured root set.

The native control captures a continuation in the real LR action selector
following a layout shift, escapes the inner parameter scope, forces GC, and
resumes that continuation twice. Both resumed requests finish parsing, with
inner frame/column contents restored and outer frame/column identities and
contents restored on return. Inner wind hooks run three times in each
direction, while the shared outer extent enters and exits once. The action
rows are compared with an independent recursive pair snapshot after GC.

The logical activation environment follows the engine's scoped parameter
bindings. Arbitrary mutation of captured parameter cells and arbitrary effects
of wind hooks are outside this model. This is not a complete Scheme
continuation interpreter, a proof of forced thread termination, or a Rust
cancellation proof.

** Backward follow-block refinement

The actual backward builder in
[[file:../../src/compiler/lr-follow-automaton.ss][lr-follow-automaton.ss]] computes successor-signature buckets inside each
old block. Its changed flag means that at least one old block produced more
than one bucket. Initial blocks in
[[file:../../src/compiler/lr-conflict-candidates.ss][lr-conflict-candidates.ss]] are created from actual follow bits and are
nonempty. The model retains that essential premise.

=Backward.insert= and =buckets= construct the buckets; =buckets_mass= proves
exact occurrence preservation and =buckets_nonempty= proves each emitted
bucket is nonempty. =refine= never merges different old blocks.
=changed_grows= derives strict block-count growth from the constructed bucket
predicate, rather than assuming that any changed flag implies progress.
=rounds= recomputes signatures at every round and recurses on the measure
=vertices - blocks=. =round_bound= bounds the complete run by the initial
measure plus one. Quint demonstrates why empty old blocks invalidate that
argument. Native controls check positive, pairwise-disjoint block masks and
exact coverage of each core's forward follow mask.

Native bitset enumeration, successor-index equality, cache invalidation and
active dependency scheduling remain representation and producer obligations.
The round theorem alone does not prove these adapters or semantic quiescence.

** Canonical closure and interning

The canonical closure in
[[file:../../src/compiler/lr-lookahead.ss][lr-lookahead.ss]] can append an owner already pending when new mask bits
arrive. This differs from the coalesced LALR scheduler. The canonical model
retains duplicate queue entries: =closure_enqueue_decreases= proves progress
with =2 * remaining facts + pending owners= because every publication consumes
at least one fresh fact. A stale publication is unchanged.

For physical core count C and terminal count T, =matrices= enumerates every
length-C mask vector bounded by 2^T. =catalogue= converts them to sparse keys,
omitting zero masks in physical core order. =native_key_admitted= proves
membership for arbitrary bounded input vectors; =catalogue_count= derives
catalogue size (2^T)^C. This is a finite upper bound, not an expected state count
or a performance claim. Native tests reconstruct dense vectors from real
canonical states and check their normalized sparse keys, mask bounds, key
uniqueness, state zero and transition endpoints.

=Canonical.intern= reuses existing keys without enqueueing them and appends
only novel keys. =Admitted= carries unique discovered keys, catalogue
membership and =pending + processed = discovered=. =admit=, =removeHead= and
=expand= preserve those invariants. =finish= runs the complete drain/expand
loop by well-founded recursion on
=2 * (catalogue size - discovered keys) + pending owners=.
=finish_quiescent= derives an empty queue and =finish_processes_all_keys=
derives equality of final processed and discovered counts. These results do
not assume a final execution certificate supplied by the caller.

Targets must be finite, catalogue-admitted and generated by a terminating
callback. Relating native hash tables, queue identities and target generation
to these operations remains a source-level refinement obligation. In
particular, the native builder's returned state count is not an independently
instrumented dequeue count; the test does not use it as such. Neither the
catalogue bound nor queue accounting proves language completeness or conflict
resolution semantics.
